# docs/design/version-history/ — 视频的版本记录

不依赖 git 的版本记录。每部视频在自己的目录里保存两样文本：

- **最新快照**：当前状态，行稳定的排版；
- **最近版本**：最近 10 个版本，每个是一份 unified diff，开头列出这一版的操作。

按版本回滚靠这串 diff。`video.db` 仍是唯一的权威（[架构设计 §5.1](../../architecture/architecture-design.md#51-存储分层)），快照与版本是派生物。项目在 git 仓库里时，快照随时可以提交。

| 文件 | 内容与状态 |
| --- | --- |
| [`version-history-design.md`](version-history-design.md) | **方案稿（2026-10-17；一期、二期已实现，与方案不同之处见 §12；三期方案见 §13，待确认）**：三层历史（撤销、版本、可选的 git）、工作区快照的投影与行稳定序列化、版本的边界与版本文件、回滚靠 diff 而动作清单用来读、保留与清理、回到版本与保存版本、重建与外部改动的导入、可选的 git（忽略规则、代为提交、安全）、多端与智能体、实现与分期、待评审事项 |

一期（快照、版本、回到与保存版本、重建、协议与智能体工具）、二期的外部改动导入（导入为「外部变更」、两边都改了时的选择）、版本记录面板与冲突提示，以及 git 桥（后端、协议、CLI、智能体工具与项目设置里的 git 一节：代为提交、自动提交、初始化、本地过滤器的闸门）已实现，规则以[视频格式规范 §9](../../spec/video-format-spec.md#9-工作区快照与版本文件)与[架构设计 §5.12](../../architecture/architecture-design.md#512-视频的版本记录)为准。还没做的（项目设置里的版本频率、项目级的设置、视频主题推送版本的变化）见设计 §12。三期（文档、幻灯片、设计稿与设计系统纳入版本记录，以及合并参数、摘要与便携包的建议）见设计 §13，待用户确认。用户可见界面在实施前须原型先行。
