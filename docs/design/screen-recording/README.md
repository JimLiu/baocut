| 格式版本 | 版本 4：写出去的一律是 4，版本 3 的视频照常打开、第一次被改时升上来 | 规范 §1.4 |

## 3. 数据怎么分层

| 层 | 存什么 | 在格式里是什么 | 谁能改 |
| --- | --- | --- | --- |
| 录下来的事实 | 媒体、鼠标事件、光标图片、分段与对时 | 素材 + 录制清单 | 写好之后不改 |
| 编辑意图 | 片段的剪辑与布局、缩放区间、光标样式 | 实例、联动组、屏幕取景文档 | 用户与智能体，经事务 |
| 派生结果 | 取景曲线、光标曲线、帧计划、缓存 | 不进格式 | 按输入与算法版本重算 |

两条容易漏的规则都写进了规范：

- **各路流不保证同时开始。** 摄像头比屏幕晚 400 毫秒，就晚 400 毫秒出现，不把它的第一帧对到屏幕的第一帧。断流的区间画面露出下层、声音是静音，不停在最后一帧。
- **有轨迹不等于光标能换。** 光标录进了画面（`baked`）时轨迹只用来取景；界面要关掉隐藏、放大、替换光标这些做不到的选项。

## 4. 参考：Cap 的数据怎样对应

BaoCut 不用 Cap 的代码，也不把导入 Cap 工程当成一个阶段（[§8](#8-许可与-cap)）。下表留作参考：定格式时逐项对照过 Cap Studio 模式的工程（`recording-meta.json` 的 `MultipleSegments`），它说明这套格式装得下一个成熟录屏工具录下的全部事实，也是自己写录制后端时核对「有没有漏记」的清单。以后要是做「导入 Cap 工程」这个可选功能，换算照这张表。

| Cap（`crates/project`） | BaoCut | 换算 |
| --- | --- | --- |
| `segments[i]` | 清单的一段 `segments[i]` | 段的长度取这一段屏幕流的有效长度；各段首尾相接 |
| `display`、`camera`（`VideoMeta`） | `screen`、`camera` 流，视频素材 | `start` = 段的 `t0` +（这路的 `start_time` − 这一段最晚的 `start_time`） |
| `mic`、`system_audio`（`AudioMeta`） | `microphone`、`system-audio` 流，音频素材 | 同上 |
| `cursor`（每段一个 JSON：`moves`、`clicks`） | `pointer` 流，指针轨素材 | `time_ms`（浮点毫秒，从这一段的管线起点算，流的 `start_time` 也从这个起点算）换成整数刻度，所以 `start` = 段的 `t0` − 这一段最晚的 `start_time`。Cap 自己的渲染也是这样对的：查光标用的时间是段内时间加上最晚的 `start_time`（`crates/rendering/src/segment_timing.rs` 的 `segment_frame_times`）。还没有拿真实录制实测；每条事件上的 `cursor_id` 换成 `cursors` 的切换表；`clicks` 的 `cursor_num` 是按键编号 |
| `cursors`（`CursorMeta`：图片、`hotspot`、`shape`） | 清单的 `pointer.cursors`，图片素材 | `hotspot` 在 Cap 里已经是图片宽高的比例，照搬 |
| 移动事件的 `x`、`y` | 指针轨的坐标 | 已经是相对捕获区域的归一化坐标，窗口录制时跟着窗口走；在区域之外的值越出 [0, 1]，照搬不夹 |
| `status`（`InProgress`、`NeedsRemux`、`Failed`、`Complete`） | 不进格式 | 只有 `Complete` 的工程可以导入 |
| `keyboard`（`presses`：`key`、`key_code`、`time_ms`、`down`） | `keyboard` 流，键盘轨素材 | 键名换成 UI Events 的 `code` 与 `key`（规范 §4.10）；时间的换算同 `cursor` |
| `ProjectConfiguration` 的 `zoomSegments`（`start`、`end`、`amount`、`mode`） | 屏幕取景文档的 `zooms` | 可选：`auto` → `focus: pointer`，`manual {x, y}` → `focus: point`；时间从 Cap 的编辑时间换回录制时间 |
| `ProjectConfiguration` 的 `camera`（位置、大小、形状、镜像） | 摄像头实例的 `place`、`mask`、`flipX` | 可选：只换成初始布局 |

录制产物进视频在一笔事务里完成（自己的录制后端同样）：登记素材、写清单、写一份屏幕取景文档、按 `coverage` 放实例并登记联动组。事务失败时没被引用的文件由现有的清理回收；重试用同一个 `commandId` 找回回执，不重复插入。

## 5. 时间线上的样子

一次录制默认显示成一个可以展开的组：

| 行 | 是什么 | 能做什么 |
| --- | --- | --- |
| 录制 01 | 联动组 | 整组移动、拆分、修剪、变速 |
| 屏幕 | 视频实例，`role: 'screen'` | 剪辑、裁剪、布局 |
| 屏幕 · 缩放 | 屏幕取景文档的 `zooms` | 拖边界、改倍率、改焦点 |
| 屏幕 · 鼠标 | 指针轨的点击标记与文档的 `pointer` | 改样式、平滑、点击提示 |
| 摄像头 | 视频实例，`role: 'camera'` | 位置、大小、圆角、镜像、显隐 |
| 麦克风 | 音频实例，`role: 'microphone'` | 音量、转录、混音 |
| 系统音频 | 音频实例，`role: 'system-audio'` | 音量、静音 |

「缩放」与「鼠标」是屏幕实例的附属行，显示文档的内容，不是新的轨道种类。摄像头的布局预设（右下角圆形、左下角圆角矩形、左右分屏、摄像头全屏、某一段隐藏）都落在现有的 `place`、`mask`、`enabled` 上。界面改动属于「复杂」一档，先做原型。

**录完之后怎么编辑。** 停止后直接进现有的编辑器，不另开一个录制专用的编辑界面。每项编辑都落在已有的字段上，格式表达不了的不做成功能（[§14](#14-待评审事项)）：

| 想做的事 | 怎么做 | 落在哪里 |
| --- | --- | --- |
| 剪掉说错的、停顿的 | 文稿里删句子、时间线上拆分与修剪、剪口播的固定流程；都按组进行，屏幕、摄像头与声音一起动 | 联动组的时间编辑（规范 §3.18），剪口（§6.7） |
| 调某一次放大 | 「屏幕 · 缩放」行上拖区间的两端、拖动整段；检查器里改倍率、过渡长短、跟随鼠标或固定看一点；固定看一点时在舞台上拖取景框 | 取景文档的 `zooms[].t0 / t1 / scale / focus / rampIn / rampOut`；改过的自动区间记 `edited` |
| 加一次放大、删一次放大 | 缩放行的空白处拖出一段；选中后按删除 | `zooms` 加一项（`origin: 'manual'`）或去一项 |
| 重新自动缩放 | 检查器「屏幕取景」一节的「重新生成」；只换没改过的自动区间 | `zooms` 里 `origin: 'auto'` 而且没有 `edited` 的项（[§6](#6-自动缩放)） |
| 镜头跟得紧一点或松一点 | 检查器的两个滑块：安全区、平滑 | `follow.safeArea`、`follow.smoothing` |
| 光标的大小、平滑、静止隐去、点击提示、不显示 | 检查器「光标」一组；光标录进了画面（`baked`）时整组置灰并说明原因 | 取景文档的 `pointer` |
| 摄像头放哪、什么形状 | 舞台上直接拖与缩放；检查器里的布局预设（角落圆形、圆角矩形、左右分屏、摄像头全屏） | 摄像头实例的 `place`、`mask`、圆角、镜像 |
| 某一段不要摄像头，或换一种布局 | 在那一段的两端拆分整组，再改中间那一段的摄像头实例 | 拆分出的实例各自的 `enabled`、`place`、`mask` |
| 屏幕不铺满，留边、圆角、阴影 | 检查器的「演示样式」预设：全屏，或缩小留边 | 屏幕实例的 `place`、圆角与 `fx.shadow`（规范 §3.9），底色是 `canvas.background`（§3.2，只有纯色）；要图片背景就在下层放一个图片实例 |
| 声音 | 麦克风与系统音频各自的音量、淡化、静音；降噪、响度沿用现有的音频功能 | 两个音频实例的混音字段（§3.9） |
| 字幕 | 对麦克风转录，再做字幕层；与普通视频相同 | 转写文档与字幕层 |
| 做竖屏版 | 现有的短视频取景（`focalPoint`、`panels`）；有 `panels` 的实例不能同时有屏幕取景，改竖屏时界面提示二选一 | 规范 §3.18 的约束 |
| 整组拆开各剪各的 | 组的菜单「解组」 | `unlinkItems` |

选中屏幕实例时，检查器多出「屏幕取景」一节（缩放区间的列表、跟随、光标、重新生成），其余各节不变。Web 端可以做上表里全部的编辑，只是不能录。

## 6. 自动缩放

分三步，都不需要大模型：

1. **什么时候放大。** 读有效录制区间里的按下事件，在每次点击前后留出一段，挨得近的并成一段，丢掉太短的。结果写成 `origin: 'auto'` 的缩放区间。数值见规范 §4.9「求值算法 1」。
2. **看哪里。** 指针在可见区域中间的安全区里移动时镜头不动，越出去才跟；可见区域不露出画面之外；用户给了固定焦点就用它。
3. **按时刻取值。** 曲线由文档、清单、指针轨与算法版本确定地算出来，任意时刻可以直接取值，不依赖播放顺序。

导入录制时，清单与取景文档那一笔之后紧跟一笔 `regenerateAutoZooms`，生成第一批自动区间；`--no-auto-zoom`（选项 `autoZoom: false`）或实际的鼠标模式是 `none`（没有指针轨）时不调。这一笔被引擎拒绝时导入照常完成，任务带一条警告。

重新生成（`regenerateAutoZooms`）只替换没被改过的自动区间。智能体在这些区间上再调整（「这一段保持全景」「这两次点击合成一次」）。

## 7. 进程与职责

- **Recording Worker**（新进程，与 `engine-host` 并列，自己实现）：枚举屏幕、窗口、摄像头与声音设备，处理系统权限，倒计时、开始、暂停、恢复、停止，采集与编码各路流，记鼠标与键盘事件，收尾与恢复，产出一个可以导入的录制包。控制消息沿用 Worker 的 JSON 行协议。摄像头的预览不经 Worker，见下面「摄像头预览」。
  - 采集直接用系统接口：macOS 是 ScreenCaptureKit（屏幕、窗口、系统音频）与 AVFoundation（摄像头、麦克风），Windows 是 Windows.Graphics.Capture、WASAPI（含回环）与 Media Foundation。编码沿用 BaoCut 已有的硬件编码路径。平台专属代码条件化（开发流程 §4）。
  - 各路流打同一个单调时钟的时间戳，清单的 `start` 与 `coverage` 由它算出；不为了与别的流对齐而丢帧或补帧。唯一的补帧是下面「画面静止时」的重复帧，它不改变哪一段有内容。
  - **开始时要有画面**：`start` 等到屏幕那一路第一帧完整的画面才回答（最多三秒），没有画面就失败，不会只录到声音。
    - 选的窗口此刻没有画面（被隐藏、最小化、不在当前桌面上，或者屏幕锁着）：Worker 报 `SOURCE_NOT_CAPTURABLE`，Runtime 换成 `RECORDING_SOURCE_NOT_CAPTURABLE`，请用户把窗口放回屏幕上。
    - 整屏与区域等不到画面：`CAPTURE_UNAVAILABLE`。
    - `sources` 只列出在当前屏幕上的窗口，但窗口可能在列出与开始之间被收起，所以开始时还要再挡一次。
  - **窗口的位置与次序**：`sources` 的窗口表按从前到后排好，每个窗口可选地带 `order`（0 在最前）与 `bounds`（`displayId` 与 `displays[].id` 同一套，`x`、`y`、`width`、`height` 是逻辑点、相对那块屏幕的左上角），供界面按窗口边界画高亮。跨屏的窗口归到相交面积最大的屏幕，坐标可以为负或越界；与哪块屏幕都不相交（Windows 上最小化）时没有 `bounds`，问不出次序时没有 `order`。macOS 取 `SCWindow.frame` 减去 `CGDisplayBounds` 的原点（都是左上原点、主屏为基准的全局点，与 Electron `screen` 的坐标一致），次序取 `CGWindowListCreate`；Windows 取 `DWMWA_EXTENDED_FRAME_BOUNDS` 减去显示器左上角再除以缩放比例，次序取 `EnumWindows` 的 Z 序。两项都是后加的可选字段，旧的 Worker 不给。
  - 输出文件的容器与编码：
    - 画面（屏幕、摄像头）是 MPEG-4 里的 H.264：8 位 4:2:0，宽高取偶数，不重排帧（没有 B 帧），关键帧至少两秒一个。
    - 测试用的假 Worker 合成的画面同样用 H.264：浏览器不认 MPEG-4 Part 2，那样的文件在编辑器里报「源文件无法播放」。
    - 声音（麦克风、系统声音）是 M4A 里的 AAC。
    - 采集中每秒写一个分片（第一个分片半秒），崩溃后已经写下的分片读得出来。正常收尾后是普通的 MP4：一个 `mdat`，`moov` 在文件末尾。
    - **画面静止时**：写入端至少每半秒写一帧，把上一帧完整的画面换到当前时刻重写一次。系统在画面不变时不送新画面，只写真帧的话，静止期间被强杀会丢掉最后一个分片之后的全部画面，开头就静止的文件读不出来。补了帧之后，崩溃最多丢最近一秒多。窗口被收起时系统什么都不送，由定时器一秒补一帧。
    - 这几种文件编辑器的 `<video>` / `<audio>` 直接播放，不做兼容副本（`media.playback` 只处理 WebM 与 QuickTime）。
    - 收尾时读不出时长的流不进录制包：丢掉这一路并记一条警告，没有可读画面的段整段丢掉。所以写坏的文件进不了时间线。
  - 鼠标：缺省让系统不把光标画进画面（两个平台的采集接口都有这个开关），另记位置、按键与光标图片，清单的 `pointer.mode` 是 `separate`；拿不到不带光标的画面时是 `baked`。
  - 键盘：缺省不录。用户打开时缺省只录快捷键（清单的 `keyboard.scope: 'shortcuts'`），「全部按键」要单独选，界面说明它会录下输入的文字；系统的安全输入（密码框）期间拿不到按键，也不补。macOS 上监听键盘要「输入监控」权限，与录屏权限分开申请。
  - Windows 的规则（代码在 `crates/recording-worker/src/platform/windows/`，**没有在 Windows 上运行过**，见 [§9](#9-分期与验收) 的现状与 [§14](#14-待评审事项)）：
    - 缺省不开放：`hello` 回答 `supported: false`、`reason: "windows-capture-unverified"`，`sources` 只报空的来源，`start` 以 `UNSUPPORTED_PLATFORM` 拒绝。开发时在 Worker 的环境里设 `BAOCUT_RECORDING_WINDOWS_EXPERIMENTAL=1` 才启用（Runtime 只看 `hello.capture.supported`，TypeScript 一侧不用改）。实机验证通过之前不去掉这个开关。
    - 时钟：所有流都在 QPC（`QueryPerformanceCounter`）上，清单的 `start` 与 `coverage` 由它算出。屏幕帧的 `SystemRelativeTime` 与 WASAPI 的 `pu64QPCPosition` 本来就是 QPC；摄像头样本的时刻在 `MFGetSystemTime` 的时钟上，第一帧时换算一次。
    - 坐标：进程声明每显示器 DPI 感知 v2，Win32 给的都是物理像素。`sources` 报的宽高与区域的 `rect` 是逻辑单位（物理像素 ÷ 缩放比例，与 macOS 的「点」同义），`capture` 是物理像素。显示器 ID 是设备名（`\\.\DISPLAY1`），窗口 ID 是窗口句柄的十进制值，摄像头 ID 是设备的符号链接，麦克风 ID 是音频端点 ID。
    - 画面：Windows.Graphics.Capture 录整屏、窗口；区域录制是整屏帧里裁出的一块。帧在 CPU 上换成 NV12（BT.709、16–235），Media Foundation 的 Sink Writer 压成 H.264（硬件编码优先，High profile，不要 B 帧，关键帧两秒一个）。窗口改了大小，编码尺寸不变，画面左上对齐，余下是黑。
    - 文件：录制中写分片 MP4（`MFTranscodeContainerType_FMPEG4`），崩溃后已写下的分片可读；一段正常结束后不重新编码地转成普通 MP4（Source Reader 读出、Sink Writer 原样写入），转不成就留下分片 MP4（照样可读，记一行日志）。
    - 声音：WASAPI 共享模式，先请系统转成 48 kHz 立体声 16 位，不行用混音格式自己转；只收 44.1 / 48 kHz。系统声音是默认输出设备的回环。回环在没有声音时不送包，Worker 补静音，声音的长度与段一致。
    - 光标：`GraphicsCaptureSession.IsCursorCaptureEnabled`（Windows 10 2004 起）控制画面里有没有光标；没有这个属性时退到 `baked`。光标图片取自 `GetCursorInfo` + `GetIconInfo`，`scale` 是 1（光标位图按物理像素画在屏幕上）。
    - 键盘：低级键盘钩子（`WH_KEYBOARD_LL`），不需要权限，`sources` 的 `inputMonitoring` 报 `granted`。`code` 由扫描码与扩展位换成 UI Events 的 `KeyboardEvent.code`；`shortcuts` 时 `key` 是空字符串。以管理员运行的窗口里的按键收不到。
    - 黄框：Windows 11 起先请求 `GraphicsCaptureAccess`（`Borderless`）再关掉捕获时的黄色边框；请求不成就照旧有黄框。
    - 排除应用做不到：Windows.Graphics.Capture 录整屏时没有排除别的进程窗口的接口，`exclude` 被忽略（记一行日志）。BaoCut 自己的窗口要不被录进去，只能由桌面端自己声明（`SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`，Electron 的 `setContentProtection`），这不在 Worker 里，还没有做。
- **Runtime**：持有录制会话与状态，管 Worker 的启动、停止与恢复，核对录制产物，经现有的 `edits.apply` 提交导入。停止的确认只表示命令收到了，素材可以编辑之前都不算成功：录制中、停止中、收尾中、可导入、导入中、已进时间线是六个不同的状态。开始之前另有三个：等待开始（面板开着，还没有采集）、准备中（启动设备、核对权限）、倒计时；录制中可以进出「已暂停」。任何一步失败进「失败」，用户主动丢弃进「已丢弃」，两者都把已经写下的临时文件留到用户确认删除或恢复之后（[§11](#11-入口与录制过程)「收尾与恢复」）。
- **失败的录制**：开始采集之前就失败的（Worker 起不来、系统拒绝权限、找不到来源），会话以「失败」留在 Runtime 里，`recordings status <id>` 与 `recordings list` 照样查得到状态与错误（`--no-wait` 之后才知道为什么没录成）；什么都没录，临时目录随即删掉，所以不能恢复（`RECORDING_NOT_RECOVERABLE`）。它留到用户丢弃（`recordings discard`）或 Runtime 重启为止，最多留最近的 10 次。主动取消（关掉面板、倒计时中停止）与丢弃的会话随即去掉，之后查不到（`RECORDING_NOT_FOUND`）。开始采集之后的失败按上一条：可导入的留着目录，等恢复或丢弃。
- **自己的窗口**：整屏与区域录制缺省不录进 BaoCut 自己的窗口。Runtime 在 `start` 里给 Worker 一份排除名单（`exclude`：bundle id 与进程 ID），macOS 上 Worker 用 `SCContentFilter initWithDisplay:excludingApplications:exceptingWindows:` 把这些应用的窗口挖掉，桌面与程序坞照常录。名单是打包的桌面端（`com.baocut.app`），加上桌面端拉起 Runtime 时的父进程（开发态的桌面端 bundle id 不同，按进程认）。录制选项 `includeSelf: true`（命令行 `--include-self`）不排除；录单个窗口时不排除（选的就是那个窗口）。
- **摄像头预览**：录制面板里的小预览由界面自己用浏览器的 `getUserMedia` 取，Worker 不提供预览通道。
  - 选它而不是 Worker 的低分辨率预览帧：预览只在面板开着、还没开始录时要，`getUserMedia` 在 Electron 里现成可用，不必给 Worker 加一条传图片的通道，也不必让 Worker 在开始之前就占着摄像头。代价是浏览器的设备 ID 与 Worker 的不同。
  - 规则：界面在调 `recordings.start` 之前停掉预览的每一条轨道，释放摄像头，再由 Worker 打开同一个设备。
  - 对设备按名字配：浏览器的 `deviceId` 是按来源加了盐的散列，不是 `recordings.sources` 里的设备 ID；两边的名字都来自系统的设备名。
  - 授权：`getUserMedia` 与 Worker 的摄像头权限都记在桌面端的应用上，系统的授权窗口最多弹一次。用途说明（Info.plist）属于桌面端的打包。
  - Web 没有录制入口，所以没有预览。
  - 未验证：预览释放之后 Worker 打开同一个摄像头没有冲突。验证用的电脑上没有摄像头，摄像头也没有授权过。
- **VideoEngine**：仍是唯一的写入端。登记素材与文档、放实例、登记联动组、执行成组的编辑、维护撤销与导出冻结。
- **录的是哪台机器的桌面**要明确：桌面端提供录制入口；Web 端继续编辑已经导入的录制，远程的 Web 会话不能把服务器的桌面当成用户的桌面。首版只做 macOS 与 Windows。

## 8. 许可与 Cap

**已定（2026-11-15）：录制后端尽可能不用 Cap，自己实现。**

- Cap 的根许可证：`cap-camera*`、`scap-*` 两个 crate 家族是 MIT，其余（包括 `cap-recording`、`cap-project`、`cap-rendering`、`cap-cursor-*`）是 AGPLv3。BaoCut 用自己的 Community License，与 AGPL 不能默认兼容。
- 所以：不依赖、不移植、不改写 Cap 的 AGPL 代码。实现录制后端时照系统接口的文档与本稿的格式写，不对着 Cap 的源码写。本稿与规范里从 Cap 得到的只有事实层面的对照（它录了哪些数据、怎样对时），格式是 BaoCut 自己定义的。
- MIT 的那部分（`scap-*`、`cap-camera*`）也不作为缺省依赖：它们的依赖链要逐个审（例如 Windows 的 `scap-direct3d` 依赖不在 MIT 例外里的 `cap-d3d-adapter`）。某个平台的采集确实绕不开时，单独评估、单独决定。
- 「导入 Cap 工程」不在分期里。它只读 Cap 写出的数据文件，不涉及 Cap 的代码，以后想做可以做（[§4](#4-参考cap-的数据怎样对应)）。

- **协议**：stdio 上的 JSON 行（`packages/runtime-core/src/recordings/worker-protocol.ts`），两边共用的样例在 `crates/recording-worker/tests/fixtures/protocol.json`。Runtime 收尾时只读 Worker 写的 `journal.jsonl`，正常停止与崩溃之后的恢复是同一条路径。

    - 「演示样式」与摄像头布局预设。
  - Web 有编辑器的全部编辑，没有录制入口。
  - 用假 Worker 驱动隔离的 Runtime 与 Electron 验证过面板、控制条、恢复、附属行的拖动与新建、解组、重新生成和演示样式；后来又验证过舞台取景框、成组修剪的预览、区域框选（拖出、Esc 取消、开始录制带上区域）、「把 BaoCut 也录进去」开关的显示与设置里的录制一组（开始录制的快捷键在不录时注册、录制中让出，收到按下的消息后打开面板；帧率与倒计时随开始送给 Runtime）。没有试过的：真的按下全局快捷键（主进程带回窗口的那一步）、快捷键注册不上的提示、多块屏幕与真实 Worker 的屏幕 ID 对应；打开开关时录制中不收起窗口只有单测；磁盘提醒没有在页面上出现过（Runtime 不给剩余空间），只有单测。
  - 摄像头布局预设与五种布局的编辑操作经 Runtime 接受（没有相机素材，没有看画面）。
- **还没有**：
  - 界面里的摄像头预览（后端不需要改，规则见 [§7](#7-进程与职责)「摄像头预览」）。
  - 设置里的缺省帧率只在界面里（本机存储），`baocut record` 读不到，仍按 30（[§14](#14-待评审事项)）。
  - 控制条窗口与 BaoCut 自己的窗口确实没被录进画面，还没有在实机上确认。
  - Windows 采集的实机验证（[§14](#14-待评审事项)「系统接口：Windows」），以及在 Windows 上实际构建、打包（`build:engine` 会构建 Worker，但没有在 Windows 上跑过）。
  - 上面两处修复里实机验证过的（macOS 27，2026-11-15）：整屏经 Runtime 照常开始，暂停后恢复、停止、导入进时间线，命令行导出的成片可读；静止区域录 5 秒后强杀，屏幕文件读得出。还没有验证：正常在屏幕上的单个窗口照常开始；收起的窗口开始时报 `SOURCE_NOT_CAPTURABLE`。
  - 原型已同步录制入口与编辑界面：Space「新建」与素材面板的「录制」、Home 的恢复提示、智能体录制卡与预填面板、编辑器的联动标记与解组、「缩放」「鼠标」附属行、检查器的「屏幕取景」、演示样式与摄像头布局预设，以及设置里的「屏幕录制」一组；录制入口只在 App，编辑在 App 与 Web 都有。原型比实现多走了几步，文案待与实现对齐：面板里的「把 BaoCut 也录进去」、磁盘空间提醒，设置里的「开始录制」快捷键、缺省帧率与缺省倒计时，舞台上「固定看一点」的取景框。

实机验证到哪里：在 macOS 27 上直接经 stdio 驱动 Worker，`sources` 不弹授权窗口；整屏加系统声音、另画光标、只录快捷键，录 3 秒、暂停 1 秒、再录 2 秒，两段 H.264 与 AAC 都可读，时长与日志一致，Runtime 的录制包构建读得懂；录制中强杀 Worker，已经写下的分段文件仍可读。单个窗口（加系统声音与快捷键）和一块区域也各录过两秒：画面尺寸与窗口、区域一致（区域的宽高取成偶数）。整屏录制的应用排除实机录过：排除一个在屏幕上的应用（按 bundle id）时它的窗口不在画面里，排除一个没有运行的 bundle id 时画面照常。录窗口时 Worker 一度因 CoreGraphics 没有初始化被系统结束，现在启动时先连上窗口服务器。显示器睡着时 ScreenCaptureKit 列不出显示器，`start` 以 `CAPTURE_UNAVAILABLE` 失败。没有实机验证的：摄像头与麦克风（那台电脑上这两项还没有授权过，没有去触发授权窗口）、指针移动与点击、真的按键、录制中移动窗口、设备中途断开，见 [§14](#14-待评审事项)。开始时被系统拒绝屏幕、摄像头或麦克风权限，Worker 按 SDK 头文件里的错误码报出是哪一项，Runtime 换成 `RECORDING_PERMISSION_DENIED` 并带上系统设置的位置；实机上没有触发过这几种拒绝，Runtime 这一半由假 Worker 的测试覆盖。经隔离的 Runtime 做的整屏端到端录制（系统声音、另画光标、暂停与继续）没有录成：屏幕锁着，`start` 以 `CAPTURE_UNAVAILABLE`（ScreenCaptureKit 列不出显示器）失败，CoreGraphics 那边 `sources` 仍然列出显示器。同一条路径换成假 Worker 走通了：任务完成，视频里有清单、取景文档、4 个实例与联动组，命令行 `export` 出的 MP4 用 ffprobe 读得出，长度 6.07 秒，与录的 6.04 秒一致。

必须覆盖的用例：摄像头晚于屏幕启动；暂停后恢复；摄像头中途断开；删掉中间一段；只拆分（画面逐帧相同）；两倍速；同一次录制用两次（效果互不影响）；Retina 与 Windows 的不同缩放比例下光标对得上点击处；窗口移动与区域录制；随机拖动播放头；改导出帧率；导入中进程退出（没有悬空引用、没有重复插入）；撤销、重做与重新打开；便携包换一台机器仍能编辑。

## 10. 已定的裁决

2026-11-15 定下四项：

1. **格式版本。** 新视频一律是 4，旧视频保持兼容：版本 3 照常打开，被这一版第一次修改时升到 4（规范 §1.4）。后果是旧视频被新版本改过之后，旧版本的 BaoCut 不能再打开它。
2. **录制后端。** 尽可能不用 Cap，自己实现（[§8](#8-许可与-cap)）。
3. **屏幕放大时摄像头不缩放。** 摄像头是独立的实例，位置与大小都不变；格式里不加联动（规范 §3.18）。
4. **键盘事件要收。** 加了 `keyboard` 流与键盘轨（规范 §4.7、§4.10）。按键提示怎样显示在画面上还没有定义，放在阶段 5。

还没有定的都在规范 §10 的状态行里：按键提示的显示、键盘轨从历史里彻底清除的办法、成组编辑的细节。

## 11. 入口与录制过程

录制是「不经过智能体、直接产出一个视频」的动作，与「新建空白视频」同类；它不是一个新的工作区域，不占 Rail（产品设计 §2.1：单个动作不单独占一格，同类归入已有区域）。只有 BaoCut 桌面端、而且 Runtime 就在这台电脑上时才有入口：Web 端不显示；桌面端连着远程 Runtime 时入口置灰，说明「只能录运行 BaoCut 的这台电脑」。

**入口**

| 位置 | 样子 | 结果落在哪 | 为什么在这里 |
| --- | --- | --- | --- |
| Home 的快速开始旁 | 与「新建空白视频」并排的「录制」 | 当前项目里的一个新视频 | 不依赖当前对象，直接完成核心工作，不经智能体（产品设计 §3.2.1） |
| Space「新建」菜单 | 「录制新视频」 | 当前所在项目里的一个新视频 | 与新建空视频、从文件新建同属「新建」（§4.8） |
| 编辑器素材面板 | 「导入」旁的「录制」 | 当前视频：素材入库，联动组放在播放头处的新轨道上 | 依赖当前视频，属于页面内部（§5.9） |
| 工具总览 | 「视频文件」组第一张卡「屏幕录制」，侧栏同组第一行 | 当前项目里的一个新视频（Home 此刻用的项目，与 Home 的入口相同） | 用户在工具页找「不经智能体直接做一件事」的能力，录屏是其中之一（产品设计 §2.7） |
| 会话里的智能体 | 智能体调 `record`，弹出预先填好的录制面板 | 会话的视频，或一个新视频 | [§13](#13-智能体) |
| 命令行 | `baocut record` | `--video` 指定的视频，或一个新视频 | [§12](#12-命令行) |

工具页上的「屏幕录制」只是一个入口，不是一个工具：按下直接打开录制面板，没有自己的工具工作台与路由，也不进 Runtime 的工具注册表（`tools.list`、MCP、命令行与智能体的工具目录都没有它，智能体用 `record`）。工具工作台是「给一个输入、得到一个产物」的骨架（输入、模型、选项、保存位置、开始），录制没有输入，产物是进编辑器继续剪的视频，套进去只会多一层空壳。显示规则同其他入口：Web 不显示，不能录时置灰并写原因。

**录制面板。** 各处入口打开同一个面板（不是新页面）：

1. **录什么**：整块屏幕（多块屏幕时选一块）、一个窗口、一个区域。BaoCut 自己的窗口缺省不录进去（[§14](#14-待评审事项)）。
2. **摄像头**：不用，或选一个设备；有小预览（界面自己取，按开始之前释放摄像头，[§7](#7-进程与职责)「摄像头预览」）。
3. **麦克风**：不用，或选一个设备；有电平条。
4. **系统声音**：开或关。
5. **鼠标**：另画光标（缺省，之后可以改大小、隐藏）、录进画面、不要光标。选「不要光标」时说明自动缩放也就没有了。
6. **键盘**：不录（缺省）、只录快捷键、全部按键；选「全部按键」时说明会录下输入的文字。
7. **倒计时**：3 秒（缺省）、5 秒、不倒计时。
8. **开始录制**。

- 每一路旁边显示权限状态。没有权限的那一行给出「打开系统设置」并说明要开哪一项；BaoCut 不替用户改系统设置。缺的是必需的一路（屏幕）时开始按钮不可用，缺的是可选的一路时可以去掉它继续。
- 面板记住上次的选择（按这台电脑记，Web 没有这份记录）。设备已经不在时退回「不用」并提示。
- 开始之前检查落点所在磁盘的剩余空间，不足以录十分钟时警告，可以继续。

**录制中**

- BaoCut 的窗口收起；屏幕上只剩一个小控制条：已录时长、暂停与继续、停止、丢弃。控制条不被录进画面。
- 菜单栏（Windows 是托盘）有录制中的图标，点开是同样的四个动作；全局快捷键可以停止、暂停与继续，在设置 › 通用 › 屏幕录制里改。
- 系统自己的录屏指示照常显示，BaoCut 不去隐藏它。
- 暂停的时间不进成片。丢弃要确认一次。
- 设备中途断开（摄像头被拔掉、麦克风换了）不中断录制：那一路从此没有内容，控制条提示一次，清单用 `coverage` 照实记下。
- 磁盘快满时自动停止并收尾，已经录下的保留。

**停止之后**

- 控制条变成「正在收尾」，BaoCut 的窗口回来，直接打开编辑器：联动组已经在时间线上，自动缩放已经生成，摄像头缺省在右下角、圆形。此后的编辑见 [§5](#5-时间线上的样子)。
- 收尾与导入是一个后台任务（种类 `recording`），在后台任务页与视频卡上都看得到；收尾慢的时候可以先去做别的。任务完成才算录制成功（[§7](#7-进程与职责)的状态）。
- 录进当前视频时，整次导入是一笔可以撤销的事务：撤销之后素材留在素材库，时间线恢复原样。

**收尾与恢复**

- 录制中的数据先写在 Runtime 的临时目录，导入成功后才成为视频里的素材。
- BaoCut 或电脑在录制中、收尾中退出：下次启动时 Home 提示「有一次没有收完的录制（日期、时长）」，可以恢复（把已经写下的部分收尾并导入）或删除。没有选之前不自动删。
- 导入中退出：按幂等键重做，不重复插入，不留悬空引用。

**设置**

设置 › 通用里的「屏幕录制」一组（只有桌面端有；按这台电脑记）：

- 快捷键：开始录制、停止、暂停与继续。开始录制在不录时一直占着，按下时把 BaoCut 带到前台并打开录制面板（录成当前页项目里的新视频，与 Home 的入口相同）；它缺省不用，因为占着时别的应用用不了这组键。停止与暂停只在采集时占着。
- 缺省帧率（30 或 60 fps）：用户自己开始的录制用它，智能体发起的用它给的。
- 缺省倒计时：就是面板记住的那一项，两处改的是同一个值。
- 录制时是否收起 BaoCut 的窗口。
- 权限不在设置里管：它们是系统的开关，只在录制面板与诊断里显示状态。

## 12. 命令行

沿用智能体面与命令行的命名（agent-surface 设计 §4.1）：开始录制是一级动词 `record`（一个任务），录制会话的读与控制是名词组 `recordings`。工具与命令同名同参数，`surfaces` 是 `agent` 与 `cli`；不进对外的 MCP 服务：外部客户端不应该能让这台电脑开始录屏。

**录的是哪台机器。** 录的是 Runtime 所在的那台电脑的桌面。`baocut` 连着远程 Runtime 时 `record` 拒绝（`RECORDING_UNAVAILABLE`，说明原因），不去录远端。没有窗口、由命令行自己拉起的 Runtime 能不能录、系统权限算在谁头上，见 [§14](#14-待评审事项)。

| 命令 | 效果 | 做什么 |
| --- | --- | --- |
| `baocut record` | job | 开始一次录制。缺省 `--wait`：阻塞到「已进时间线」或失败，结果里是 `videoId`、`recordingId`（录制会话，开始时就有，`recordings` 各命令用它）、`manifestDocumentId`（清单的文档，导入时才写）、`screenViewDocumentId`（取景文档，自动缩放已经在里面）、`groupId`（联动组）、`itemIds`、`duration`（有效录制长度，秒）。结果里另有一个弃用的 `autoZoomPending`，恒为 `false`，只为早先的读取方留着。`--no-wait` 时这些字段在任务完成后的 `jobs inspect` 的 `recording.result` 里 |
| `baocut recordings sources` | query | 列出能录的屏幕、窗口、摄像头、麦克风，各带 ID、名字、尺寸（窗口另带所在屏幕上的位置 `bounds` 与前后次序 `order`，[§7](#7-进程与职责)）；另列每项系统权限的状态（`screen`、`camera`、`microphone`、`inputMonitoring`）、录制落点所在磁盘的剩余空间（`disk.freeBytes`），与这台电脑能不能录、不能时的原因（给人看的 `reason` 与机器可读的 `unavailable.code`） |
| `baocut recordings status [id]` | query | 一次录制的状态（[§7](#7-进程与职责)）、已录时长、各路流是否在录、落点；不给 ID 是当前这一次。开始之前就失败的也查得到（[§7](#7-进程与职责)「失败的录制」） |
| `baocut recordings list` | query | 当前的、没有收完的与开始之前就失败的录制 |
| `baocut recordings pause [id]`、`resume [id]` | mutation | 暂停与继续 |
| `baocut recordings stop [id]` | mutation | 停止并保留。返回只表示命令收到了，带 `jobId`；要等到可以编辑用 `--wait` 或 `baocut jobs wait <jobId>` |
| `baocut recordings discard [id]` | destructive | 丢弃这一次，要 `--yes` |
| `baocut recordings recover <id>` | job | 把没有收完的录制收尾并导入 |

`record` 的参数：

| 参数 | 含义 | 缺省 |
| --- | --- | --- |
| `--display <id>` / `--window <id>` / `--area <x,y,w,h>` | 录什么，三选一；ID 来自 `recordings sources`，区域是所选屏幕上的逻辑点（配 `--display`） | 主屏幕 |
| `--camera <id>` | 加摄像头 | 不录 |
| `--mic <id>`、`--no-mic` | 麦克风 | 系统缺省的麦克风 |
| `--system-audio` | 录系统声音 | 不录 |
| `--cursor separate \| baked \| none` | 鼠标模式（规范 §4.7）；`none` 没有指针轨，也就没有自动缩放 | `separate` |
| `--keys off \| shortcuts \| all` | 键盘（规范 §4.10） | `off` |
| `--fps <n>` | 屏幕的目标帧率 | 设置里的缺省 |
| `--countdown <秒>` | 倒计时；0 是不倒计时 | 3 |
| `--duration <秒>` | 到时自动停止 | 不限 |
| `--video <id>` | 录进这个视频；不给就新建 | 新建 |
| `--name <名字>`、`--project <项目>` | 新视频的名字与项目 | 「录制 日期 时间」、当前项目 |
| `--no-auto-zoom` | 不生成自动缩放 | 生成 |
| `--include-self` | 整屏与区域录制也录进 BaoCut 自己的窗口（[§7](#7-进程与职责)「自己的窗口」） | 不录 |
| `--no-open` | 完成后不在桌面端打开编辑器 | 打开 |

- **等待与停止。** `--wait` 时进度写到 stderr（状态与已录时长，没有总量）。录制中在终端按第一次 Ctrl-C 是**停止并保留**，继续等到收尾完成；第二次才是退出等待（任务照常收尾）。这与别的任务「Ctrl-C 取消」不同，是有意的例外：按 Ctrl-C 的人要的是录到这里，不是把录好的扔掉；要扔掉用 `recordings discard`。落地时要在 agent-surface 设计 §5.4 写明这个例外。
- **`--no-wait`** 开始之后立即返回 `jobId` 与 `recordingId`，之后用 `recordings stop`。同一时刻只能有一次录制，已有一次在录时 `record` 拒绝（`RECORDING_BUSY`）。
- **`--dry-run`** 只做预检：解析来源与设备、核对权限与磁盘，报告会录什么，不开始。
- **权限。** 缺系统权限时失败，错误的 `details.systemAccess` 列出缺哪几项与各自在系统设置里的位置；命令行不弹系统的授权窗口之外的任何东西。`baocut doctor` 多一项「录制」：这台电脑能不能录、各项权限的状态。
- 没有选项的 `baocut record` 等于面板的缺省：主屏幕、缺省麦克风、另画光标、不录键盘、3 秒倒计时。

例子：

```bash
baocut recordings sources --json
baocut record --display 1 --camera cam_2 --name "产品演示"
baocut record --window 4821 --no-mic --duration 30 --video vid_01H…
baocut record --no-wait && baocut recordings stop --wait
```

## 13. 智能体

智能体可以发起录制、读它的结果、在录完之后帮着剪；它不能在用户不知情时开始录，也不替用户操作屏幕。

**怎么唤起。** 智能体调 `record`（与命令行同一个工具），参数是它从用户的话里读出来的（「录我的屏幕加摄像头，讲一下这个功能」→ 屏幕加摄像头加麦克风）。会话里的 `record` 不直接开始采集：

1. 工具立刻返回 `jobId`，录制处在「等待开始」。会话里出现一张录制卡，同时弹出预先填好的录制面板。
2. 用户看一眼要录什么，可以改，按「开始录制」；也可以关掉面板，任务以「已取消」结束。**这一下点击就是批准**：不另外弹审批卡，也因此任何访问模式（包括完全访问）下都要有这一下。
3. 智能体这一轮到此结束，回一句「录完按停止，我接着处理」。它不轮询。
4. 用户停止，任务收尾、导入、完成。Runtime 经完成收件箱（架构设计 §7.2）把结果交回会话，智能体接着做用户原先要的事：转录、按文稿剪掉口误与停顿、调缩放、加字幕、导出。失败时同样交回，智能体说明原因。

选「预填面板、用户按开始」而不是「工具直接开始采集」，是因为批准、确认人在场、确认录的是什么三件事合成一步，而且面板本来就要有；直接开始的做法留给命令行。

**没有人在场时不录。** 定时任务、Bot 会话与别的无人看守的运行里，`record` 直接拒绝（`RECORDING_UNATTENDED`），不转成待办去等人。远程 Runtime、Web 会话同样拒绝，理由写在错误里，智能体转告用户到桌面端来录。

**权限。** 缺系统权限时面板上照常显示（[§11](#11-入口与录制过程)）；智能体没有打开系统设置的工具，只把 `details.systemAccess` 里缺的项目告诉用户。

**工具的风险等级。** `record` 是 `high`；`recordings_pause / resume / stop` 是 `command`；`recordings_discard` 是 `high`（丢掉的是用户的录制）；`recordings_sources / status / list` 是 `read`。窗口的名字可能带出隐私（文档标题、网页标题），`recordings_sources` 的结果只在本机的会话里用，不进对外服务。

**录完之后智能体能做的**，都走现有的工具，与用户在界面上做是同一套命令：

| 用户的话 | 智能体做什么 |
| --- | --- |
| 「把口误和停顿剪掉」 | `transcribe` 麦克风，再用剪口（规范 §6.7）；剪口按联动组落到每一路 |
| 「这一段别放大」「这两次点击合成一次放大」「这里放大到按钮上」 | 读取景文档，改 `zooms` 后写回（`edits_apply` 的 `patchDocument` 或 `putDocument`）；改过的自动区间记 `edited`。要按点击重来用 `edits_apply` 的 `regenerateAutoZooms` |
| 「光标大一点」「加点击提示」 | 改取景文档的 `pointer` |
| 「讲到代码的时候把摄像头收起来」 | 按文稿找到区间，在两端拆分整组，改中间一段的摄像头实例 |
| 「做成带圆角留边的样子」 | 改屏幕实例的 `place`、圆角与阴影，改画布底色 |
| 「加字幕、出一条竖屏的」 | 现有的字幕与短视频流程 |

**现在还缺的**（落地时补，不是新格式）：

- `documents_read` 与 `documents_put` 现在面向文稿类文档，收不收 `screen-view`、读出来的形状要补一份说明；在那之前智能体用 `edits_apply` 改取景文档。
- 指针轨是素材不是文档，智能体要「看鼠标点了哪里」需要一个只读的摘要工具（按时间列出点击与停留），属于阶段 5。
- BaoCut 的 skill 里加一份「录屏与讲解视频」的做法：先确认录什么、录完的缺省处理（转录、去口误、检查自动缩放）、哪些事要问用户。

## 14. 待评审事项

- **命令行的 Ctrl-C。** [§12](#12-命令行) 把录制中的第一次 Ctrl-C 定为「停止并保留」，与通用约定不同。已按这个例外实现并写进 agent-surface 设计 §5.4；要不要保留仍待评审。
- **没有窗口的 Runtime 能不能录。** 命令行自己拉起的 Runtime 没有界面：系统的录屏、摄像头、麦克风权限算在哪个进程头上，没有控制条与倒计时算不算「用户知情」，都没有核实。现在的实现在这种情况下 `record` 拒绝（`RECORDING_UNAVAILABLE`），请用户打开 BaoCut 再录。
- **系统接口：macOS 已核实的。** 对着 Apple 的 SDK 头文件与开发者文档核实，并在实机上用过：
  - 不画光标：`SCStreamConfiguration.showsCursor`（ScreenCaptureKit 文档「SCStreamConfiguration」）。`separate` 时关掉，`baked` 时打开。
  - 光标图片：`NSCursor.currentSystemCursor`（AppKit `NSCursor.h`）。新的 SDK 已标为过时，头文件说以后的系统上会一直返回空，给的替代是 ScreenCaptureKit 的 `showsCursor`（把光标画进画面，即 `baked`）或只能取本应用光标的 `NSCursor.currentCursor`；公开接口里没有别的取系统光标图片的办法。拿不到时 Worker 退到 `baked`，`start` 的回答与清单如实写出。系统真的停掉它之后 `separate` 怎么办见下面「光标图片的来源」。
  - 光标的 `scale`（规范 §4.7：图片的几个像素对应捕获画面的一个像素）：存下的位图（TIFF 里像素最多的那张）的像素宽 ÷（光标的点宽 × 捕获画面每点的像素数 `SCContentFilter.pointPixelScale`）。macOS 27 的 1 倍屏上实测：箭头光标 28 点宽，存下的位图 280 像素宽，`scale` 是 10。
  - 排除应用：`SCContentFilter initWithDisplay:excludingApplications:exceptingWindows:`（ScreenCaptureKit 文档「SCContentFilter」），应用取自 `SCShareableContent.applications`，按 `SCRunningApplication.bundleIdentifier` 与 `processID` 认。实机上排除一个在屏幕上的应用，它的窗口不在画面里。
  - 屏幕权限：`CGPreflightScreenCaptureAccess`（CoreGraphics `CGWindow.h`）只问不弹窗，但只分得出「已允许」与「没有」，所以 `sources` 里屏幕只会是 `granted` 或 `not-determined`。
  - 摄像头、麦克风权限：`AVCaptureDevice.authorizationStatusForMediaType:`（AVFoundation「Requesting authorization to capture and save media」），四种状态一一对应。
  - 监听键盘要单独的「输入监控」权限：状态用 `IOHIDCheckAccess(kIOHIDRequestTypeListenEvent)`（IOKit `IOHIDLib.h`）读，监听用只听不改的 `CGEventTapCreate`（CoreGraphics `CGEvent.h`）。实机上监听建得起来（录过的几段里没有按键）；建不起时 `start` 以 `INPUT_MONITORING_UNAVAILABLE` 失败、Runtime 换成 `RECORDING_PERMISSION_DENIED`，这条路径没有实机触发过。
  - 时钟：SCStream 与每个 AVCaptureSession 的 `synchronizationClock`，经 `CMSyncConvertTime`（CoreMedia `CMSync.h`）换到主机时钟。实机上只用过 SCStream 的；AVCaptureSession 还没有开过。
  - 崩溃后可读：`AVAssetWriter.movieFragmentInterval`（AVFoundation `AVAssetWriter.h`）设成 1 秒，录制中强杀之后已写下的片段可读（实机验证）。打开分段时 H.264 不能用 B 帧（实机上会以 `-16341` 失败），所以关掉了帧重排。
  - 录单个窗口：`SCContentFilter initWithDesktopIndependentWindow:`（ScreenCaptureKit 文档「SCContentFilter」），画面尺寸取窗口的大小（实机录过）。
  - 每个画面样本的状态：`SCStreamFrameInfoStatus`（ScreenCaptureKit 文档「SCFrameStatus」；`complete` 0、`idle` 1、`blank` 2、`suspended` 3、`started` 4、`stopped` 5）。文档说 `idle` 是「画面没变，系统没有生成新帧」。实机上（macOS 27）：静止的整屏或区域每秒约 28 个 `idle`，五秒里只有 2 个 `complete`；静止的窗口照样约每秒 10 个 `complete`；窗口在开始前被隐藏或最小化，或者录制中被最小化，只来一个 `suspended`，之后什么都不送；屏幕锁着时录窗口也是这样，录整屏则列不出显示器。被别的窗口挡住的窗口照常录。
- **系统接口：按文档实现、还没实机验证的。** 第一个分片提前到半秒：`AVAssetWriter.initialMovieFragmentInterval`（AVFoundation `AVAssetWriter.h`）；静止时补写的重复帧与开始时等第一帧（[§7](#7-进程与职责)）。窗口移动时指针坐标跟着窗口走（位置从每帧的 `SCStreamFrameInfoScreenRect` 读，录的时候窗口没有动过）；指针移动与点击、真的按键（录过的几段里没有动鼠标、没有按键，事件文件里只有起始那一行或是空的）；设备中途断开；摄像头与麦克风的采集。「安全输入（密码框）期间拿不到按键」只按文档的说法记，没有实机试过；「控制条不被录进画面」要等控制条做出来：它属于桌面端，按同一份排除名单排除，若改由别的进程画，要把那个进程加进名单。BaoCut 自己的窗口实机上没有专门对着桌面端录过（那次桌面端的窗口被别的窗口挡着），排除的机制是用别的应用验证的。Windows 一侧都还没有核实。
- **系统接口：Windows（只写了代码、只过了编译检查）。** 对着微软的接口文档写，在 macOS 上交叉编译通过，**没有一项在 Windows 上运行过**。打开开发态开关之前要在实机上逐条核实：
  - 系统版本：Windows.Graphics.Capture 的 `CreateForMonitor` / `CreateForWindow` 要 Windows 10 1903；`IsCursorCaptureEnabled` 要 2004；`IsBorderRequired` 与 `GraphicsCaptureAccess` 要 Windows 11；`MinUpdateInterval` 要 Windows 11 24H2；`ToUnicodeEx` 的「不改键盘状态」标志要 1607。缺了的属性按 `ApiInformation.IsPropertyPresent` 跳过，这条判断本身要在老版本上试。
  - 光标开关：`IsCursorCaptureEnabled = false` 时画面里确实没有光标；`baked` 时有。
  - 黄框：没有打包的桌面程序调 `GraphicsCaptureAccess.RequestAccessAsync(Borderless)` 会不会弹提示、会不会被拒、等三秒够不够；被拒时黄框会不会被录进画面（文档说不会）。
  - 权限：「设置 › 隐私和安全性」里关掉摄像头、麦克风后，`AppCapability.CheckAccess` 对没有打包的程序报什么；采集时是不是返回 `E_ACCESSDENIED`（Worker 按它报 `CAMERA_PERMISSION_DENIED` / `MICROPHONE_PERMISSION_DENIED`）；第一次用时系统会不会弹提示。
  - 回环的静音：没有声音播放时确实不送包；Worker 补的静音让声音与段一样长、与画面对得上。整段都没有声音播放时不会出系统声音文件（第一个包到了才开文件），Runtime 是否接受这种情况。
  - 声音格式：`AUTOCONVERTPCM` 在常见声卡上是否成功；退到混音格式时多声道、24 位、浮点的换算；设备是 96 kHz 时 `start` 报错是否合适。
  - 编码：Sink Writer 是否真的用了硬件编码器；硬件编码器是否接受经 `SetInputMediaType` 传入的关键帧间隔、不要 B 帧与低延迟（ffprobe 看帧类型与关键帧间隔）；码率是否合适；颜色范围与 BT.709 标记在编辑器里颜色是否正确。
  - 分片 MP4：录制中强杀 Worker 后文件可读；正常结束后转普通 MP4 成功、替换时文件没有被 Source Reader 占着；ffprobe 读出的时长与日志一致。
  - 静止画面：画面不变时 Windows.Graphics.Capture 不送帧，段首段尾补的帧让文件长度等于段长。
  - 窗口：改大小（帧池 `Recreate`、黑边）、移动（指针坐标跟着窗口）、最小化、关掉（记为断开）。窗口 ID 用句柄值，窗口重建后会变。
  - 缩放比例：125%、150%、多块缩放不同的显示器上，`sources` 的逻辑尺寸、区域的裁切与指针的归一化坐标是否对得上；光标图片的 `scale = 1` 与「指针大小」放大后的位图是否一致。
  - 摄像头：样本时刻是不是在 `MFGetSystemTime` 的时钟上（Worker 按「相差不到一秒」判断）；与屏幕、声音是否对得上；`MF_SOURCE_READER_ENABLE_ADVANCED_VIDEO_PROCESSING` 转 NV12 在 MJPG 摄像头上的开销；拔出时 `ReadSample` 是否报错（记为断开）。
  - 麦克风拔出：`AUDCLNT_E_DEVICE_INVALIDATED` 是否到达、记为断开。默认设备在录制中切换时的行为（现在不跟着切）。
  - 键盘：低级钩子在实际负载下会不会因为超过 `LowLevelHooksTimeout` 被系统摘掉；以管理员运行的窗口与 UAC 提示期间收不到按键；`code` 与 `key` 在非美式布局（法语、德语、日语输入法）下是否正确。
  - 指针：左右键互换时记的是主键；锁屏与 UAC 安全桌面期间 `GetCursorPos` 失败时不写。
  - 光标图片：彩色、单色（I 形）、反色、动画光标的取图结果；PNG 在编辑器里显示正确（编码器已用 macOS 的 `sips` 与 zlib 解码核对过）。
  - 磁盘剩余空间：`GetDiskFreeSpaceExW` 的检查与 `disk-low` 推送。
  - 自己的窗口：Worker 排除不了（[§7](#7-进程与职责)「Windows 的规则」），桌面端是否要设 `setContentProtection`，待定。
- **BaoCut 自己的窗口。** 缺省不录进去是为了不把会话内容录下来；要录 BaoCut（做教程）时给 `includeSelf`（命令行 `--include-self`），选 BaoCut 的单个窗口时也照录（[§7](#7-进程与职责)「自己的窗口」）。面板上整屏与区域有「把 BaoCut 也录进去」开关，打开时录制中也不收起 BaoCut 的窗口。排除名单覆盖不到的情形：命令行拉起的 Runtime（父进程不是桌面端）遇上开发态的桌面端（bundle id 不是 `com.baocut.app`），这时桌面端的窗口会录进去；打包的桌面端不受影响。
- **光标图片的来源。** `NSCursor.currentSystemCursor` 已标为过时、以后会一直为空（见上面「macOS 已核实的」）。到那时 `separate` 拿不到系统光标图片，只能退到 `baked`（光标画进画面，不能再改大小、隐藏），或者 Worker 按光标的形状（`shape`）画自带的一套光标图片。哪一种、要不要提前准备自带的图片，待定。
- **完全访问模式下的 `record`。** [§13](#13-智能体) 定为仍要用户按一次开始。要不要给「我信任这个会话，直接开始」留口子；本稿的立场是不留。
- **按键提示怎样显示。** 键盘轨已经能存，画到画面上的样式还没有定义，要补格式（规范 §10）。
- **图片与渐变背景。** 留边时的底色现在只有纯色（`canvas.background`）；常见的渐变与壁纸背景要么用下层的图片实例，要么给格式加背景的种类。
- **摄像头的布局随段落切换。** 现在靠拆分整组再逐段改；要不要一个「布局场景」的概念（一次定义、多处套用），放在阶段 5 评估，可能要补格式。
- **并入产品设计。** 入口与编辑已写进产品设计 §3.2.1、§4.8、§5.9，需求是 CRE-05（P1，关联 S11），验收条目还没有定义。命令已经实现，已写进 agent-surface 设计 §4.2、§4.3 与 §5.4。
- **Home 录制落在哪个项目。** 现在没选项目时每次都新建一个「录制」项目（重名加编号），录几次就多几个项目。是改成复用同一个「录制」项目，还是保持每次一个，待评审。
- **快捷键放在哪里。** 原先写的是设置 › 快捷键；现在 §11 与实现都放在设置 › 通用的「屏幕录制」一组，与录制的其他设置在一起（快捷键页只列出应用内的快捷键，不能改，也不含这三个全局的）。要不要在快捷键页也列出它们，待评审。
- **缺省帧率到不了命令行。** §12 说 `--fps` 缺省取设置里的值，但这项设置记在界面的本机存储里，Runtime 与 `record` 读不到；`record` 现在仍按 30。要让两边一致，得把它挪进 Runtime 的设置。
