# 11. 增量、指纹与 provenance

> 出自 [BaoCut 文件契约字幕 AI 管线设计（File-Contract Pipeline, v0.3）](../bcut-file-contract-subtitle-ai-design.md)

## 11.1 阶段戳（不变）

`stages.polish`（内容指纹）/`stages.segment`（id 指纹）/`stages.chapters`、`transSrc`（句级可见词指纹）判脏机制完全沿用。**缺 `transSrc` 戳 ≠ stale**（缺译与过期是两条独立通道，现行语义）。

## 11.2 文件产物复用

见 §4.2：manifest `inputFingerprint` 管文件级复用（含"直接从 `merged.*` 恢复而不发调用"），句级复用只看 `transSrc`。

## 11.3 术语/上下文 provenance（新增，补齐用户术语表的传导链）

改术语表**不会**让任何句子按 `transSrc` 变 stale（它只哈希源词）——没有这条通道，用户改锁定译名后无法定位受影响句子；把术语 hash 塞进 `transSrc` 又会污染"只表示源词指纹"的语义。因此新增：

```jsonc
// ai/state/translation.zh.json —— 不含译文正文
{ "s-g1.0": { "contextHash": "…", "styleHash": "…", "termHashes": ["…"] } }
```

- 翻译每句提交时记录当时使用的 context/style/命中术语 hash（`term_hash` 覆盖 `source / target / note / lock` 四元，改锁定态也算变更）。
- 待重译集合 = `stale_sentences` ∪ `provenance_stale_sentences`。
- **缺此文件的旧译文继续按 `transSrc` 判断，报 `provenance-unknown` advisory，而不是被无条件判 stale。**

**M4 实现裁决——stale 判据收窄为"术语哈希集合变化"**，摘要/文风变化只出 `context_drift` advisory、不进重译集合。三档语义：

| 情形 | 判定 |
|---|---|
| 无生效简报（`ContextDigest::has_basis() == false`，例如 `--no-brief`） | **全部清白**，直接返回空扫描——没有 basis 就没有"当时用了什么"这个事实，凭空判 stale 等于每次跑都重译全文 |
| 账本里没有这一句 | `unknown`（advisory，按 `transSrc` 走） |
| 命中术语哈希集合与记录不同 | `stale`，进重译集合 |
| 术语集合相同、但摘要/文风 hash 变了 | `context_drift`，**仅 advisory** ——摘要重写是 analysis 重跑的常态副作用，让它触发全文重译会把 provenance 变成一个"重跑 analysis 就烧一遍翻译"的陷阱 |

注意实现里**没有** `ProvenanceBasis` 这个类型，basis 是 `ContextDigest::basis` 字段 + `has_basis()` 谓词。
