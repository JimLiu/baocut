# 8. 阶段 3：对齐（HTML 表格契约）

> 出自 [BaoCut 文件契约字幕 AI 管线设计（File-Contract Pipeline, v0.3）](../bcut-file-contract-subtitle-ai-design.md)

## 8.1 只发问题句，四档分类（与两份参考方案一致，非分歧点）

超长检测是确定性代码，LLM 从不参与检测。现行四条件：`exceeds_one_line_fit`（宽度超一行）、`target_cps_chars > hard`（读速超硬上限）、停留 > 7s（`LONG_DWELL_SECONDS`）、配对行源侧时窗超限（`whole_sentence_source_ceiling_issue`，阈值 `PAIRED_SOURCE_MAX/HARD_SECONDS = 4/6 秒`——是**时窗**判定，不是源文长度阈值）。注意"四条件全 false"意味着零 LLM 调用，但 projected 模式下仍会写整句 `TransAlign` 条目（非零写入）。

据此把全部句子分四档：

| 档 | 处置 |
|---|---|
| 合格 | 不进表 |
| 可由确定性切分器安全处理 | `split_independent_for_lang_protected` 直接切，零 LLM |
| 需要语义切分 | 进 LLM 表格 |
| 配置 blocker（如**锁定术语自身超过 hard**） | 报 blocker，**绝不在术语中间硬切**；这是循环的终止条件之一 |

**标记色降级为人类/Agent 预览辅助**：协议信号只有一个——出现在表格里的句子都需要处理。样式与语义分离，解析器不看 class。**M1–M4 实现裁决：预览 `<style>` 内联未做，且是有意不做**——§16 要求解析器无条件丢弃 style 节点，而 `data-soft` 之后的提交期 lint 要对**落盘的那份 HTML** 做往返解析；内联 style 会在每次往返上稳定产出一条 `node-dropped` 假告警。可视化留给外部预览工具，不进载荷。

## 8.2 渲染

装箱只按**源文词数**约束：每页最多 8000 源文词，Latin 按词、CJK 按字。句数、HTML/JSON 序列化体积、定点/全量模式与 worker 槽数都不改变页形：

```html
<table data-lang="zh" data-fit="16" data-soft="18" data-hard="20" data-bcut-format="align-table/1">
  <tbody data-sid="s-g1.0" data-max-lines="2" data-budget="每行≤16字，建议2–3片">
    <tr><th rowspan="1" scope="rowgroup">s-g1.0</th>
        <td class="src">Ninety days, eight times the growth, and we did it without any paid marketing.</td>
        <td class="tgt">九十天翻了八倍，而且我们没有花一分钱做付费营销就做到了。</td></tr>
  </tbody>
</table>
```

属性清单（`align_table.rs` 落地口径，渲染与解析双向对称）：

| 位置 | 属性 | 语义 |
|---|---|---|
| `<table>` | `data-lang` / **`data-source-lang`** / `data-fit` / **`data-soft`** / `data-hard` / `data-bcut-format` | 目标语、源语与 `TransParams` 三阈值 + 格式版本 |
| `<tbody>`（句组） | `data-sid` / `data-max-lines` / `data-budget` | 句 id、最大行数、相对预算文案 |
| `<tbody>`（模型可写） | `data-unsplittable` / `data-reordered` / `data-crossing` | 不可拆出口、改写声明、残余语序交叉（§8.3） |
| `<tbody>`（引擎写、模型只读） | `data-no-rewrite` | paired 重切轮标记：译文已验收，只准重选切点；同 `data-target-frozen` 一样禁用 `data-reordered`，但不规定片文本 |
| `<tbody class="ctx">` | 无 `data-sid` | 只读上下文行 |
| `<th>` | `rowspan` / `scope` | 冗余校验 |

- **`data-soft` 是 v0.2 属性清单之外的增补（M1–M4 实现裁决）**：提交期 lint 只拿得到落盘的载荷 HTML，`parse_align_table_input` 必须能完整还原 `TransParams`（fit/soft/hard 三值都进 `lint_pieces` 的接缝判据）才能复算与引擎完全相同的一套判据。缺 `soft` 就只能猜默认值，猜错等于两份不同的校验——正是 §2 要消灭的东西。
- **`data-source-lang` 同属增补（2026-09-28）**：契约允许「源行过密 + 两侧都是完整并列动作」时切在 `、` 上，json-v0 验收与 `bcut check` 早按 `allowed_balanced_list_seams` 豁免，align-table 提交期 lint 却漏了这一条，照普通列表报 `align-illegal-seam`（Shorts 验收 C6）。豁免要按**源语**单行预算量相邻两行源文的合计宽度，载荷又不带词时间，所以只取宽度半边（`allowed_list_seam_indices_for_source_rows`），源语随载荷往返；旧载荷缺该属性时按拉丁源语预算计。
- 源格是整句源文（可见词序拼接）；不预切、不暴露 word id、不暴露源 Cue 边界、**不让模型挑 `b7` 候选断点 id**（模型只切文本，程序映射）。
- `data-budget` 只携带相对预算：fit/soft/hard、由停留秒数**折算成的建议片数**——绝对时间戳不进载荷。
- 若源列附停顿软标记，文件载体统一走 `markers::pause_marks` 一套阈值（0.6/1.0/1.8s）。align 侧私有的 `pause_tier` 仍用于草稿词元的停顿元数据，但不参与分页；私有档位不得跨进文件载体（§13.1）。
- 上下文：前后各一句以 `<tbody class="ctx">`（无 data-sid）只读附带。**M1–M4 实现裁决：载体已实现，引擎未接线**——`align.rs` 建请求时 `context_before`/`context_after` 恒为空向量（§17）。

## 8.3 输出：`tbody` 分组，行片 1:1，rowspan 只做冗余校验

模型把一句拆成 N 行，**每行 = 一个译文片 + 对应的连续源文段**（1:1）：

```html
<tbody data-sid="s-g1.0">
  <tr><th rowspan="2" scope="rowgroup">s-g1.0</th>
      <td>Ninety days, eight times the growth,</td><td>九十天翻了八倍，</td></tr>
  <tr><td>and we did it without any paid marketing.</td><td>没花一分钱做付费营销。</td></tr>
</tbody>
```

- 双列同步拆是必须的：`pieces[].from/to` 需要每片连续源词区间做时间锚定。规范次序不变——先按译文自然度决定拆分，再切源文对应段。
- **rowspan 只出现在 id 列 `<th>`，值必须等于该组行数**——纯冗余校验（模型算错即抓），不承载语义。数据行永远 1:1，与 `pieces` 数据模型同构。拒绝"源格/译格 rowspan 表达 N:1 共享"的设计：`pieces[]` 的连续/不重叠/全覆盖结构装不下共享区间。
- **不可拆出口**：源侧确无切点时，模型在 `<tbody>` 上标 `data-unsplittable="true"`（语义信号走属性，不从网格形状反推）→ 走现行"故意不自动修"语义：整句上屏或 independent 比例锚定。**M1–M4 实现裁决**：v0.2 写的 `translation-unsplittable` **不是错误码**，`ProblemCode` 里没有这一项——不可拆是一条正常出口，不消耗重试预算、不进 §10.1 表，只由 `data-unsplittable` 属性驱动分类。
- **译文改写**：允许改写译文消除语序交叉，`<tbody data-reordered="true">`，走现行 ±max(25%, 4 单位) 改写幅度护栏后回写句级 `trans`（先 trans 后 transAlign 由 apply 层保证）。残余语序交叉用 `data-crossing="true"` 表达（对应现行 `crossing` 字段，与 reordered 互斥）。保留"能改写"的现行立场，不引入 translate-repair 回边（多一次跨阶段调用、收敛难证，轮次预算下负收益）。

## 8.4 解析、验收与轮次

1. 按 `data-sid` 聚组；每片源文段与整句源文做顺序游标 + atom-LCS 前缀对齐、**吸附到词边界**（不在词边界的切点取最近边界并记 warning）→ 得每片 `from/to`。现行 `sourceBreaks`/`useDraft` 应答通道随融合一并下线。
2. 逐句过现有验收器：拼接不变式、连续/不重叠/全覆盖、每片 ≤ hard、`seam.rs` 接缝 lint（悬空连词、"的"尾巴、数字+单位跨缝等）。
3. **非回退检查**：每行的源跨度、时长、目标密度都不得比输入最坏行更差——堵死"切成一个超短片 + 一个仍超长片"的伪修复。
4. **轮次硬预算**：round1 全量问题句按 8000 源文词分页并行 → round2 失败句仍按同一 8000 词预算生成定向页（1 轮）→ round3 确定性兜底 `split_independent_for_lang_protected` + `repair_lint_pieces`（永不失败），记入 `fallback.json` **并显式标记为确定性兜底**——不伪装成模型结果。总 LLM 轮次 ≤ 2。
5. 每轮之后**代码重新跑超长检测**决定下一轮集合；不相信模型自报完成（`data-status` 之类一律忽略）。最终成功条件 = 代码扫描零可执行 hard defect + blocker 档已上报。

**M1–M4 实现裁决：`align-over-hard` / `align-illegal-seam` 在文件契约下降为逐句 advisory**（`problem_blocks_acceptance` 对这两码返回 `false`）。理由：它们描述的是"这一句切得不够好"，而不是"这份文档没法解析"；让它们否决整批会把一句的质量问题升级成整表重来，与句级记账原则冲突。这两码仍然进 `report.json`、仍然驱动定向轮的句子集合，只是不阻断本批验收。

**KeepWhole 收下但仍超 hard 的句：先存 salvage、再定向补**（实现补充，2026-08）：worker 交的某片本来就超 `hard`，引擎自己的确定性重切又因破坏配对可读性被放弃（`AcceptanceMode::KeepWhole` 路径）时，不再当场落库。与 polish 的"首轮即接受 + 定向补"同一口径：该答案存进 `salvaged`（修复预算耗尽时原样顶上，结果不比直接接受更差），同时只把**这一句**连同定向说明（"target segment k is N display units — over the absolute hard ceiling H … move a boundary … or declare `data-unsplittable="true"`"）作为 failure 送进修复轮，其它句照常验收落地。两个例外不回炉：worker 已自述 `data-unsplittable="true"`（契约兑现，直接接受），或答案是 `data-reordered` 重排回写（救回意味着跳过 `trans` 回写的一致性前提，宁可走确定性兜底）。轮次仍受第 4 条硬预算约束（`GLOBAL_REPAIR_CALLS` 一轮定向），不新增 LLM 轮。

**同时有意保留的不对称**：提交期 lint 会把**全量** `Problem`（含上述两个 advisory 码）推给 worker，也就是说 worker 可能被要求修一个引擎自己会接受的缺陷。这是刻意的——worker 手上有整表语境、修一次成本低，而引擎的宽容是给"最终仍修不好"留的出口，两者目标不同（§13.1）。

**`align-over-hard` 的可操作提示与唯一放行口**（2026-08，01a00494 复盘）：裸消息「第 N 片 X 单位超过 hard」下 worker 会对着同一片反复提交（现场 s-g109.20 明明在「，」处就有合法切点，仍连吃三次 lint try、末了 force-through 再由引擎机械硬切）。现在 `check_rows` 用严格合法切分器 `split::legal_split_for_lang`（只切非客观语病缝、每片 ≤ hard、不做字符位硬切）替 worker 探路：片内有标点/空白背书的合法切分 → detail 直接给「可切为「…」｜「…」」；只剩 CJK 字界 → 「片内无标点/空白缝，请在词边界处切开」（切分器无词典，不替 worker 选词边界）；片内无解但整句有解 → 「片内无合法切点，需连同相邻片一起重切」并附整句切法。三者仍是 `Problem`、仍拒收。**唯一放行口**：整句译文都不存在合法切分（巨型 Latin 记号、每条缝都是客观语病）时只记 `WarningCode::AlignOverHardUncuttable`，不拒收——worker 除改写译文外没有合法动作，拒收只烧 try；引擎验收侧本就把此码当 advisory 并按 `enforce_target_hard_limit` 机械硬切，提交期放行不改变落盘结果。`data-unsplittable` 仍不抑制任何检查（源侧不可拆 ≠ 译侧不可切）。

## 8.5 缺省载体改为块对齐边：`align-edges/1` 与 `align-rewrite/1`（对齐块设计 M3）

自 [对齐块设计](../bcut-alignment-block-subtitle-split-design.md) M3 起，§8.1–§8.4 的两列切分表
`align-table/1` 降为**审阅/修复载体**（`bcut translate --align-carrier table`），缺省载体
是 `filepipe/align_edges.rs` 的两张同形表（kind `align-edges` / `align-rewrite`，都是
file-v1 HTML、`text/html`、`payloads/<callId>.html`）：

```html
<table data-lang="zh" data-fit="16" data-soft="14" data-hard="20" data-bcut-format="align-edges/1">
  <tbody data-sid="s-g1.0">
    <tr><th scope="rowgroup">s-g1.0</th>
        <td class="src">[1]I [2]didn't [3]go [4]because [5]I [6]was [7]sick.</td>
        <td class="tgt">因为我病了，所以没去。</td></tr>
  </tbody>
</table>
```

- **渲染**：`td.src` 是句内锚定词的序号词串（`[N]词`，一词一序号，与 `TransAlign.words`
  同下标；CJK 源按 `words[]` 原子计），`td.tgt` 是完整自然译句。不带停顿提示、秒数、
  源 Cue、切点建议、片数建议——模型的任务里没有"切"。`align-rewrite/1` 同形，另在
  `<tbody>` 上带 `data-over-hard="chunk 1 (words 1-9): 27 units > hard 20"`（只有相对
  预算，无秒数）。
- **应答**：模型只改 `td.tgt` 内容：`<span data-src="../4-7">因为我病了，</span><span
  data-src="../1 2 3">所以没去。</span>`。`data-src` 为空白/逗号分隔的 1-based 序号与
  区间（`4-7`、`1 2 3`、`1-3,9`），可乱序、可不连续、可为空（省译/功能块）；每个序号
  一句内至多归属一块；span 文本按 `normalize_chars` 口径拼接后必须等于译文（与
  §8.3 拼接不变式同一容忍度）；span 外的正文按空归属块计。`align-rewrite/1` 的
  `td.tgt` 允许被改写（单调化：小句顺序贴近源语、每块 ≤ hard），同时带 span 标注。
- **解析与验收（一份校验器）**：`parse_align_edges` 是这两个 kind 的唯一字符串级校验，
  引擎（`engines::align`）与提交期 lint（`lint_agent_answer_edges` /
  `lint_agent_answer_rewrite`，`task submit` 按 kind 路由）都调它。新增闭集码
  `align-edge-ordinal`（序号不可解析/越界/跨块重复）与 `align-edge-text`（span 拼接
  ≠ 译文）；rewrite 模式改用 `empty-translation`（改写为空）与 `align-content-drift`
  （幅度超 `reordered_rewrite_exceeds` ±max(25%,4)，或数字/URL/原样 Latin 硬锚丢失）。
  截断 vs 散点缺失、裸 `<tbody>` 恢复、体积护栏与 §8.4 同口径。`td.tgt` 没有任何
  span 只记 `content-ignored` 警告，按"无对齐边"返回。反解 `parse_align_edges_input`
  是 `render_align_edges` 的严格逆（往返逐字节相等由单测钉死）。
- **引擎侧**：块 → 软边（权重 0.75）+ `AnchorAligner` 硬边 → `align_block::plan_sentence`
  （安全边界 → 最小单调块 → 双语 DP）；`NeedsRewrite` 进 `align-rewrite` 轮（无修复，
  验收另加锁定术语/双语锚保留、目标 AutoCorrect、改写文本上重跑块核必须 `Aligned`
  才写 `transDisplay{basis:"monotonic-rewrite"}` + `text_basis: display`）；否则整句对应。
  首轮 `b…` / 修复 `r…` / 改写 `w…` 三类页工件同落 `ai/align/<lang>/vNNN/`。
- **表格载体的语义变化**：`data-crossing` 不再写 `crossing:true`，改落
  `correspondence: sentence`（整句一块一片）；`data-reordered` 改写不再回写 `trans`，
  改写 `transDisplay{basis:"table-reorder"}` 且条目 `text_basis: display`。§8.4 里
  "reordered 回写 `trans`" 的表述以本节为准。
- **translate 融合**：`data-align-*` 属性简化为 `data-align-words`（同一序号词串）+
  `data-align-needed`；模型在 `<p>` 内以同一 `<span data-src>` 微格式标注（§7 载体，
  `parse_translate_page` 从 `<p>` 子节点抽块），坏草稿只丢草稿不拒译文。
