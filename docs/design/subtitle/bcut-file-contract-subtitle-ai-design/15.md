# 15. 测试与验收

> 出自 [BaoCut 文件契约字幕 AI 管线设计（File-Contract Pipeline, v0.3）](../bcut-file-contract-subtitle-ai-design.md)

- **纯函数 golden**：渲染/解析/diff 的输入输出对拍；负例夹具必备一组——故意缺 id、重复 id、重叠冲突、非法 rowspan、截断页、多 fence、冻结句被改。
- **属性测试**（三条最低限）：
  1. 任意 words 序列 render→parse 往返后 id 集合与顺序不变；
  2. 任意合法 align 表解析出的 pieces 满足连续 + 不重叠 + 全覆盖；
  3. 任意 polish 输出经 rebind 后 `join_word_texts(words)` 与归一化输出相等。
- **双路径共享回归**：同一批夹具必须同时覆盖 agent 文件提交与 provider 原文响应（含围栏、残缺标签、缺 id、重叠冲突），不允许只测一条执行路径。
- **端到端**：p850/p130 基准项目全链路 + stale-only + timeline 各一遍。
- **性能验收**：调用数、总 token、墙钟对比现行基线；CJK 计数口径压测（§12）；翻译与对齐 8000 词页的质量非回退验证。

**M1–M4 覆盖现状**：纯函数 golden、负例夹具、双路径共享回归、`filepipe` 往返对拍均已落地；provenance 除 `provenance.rs` 的 core 单测外，宿主侧端到端用例也已落地（`core/crates/bcut-kernel/src/cmd/ai/tests.rs` 的 `translation_provenance_round_trips_and_detects_term_changes`：真实读写 `ai/state/translation.<lang>.json`，覆盖术语改名只命中相关句、账本缺失、`--no-brief` 无 basis 三种情形）。**尚未做的是性能验收**——本节最后一条的调用数/token/墙钟对比与 CJK 压测都还没跑，§12 与 §17.1 的所有数字仍是设计初值而非实测标定值。
