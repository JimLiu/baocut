# 3. 总体架构：契约换轨

> 出自 [BaoCut 文件契约字幕 AI 管线设计（File-Contract Pipeline, v0.3）](../bcut-file-contract-subtitle-ai-design.md)

每个 LLM 阶段统一为四段式：

```
render（代码）→ edit（LLM/Agent 编辑文件）→ parse+lint（代码）→ apply（代码写真相）
```

| 阶段 | 输入文件 | LLM 做什么 | 输出文件 | 解析回写 |
|---|---|---|---|---|
| analysis | 全文 txt（分页） | 摘要 + 术语表 | `context.md` | 落 `ai/`，供后续引用 |
| polish+segment | 页级 txt（只读上下文围栏） | 原地修订文本，段落处插空行 | 页级 txt | diff → LCS 重绑 `words`，空行 → `paraBreaks` |
| translate-brief | `context.md` | 翻译摘要与术语表 | `context.<lang>.md` | 落 `ai/` |
| translate | 句级 HTML（按段分页） | 整页翻译，id 不动 | 同构 HTML | 按 id 解析 → `trans` + `transSrc` |
| align | 超长句 HTML 表格 | 双列同步拆行 | 同构表格 | 解析行片 → `transAlign` |

关键点：

- **渲染器、解析器、校验器都是 `bcut-flow-core` 内的纯函数**（零 I/O，输入输出都是内存字符串/结构体，新模块 `filepipe/`）。宿主只搬文件。这保证 submit lint、provider 路径、离线测试三处是同一份实现。
- **HTML 一律用真正的 HTML5 容错解析器**（html5ever 或等价），不用正则啃标签。理由：正则无法确定元素文本的边界（内嵌 `<em>`、模型加的 `<br>`、`a > b` 字面量都会破坏启发式），而 html5ever 对未闭合标签、错位嵌套的容错正是我们要的"宽松"。**标签名不进协议**：解析器按 id/data 属性抽取节点，模型把 `<p>` 写成 `<div>` 不算错（§7.4）。
- LLM 输出永远先落盘成文件、再解析——provider 路径也是先写 `pages/pNNN.out.*` 再进解析器，保证两条路径的产物与审计轨迹完全同构。
