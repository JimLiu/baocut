# 5. 阶段 0：analysis —— 摘要与术语表

> 出自 [BaoCut 文件契约字幕 AI 管线设计（File-Contract Pipeline, v0.3）](../bcut-file-contract-subtitle-ai-design.md)

润色与翻译共享同一份参照物，先于一切 LLM 编辑阶段执行。

## 5.1 产物格式

`ai/context.md`（源语，替代 `ai/brief.json` 的 `summary/terms/namedEntities`）：

```markdown
---
fingerprint: "1024:g1.0:g88.4:ab12cd"
referenceFingerprint: "…"
---
# Summary
（整体摘要：题材、语域、说话人角色、文风要求）

# Canonical Terms
| Source | Category | Variants | Note | Lock | Origin |
|---|---|---|---|---|---|
| BaoCut | product | 宝卡特, 包卡 | 保持英文大小写 | yes | user |
| KV cache | tech | KV 缓存 | 首次可译，后文统一 | no | analyzed |
```

`ai/context.<lang>.md`（目标语，替代 `ai/brief-<lang>.json`，**必须保全其全部字段**——`tone`/`styleGuide` 落 `# Translation Style`，`difficulties` 落自由说明段，`analysisFingerprint`/`instructionsFingerprint` 进 frontmatter）：

```markdown
---
targetLang: zh
fingerprint: "…"
analysisFingerprint: "…"
instructionsFingerprint: "…"
---
# Translated Summary
# Bilingual Glossary
| Source | Target | Note | Lock | Origin |
|---|---|---|---|---|
| BaoCut | BaoCut | 产品名保留英文 | yes | user |
# Translation Style
```

格式约定：

- **表头用英文**（机器契约，多语言模型更稳定）；`Category` 是闭集：`product / person / tech / proper / other`，未知类别即 lint 失败。
- **Variants 必须是正文里真实出现的误识别，禁止编造**（反幻觉条款，进 prompt 也进校验说明）。
- **`Lock` + `Origin` 双列取代独立用户术语表文件**：一张表同时承载用户条目（`Origin=user`）与模型条目（`Origin=analyzed`），用户在同一张表里看到最终生效结果，不需要第三个合并视图。优先级：`Origin=user` 且 `Lock=yes` > `Origin=user` > `Origin=analyzed`。
- **重建规则**：analysis 重跑整表覆盖 `Origin=analyzed` 行；`Origin=user` 行逐条保留、禁止删除或改写；translate-brief 只翻译"尚未有 Target"的行，已锁定行逐字沿用。**术语表解析失败时保留旧的已验证上下文，绝不以空表覆盖。**
- **CJK 语境标点规范化（引擎侧确定性清洗）**：`Translated Summary` 与 `Translation Style` 在验收落盘和 `context.<lang>.md` → brief 转换两处统一规范化——ASCII `,` `:` `;` 的直接邻字符是 CJK 词字符时替换为 `，` `：` `；`（`3,000`、`10:30`、URL、纯英文不受影响；`.` 不映射，文件名/缩写歧义无法靠邻字判定）。理由：这两个字段会逐字回显进 translate 的 system prompt，风格指南里的半角标点会传染整篇译文（file-v1 基准 zh-Hans 半角逗号/冒号 14 处 vs json-v0 基线 0 处）。清洗幂等，存量残留在转换读取侧同样被覆盖；术语表 `Target`/`Note` 不清洗（locked `rt` 链要求逐字节沿用）。json-v0 的 brief 验收同口径。

## 5.2 与现行 locked 链路的衔接（不是格式平移，是链路迁移）

现行用户锁定通道是 `ai/brief-<lang>.json` 里的 `GlossaryEntry.locked`，其下游有四道硬约束：locked 条目 → translate payload 的 `rt`（required targets）→ `validate_translated_page` 缺失判 Malformed → `lint_agent_answer` 同构复检 → `check` 出 `missingTargets`。迁移要求：

1. `Lock=yes` 行继续编译为 `rt` 集合，四道下游链原样接通；
2. 存量 `ai/brief-<lang>.json` 中 `locked=true` 的条目在首次迁移时转为 `Origin=user, Lock=yes` 行；
3. 现状没有任何 CLI 子命令编辑术语（用户手改 JSON），Markdown 表本身就是新的用户界面——`bcut glossary lock/set` 子命令列为 M4 可选项，非必需。**M1–M4 实现裁决：未实现**（可选项，M4 未取）；`context*.md` 手改即是唯一入口。

## 5.3 注入方式

润色/翻译页的契约不内联全文术语表，由渲染器把**本页命中的术语行**筛出内联。页载荷只带相关术语，全局统一由同一张表保证。**M1–M4 实现裁决**：括号里"agent 路径额外在 references 中给出完整 `context*.md`"**未实现**——`references` 通道在两条执行路径上都还没接（§9.2/§9.3），worker 与 provider 一样只拿到本页命中的术语行。
