# 7. 阶段 2：翻译（HTML 契约）

> 出自 [BaoCut 文件契约字幕 AI 管线设计（File-Contract Pipeline, v0.3）](../bcut-file-contract-subtitle-ai-design.md)

## 7.1 渲染

`derive_sentences` + 段落投影 → 句级 HTML。结构：**`section` 承段、`p` 承句**（用户原设想的 `<p><div>` 嵌套非法；`<span>` 行内方案也放弃——行内元素间空白有歧义、模型整段 reflow 时易合并相邻 span，块级元素给出明确的独立单元信号）：

```html
<article lang="en" data-target="zh"
         data-bcut-format="translation-source/1"
         data-project-fp="1024:g1.0:g88.4:ab12cd">
  <section id="p-g1.0" data-sp="S1">
    <p id="s-g1.0" data-budget="整句≤26字">Ninety days, eight times the growth.</p>
    <p id="s-g1.7" data-budget="整句≤17字">We did it without ads.</p>
  </section>
</article>
```

- 根节点用裸 `<article>`，**不要**完整 `<!doctype html><html><body>` 包装（每页固定 token 开销，且诱导模型补 `<head>`/`<title>`）。`data-bcut-format` 版本标记是 §9.5 缓存键中 renderer 版本的落地锚点。
- 不含时间戳；说话人以 `data-sp` 附在 `<section>` 上（供模型调语气，不要求回写）。
- 所有 transcript 文本经 HTML escaping 后写入（§16）。
- **`data-budget`（长度通道）**：句级阅读预算，口径同 json-v0 的 `maxChars`——`floor(显示时长 × 目标语 cps)`，计数按**阅读单位**（与 `target_cps_chars` 同口径：空白与普通逗号/句号免费，CJK 目标语下 Latin 字母/数字约计半字），**不是**裸的非空白字符数——后者对「短句 + 必带 Latin 锁定术语」恒不可满足（如预算 11 遇上 `data-rt` 里 11 个字母的 "description"）。与 §8 align 表格的 `data-budget` 一样**只带相对预算文案、绝不带秒数**，单位随目标语在 `字`/`字符` 间切换。只挂**可编辑句**：冻结句（§7.6）要的是逐字复制，挂预算只会诱导模型改动不该动的译文。契约文本同时声明「成品是字幕」与反向护栏（该长就长优先于压缩，绝不为压缩删因果、否定、数字、专名）；每行展示上限按目标语言而变（CJK ≈16 格、拉丁 ≈42 字符），因此**只有性质进契约常量、具体数值一律走 `data-budget`**。解析器对该属性一律忽略（不参与校验、不反解），旧任务目录里不带 `data-budget` 的 `src.html` 判定完全不变。
  - **v0.3 增量裁决**：M1–M4 落地时漏移植这条通道，实测 file-v1 译文展示宽度比 json-v0 高约 13%、translation-unsplittable 从 1 句涨到 31 句；本项补齐后，file-v1 的长度约束 = 契约里的字幕语义 + `data-budget`，仍不引入被 §7.8 移除的融合段。

## 7.2 术语表先行

翻译顺序强制：`context.md → context.<lang>.md → 正文`。正文页契约内联摘要 + 本页命中术语的译名行；`Lock=yes` 行编译为 `rt` 进校验（§5.2）。

## 7.3 分页与并行

- **按自然段落整段分页，无冗余**——`<section>` 是原子，不跨页拆分。页预算为 8000 源文词；Latin 按词、CJK 按字，句数与 worker 槽数不参与分页。
- 跨页语境用 HTML 注释静态注入：`<!-- context-before: … -->`，不要求模型输出。
- 页间无依赖，批量分发；每页成功即解析回写。

## 7.4 输出解析：症状对账表

模型输出同构 HTML：id 一个都不能少、不能改，`<p>` 内为译文。解析器（html5ever，按 id 抽取）逐项对账：

| 症状 | 错误码 | 处理 |
|---|---|---|
| 缺句 id | `missing-id` | 部分提交本页已到句，缺失句进修复波次 |
| 未知 id | `unknown-id` | 忽略该节点 + advisory |
| 空译句 | `empty-translation` | 视同缺 id |
| 重复 id | `duplicate-id` | **本页拒绝重试**（无法判定哪个是答案） |
| 段 id 丢失但句 id 齐 | — | 接受句译；段落从属以源结构为准 |
| 标签被改成 `div`/`span` 但 id 在 | — | 按 id 抽取，标签名不进协议 |
| Markdown 围栏/前后闲话 | `document-wrapped` | 取整棵树中全部带句 id 的节点；单外层 fence 零成本剥除 |
| 输出截断（尾部句连续缺失+HTML 未闭合） | `document-truncated` | 本页重试，并检查 `max_tokens` 定标（§9.3） |
| 锁定术语缺失 | `glossary-missing` | 该句进修复波次 |
| 冻结句被改动（§7.5） | `frozen-modified` | 本页错误，冻结句绝不覆盖写 |

## 7.5 重试波次与终态（句级记账）

页级整体重发是浪费——已通过的句子已逐句落盘。记账单位统一为 **Sentence，每句尝试预算 3 次**（页级首次响应计一次）：

1. **首波**：全部页并行；
2. **修复波**：每页失败句聚合成本页 repair 小页（携带结构化 problems）；
3. **残余波**：全任务剩余失败句合并为最后一个 residual 批次。

三次后仍无译文：**保持未译、绝不写伪译文、绝不把源文复制为译文后报成功**。终态语义与现行 check 一致：部分缺译 → `translation-partial`（warning，不挡门禁）；整语言缺失 → `translation-missing`（blocker）。**渲染层对缺译句是画面留空，不存在"回落原文"**（`derive_trans_cues` 对未翻译句不产出 cue；双语模式只烧原文行是双行各自正常工作，不是兜底）。通过的句子：CJK 先过幂等 AutoCorrect → 写 `trans` + `transSrc` → `save_doc` checkpoint。

## 7.6 增量（stale-only）

待重译集合 = `stale_sentences`（`transSrc` 判定，语义不变）∪ provenance 判定（§11.3）。渲染 stale-only 页时：整段照渲（保语境），**全部句子保留 id**，非 stale 句加 `data-editable="false"` 并以注释附现有译文（只读参照）。模型必须原样保留冻结句；解析器只提交 editable 句，**冻结句发生任何变化都是当前页错误**（`frozen-modified`），绝不覆盖已有译文。（保留 id 才能检测模型是否动了它；无 id 的裸文本方案出错是静默的。）

## 7.7 timeline（多源路由）

沿用现行 route id 机制：HTML `id` 用全局唯一 route id（现行 `r%06d` 格式），另带 `data-source-id` 与 `data-sid`；解析器按 `(srcId, sentenceId)` 二元组分散回写（持久化键不变）。同一文档内绝不出现重复 HTML id。`transSrc` 仍是剪后可见词指纹。

## 7.8 融合对齐草稿：移除（改变现行默认）

融合（translate 顺带产 sourceBreaks 草稿）是**当前默认开启**的路径（`--align many-to-one` 默认值）。本方案将其移除：它把 align 复杂度前置进翻译契约，且把翻译页预算压到 1000 词——移除本身就是 §1 的最大收益来源。align 只处理超长句（§8），调用量已大幅下降，不再需要预验收通道。**不留 `data-hint` 回补口**（留口就保留了把页预算拉回去的可能性）。

**M1–M4 实现裁决（已被弃用执行推翻）**：灰度期内融合只是"契约内移除"。**2026-08 弃用执行后为全局退役**：`TranslateOptions` 不再有 `align` 字段，`TRANSLATE_FUSED_WORDS`/`TRANSLATE_WORDS` 常量删除，页预算恒为 `TRANSLATE_FILE_WORDS = 8000`；`--align-mode` 只影响 align 阶段的对齐策略。
