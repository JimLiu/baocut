# 4. 目录布局与版本化

> 出自 [BaoCut 文件契约字幕 AI 管线设计（File-Contract Pipeline, v0.3）](../bcut-file-contract-subtitle-ai-design.md)

所有中间产物落在项目包 `ai/` 下（已在项目目录白名单内）：

```
ai/
  context.md                  当前有效的源语摘要+术语表（稳定路径，消费方直读）

  state/
    translation.zh.json       译文 provenance（§11.3），不含译文正文
  brief/v001/…                context 历史版本归档（含 manifest.json）
  polish/v001/
    manifest.json             指纹、模型、参数、页表、状态
    input.txt                 全文快照（含软标记，审计用）

    pages/p001.out.txt        LLM 输出（重试轮：p001.out.a2.txt）
    merged.txt                去围栏合并后的全文（润色分段定稿）
    report.json               逐页相似度、回退、局部重润记录
  translate/zh/v001/
    manifest.json
    source.html               全文句级 HTML
    pages/p001.src.html / p001.out.html
    merged.html               合并后的双语对照（审计/预览用）

    manifest.json

    round2.src.html / round2.out.html    （定向修复轮）

    fallback.json             确定性兜底清单（收编 ai/align-fallback-<lang>.json）
```

## 4.1 版本规则

- 每次**用户显式重跑**某阶段（重新润色、重新翻译、重新对齐）→ 该阶段目录下新建 `v002/`、`v003/`…；增量续跑（指纹判脏后补跑 stale 部分）**复用当前版本目录**，在 manifest 里追加 run 记录。**M1–M4 实现裁决：复用分支未实现**——`ArtifactWriter::open` 一律 `max_version + 1` 开新目录，增量续跑也开新版本（§17）。
- 阶段目录内不放 current 指针；**当前生效版本 = manifest `status: done` 且 `inputFingerprint` 与 transcript 现指纹匹配的最大版本号**，由代码推导（指针也不持久化，与"分页边界不持久化"同源）。`context*.md` 是唯一的例外——它们是"当前有效副本"的稳定路径，重跑 analysis 时原子替换，历史归档在 `brief/vNNN/`。
- **保留策略**：默认保留最近 3 个版本的完整产物 + 全部版本的 `manifest.json`/`report.json`（体积小、审计价值高）；更老版本的 `pages/` 与 `input.txt`/`source.html` 由 `bcut ai clean --keep N` 清理。`ai/` 下一切都是可重算的审计工件，不是项目真相；过期工件可用于 diff/回溯，但不允许再次自动写回 transcript。

## 4.2 manifest 语义（两条边界必须说清）

```jsonc
{
  "stage": "translate", "lang": "zh", "version": 3,
  "protocolVersion": "file-v1",                       // 渲染器/解析器协议版本
  "inputFingerprint": "1024:g1.0:g88.4:ab12cd",
  "parents": { "context": "v001", "polish": "v002" },
  "model": "provider:anthropic/claude-sonnet-5", "params": { "fit": 16 },
  "pages": [ { "id": "p001", "status": "done", "attempts": 2, "src": "...", "out": "..." } ],
  "runs": [ { "at": "...", "kind": "full" }, { "at": "...", "kind": "stale-only", "sentences": 12 } ],
  "status": "done"
}
```

**M1–M4 实现裁决**：`manifest.rs` 落地字段与上表一致，两处补充——`pages[]` 每项额外带 `problems: Problem[]`（逐页协议问题留档，审计用）；`protocolVersion` 由 `Manifest::new` 硬编码为 `file-v1`，`protocol_supported()` 也只接受 `file-v1`。也就是说 **manifest 目前表达不了 `json-v0`**：json-v0 路径根本不写 manifest，§9.6 的"两种协议共处一份 manifest"只在 claim 信封那一侧成立。

- **`pages` 表是审计记录，不是续跑权威**。断点续跑时重新确定性投影页面，跳过"检查点新鲜"的单元；分页参数变化后旧页表自然作废，不会被误读。
- **文档级 `inputFingerprint` 只回答"这份文件产物能否被人/Agent 直接复用"**（审计层面）。句级增量判据仍然是 `transSrc`（改一句源文只重译一句，不因文档级指纹失配而作废整个版本）。各阶段的 checkpoint 单位：analysis→页笔记、polish→已验收源词 patch、translate→sentence id、align→sentence id。
