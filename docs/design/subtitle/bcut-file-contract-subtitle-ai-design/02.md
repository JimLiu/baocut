# 2. 不变的部分（红线）

> 出自 [BaoCut 文件契约字幕 AI 管线设计（File-Contract Pipeline, v0.3）](../bcut-file-contract-subtitle-ai-design.md)

以下全部继承自现行架构，文件化改造**不得触碰**：

- **真相模型**：`words[]` 是唯一文本/时间真相；Cue/Sentence/Para 永远是派生投影；`breaks`/`paraBreaks`/`hidden` 稀疏覆盖表键为 word id；`trans[lang][sid]` 是句级译文真相；`transAlign[lang][sid]` 只是显示切分覆盖层，`normalize(concat(pieces.text)) == normalize(trans)` 不变式必须成立，写盘顺序先 `trans` 后 `transAlign`。
- **五条纪律**：绝对时间戳永不进 LLM（相对时长/预算折算后以属性承载）；确定性校验而非 prompt 信任；分层降级、整体永不失败（401/403/404 除外）；指纹驱动脏检测；分页边界不持久化、断点续跑靠确定性重推。
- **对齐规范次序**：先按目标语自然度冻结译文片，再映射连续源词区间；源 Cue、源 Cue 边界、`breaks` 表不得进入载荷、不得被反推。
- **人工版式优先**：`ensure_balanced_cue_layout` 仅在 `doc.breaks` 为空时铺均衡断点（`layout.rs` 现行早退），`asrLayout` 戳 stale 即意味着存在人工版式干预。任何降级路径（包括 §6.6 的确定性兜底）都不得在存在人工段钉/断行时静默重排版式；显式 `--segment`/`--repair` 除外。
- **写权归属**：transcript、阶段戳、指纹只能经 `bcut` / `bcut serve` / apply 脚本写入；`ai/` 产物头部（或 manifest）带 fingerprint，读取方必须先校验再用。
- **校验只有一份**：agent 提交时的 lint 与 provider 路径的 validate 必须是同一个 core 函数。**M1–M4 实现裁决**：reordered 改写幅度护栏的**算术**已合并为 `split.rs::reordered_rewrite_exceeds` 单一实现（三处调用共用），但 provider 验收（`align.rs:4721`）与 agent 提交期 lint（`align.rs:5410`）仍是两个调用点、两串逐字节相同的失败文案——判据统一了，调用点没统一（§13.1）。
- **复用清单**（代码层面直接沿用）：`rebind.rs`/`lcs.rs` 原子级 LCS 重绑定、`atomize.rs`（含 `word_count`）、`seam.rs` 接缝 lint、`split.rs` 确定性切分与 `TransParams` 三阈值、`fingerprint.rs`、`sentence.rs` 派生与 `stale_sentences`、`markers.rs` 停顿标记、`complete_batch_retry_with` 的"只重发失败单元 + 流式 on_ready"骨架、`ProjectLock` + `save_doc` 逐单元 checkpoint、tasks/ 租约体系。
