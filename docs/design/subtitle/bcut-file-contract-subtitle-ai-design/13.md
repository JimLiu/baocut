## 13.1 已实现的有意限制（M1–M4 裁决汇总）

以下每一条都是**有意为之的当前状态**，不是待修缺陷。记在这里是为了避免将来被当成 bug 重新"修"回去；真正的未实现项在 §17。

**（一）brief.json / context.md 双写与灰度并存**

`ai/context.md` / `ai/context.<lang>.md` 是新真相，但 `ai/brief.json` / `ai/brief-<lang>.json` **在同一次运行里继续原子双写**。首次迁移从 brief.json 播种 context.md，之后以 context.md 为准回写两份。保留双写的原因是 json-v0 消费者仍在读 brief：`bcut check`、Subtitle Studio、存量用户脚本，以及 **Mac App 的唯一读点** `apps/mac/Sources/VoiceInk/Presentation/SubtitlePresentationContext.swift:41`（拼 `brief-<lang>.json` 路径）。双写在 §13"互认期"结束、且 Mac 侧改读 context.md 之后才能拆。

**（二）~~固定 json-v0、不暴露 `--contract` 的入口清单~~（2026-08 弃用执行后失效）**

`--contract` 已整体移除，原清单里的所有入口（workflows 内嵌 pre-polish、成片 timeline 路由、`bcut refine`、workflow / `auto`、`bcut serve` 发起的作业）与直接命令一样**恒走 file-v1**。原表保留的唯一遗产是 serve 任务白名单仍然没有 `contract` 键——现在也没有这个参数可暴露。

**没有"半路无声失效"的组合**：`--fit` 正交（喂 `TransParams`，文件载体以 `data-fit`/`data-soft`/`data-hard` 承载），`--align-local` 只与 `--align-mode` 冲突、与契约无关。

**（三）M2（polish）裁决**

- carry-over 全面退役；灰度期保留的 json-v0 路径与 `MAX_CARRY_CHARS` 已随弃用执行删除（§6.5）。
- `resplit_oversized` **不接入**文件路径：它按句末标点造段落边界，与"段落边界只有空行与 `⏹` 两个来源"冲突（§6.5）。整页糊成一句时不再整页拒绝：正文首轮即接受，超长句走 `punct-repair` 定向补标点 + 引擎确定性切句（§6.7），切开的句再由 `segment-repair` 补分段。
- 低相似度收尾仍复用 `polish-retry` 通道（json-v0 单轮 JSON 信封，属未迁移 kind）——同一个 core 修复语义，没必要为文件契约再造一个。

**（四）M3（align）裁决**

- 两份 align 校验器**未合并到一个调用点**（只合并了算术，§2）。
- `align-over-hard` / `align-illegal-seam` 在文件契约下降为**逐句 advisory**，不阻断本批验收（§8.4）。
- 提交期 lint 推给 worker 的是**全量** Problem，包含上述两个引擎自己会放行的码——**有意的不对称**，不是漏改（§8.4）。
- `pause_tier` 私有阈值只保留在草稿词元内部停顿元数据，不进文件载体、不参与分页（§8.2）。
- 预览 `<style>` 有意不内联（§8.1）。

**（五）M1（translate / 执行层）裁决**

- `default_lease_sec` 未重标定（§9.2）。
- agent 任务目录**未做数据面/控制面拆分**，仍是五目录 + `payloads/`（§9.2）。
- lint 预算仍是 `(callId, leaseId)` 键，换租约清零（§9.2）。

**（六）M4（context / provenance）裁决**

- 溯源 stale 判据收窄为**术语哈希集合变化**；摘要/文风变化只出 advisory（§11.3）。
- 无生效简报时全部判清白，而不是全部判 stale（§11.3）。
