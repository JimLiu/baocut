# 10. 错误分类、重试记账与降级阶梯

> 出自 [BaoCut 文件契约字幕 AI 管线设计（File-Contract Pipeline, v0.3）](../bcut-file-contract-subtitle-ai-design.md)

## 10.1 错误码表

`ProblemCode`（17 个）是**唯一进重试记账、唯一回灌给模型/worker** 的一层；每个 Problem 带 `scope`（`Document` / `Page{id}` / `Sentence{id}` / `Paragraph{index}`），修复范围由 scope 决定。

| 错误码 | 含义 | 修复范围 |
|---|---|---|
| `document-truncated` | 输出未闭合/只有半页 | 当前页（并检查 max_tokens） |
| `document-wrapped` | 多 fence/夹带解释 | 当前页（单 fence 零成本剥除不计次） |
| `document-oversize` | 输出体积超过按输入估算的**硬顶**（§16 的失控生成防线：`max_output_chars` = **8×** 输入字符，下限 4096；2026-08 从 4× 上调——护栏只判「载荷还值不值得解析」，偏长但结构完整的答案交给各 kind 的单元级规则去重/截断） | 整篇拒绝：四个载体（align 表 / translate HTML / polish txt / context md）解析入口统一先过 `guard_output_size`，超限即不解析、当次尝试作废。**注**：polish 的句级质量闸门已从此码迁走——冲突相邻标点改为代码归一，悬垂假句末与中文 20+ 字母英文粘连改为 `surface-artifact`（2026-08 重试策略重设计）。单句源跨度超雪球 / corrected 单句超段落容量走 `sentence-oversize`（§6.7）。 |
| `source-drift` | 润色大改源文/align 改了源文 | 最小变更窗口 / Sentence |
| `missing-id` / `empty-translation` | 缺句/空译 | Sentence（聚合修复波） |
| `duplicate-id` | 同 id 多次出现 | 当前页 |
| `unknown-id` | 多出的 id | 忽略 + advisory |
| `paragraph-move` | 句被挪到别的段 | 当前页 |
| `frozen-modified` | 冻结句被改 | 当前页，绝不覆盖写 |
| `glossary-missing` | 锁定译名缺失 | Sentence |
| `align-content-drift` | 对齐拼接漂移（含 reordered 改写幅度越界） | Sentence（定向轮） |
| `align-over-hard` | 切出的片仍超 hard | Sentence（定向轮）；**文件契约下不阻断本批验收**，见 §8.4 |
| `align-illegal-seam` | 接缝违反 `seam.rs` 判据 | Sentence（定向轮）；同上，advisory |
| `context-invalid` | `context.md` / `context.<lang>.md` 结构非法：缺 frontmatter、缺 `# Canonical Terms`、表头不符、未知 `Category`、非法 `Lock`/`Origin`、非法 `tone` | **整篇拒绝、保留旧的已验证上下文**（§5.1"绝不以空表覆盖"的执行点）；未知类别/非法枚举额外带 Sentence scope 指出是哪一行 |
| `sentence-oversize` | 超长句（单句源跨度 > 1200 字符 / 300 秒，或 corrected 超单段容量）：`punct-repair` 答案里该句被原样复述却一个句末标点都没加，或新加的标点切不出 ≥ 2 片 / 无法回贴源词（§6.7）；主 polish 页不报此码——超长句首轮即接受、波次后定向补标点 | 该句（scope `Sentence{id}`，id 为载荷内 `sNN`）：detail 就是下一轮的定向指令，经 `retry_reason` / `problems` 回灌；同一载荷里其他句不受影响。切开后的片仍超长不报此码，只进下一轮，轮次上限 `PUNCT_REPAIR_MAX_ROUNDS = 3`，耗尽后引擎按源时间轴确定性切句 |
| `paragraph-oversize` | `segment-repair` 索引契约答案里某块只回了一个区间而整块超限（§6.6）；主 polish 页不再报此码——超限段落首轮即接受、波次后定向补分段 | 该块（scope `Paragraph{index}`，index 为载荷内块序）：detail 就是下一轮的定向指令（含最少段数），经 `retry_reason` / `problems` 回灌；同一载荷里其他块不受影响。子组拆开后仍超限不报此码，只进下一轮，轮次上限 `SEGMENT_REPAIR_MAX_ROUNDS = 3`，耗尽后引擎按停顿等级确定性收口（§6.6） |
| `surface-artifact` | 表面级瑕疵：悬垂假句末（`当。`/`because.`）、中文正文里 20+ 字母的疑似英文粘连单 atom（冲突相邻标点已由代码归一，不进本码）。**从不拒页**：主 polish 页只按段落记同名 Warning，`punct-repair` 里按句记 Problem | 该句（scope `Sentence{id}` / `Paragraph{index}`）：主波次映射成句后进 `polish-retry` 的句级补做队列（`reason = surface-artifact`，≤2 轮），耗尽后**保留模型文本**并计 `surfaceArtifactSentences`；`bcut check` 的 `polish-false-sentence-end` / `polish-surface-artifact` 警告继续兜底 |
| `range-invalid` | `segment-repair` / `seam-repair` / `speaker-repair` 索引契约答案的行号区间非法：缺块、没有区间、不从 1 开始、不首尾相接、不覆盖到末行、越界（§6.6/§6.8/§6.9）；speaker-repair 另含标签不在窗口说话人里、段数多于现状 | 该块（scope `Paragraph{index}`）：detail 定位首个缺陷，是下一轮的定向指令；同载荷其他块照常落地。seam-repair 块被拒 ⇒ 保留原段钉；speaker-repair 窗口被拒 ⇒ 保持原归属 |

**五处相对 v0.2 的补充（实现裁决）**：`document-oversize` 与 `context-invalid`（M1–M4）、`paragraph-oversize`、`sentence-oversize` 与 `range-invalid`（2026-08）。第一个是 §16 最后一条"输出大小硬顶"从原则落成错误码；第二个是 v0.2 §10 只面向分页编辑阶段、漏了 `context*.md` 这一路的结构校验——analysis / translate-brief 也会失败，也需要一个能记账的码；第三个是分段退化事故（§6.1）暴露的"零段落有校验、一段糊到底没校验"缺口——它先以"整页重试 + 末轮宽恕"落地，随后改为"首轮即接受 + `segment-repair` 定向补分段"（§6.6），此码只在补分段载体里报。补分段载体随后改为索引契约（§6.6）：答案只回行号区间，正文改写在契约里没有落脚点，`source-drift` 不再出现在补分段里，取而代之的第五个码 `range-invalid` 按块记账（scope `Paragraph{index}`）：区间缺失 / 不连续 / 不覆盖即拒该块，同载荷其他块照常验收。第四个是超长句事故（§6.4）暴露的"拒页逼模型断句无效"缺口——单句超限从 `document-oversize` 整页拒绝改为"首轮即接受 + `punct-repair` 定向补标点 + 引擎确定性切句"（§6.7），此码只在补标点载体里报；`source-drift` / `missing-id` 在 `punct-repair` 里按句记账（scope `Sentence{id}`）。

**`WarningCode`（19 个）只进 observability，不消耗任何重试预算、不改变验收结论**，故不单列表格：`wrapper-stripped`（单 fence 零成本剥除）、`control-stripped`、`blank-lines-collapsed`（≥3 连续换行折叠，§6.1）、`marker-residue`（残留 `⏸` 被剥离）、`node-dropped`（丢弃 style/script 等非白名单节点，§16）、`attribute-dropped`、`sentinel-neutralized`（正文里出现围栏字面量被中和，§16 注入防线）、`rowspan-mismatch`（`<th>` rowspan 与组行数不符——纯冗余校验，不否决数据，§8.3）、`content-ignored`、`boundary-forced`（切点不在词边界，吸附到最近边界，§8.4）、`align-over-hard-uncuttable`（行片超 hard 但整句译文无合法切分，提交期放行、引擎机械硬切，§8.4）、`anchor-repaired` / `anchor-text-mismatch`（chapters 锚按开头片段修复 / 片段与段首不符）、以及 2026-08 重试策略重设计新增的 `duplicate-id`（同一 id / Source 多次出现，已取首个或合并）、`row-repaired`（列数补齐/并回、非法取值降级、垃圾行丢弃）、`fence-recovered`（哨兵栅栏由相邻栅栏推断）、`punctuation-normalized`（冲突相邻标点代码归一）、`surface-artifact`（表面级瑕疵，只记诊断）、`frozen-ignored`（冻结句被改/被移，已忽略模型文本）。它们与 `Problem` 是两条独立通道（`manifest.pages[].problems` 只装 `ProblemCode`），**不进模型回灌、不进重试判据**。

## 10.2 重试原则

- **格式层先做零成本恢复**：BOM、单外层 fence、HTML entity、换行规范化——不消耗任何预算。
- **transport 与内容分开记账**：429/5xx 重试不消耗内容重试预算；内容预算按 §10.1 的修复范围计（页级/句级）。
- **确定性兜底必须显式标记**，不得伪装成模型结果。
- `Http{408,429,5xx}`/`Malformed` 可重试，`Terminal`（401/403/404）中止 run；每次尝试的产物文件（`.a2` 后缀）全部留档。

## 10.3 阶梯汇总

| 阶段 | 逐轮阶梯 | 终态保证 |
|---|---|---|
| polish | 整页×3 → span 局部×2 → 切点恢复 → 原文兜底 | 永不丢字；人工版式永不被静默重排 |
| translate | 首波 → 页内修复波 → 全局残余波（句预算 3 次） | 缺译保持留空：`translation-partial` warning / `translation-missing` blocker；绝不伪译 |
| align | round1 → 定向 round2 → 确定性兜底 | 全部句子不超 hard 或已报 blocker；兜底显式标记 |
