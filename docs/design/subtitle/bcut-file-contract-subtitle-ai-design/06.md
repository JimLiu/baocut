# 6. 阶段 1：润色 + 分段（txt 契约）

> 出自 [BaoCut 文件契约字幕 AI 管线设计（File-Contract Pipeline, v0.3）](../bcut-file-contract-subtitle-ai-design.md)

润色与分段合并为一次编辑（现状 polish 已顺带产段落，此处把它变成显式契约）。

## 6.1 渲染与换行语义（协议核心，必须无歧义）

- 词序列按语言接合规则渲染为自然文本（`atomize` 口径；拉丁空格连接，CJK 直连）。**`hidden` 词不进投影**（与 `Sentence` 派生排除 hidden 的现行行为一致；否则润色会让已剪掉的内容复活）。
- **不含任何时间戳与 word id**。
- 软标记沿用 `markers.rs` 现行字符与阈值：`⏸`（≥0.6s）/`⏸⏸`（≥1.0s）/`⏸⏸⏸`（≥1.8s）/`⏹`（说话人切换）。多说话人文档的 `⏹` 带稳定说话人标签 `⏹S2`（标签指右侧说话人，规则见 `speaker::SpeakerLabels`；不含时间，全篇一致），裸 `⏹` 仍被识别。**软标记与标签只存在于输入，不进 diff 基线**（解析时双侧剥除后再比对）。
- 已有段落（重润时）渲染为空行；人工段钉（`asrLayout` stale 场景）必须原样预置，模型可微调但解析侧受 §2"人工版式优先"约束。

**换行语义表（输出侧）**：

| 形态 | 语义 |
|---|---|
| 单个换行 | 可读折行，解析时视为空格，**不承载任何边界语义** |
| 空行（连续两个换行） | 段落边界 → `paraBreaks` |
| ≥3 个连续换行 | 非法结构，解析时折叠为一个空行并记 warning |
| `⏹` / `⏹S<n>` | **硬保证**：说话人切换处强制断句断段，不信任模型——模型必须原位保留、不得删除/复制/跨越；解析时无论模型是否保留，程序都在原位置强制边界；输出中残留的 `⏸` / `⏹` / 说话人标签一律剥离 |

明确拒绝"单换行=句边界"与"程序补句号"两种设计：Sentence 永远由句末标点等规则确定性派生（红线"派生投影"），从版式信号反推修改 `words[]` 文本会绕过 LCS 重绑的证明。

**分段质量门（实现补充，2026-08）**：分段是强制产出而非可选项。核心区单个段落的词数超过 **Latin 300 / CJK 500**（`atomize::word_count` 口径；`is_cjk_text` 判档，常量 `MAX_PARAGRAPH_WORDS_LATIN`/`MAX_PARAGRAPH_WORDS_CJK`）即为分段退化。动机是真实事故：模型（实测 deepseek-v4-flash）整页不给空行，旧校验只拒"零段落"，9 分钟转写糊成一个段落仍被验收并盖了 `segment` 戳。系统提示词声明该上限为验收线，但**主 polish 页的 lint 不因超限拒页**——超限段在波次后由专用 `segment-repair` 载体定向补分段（§6.6），`paragraph-oversize` 只在那个载体里作为 Problem 出现（§10.1）。

## 6.2 分页与只读上下文

- 核心区预算 2200 词（`atomize::word_count` 口径，见 §12），断点打分复用 `paging.rs`（说话人切换 3 > 长停顿 2 > 句末标点 1，预算窗口末 20% 内择优）；**句界优先**（2026-08，实测修正）：窗口里只要有句末标点就取评分最高的句界，没有句界才回落到停顿——单人长讲实测（谢赛宁 7h 访谈抹平说话人）47 个页缝里 30 个落在句中（「我们大 ‖ 脑的皮层」），因为一个 0.6s 的犹豫停顿（rank 2）总能压过窗口里的句末（rank 1）；句界优先后只剩完全无标点的区段才在句中切页（同一语料 30 → 8）。有说话人的长轮次内部本就句界优先，两条路径自此一致。
- **无好断点时的规则**（现行 rank=0 直接硬切，文件契约下会造出残句诱使模型补完，必须显式处理）：允许核心区预算上溢至 +15% 去够下一个句界、再够下一个 rank≥1 的断点；仍无 → 在硬切处标 `<<<HARD-CUT>>>`，契约明示"本页首/尾可能是残句，原样保留、不要补完"。说话人切换永不被页缝跨过。**硬切页缝两侧的段落由引擎无条件合并**（`hard_cut_seams_merged`）——契约已告诉模型 HARD-CUT 不是段落边界，引擎不得再在那里落段钉。
- **两侧各附只读上下文区**：`min(200 词, 3 个完整句)` 且**至少 1 个完整句**（60 词量级在 CJK 下装不下一个句子，太小即失效）。sentinel 围栏：

```
<<<CONTEXT-BEFORE 只读，勿修改>>>
…上一页尾部…
<<<EDIT-BEGIN>>>
…本页核心区，可修订，段落之间留一个空行…
<<<EDIT-END>>>
…下一页头部…
<<<CONTEXT-AFTER 只读，勿修改>>>
```

- **归属权唯一**：解析只取 `EDIT-BEGIN/END` 之间；缝上段落边界由拥有该词的页说了算。上下文区是只读语境（下页能看到上页尾部的完整句），不做可写重叠、不做共识缝算法——那会把 token 成本翻倍并把串行性请回来（v2 若压测证明缝质量不足，再考虑参考 B 的 `TextPatchSet` 合并）。
- **页缝不是段落证据**（2026-08 实测修正）：分页只切起点，页 k 末段与页 k+1 首段之间的边界是机械产生的；此前引擎把每个页缝无条件写成 `paraBreaks`，单人长讲实测 47 个页缝里只有 9 处（19%）本来就有段落边界。现在页缝分三档处理：① 说话人切换处的页缝：⏹ 硬保证，段钉必然成立；② 后一页在 `EDIT-BEGIN` 之后、第一句之前留**一个空行**（`PolishParsed::starts_new_paragraph`）：模型显式声明「首段另起一段」，段钉保留、不再询问（`seam_signaled_paragraphs`）；契约里这是**唯一**有意义的前导空行，上文为空（首页）或硬切开头时不算信号；没留空行只表示「未表态」，不能反推为「延续」；③ 其余页缝：主波次与 punct-repair 之后交给 **seam-repair 波次**（§6.8）判定，模型说延续就合并、说边界或拒收就保留。
- 围栏行必须原样保留（解析锚点）；围栏残缺 → `document-truncated`（§10）。

## 6.3 指令与模型档位

- 指令 = 现行 polish 修改类别开关（`typo/term/punct/grammar/filler/wordy`）+ 换行语义表 + 本页命中术语行。温度 0.2。
- **`segment-only` 模式**：指令收窄为"逐字保真，只插空行"，按 kind 路由到廉价模型（§9.4）。全量重分段走此模式，替代现行 segment 引擎的主契约。润色与纯分段是两个指令强度档：前者需要主模型，后者可以极廉价。

## 6.4 解析与回写（降级阶梯）

1. 校验围栏 → 剥除围栏与软标记 → 换行语义解析 → `normalize_chars` 归一。
2. **逐字保真捷径**：归一后与核心区源文相等 → 只取空行位置写 `paraBreaks`（segment-only 的期望路径）。
3. **diff 重绑**：`atomize` + LCS 与核心区词原子对齐。**页级门槛 0.7**（`MIN_TEXT_MATCH_RATIO`），句级相似度 Latin 0.7 / CJK 0.75（三值均为现行常量；文件契约页更大，页级门槛列为待压测重标定项）。通过 → `rebind` 保 id 保时间换文本；空行吸附到词边界，段首词 id 进 `paraBreaks`。
4. **术语替换保护**：比相似度前先把命中术语的"变体→规范形"替换做不透明 token 化（否则 `宝卡特 → BaoCut` 这类正确修正会被判为低相似而误触重润）。
5. **span 局部重润**：低相似句占比 > 0.3（`MAX_SIMILARITY_FAIL_RATIO`）或匹配率不足 → 对失败词区间 ± 一句上下文发 span 级 txt 修复请求（同一契约，围栏内只有该 span），至多 2 次。
6. **切点恢复**：仍失败的 span 丢弃 LLM 文本、只取段落切点（对应现行 `low_similarity_retry` 之后的逐句回退，polish 没有 segment 的 tier 命名体系）。
7. **确定性兜底**：整页回退原文 + 规则切段（永不失败），计入 `report.json`。**受 §2 人工版式优先约束**：存在人工段钉/断行时，兜底只保留原文，不重排段落。

**雪球守卫改为"接受 + 定向补标点"**（2026-08）：单句源跨度超过 1200 字符 / 300 秒（`MAX_SENTENCE_SOURCE_CHARS`/`MAX_SENTENCE_SPAN_SECONDS`），或 corrected 单句自身超过单段容量（Latin 300 词 / CJK 500 字）的句子判为**超长句**，但**不再让本页 attempt 失败**：主波次首轮即接受正文，超长句由 §6.7 的 `punct-repair` 载体在波次后定向补标点切开，轮次耗尽再由引擎按源时间轴确定性切句。取代 M1–M4 时的"`Problem::page(document-oversize)` 整页拒绝 + 重试 + 确定性兜底"——那条路在真实事故（同一说话人、停顿丰富、没有句号的 1652 / 1822 字中文长句）里整页重试三次仍原样回传，最终整页退回原文；旧的 900 字符 corrected 重切也只认既有句号、从不创造边界，已删除。**M1–M4 实现裁决**（仍有意，见 §13.1）：

- `resplit_oversized` **不接入文件路径**——它按句末标点重切会造出既非空行、也非 `⏹` 来源的段落边界，与 §6.1"段落边界只有两个来源"直接冲突；`punct-repair` 与确定性切句只切**句**（新增句末标点），段落边界仍只来自空行与 `⏹`。
- carry-over 全面退役（`run_polish_file_contract` 逐页独立、无 carry-over）。灰度期曾保留 json-v0 路径与 `MAX_CARRY_CHARS = 600` 守卫；2026-08 弃用执行时随 json 版 `run_polish` 一并删除。

**分段退化不进整页重试，而是"首轮即接受正文 + 波次后定向补分段 + 确定性收口"**（实现裁决，2026-08；取代此前"整页重试 + 末轮宽恕"的方案）：润色文本本身有效，为一处分段缺陷丢掉整页文本、再花一整页 token 重来是更大的损失，也常常重来仍不给空行。所以主波次的 `lint_page` / `validate` 对超限段落**不拒页**，页照常验收、`words` 照常回写；主波次结束后引擎把最终接受集里仍超限的段落（无论来自第几页，含整页兜底页留下的单段大块、页缝合并后的大段）**跨页凑到一起**，走 §6.6 的 `segment-repair` 索引契约逐块补分段，直到没有超限段落或达到轮次上限；轮次耗尽后仍超限的多句段落由引擎按句间停顿等级**确定性收口**（`fallbackParagraphs` 记账：分段有效但切点是机器选的），因此出口不再有多句超限段落，`stages.segment` 照常盖戳。`degenerateParagraphs` 保留为不变量校验（收口后仍超限的多句段落数，正常恒为 0）：若非 0，好段的 `paraBreaks` 照常落地但 `stages.segment` **不盖戳**、阶段保持待办交给专用 segment 流程，绝不伪造 `segment: fresh`（CLI 以 `degenerateParagraphs` 上报并把 `next` 指向 `bcut segment`；补分段成功拆开的段落数以 `repairedParagraphs` 上报）。重润路径（`stages.segment` 已盖戳）不产出段落钉，该门直接放行、不发波次、不发告警。

回写语义与现行完全一致：文本变更写 `words`（`IdSource` 分配新词 id），段落写 `paraBreaks`；盖 `stages.polish = fingerprint(words)`，未分段过或重分段时盖 `stages.segment = id_fingerprint(words)`（分段退化时扣戳，见上）；`ensure_balanced_cue_layout` 照跑（其"仅在 `breaks` 为空时生效"的早退就是版式保护）。`report.json` 逐句保留 `firstWordId/lastWordId/t0/t1/fallback` 与 suggestions；**`ai/polish.json` 在一个版本内继续双写**（review accept 链路与 `spec.rs` 的 `writes` 声明依赖它，见 §13）。

## 6.5 并行

页间无依赖（上下文区静态渲染，不等前页结果），全部页批量分发；成功页流式回写 checkpoint，失败页进重试轮。**M1–M4 实现裁决**：`parallel_kind` 签名为 `parallel_kind(kind, file_contract)`——polish 只在文件契约下并行。弃用执行后新任务恒为 file-v1，该协议参数只对**历史 json-v0 任务**的 `workerPlan` 起作用（仍如实报 `serial`）。

## 6.6 定向补分段载体 `segment-repair`（2026-08，索引契约）

主波次首轮即接受正文（§6.4）之后，仍超限的段落由 `kind = "segment-repair"` 的独立载体补分段。它与 polish 同为 `text/plain` 文件载体（agent 任务目录写 `payloads/<callId>.txt`，`protocolVersion: file-v1`；provider 路径内联布局），但契约、解析器和验收粒度都不同——它是**索引契约**：模型看带行号的句行，只回行号区间，从不复述正文。

- **为什么不再"原样复述 + 插空行"**：首版载体要求逐行复述几百行正文、只许插空行，实测（谢赛宁 7h 单人语料、deepseek-v4-flash）87 次补分段调用里 22 次因为模型顺手改了一个字（`也是都都是`→`也是也都是`）被整段判 `source-drift`，19 次一个空行都不插，通过的也常常只拆两组、三轮不够用。答案文本本来只用于定位边界、从不回写，逐字复述是为一个用不上的东西付出的脆弱性。索引契约把验收变成纯算术，输出缩到几十个字符，且块头能写明"至少拆成几段"这种可校验的硬要求。
- **载荷**：一份载荷装**一块或多块**超限段落，每块一对栅栏、块之间一个空行；块头写序号、句数、词数（CJK 报字数）与最少段数（`ceil(词数 / 单段上限)`，`block_min_paragraphs`）；栅栏内**一句一行**（最终口径的句文本，含 polish 已改写的内容，不含时间戳、软标记与 id），每行前缀 1 起的行号 `N| `：

```
<<<BLOCK 1 | 63 sentences | 1832 characters | at least 4 paragraphs>>>
1| 第一句…
2| 第二句…
…
63| 最后一句…
<<<BLOCK-END>>>

<<<BLOCK 2 | 40 sentences | 410 words | at least 2 paragraphs>>>
1| …
<<<BLOCK-END>>>
```

- **答案**：每块回 `<<<BLOCK k>>>` … `<<<BLOCK-END>>>`，栅栏内**一行一个 `a-b` 行号区间**（一个区间 = 一个段落），区间必须从 1 开始、首尾相接、到末行结束；不复述任何句子文本，不输出栅栏之外的内容。解析器宽容：块头丢尖括号（`BLOCK 2`）、一行多个区间（逗号/空格分隔）、en/em dash 与 `~`、单行单句（`7`）、块乱序、单块载荷省略块头都接受；模型若仍复述了带行号的句行，按空行分组只认行号也接受。
- **跨页凑批与二次分页**：引擎扫描最终接受集里所有 `committed` 段落，凡词数超 `paragraph_word_limit` 且句数 ≥ 2 的都进本轮工作集（无论原来在第几页），按每段词数用 `balanced_page_sizes` 以主 polish 的核心区预算（2200 词）**二次分页**——超长段落至少独占一页，多段合并进一份或多份载荷；页 id 为 `sr{round}-{serial:03}`（如 `sr1-001`、`sr2-003`），落 `manifest.json` 与页级尝试文件，`report.json` 照常记账。
- **逐块验收**（`parse_segment_repair_page`，agent `task submit` 镜像 lint 与引擎共用同一份实现，判据全部是字符串级，因此 agent 侧就是完整校验）：先过 `guard_output_size`（超限 ⇒ 文档级 `document-oversize`，全部块作废）；然后按块头切出各块的答案：缺块 / 没有区间 / 不从 1 开始 / 不首尾相接 / 不覆盖到末行 / 越界 ⇒ 该块 `range-invalid`（detail 定位首个缺陷："第 k 行没有被任何区间覆盖"、"区间 a-b 与前一个区间重叠"、"越界"…）；区间合法但只有一个且整块超限 ⇒ 该块 `paragraph-oversize`（detail 是定向指令，含"至少拆成 N 个区间"）；≥ 2 个区间（或整块本就不超限）⇒ 该块通过，按区间切成子组，段落钉随组边界产生。**一份载荷里通过的块立即落地，被拒的块只影响自己**。子组仍超限**不是**该块的 Problem——引擎按溢出幅度处理：不到 `SEGMENT_OVERFLOW_TOLERANCE`（15%）的子组即时按停顿等级确定性补切（584→526 这类纯容量收敛不烧一轮 LLM），超过的原样进入下一轮由模型按语义拆。
- **轮次与上限**：`SEGMENT_REPAIR_MAX_ROUNDS = 3`。每轮 = 重新扫描当前仍超限的段落 → 二次分页 → 一次 `complete_batch`。轮内不做载体级重试，**轮就是重试**：被拒的块（区间非法 / 只回一个区间）和拆开后仍明显超限的子组一起进入下一轮；从第 2 轮起请求带 `attempt = round` 与 `retry_reason = "[paragraph-oversize] 第 k 块：<上一轮对该块的意见>；…"`（provider 路径注入 `[retry context …]`，agent 路径经 call 请求回灌），其中"上一轮意见"对被拒块是其 Problem 的 `[code] detail`，对拆开后仍超限的子组是"上一轮拆分后仍有 N 词，超过单段上限 M：请把该块至少拆成 K 个区间"，按段首句词下标寻址（拆开后各子组段首不同，天然区分两种来源）。可重试传输错误只算"本轮没拿到答案"，段保持原组进入下一轮；Terminal / Cancelled 照常上抛。
- **确定性收口（轮次耗尽后）**：仍超限的多句段落由引擎 `split_by_rank` 拆开：从头累计词数，某句加进来会超限时回到当前窗口最后 40% 里停顿等级最高（≥1.2s → 3，≥0.6s → 2，否则 1；并列取最靠后）的句缝切开，窗口内没有别的句缝就切在当前句前；单句本身超限只能独占一组（超长句由此前的 punct-repair 处理）。每个被收口的原段记 `fallbackParagraphs` 一次，`stages.segment` 照常盖戳——与 standalone segment 引擎的 tier-5 确定性兜底同一口径（永不失败，切点合法但不语义）。同一把尺也用于上一条的溢出容忍补切。
- **跳过条件**：单句组没有可插缝的行间位置，不进工作集（也不算退化：单句超限属 punct-repair 的账）。
- **提示词**：`segment_repair_system_prompt` 与波次内每个请求共享同一份 system（agent 路径按 `(kind, attempt)` 落 `contracts/segment-repair.md` / `-2.md` / `-3.md`），只声明"一块或多块、带行号一句一行、只回区间、区间连续覆盖、块头写最少段数、逐块验收、仍超限的块会被再次发回"，不含批次相关信息，故各轮各页可共用。

## 6.7 定向补标点载体 `punct-repair`（2026-08）

主波次首轮即接受正文（§6.4）之后、单句相似度重试与 `segment-repair` 之前，仍**超长**的句子（单句源跨度 > 1200 字符 / 300 秒，或 corrected 超单段容量）由 `kind = "punct-repair"` 的独立载体补标点。设计动机是把"润色分段"与"加标点"分开：润色页只要求顺手加句读、不再靠拒页逼模型断句；一句缺句读也不该重掷整页正文，更不该在整页重跑里制造 `。。` / `。，` 噪声。它同为 `text/plain` 文件载体（agent `payloads/<callId>.txt`，`protocolVersion: file-v1`；provider 内联布局），排在 `segment-repair` 之前是因为补分段只能在句间插缝——超长句不先切开就无缝可插。

- **载荷**：一份载荷装**一句或多句**超长句，每句一对带 id 的栅栏、句间一个空行；正文是该句最终口径的 corrected 文本，并按 atom-LCS 把源词之间的停顿投影成 `⏸`（≥0.6s）/ `⏸⏸`（≥1.0s）/ `⏸⏸⏸`（≥1.8s）软提示（提示词声明这些标记只是提示、不得抄回答案）；`min-sentences` = ⌈句词数 / (单段容量 / 2)⌉ ≥ 2，告诉模型至少要切成几句：

```
<<<SENTENCE-BEGIN id=s01 min-sentences=3>>>
…第 1 句 corrected 文本，含 ⏸ 停顿提示…
<<<SENTENCE-END id=s01>>>

<<<SENTENCE-BEGIN id=s02 min-sentences=2>>>
…第 2 句…
<<<SENTENCE-END id=s02>>>
```

- **答案**：每句原样复述栅栏（同 id）与正文，**唯一允许的改动是新增句末标点**（`.?!` / `。？！`），非标点字符逐字复述——不改错别字、不改措辞、不合并/拆分/增删词，不复制 `⏸`，不制造 `。，` / `，。` / `，，` / `,,` / `..` / `.,` 冲突标点与悬垂假句末（提示词与 polish 主页共用同一悬垂词表）；条目之间互不干扰，栅栏之外不得输出任何内容。
- **跨页凑批与二次分页**：引擎扫描最终接受集里所有 `committed` 句（无论原来在第几页，兜底页的原文句除外——它们已是原词，不再改写），按每句词数用 `balanced_page_sizes` 以主 polish 的核心区预算（2200 词）二次分页；若 `PolishOptions.worker_slots = Some(n)`（n > 1）且页数 < n、句数 > 页数，则用 `balanced_page_sizes_for_count` 把页数补到 `min(n, 句数)` 填满并发槽。页 id `pr{round}-{serial:03}`（如 `pr1-001`、`pr2-003`），落 `manifest.json` 与页级尝试文件。
- **逐句验收**（`parse_punct_repair_page`，agent `task submit` 镜像 lint 与引擎共用同一实现，判据全部是字符串级）：先过 `guard_output_size`（文档级 `document-oversize`）；然后按 id 找每句的栅栏窗口：缺栅栏 / id 不配对 ⇒ 该句 `missing-id`；去掉标点后的 atom 序列与载荷不等（被改写 / 增删）⇒ `source-drift`（detail 指出"第 k 个词被改写 / 被增删"）；正文内部一个句末标点都没有 ⇒ `sentence-oversize`（detail 是定向指令：在语义完成处补 `.?!` / `。？！`，其余不动）；含冲突标点或悬垂假句末 ⇒ `document-oversize`。通过的句由引擎按句末标点切片、逐片 atom-LCS 回贴到该句的源词区间并 `heal_boundaries`；切不出 ≥ 2 片或回贴失败 ⇒ 该句同样记 `sentence-oversize`（新加的句末标点无法投影回源词，句保持原样）。**通过的句立即落地，被拒的句只影响自己**；切开后的片仍超长不是 Problem，只是"进入下一轮"。
- **轮次与上限**：`PUNCT_REPAIR_MAX_ROUNDS = 3`。每轮 = 重新扫描当前仍超长的句 → 二次分页 → 一次 `complete_batch`；**轮就是重试**：被拒的句与切开后仍超长的片一起进入下一轮，从第 2 轮起请求带 `attempt = round` 与 `retry_reason = "[sentence-oversize] sNN: <上一轮意见>；…"`（被拒句是其 Problem 的 `[code] detail`，仍超长的片是"上一轮拆分后仍超长（原因）：请继续在语义完成处补句末标点"，按句首词下标寻址）。可重试传输错误只算本轮没拿到答案；Terminal / Cancelled 照常上抛。
- **确定性兜底（轮次耗尽后）**：仍超长的句由引擎按源时间轴切开，保证出口没有超长句：候选切点（相邻源词之间）按 说话人切换(5) > 前词以句末标点收尾(4) > ≥1.8s 停顿(3) > 0.6–1.8s 停顿且 corrected 里落在逗号/分号/顿号/冒号后(2) > 停顿或逗号任一(1) > 无(0) 评分；在词数窗口 [容量/5, 容量·4/5]（同时受 1200 字符 / 300 秒硬顶）内取最高分、同分取最靠后（吃满窗口），窗口内没有候选时退到最后一个可行位置；左片去掉尾部逗号/空白后按语言补 `。` / `.`（已是句末标点则不补），右片保持原样，对每片循环直到全部不超长。它只切句、不造段落边界（§6.1 不变）。
- **计数**：`punctRepairedSentences`（模型补标点切开的句数）/ `punctSplitSentences`（引擎兜底切开的句数）/ `oversizedSentences`（两者之后仍超长的残余，应恒为 0）随 polish 成功信封 `data` 上报。
- **提示词**：`punct_repair_system_prompt` 与波次内每个请求共享同一份 system（agent 路径按 `(kind, attempt)` 落 `contracts/punct-repair.md` / `-2.md` / `-3.md`），只声明"一句或多句、每句一对 id 栅栏、只加句末标点、`min-sentences`、逐句验收、留着不动的句会被再次发回"，不含批次相关信息。

## 6.8 页缝判定载体 `seam-repair`（2026-08，索引契约）

§6.2 第 ③ 档页缝的判定波次。与 `segment-repair` **同一索引载体、同一解析器**（`parse_segment_repair_page`；agent `task submit` 镜像 lint 为 `lint_agent_answer_seam_repair`——唯一差别是「一个区间盖住整块」在页缝块里是合法答案，不算 `paragraph-oversize`），独立 kind 只因为 system prompt 与块头不同（agent 路径按 `(kind, attempt)` 落 `contracts/seam-repair.md` / `-2.md`）。

- **时机**：主波次接受正文 → punct-repair（句文本定稿）→ 低相似度单句重润 → autocorrect → **seam-repair** → segment-repair。必须先于补分段：补分段会拆组、改变组下标，而页缝按 `committed` 组下标寻址。只在本次润色负责产出段落钉（`stages.segment` 未盖戳）时运行。
- **块 = 窗口，不是整段**：一块 = 页 k 末段的**尾窗** + 页 k+1 首段的**头窗**（`SEAM_WINDOW_WORDS = 250`：从段尾/段首累计句子直到 ≥ 250 词，累计到阈值的那一句含入，每侧至少 1 句），最终口径的句文本一句一行带行号；块头写明页缝位置 `page seam before line N`（前一页止于第 N-1 行、后一页起于第 N 行）。头窗恰好盖满右段且下一个页缝紧随其后时链成一块（块头 `page seams before lines N, M`）。窗口把块体积与两侧段落长度解耦——首版把整段拼块，单人语料整页单段时相邻页缝连锁并出 541 行 / 21k 字的巨块，模型回"整块一段"后又并成 15k 词的巨型段落、segment-repair 三轮都咬不动，是本版改窗口的直接动机。含空句行的块整块跳过（保留段钉）。
- **分页与并行**：按块词数用 `balanced_page_sizes` 以主 polish 的核心区预算（2200 词）凑载荷，一份载荷装一块或多块，整波并行派发；页 id `sm{round}-{serial:03}`。7h 单人语料 ~48 块 ≈ 10 份载荷、一轮 15–30 s——这就是「Map 并行 + Reduce 只看页缝」的形态；「末段接到下一页」的串行 carry-over 会把页波次从 2 min 拖到 13 min（deepseek-v4-flash 每页 14 s；慢模型下 6 → 47 min），故不采用。
- **判定：只采纳跨缝区间的两端**。波次先把 `committed` 摊平成句子序列 + 段首集合（全局句下标），页缝即其中的段首。答案按区间切组，对块内每个页缝找**含页缝行的区间**：该区间从页缝行起 ⇒ 保留（`seam_kept_paragraphs`）；否则去掉页缝段首（`seam_merged_paragraphs`），并把该区间在窗口**内部**的起点/终点补成段首——这正是"页缝段真正的起止"（例如页 k 末段的最后三句其实已经开启了下一话题）。窗口边缘的边界与不跨缝的区间一律忽略：窗口是截断的，边缘处的边界不可信。所有编辑都是段首集合上的集合运算，块之间互不干扰、无需按组下标平移。**不做容量补切**，合并后仍超限的段落交给紧随其后的 segment-repair 按语义拆。
- **轮次与退化**：`SEAM_REPAIR_MAX_ROUNDS = 2`：第一轮发全部候选，第二轮只重发被拒的块（`retry_reason = "[range-invalid] 第 N 块：…"`）。被拒（区间非法/缺块）、传输可重试错误、轮次耗尽 ⇒ **保留原段钉**，与不做判定完全一致——退化方向永远是现状，不会因为一次坏答案丢边界或串段。Terminal/Cancelled 照常上抛。
- **实测**（谢赛宁 7h 访谈抹平说话人、deepseek-v4-flash）：首版整段拼块的整链复跑：句界优先分页把句中页缝从 30 个压到 1 个（仅剩完全无标点区段）；48 个页缝 → 37 合并 / 2 保留 / 9 两轮被拒保留，波次 32 次调用；保留下来的页缝都是提问/应答或「嗯。」插话处；与多说话人 run 的自然分段对照，合并处 21/36 在自然版里同段、13 处是单人文本里看不见的说话人切换。显式信号（前导空行）deepseek-v4-flash 0/49 触发——它对这条契约无感，退化到 seam-repair 判定，正是设计预期。多说话人 run 46 个页缝全是 ⏹，波次不触发。**索引契约 + 窗口版整链复跑**（同一语料、同一模型）：单人 48 个页缝 → 29 合并 / 19 保留、11 次调用全部首轮通过（含"边界后挪一句"的判定：区间 `1-15 / 16-21` 使页缝并入并在第 16 行另起段）；segment-repair 47 次调用**零** `range-invalid`、零改字，3 轮收敛（第 2 轮 5 块、第 3 轮 1 块），`repairedParagraphs 66`、`fallbackParagraphs 0`（确定性收口一次都没触发）、`degenerateParagraphs 0`、`segmentedByPolish true`；段落 343 → 467，中位 338 → 290 字，最长 **19625 → 711** 字。多说话人 run：46 个页缝仍全是 ⏹、波次不触发，segment-repair 6 次调用两轮收敛、`repairedParagraphs 17`、`fallbackParagraphs 0`、`degenerateParagraphs 0`，1950 段里 `shortInterjectionParagraphs 750`（≤10 字 ≤3 s 的「嗯。」类插话，规范 §18.5 使然、只报不改）。

## 6.9 说话人归属修复载体 `speaker-repair`（2026-08，索引契约，分页之前）

polish 把 ⏹ 当硬保证（§6.1：句不得跨、必分段），所以 diarization 判错的碎片（「打 DOTA 什么 | 的 | 就是宿舍…」的「的」被判给对面）在主润色里只会被逼成独立句加标点。修复因此放在**分页之前**、作为 polish 的第一波（`engines/speaker_repair.rs`，`kind = "speaker-repair"`），只改 `words[].sp`（`sp` 不进任何指纹，不引发阶段重跑）。它之前还有一步确定性的行归属还原（联合模型项目按 `ai/asr-rows.json`，见 AI 管线设计 §4.3/§5.0），不属于载体契约。

- **门禁**：`speaker_turns(words).len() > 1` 才跑（单说话人零调用，`skipped: single-speaker`）；`--paragraphs` 定向重润跳过（`scoped-run`）；`--no-speaker-repair` 关掉（`disabled`）；候选为空 `no-candidates`。
- **候选**（引擎确定性筛出，**不依赖标点是否存在**——原始 ASR 的标点分块不稳定，MOSS 同一次转录 3385 行里 1115 行无标点、按块起伏，「前词无句末」只当负向信号）：夹心短岛（轮次 ≤4 词且 ≤1.2 s、两侧同一说话人；文本剥标点后整体落在应答白名单「嗯/哦/对/OK/是的/对吧…」的岛直接保留、不送模型——「啊/呃」故意不在表里）与不自然切换点（间隙 <0.25 s 且前词无句末标点）。候选两侧各带 40 词上下文合成窗口，重叠/相邻窗口合并、合并后 ≤240 词；每次调用 ≤8 个窗口，页 id `sk{round}-{serial:03}`。
- **载荷**：每窗一对栅栏 `<<<WINDOW k | n lines | speakers S1,S2 | current: 1-13 S1, 14-14 S2, 15-31 S1>>>` / `<<<WINDOW-END>>>`；栅栏内**一词（CJK 一字）一行** `N| 词`，词后跟 `⏸`/`⏸⏸`/`⏸⏸⏸` 停顿标记（时间是除语法外最强的信号）；块头写窗口里出现的说话人标签（`SpeakerLabels`，与 polish 载荷的 ⏹S2 同一张表）与**现状**归属区间。
- **答案**：每窗 `<<<WINDOW k>>>` … `<<<WINDOW-END>>>` 内一行一个 `起-止 标签`，不复述词。宽容形态与 §6.6 同款：块头丢尖括号、en/em dash、`a LABEL` 单行、`a-b: LABEL`、小写标签、单窗口页省块头都认。
- **验收**（`parse_speaker_repair_page`；agent `task submit` 镜像 lint `lint_agent_answer_speaker_repair` 与引擎同一份实现）：区间从 1 起、首尾相接、到末行；标签 ∈ 块头 `speakers`；合并相邻同标签后**段数 ≤ 现状段数**——只能把碎片并回邻居或挪动现有切换点，不能凭空造新的换人。任一不满足 ⇒ 该窗口 `range-invalid`（detail 定位首个缺陷，是下一轮的定向指令）；同载荷其他窗口照常落地。
- **应用与退化**：窗口互不重叠，逐窗口把区间落到 `sp`（`relabelledWords`；段数减少记 `islandsMerged`、只挪边界记 `boundariesMoved`、与现状一致记 `windowsConfirmed`）。落地前再过一道**确定性改动上限**：单窗口改动词总数 >12，或任一连续改动串 >8 词 / >2.5 s ⇒ 整窗口忽略（`windowsCapped`）——契约上"段数不增"挡不住模型把一整段引语并给旁白（实测 flash 在 7h 访谈片头把 38 词嘉宾原声并给了 S1，其余 266 个窗口全部确认现状），这一波的证据范围只到碎片与几个词的边界偏移，成段改判不归它。`SPEAKER_REPAIR_MAX_ROUNDS = 2`：第二轮只重发被拒窗口（`retry_reason = "[range-invalid] 第 N 个窗口：…"`），耗尽仍拒或传输可重试错误 ⇒ **保持原样**（`windowsRejected`），与不做修复完全一致。
