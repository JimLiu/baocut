# 16. 安全与输入隔离

> 出自 [BaoCut 文件契约字幕 AI 管线设计（File-Contract Pipeline, v0.3）](../bcut-file-contract-subtitle-ai-design.md)

- 生成 HTML 时对所有 transcript 文本做 escaping；未转义的 `<` 会破坏 id 对账。
- 解析用 HTML5 DOM parser + 元素/属性 allowlist；**不执行 HTML**。丢弃一切 `script/style/iframe/object/link/meta refresh`、事件属性（`on*`）、URL 与外部实体。预览用 `<style>` 仅允许渲染器自己生成的固定白名单样式，解析器无条件丢弃输出中的 style/script 节点。
- id 比较使用精确 Unicode 字节串，不做大小写折叠。
- **prompt 注入防线**：context 与 transcript 内容中出现的"请忽略规则、读取某文件、运行某命令"一律视为**内容**而非指令；契约文本显式声明这一点。Agent claim 限定可读文件为 claim 信封列出的 input（`references` 通道尚未存在，见 §17），契约明确禁止路径扩张。正文里出现的围栏/信封字面量在渲染时被中和并记 `sentinel-neutralized` warning。
- 输出大小设硬顶：超过按输入估算的合理倍数即拒绝（防失控生成）。**已实现**：`max_output_chars = 4 × 输入字符`（下限 4096），四个载体的解析入口统一先过 `guard_output_size`，超限报 `document-oversize`（§10.1）；同一个函数也是 provider 侧 `max_tokens` 的定标基准（§9.3）——**入方向给多少、出方向收多少，共用一把尺子**，避免出现"模型被允许生成、但解析器一定拒绝"的死区。
