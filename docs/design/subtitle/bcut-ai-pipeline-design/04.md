# 4. 阶段〇：词级时间戳与强制对齐

> 出自 [bcut 转录后处理 AI 管线技术方案（润色 / 分段 / 分章节 / 翻译 / 字幕对齐）](../bcut-ai-pipeline-design.md)

目标：无论走哪条 ASR 路径，落盘的 transcript 都满足「每个词有可信的 `t0/t1`，
每个词有说话人」。

## 4.1 三条取时路径（按优先级）

| 路径 | 适用 | 词时间质量 |
| --- | --- | --- |
| **A. 转录期强制对齐**（现状主路径） | Qwen3 / Whisper：VAD 切段 → 每段 ASR → `aligner.align(span_audio, text, lang)` | 80ms 格，真实 |
| **B. 转录后选择性精修**（接线 `refine.rs`） | MOSS / 云端等只给行级时间的引擎 | 80ms 格，真实 |
| **C. 字符权重合成**（兜底） | 对齐器不可用 / 对齐结果为空 / 精修失败 | 行内均匀插值 |

**B 是本方案的第一件实施项**（P0）：`refine_word_timings` 已在 `bcut-speech-core`
写好并有测试，只差在 MOSS 路径（`speech_cli.rs` 的 MOSS 分支）接线。门控与降级完全
照搬 voice-ink `WordTimingRefiner` 的结论：

- 只精修「引擎没给词时间 **且** 行时长 > 5s **且** 文本非空」的行（短行的 char-weight
  漂移不可感知，不值得花推理）；
- 行边界**永不改动**——精修只在行窗口内部重排词时间；
- 任何单行失败静默保留 char-weight 结果。**精修绝不能作废一次已完成（可能是付费）的转录**；
- 长行用 `align_long`（240s 分块 + 尾部平台切分，已实现、现仅 example 引用）。

**C 的权重公式**（与 voice-ink / DocBuilder 一致，保证两端行为可对拍）：
`weight = max(2, 字母数字数) + 1.4`，行时长按权重比例切给各词，单调钳制进行窗口。

## 4.2 归一化与修复（确定性收尾）

所有取时路径的输出统一过两道确定性工序（移植 voice-ink 的
`WordTimingNormalization` / `WordTimingRepair`）：

1. **归一化** `normalized_word_timings(words, range_start, range_end)`：换算厘秒 tick，
   每词保底 1 tick，保证严格递增、无零时长、不越行窗（对齐器偶尔预测越界一格，
   放任逃逸会让相邻 VAD 行看起来时间倒流）；
2. **修复** `word_timing_repair`：五种病症检测（`nonFinite` / `negativeDuration` /
   `zeroDuration` / `startRegression` / `overlap`），坏段锚定两侧健康邻居重排，
   放不下则向邻居扩张，实在不行记 `unrepairable` 而不硬塞坏 tick。
   **修复是纯时间操作，不触碰任何阶段戳**——文本指纹只含 text 与端点 id，
   时间修复随时可跑、不会误伤润色/翻译的新鲜度。

## 4.3 词化落盘（rows → §18 transcript）

确定性 build 步骤（`bcut-flow-core/src/build.rs`），对应 voice-ink 的 `DocBuilder`：

```
RowIn[]（含可选 words / speaker）
  → 每行：有真实词时间则采用并钳进行窗；否则 char-weight 合成
  → 词 id 分配：`g<行号>.<列号>`（"g3.7"）；后续编辑新造词用 `w<base36ms>-<n>`
  → 说话人：MOSS 的行级 speaker 下沉为词的 sp；无说话人引擎恒 "s1"
  → 归一化（§4.2）→ 写 transcript.json（§18）+ stages.asr / stages.asrLayout
```

说话人边界精修分两种策略（`build::SpeakerBoundaryPolicy`）：

- **区间投影**（无说话人、云端行级标签、事后 pyannote 词级投影）：沿用 voice-ink
  参数——短外来岛（<4 词、≤1.2s、无停顿、前词非句末）并回宿主，切换点吸附到 ≥0.25s
  的最近停顿（±1s 窗口内），避免切在词中间。
- **行级权威**（`moss-transcribe-diarize`，含 `remote:` 转发）：行级说话人是联合
  ASR+diarization 模型生成文本时一并给出的**文本归属判决**，行边界只是时间戳有 slop
  （7h 双人访谈里 10% 的相邻行在时间上互相重叠），一个词都不挪。实测两遍吸附对
  MOSS 都是帮倒忙：Pass 2 把答句开头的「呃」、句尾的「一个经历对」挪给对方（切点落到
  了停顿上，事后看起来反而"自然"，LLM 候选筛选筛不到）；Pass 1 在 MOSS 没出标点的
  分块里（同一次转录 3385 行里 1115 行无标点、按块起伏）把 142 个真实应答「嗯/哦是吗/
  当然」整行并进对方的句子——无标点 ⇒ "前词非句末" 恒成立。已有 MOSS 项目由
  `bcut polish` 的 `speakerRepair.rowRealign` 按 `ai/asr-rows.json` 把吸附挪走的词
  还原（词 id `g<行>.<列>` 指回行号；只还原 ≤6 词 / ≤1.5s 的失配串；失配率 >5% 或
  说话人 id 表已重编则整步跳过，见 §5.0）。
  `bcut speakers reidentify` 的 MOSS 分支同理：新一轮的**行区间**按中点劈开重叠、词取
  中点落行，不做声纹区间那套投票 / 逃生口 / 岛屿吸收（那套会把重叠区抖成「啊，/的，/
  吗？」逐字换人的碎片——2026-08 截图事故的另一半成因；另一半是 rebind 把新 token
  的 `sp` 一律取 `span[0]`，见 §5.5）。
