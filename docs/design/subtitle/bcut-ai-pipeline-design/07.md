# 7. 阶段三：分章节（chapters）

> 出自 [bcut 转录后处理 AI 管线技术方案（润色 / 分段 / 分章节 / 翻译 / 字幕对齐）](../bcut-ai-pipeline-design.md)

## 7.1 契约：file-v1 HTML（2026-08 起）

分章节自 2026-08 起走文件契约（原 NDJSON+`json_object` 单次整篇的历史契约见 §7.5），
载体在 [`filepipe/chapters_html.rs`](../../../../core/crates/bcut-flow-core/src/filepipe/chapters_html.rs)：

```
输入（chapters-source/1）：
  <article data-bcut-format="chapters-source/1" data-part="k/N"
           data-range="HH:MM:SS–HH:MM:SS" data-total="HH:MM:SS" data-aim="N" data-project-fp="…">
    <p id="p-<首词id>" data-at="HH:MM:SS">段落全文</p>…
输出（Map 页与 Reduce 大纲同形）：每章按时间顺序
  <h2>章节标题</h2>
  <p class="summary">一句话概要（≤20 词）</p>
  <p id="<起始段 id>">该段开头几个字</p>
```

- 段落投影同 §18.5（`derive_cues` + `derive_paras`，段 id `p-<首词id>`）；`data-at`
  是相对媒体起点的偏移，只读不写（分章需要时长感；模型永远不回写时间）。
- 用户级设定（`--title-style`、`--instructions`、录音背景）进 system；页级差异
  （第几部分、时间范围、`data-aim` 单元/章节目标）只进载体属性——agent 路径的契约文件
  按 kind 唯一，不能逐页不同。
- 输出**只写代码推不出的东西**：尾锚、`end` 都不进协议（`end` 由下一章 `start` 确定性
  回填）。首段开头片段是锚 id 的兜底：id 抄错（`p-g1203.0` → `p-g1230.0`）时按片段
  唯一命中修复（`anchor-repaired` 诊断），命不中才丢行（`unknown-id`）。
- 解析用 html5ever、标签名不进协议：h1–h6 或 `class="title"` 视为标题、带 `id` 的元素
  视为锚、两者之间的无 id 文本块视为概要；`<section id>` 容器写法、围栏、闲话都容忍。
- 问题码：`missing-id`（标题后无锚 / 整份无行）、`unknown-id`、`empty-title`、
  `chapter-overflow`（仅 Reduce）；同锚重复只保留首行（诊断）。`temperature 0`，每页 ≤3 次尝试，重试原因是结构化 problems。

## 7.2 分页与 Map/Reduce（长录音）

段落按词预算（`budgets::CHAPTERS` = 8000 词，`BCUT_LLM_PAGE_WORDS` 覆盖）均衡分页，
段落是原子（单段超预算独占一页）：

- **单页**（≤ 约 100 分钟）：一次调用直接出章节，`data-aim` = 全局目标。
- **多页**：
  1. **Map**（kind `chapters`，整批并行）：每页切「话题单元」，`data-aim` ≈ 页时长 /
     粒度秒，钳 2–40（与章节同档：实测 deepseek-v4-flash 非 thinking 对「合并到
     data-aim」三次都照抄大纲，Reduce 因此只负责页缝与统一命名）。非首页的开头可以
     延续上一页话题——首单元不必落在页首。
  2. **Reduce**（kind `chapters-outline`，一次小调用）：把全部单元按序拼成大纲
     `chapters-outline/1`（`<h2 data-at>` + 概要 + `<p id>` 片段），页缝处插
     `<hr data-seam="k|k+1">`（根节点带 `data-units` / `data-aim`）；模型按全局 `data-aim`
     合并/取舍/统一命名，锚只能取自单元起点。行数护栏：输出超过 `aim + max(2, aim/5)` 行
     报 `chapter-overflow` 重试，三次仍超则采用行数最多的一次（章节偏多但覆盖完整）。
     7 小时录音的大纲也只有百余行、几千 token。
  3. 七步确定性清洗（§7.3）→ 写回。
- 分层降级、整体永不失败：某页 Map 三次都无可用行 → 该页降级为一个**无标题占位单元**
  （`<h2 data-untitled="true">` + 「无摘要」说明，锚在页首），由 Reduce 命名或并入邻章；
  三次都有行但带问题 → 采用行数最多的一次（`degraded: true`）。Reduce 三次都失败 →
  直接采用 Map 单元作为章节（占位单元无标题被跳过，其时间并入前一章）。
  Terminal（鉴权/模型不存在）与 Cancelled 照旧直接中止。

## 7.3 确定性清洗

模型输出经七步清洗，任何一步都不信任模型：

1. 丢弃未知段 id / 空标题；
2. 按（段起始时间, 输出顺序）排序；
3. 相同起点去重；
4. **强制首章从 0 开始**；
5. 强制起点严格递增；
6. 回填每章 `end = 下一章.start`（末章到媒体时长）。

写回 transcript 的 `chapters[]`（id `c-<base36ms>-<n>`），提交盖
`stages.chapters = fingerprint(words)`。

## 7.4 章节数与产物

- 目标章节数 `chapter_count(duration, granularity)`：broad ≈10 分钟/章、balanced ≈5、
  detailed ≈2.5；下限 2，上限**随时长放大** `max(20, round(小时数 × 20))`（≤60 分钟与旧的
  固定 2–20 一致；7 小时 balanced ≈81 / detailed 135 / broad 40）。Mac
  `PolishEstimator.chapterCount` 与 GPUI `ai_estimates::chapter_count` 是平价副本，
  三处必须同改。`--target` 仍是全局总数，显式覆盖公式。
- 页级尝试归档 `ai/chapters/vNNN/{manifest.json, pages/pNNN.src.html, pNNN.out[.aN].html,
  pages/outline.*}`（§4 布局，manifest `params` 记 `pageBudget/granularity/target`）；
  稳定指针 `ai/chapters.json` 含 `fingerprint / rows / review / parts`，`parts` =
  `{count, pages[]{id,start,end,segments,units,attempts,degraded}, outlineAttempts,
  outlineFallback}`，是排查长录音的第一入口。
- `--review` 下的候选是**覆盖层形状**（`ai/reviews/chapters.json`，`reviewVersion 4`）：
  只存 `candidateOverlay.{chapters, stages.chapters}` + `mediaHash/mediaDuration` + `parts`，
  不再内嵌整份 transcript；`review accept` 只改这两个字段，基线校验按媒体身份
  （hash + 时长），审阅期间改字不再让「Replace N chapters」失败。

## 7.5 边界来源：LLM，或来源自带的章节

章节边界由模型在段落投影上提出，再走 §7.3 的确定性清洗；唯一的例外是**来源自带的
章节**。URL 建项时 yt-dlp 的 `chapters[]` 与视频描述整份存进 `project.json` 的
`media.sourceMetadata`（App 与 CLI 下载腿同一形状），`bcut-flow-core::source_chapters`
负责把它读成结构化时间戳（`chapters[]` 优先，其次解析描述里行首 `M:SS` / `H:MM:SS`
时间戳 + 标题或标题 + 行尾时间戳的大纲行，超过一小时照收），两条路都用它：

- **走模型**：大纲整份进 `chapters` / `chapters-outline` 契约当参考（「优先采用作者
  的边界与标题，仍锚在输入段落 id 上，只在文稿明显分歧处增删合并」），缺省目标章数
  改为大纲条数，分页时每页 `data-aim` 改为落在该页的条数。
- **不走模型**（CLI `bcut chapters --from-source`、App 章节页「直接采用视频章节」）：
  每条来源章节按时间吸附到文稿的结构起点——段落 > 句 > cue 三层先在 `[-1 s, +2 s)`
  的近窗里找，都没有再把段落 / 句放宽到 `[-4 s, +6 s)` 取最近的，最后才认近窗里的
  词起点；同一秒对上多个起点算
  **歧义**（CLI 取最早的一个并在 `source.ambiguous` 里计数，App 列出候选让用户单选
  或保留来源时间），完全没对上的保留来源时间。写回仍走 §7.3 的行规则（排序、同起点
  去重、首章拉到 0、尾章到片长）并盖 `stages.chapters`，与模型分章落盘后无异。
