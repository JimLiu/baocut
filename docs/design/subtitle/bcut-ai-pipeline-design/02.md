# 2. 总体架构

> 出自 [bcut 转录后处理 AI 管线技术方案（润色 / 分段 / 分章节 / 翻译 / 字幕对齐）](../bcut-ai-pipeline-design.md)

## 2.1 阶段流水

```
 媒体文件
   │  bcut transcribe（无 LLM）
   ▼
 ┌──────────────────────────────────────────────┐
 │ 阶段〇  ASR + VAD + 强制对齐 → 词化落盘        │  rows → Word 原子
 │        interview.transcript.json (§18)        │  words 是唯一真相
 └──────────────────────┬───────────────────────┘
                        │  bcut polish / auto
   ┌────────────────────▼───────────────────────┐
   │ 阶段一  润色 polish（LLM）                   │  改 text，保 id/t0/t1
   │ 阶段二  分段 segment（LLM+确定性阶梯）        │  写 breaks/paraBreaks
   │ 阶段三  分章节 chapters（LLM）                │  写 chapters
   └────────────────────┬───────────────────────┘
                        │  bcut translate --lang zh
   ┌────────────────────▼───────────────────────┐
   │ 阶段四  翻译 translate（LLM，句级）           │  写 trans / transSrc
   │ 阶段五  展示切分 + 对齐（LLM+确定性）          │  句译文 → 逐 Cue 片段
   └────────────────────┬───────────────────────┘
                        │  bcut export / BCF `from` 派生
                        ▼
        SRT / VTT / 双语 karaoke 字幕 / .bcut.json captions
```

`bcut auto` 的完整顺序是 `transcribe → [chapters 骨架] → [polish] → [chapters] →
[translate 含流式对齐] → [收尾重对齐]`，实际执行序列进信封 `data.steps`。

## 2.2 五条核心纪律（全管线不变量）

这五条是 voice-ink 用大量里程碑迭代换来的结论，本方案作为**硬性设计约束**继承：

1. **时间戳永不进 LLM**。LLM 只见纯文本（外加软性的停顿/说话人标记），只回文本；词的 `id / t0 / t1` 由确定性算法在收到响应后重新锚定。时间轴的正确性从不依赖模型自觉。
2. **确定性校验，而非 prompt 信任**。每个阶段对 LLM 输出做可判定的语义校验（覆盖性、归一化字符相等、id 对账、相似度门槛），不过关即本次 attempt 失败。「模型只许加标点」这类规则靠 `normalize_chars` 严格相等来**证明**，不靠措辞恳求。
3. **分层降级，整体永不失败**。重试耗尽后逐级退到更保守的确定性算法（最底层是纯规则切分，永不失败）；文本可以降级回原词，**边界与时间轴永远有效**。唯一例外：鉴权/模型不存在等不可重试错误直接中止整个 run——绝不拿降级结果掩盖配置问题。
4. **指纹驱动的脏检测**。每个阶段产物记录其输入的内容指纹；文本编辑使润色/翻译过期、却不使分段过期（分段键在 id 上）；重转录换发所有 id，使一切过期。「哪些要重跑」是推导出来的，不是记账记出来的。
5. **断点续跑**。分页边界由指纹化的词流确定性重导出，进度文件只存已完成的最小状态；崩溃/取消后重入安全，完成后必须删除进度文件。

6. **语言与内容先于结算**。转录写入前核对显式源语言、模型检测与全文主导脚本；翻译答案在缓存、hedge 结算和 `trans` 写入前必须通过目标脚本、占位、源文复制、异常短译与批次塌缩检查。HTML/ID 合法只证明载体可解析，不代表翻译完成。翻译载体携带校验器版本，版本升级自动使旧应答缓存失效。

## 2.3 Rust 落点

```
core/crates/
├─ bcut-speech-core       (已有) + refine 接线、词化 build 步骤
├─ bcut-speech            (已有) 宿主推理层，不变
└─ bcut-flow-core         (新) 纯逻辑：指纹、分页、atom-LCS、rebind、
                               各阶段引擎（LLM 以 trait 注入）、校验、降级阶梯

apps/cli/
└─ bcut                   (已有 CLI) + bcut-flow-core 的宿主执行器：
                               provider 直连（ureq）/ agent 应答循环（文件契约）、
                               进度落盘、命令面
```

分层原则与 speech 侧一致：`bcut-flow-core` **零 I/O、零网络依赖**，LLM 是一个 trait
（`LlmJson`），全部引擎逻辑可用脚本化假实现离线测试（对应 voice-ink 的 `FakeLLMJSON`）。

```rust
// bcut-flow-core/src/llm.rs
pub trait LlmJson: Send {
    /// 一次 JSON-mode 调用：system + user → 原始响应文本。
    /// 解析、fence-strip、语义校验都在引擎侧（§10）。
    fn complete(&mut self, req: LlmRequest) -> Result<String, LlmError>;
}
pub struct LlmRequest {
    pub kind: &'static str,       // "polish" | "segment" | "chapters" | "translate" | "align"
    pub model: String,
    pub system: String,
    pub user: String,
    pub temperature: f32,
}
```
