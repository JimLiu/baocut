# 6. 阶段二：分段（segment）

> 出自 [bcut 转录后处理 AI 管线技术方案（润色 / 分段 / 分章节 / 翻译 / 字幕对齐）](../bcut-ai-pipeline-design.md)

## 6.1 契约：只许加标点，靠归一化相等来证明

分段阶段的 LLM 契约比润色更窄：**逐字保留原文，只允许添加/修正标点，再按 1–4 句
分段**。「只许加标点」不是恳求而是可判定命题——`normalize_chars`（剥标点/空白/大小写）
后必须与源词区间**严格相等**，不等则该段文本降级为原词、边界照用：
**边界容忍漂移，文本从不说谎**。

prompt 要点（继承 voice-ink `SegmentPrompts`）：

- 明确下游是字幕切分器，「你的标点就是切点」——从句边界一律加逗号；
- 缩写/小数/版本号/文件名中的点不是句末（`agents.md`、`2.14`、`e.g.`）；
- `⏹`（说话人切换）必断——但这只是提示，**收到结果后还有确定性的
  `split_at_speaker_changes` 硬保证**；
- 响应：`{"paragraphs": ["…", "…"]}`。

## 6.2 五层映射阶梯

```
tier 1  exact — 页级归一化字符相等 → O(n) 字符偏移映射（最常见）
tier 2  diff  — atom-LCS（模型顺手修了个错字），匹配率 ≥ 0.75
tier 3  align — 逐段游标扫描恢复词区间（文本一律丢弃，只留边界）
tier 4  json  — 3 次 attempt 失败后，一次索引契约调用（只回区间下标；
                钳位 + 连续性自愈，≤10 词空隙自动吸附）
tier 5  split — 确定性兜底：说话人切换 / ≥1.2s 停顿 / 200 字符后的句末 /
                400 字符硬断。永不失败。
```

1–3 每次 attempt 内依序尝试；4–5 是升级。401/403/404 中止整个 run。

## 6.3 产物与写回

- 运行态 `SegmentedParagraph`（词下标，易变）→ 落盘态 `SegmentRecord`
  （`firstWordId/lastWordId/t0/t1/text/source`）写 `ai/<media>/segment.json`；
- 复原（artifact → 段落计划）**极其保守**：指纹匹配、id 无重复、区间连续、
  全覆盖，任一不满足返回失败——部分/过期产物绝不静默成为结构来源；
- **写回 transcript**：标点修正走 rebind 落到词文本；段落结构导出为后续段落首词的
  `paraBreaks` 钉（尾段与说话人边界已强制处跳过）。Cue 派生本身仍走 §18.5 的
  规范算法——分段阶段喂给它更好的标点与段落钉，不另立切分体系。若模型吞掉
  多个 Latin 源词间的空格并生成超过单行硬预算的新原子，文本门丢弃该段标点
  答案、保留原词与段落边界，避免 rebind 造出没有内部词缝的超宽 Cue;
- 提交：rebind 后先按时间邻近迁移并清除失效的 `breaks` / `paraBreaks` / `hidden`
  键；若旧 `nobreak` 把修订后的 Cue 焊到单行硬预算之外，只移除该超宽 Cue 内的
  `nobreak`，保留其它人工钉。随后写 `stages.segment = id_fingerprint(words)`；若
  segment 接在已完成 polish 后，则标点修订属于合法后处理，同步刷新 polish 内容
  指纹而不误报 stale。段落钉落定后与润色阶段同一策略铺设均衡断点布局（仅当尚
  无 `breaks` 覆盖，见 §5.6），并以最终钉集刷新 `stages.asrLayout`。

参数：页预算 8000（§5.3 均衡分页），`temperature 0.2`，重试 3 × 2s，串行。
另有**行宽复核**（可选二次调用，kind `repunct`）：对最宽子句超一行的段落重打标点，
零溢出时零调用，答案被拒则保留原文。
