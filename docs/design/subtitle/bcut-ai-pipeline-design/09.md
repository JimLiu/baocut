# 9. 阶段五：展示切分与字幕对齐（display split / align）

> 出自 [bcut 转录后处理 AI 管线技术方案（润色 / 分段 / 分章节 / 翻译 / 字幕对齐）](../bcut-ai-pipeline-design.md)

## 9.1 问题

翻译按句产出自然语序的整句译文；源 Cue 只是独立的原文换行。需要让 LLM
按目标语语义**拆行**，再把译片回锚到连续源词区间——词区间提供语义时间锚，
展示边界可在不覆盖相邻字幕的前提下利用句内余量与真实静音平滑，不能锁死在旧
Cue 边界。

**M8.2（2026-08-17）已砍除本地对齐评分器**：`--align-scorer` / config `align.scorer`
连同 `reranker` / `hybrid` 两档一起下线（依据
[`core/fixtures/align/golden/REPORT.md`](../../core/fixtures/align/golden/REPORT.md) M8.1），
证据来源恒为 `llm`——即本节描述的路径，§9.4 记的三轮编排同随之退役。历史设计见
[语义评分器方案](../../../archive/subtitle/bcut-semantic-reranker-alignment-design.md)（**已归档**）§0
状态框与 §4–§6（研究记录）。

## 9.2 方案：块对齐边（缺省）/ LLM 断句 + 确定性对账（表格载体）

**缺省载体 `align-edges/1`（对齐块设计 §4/§6，`AlignCarrier::Edges`）**：LLM 不切源、
不切译、不解决交叉，只标注"译文语义块 → 源词序号集合"；块合并、安全边界、双语 DP、
时间分配全是 `align_block.rs` 的确定性代码。

```
输入：一张 HTML 表，一句一个 <tbody data-sid>：td.src = 带 [N] 序号的句内锚定词
      （一词一序号，与 TransAlign.words 同口径），td.tgt = 完整自然译句；
      system prompt 只带 fit/soft/hard 与锁定术语（不带秒数、源 Cue、停顿提示）
输出：同一张表，只改 td.tgt：<span data-src="4-7">因为我病了，</span>
      <span data-src="1 2 3">所以没去。</span>——最小自然语义块按译文自身顺序，
      data-src 列出源词序号（可乱序、可不连续、可空），每序号一句内至多一块
校验（字符串级，filepipe/align_edges.rs，引擎与提交期 lint 共用）：
      序号可解析且 ≤ 源词数（align-edge-ordinal）；跨块重复（同上）；
      span 文本拼接归一化后 == 译文（align-edge-text）；缺句/截断/重复 id 同表格载体；
      tgt 无 span 只记警告，按"无对齐边"处理
块核（确定性，align_block.rs）：块 → 软边（权重 0.75）+ AnchorAligner 硬边（数字/
      日期/URL/原样 Latin/双语术语）→ 安全边界（leftMax < rightMin）→ 最小单调块
      → 双语 DP（块为原子，片 = 连续块的并；目标版式 + 源版式 + 共享时窗 + 两侧缝）
决策：Aligned ⇒ 落 correspondence:block + blocks[]；
      某块 > hard ⇒ align-rewrite/1 改写轮（同表形状，<tbody data-over-hard="chunk 1
      (words 1-9): 27 units > hard 20">，模型一次给出按源语小句顺序改写的整句 +
      span 标注；验收：±max(25%,4) 阅读单位护栏、数字/URL/Latin/术语硬锚与锁定
      术语不得丢失、目标 AutoCorrect、在改写文本上重新跑 edges→blocks→DP 且必须
      Aligned ⇒ 写 transDisplay{basis:"monotonic-rewrite"} + text_basis:display；
      否则整句对应；改写轮无修复）；
      证据不足 / DP 无解 ⇒ correspondence:sentence 整句一块（advisory）
轮次：首轮批调用（页 id b…）→ 失败句共享一次全局修复（r…，retryReason 复述逐句
      问题）→ 改写轮（w…）→ 修复预算耗尽：先试纯 AnchorAligner 边的块对齐，
      Aligned 才落，否则确定性目标语切分兜底（fallback_sentences）
增量：display-stale（trans 已变）先删过期 transDisplay 与其 display 基准条目；
      既有条目按 text_basis 取基准文本判有效（align_entry_valid_for_lang）
```

**审阅/修复载体 `align-table/1`（`--align-carrier table`，`AlignCarrier::Table`）**：
保留原两列切分表协议如下；两处语义变化——模型自报 `data-crossing` 不再写
`crossing:true`，改落 `correspondence: sentence`（整句一块一片）；`data-reordered`
改写不再回写 `trans`，改写 `transDisplay{basis:"table-reorder"}` 且条目
`text_basis: display`。

```
输入：一句的源词原子序列（含停顿提示）+ 该句整句译文
      + 目标驱动 lengthPlan（片数只由译文阅读需求决定；源侧长度仅作建议）
      + sourceBreakCandidates
      + 确定性 draftSource / draftTarget / draftWidths / draftSeconds / draftReady
      + draftWorstSourceUnits / draftWorstSourceSeconds（入轮草稿最坏配对源行的
        宽度与时窗；答案若把仍越档的最坏源行做得更差，引擎验收与提交期 lint
        同判拒收——定向修复轮不得净倒退。旧任务目录缺这两个字段时不触发）
      + draftBlockers（ready=false 的逐条原因：超 hard 片 / 单源词片 / 碎片源片 /
        risky 或 blocked 源缝 /
        疑似词内切 / 有缝超 fit 片 / 未完成中文数量短语 / 条件性片数下限 /
        存在目标语自然缝的双语源行过密 / 阻塞级缝 lint——worker 只修被点名的缝，
        不必整句盲改）
      + data-target-frozen（融合目标片已验收而源锚失败时出现；目标片边界不可改）
      + sourceWordUnits（提交期与 provider 验收同规复算源行密度）
      + sourceWordEndsSec（每源词相对句首的累计结束秒，0.1s 取整；自定切点
        据此估算每片语音时窗，避免长译文压进亚秒源片；全零时间戳时省略）
输出：草稿合格时 {"key":"…","useDraft":true}
      或 {"key":"…","sourceBreaks":["b…"],"target":"… | …"}
      （语序交叉时优先 "reordered":true——worker 自身具备语言能力，直接在
      不改变语义的前提下重排译句小句顺序消除交叉，验收后回写句级 trans 真相；
      重排也不自然时才 "crossing":true 落库 TransAlign.crossing，两标记互斥）
      —— LLM 只审阅语义边界，源词区间由候选 id 恢复，不重抄源文
校验（确定性）：片段拼接 == 整句译文（归一化后；reordered 句改为逐片过目标语
       格式化 + 长度带宽护栏 ±max(25%, 4 单位)，超带宽按改写拒收——重排只许
       调语序和必要的连接词/助词，不许压缩或丢内容）；词区间连续、不重叠、全覆盖；
       每片目标语投影阅读单位不超过 hard（绝对上限，无语序交叉例外）；缝 lint（悬垂连接词 / 黏着助词 /
       定语「的」悬垂尾（目的/标的等完整词除外）/ 未完成中文数量或类别短语 /
       数字与单位量词跨缝 /
       可合并的顿号并列拆分 / 可合并的 3 字及以下短片）与源语冠词/修饰语/关系词
       悬空均阻塞重试；普通 risky 源切点仅在无小句缝（seam）同界时阻塞——缝上的
       弱 bound-phrase 检测可放行；`blocked` 以及双语术语锚错配恒为硬失败，停顿、
       seam 或草稿来源均不能覆盖（provider 与 Agent submit lint 同规）；
       `pieceCount.min` 通常是 advisory，但实际片数低于 min 且仍有片达到 fit 时阻塞
       （`data-target-frozen` 句豁免：译文片已冻结、无法再加刀，两侧校验器均跳过该检查）；
       soft+1..hard 的 preferred seam 与仅由自然语序交叉造成的源片长不均仍是 advisory；
       源片超过语言感知单行预算或约 4s 时，只有对应目标片自身已有完整小句/并列动作缝
       才阻塞并要求沿该目标语自然缝拆分；此时允许在完整并列动作间使用顿号缝，普通名词
       列表仍按可合并顿号规则处理；
       源侧同时有**下限**：多片句里某片只挂 ≤2 个源词、这些词的显示宽度又不足单行
       预算的 1/4（en 10 / zh 4 单位）、且译文片自身也短于退化阈值（8 单位）时，
       这片是"碎渣"，契约要求把它并进延续同一小句的相邻片。该判据与源行硬上限
       同进同退：只挂 draftBlocker、只由 `bcut check` 出 `align-source-fragment`
       并驱动 `refine-align` 定向重对齐，引擎验收与提交期 lint 一律不拒——拒绝
       只会烧掉唯一一次全局修复调用、换来语义盲的确定性兜底。译文片宽度已达
       8 单位的窄源片归 `degenerate_paired_row` 拒绝通道，两条通道不重叠；
       时间预算仅 advisory：整句阅读需求超语音时窗提示减片/压缩，
       某片缺口大且邻片有富余时提示移界（"短源配长译"闪行的根治通道）
降级：批内逐句收下；每批一次首轮调用，所有失败句进入唯一修复轮
       （轮数上限 1，轮内按批扇出并行调用）；
       修复轮 retryReason 携带上一轮全部验证失败明细，并复述 budgets
       （fit/soft/hard）、逐句 pieceCount 与关键 draftBlocker，不再只留最后一条；
       LLM 留下的超 hard 目标片在同次响应内确定性续拆，不触发修复调用——
       但续拆结果必须重新通过配对验收：续拆若自身破坏双语锚定等判据，
       放弃续拆、保留 worker 提交的切分（超 hard 片整片落盘，
       经 check 的对齐告警上报，而非引擎改写）；
       修复预算耗尽时，若存在已通过提交期 lint 的 worker 答案，
       优先采纳（salvage）而不是确定性等宽兜底；
       确定性兜底硬切按原子边界并在 ±3 原子窗口内向最强缝吸附，
       禁止在存在合法词边界时切进 CJK 词内（DP 切分器同规：词内边界
       与客观缝语病同级参与罚分）；
       能逐片安全分配源词时比例重锚；若比例切点落入源语绑定短语，或目标片多于
       源词，则转 independent 并按阅读长度分配整句时窗；
       其他结构错误仍失败时也按上述策略做目标语合法缝切分 + 缝 lint 修复
长句判定：目标语超过 fit/hard，或整句语音时窗超停留护栏（~7s），进入批量 LLM；
       源语长度本身不再触发拆分——多对一是默认形态，几条短源短语共享一条
       紧凑译文；但双语配对行过密且目标片已有自然语缝时按上条执行，避免在编辑器中留下
       三行原文对应一行译文；`--align-local` 是弃用兼容参数，不再绕过长句 LLM
阈值：按目标语言选择（CJK fit/soft/hard = 16/14/20，`--fit` 可覆盖）；
      简中混排按两个 Latin 半角格约等于一个汉字阅读单位；
      源侧长度统一字符口径（Latin 非空白字符、CJK 阅读单位），词数口径废弃
批量：保持句序连续，页数取三条约束的最大值：源文 `word_count` 执行器档位
      （agent / provider 目前都是 2000 词，§5.3 slack 冗余）、每页最多 40 个
      待对齐项、每页 16000 的确定性复杂度预算（HTML 正文、建议片数、术语与
      双语锚点的近似成本）；再按复杂度均衡连续页。`targeted` 与 worker 槽位
      不参与页形。首轮、全量 `align-only`、`--sentences` 定点修复及唯一的
      全局修复轮共用这套三约束分页；
      诊断经 `alignDiag` / check `align-overfit` 暴露；advisory 明细在单文档
      与 routed 路径都经 `data.advisories` 原样透出（只给计数编排者不可见）；
      `task submit` 期 lint 与引擎同规拒目标侧黏着首/悬垂尾，worker 当轮
      修复，不再拖到聚合 repair 批
```

## 9.3 写回与消费

- 完整自然译句写 `trans[lang][s-…]`；词级锚定切法写
  `transAlign[lang][s-…]`；目标片先独立冻结，再映射连续源词区间，源 Cue 与
  `breaks` 不参与任何一步。派生目标流在整句
  时长可行时平滑片间边界到最低阅读时长，并只用真实字幕间隙补足短句；
- 时间线只保留半句时，`transAlign.words` 可保存该 Sentence 内**有序可见词子序列**，
  manyToOne 的 from/to 相对这份子序列求值；independent 也可用同一集合限定展示时窗。
  这样持久锚点不会重新覆盖已经 cut 掉的词；空 `words` 仍保持“完整句”兼容语义；
- **BCF `from` 派生**（格式规范 §8.4）直接可用：源 lane 取词原子（真实词时间戳 →
  karaoke 高亮），译文 lane 按 Cue 取 `trans` ——整句上屏的降级设计天然吻合;
- **导出端**：SRT/VTT/ASS/JSON/Markdown/MP4 与六类工程导出消费同一个目标流；
  cut 中间的同句译片会在同一 clip 内重新合并，素材复用的不同 occurrence 保持分立。

## 9.4 轮次编排：流式本地对齐 + LLM 兜底集合（M8.2 已退役，本节降为历史记录）

> **M8.2 已砍除**：本节描述的三轮编排（流式本地轮 / 本地扫尾轮 / LLM 兜底轮）随
> `align.scorer` 一起下线——align 阶段现在总是走本节末尾「`align.scorer = llm`」
> 那条编排：整篇译完后一次整跑 align。以下内容保留供理解历史实现。

`align.scorer` 是 `reranker` / `hybrid` 且至少注入了一个本地后端时，align 阶段
拆成三轮（语义评分器方案 §20.4；引擎入口 `run_align_local` / `run_align_fallback`）：

1. **流式本地轮**（在 translate 引擎内）：每个翻译批次的译文一落地（写 `trans`），
   立刻只对该批句子跑一次本地两级评分并写 `transAlign`，零 LLM 调用。事件顺序
   固定为「批次 i 译文落地 → 批次 i 对齐落地」，App 的翻译卡片因此在译文出现后
   1–2 s 内就有双语切分。本轮判为低置信的句先写整句对应保证可展示，句 id 进
   `AlignOutcome.low_confidence`。
2. **本地扫尾轮**：整篇译完后对全篇再跑一次本地轮，覆盖本轮没重译（因而没进流式
   批次）的句与 `--align-only` 的 force 重切。已有有效条目在评分之前就被跳过，
   全篇已对齐时这一轮几乎零成本。
3. **LLM 兜底轮**：对前两轮低置信集合的并集发唯一一次 dedicated `align-edges`
   修复轮 + `align-rewrite`。集合就是覆盖面——集合外的条目一个都不重写（D6），
   集合为空 ⇒ 本次运行的 LLM 对齐调用数为 0。`reranker` 在这一轮仍不发 dedicated
   `align-edges`，草稿不足以定案的句直接整句对应。

`align.scorer = llm` 不走这条编排：整篇译完后仍是一次整跑 align（融合草稿 →
dedicated → 改写 → 兜底），行为逐字不变。routed（最终时间线）翻译逐源投影可见词
后才对齐，也不走流式轮。

## 9.5 重对齐入口

`bcut translate --align-only [--sentences s-g1.0,s-g2.0]`（`--groups` 为别名）：
跳过整句翻译，只重跑拆行。键是句 id（`s-<首词id>`）；若传入过期键或裸词 id，
CLI 会 remap 到今天包含该词的句并记 `alignDiag`。全量重对齐必须 `--yes`
（CLI 强制，不靠文档自觉）。`bcut check` 只对**当前展示流仍有超 hard，或超
fit 且存在可执行自然缝**的句输出 `align-overfit` 清单（含 seam 预览与现成
`--sentences` 命令），避免已正确对齐或没有安全缝的句陷入无限重跑。超 fit、
未超 hard 且**没有**自然缝的句归 `infos[]` 的 `translation-unsplittable`（整份
明细照报，但分级为可交付的结构事实，不产 fix、不进 next、不进 refine 热点）：
这一档只有更短的译文才能改善，重跑 align 无效。
