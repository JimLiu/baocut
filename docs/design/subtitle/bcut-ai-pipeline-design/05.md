# 5. 阶段一：润色（polish）

> 出自 [bcut 转录后处理 AI 管线技术方案（润色 / 分段 / 分章节 / 翻译 / 字幕对齐）](../bcut-ai-pipeline-design.md)

## 5.0 分页之前：说话人归属修复（speaker-repair）

polish 把 ⏹（说话人切换）当**硬保证**——句不得跨、必分段。所以只要 `words[].sp`
还错着（diarization 把「打 DOTA 什么 | 的 | 就是宿舍…」里的「的」判给对面，或把切换点
挪前挪后几个词），主润色就被迫把「的」当独立句加标点，UI 里表现为两个说话人逐字交替。
修复必须在分页之前、而且必须给 polish 一条能改 `sp` 的合法通道；`sp` 不进任何指纹，
改它不引发阶段重跑。两步，都只改 `sp` 不改字，账目进信封 `speakerRepair`：

1. **`rowRealign`**（确定性，无 LLM，仅行级权威引擎即 MOSS 项目）：见 §4.3。
2. **`wave`**（LLM，`kind = "speaker-repair"`，`engines/speaker_repair.rs`）：
   - 门禁：`speaker_turns(words).len() > 1` 才跑；单说话人零调用（`skipped:
     single-speaker`）；`--paragraphs` 定向重润跳过（`scoped-run`）；`--no-speaker-repair`
     关掉（`disabled`）。
   - 候选由引擎按时间/形态确定性筛出，**不看标点是否存在**（原始 ASR 的标点分块不
     稳定，「前词无句末」只当负向信号）：夹心短岛（轮次 ≤4 词且 ≤1.2s、两侧同一说话
     人）与不自然切换点（间隙 <0.25s 且前词无句末标点）。岛的文本剥标点后整体落在应答
     白名单（嗯/哦/对/OK/是的/对吧…；「啊/呃」故意不在表里）的直接保留、不送模型——
     多人 7h 访谈实测 1911 轮次里 577 个夹心岛，白名单能挡掉约 530 个；不自然切换点
     153 个。候选两侧各带 40 词上下文合成窗口（合并后 ≤240 词），每次调用 ≤8 个窗口。
   - **索引契约**（与 segment-repair / seam-repair 同一思路，改字没有落脚点）：载荷每窗
     `<<<WINDOW k | n lines | speakers S1,S2 | current: 1-13 S1, 14-14 S2, 15-31 S1>>>`
     + **一词（CJK 一字）一行** `N| 词`（词后跟 ⏸ 停顿标记）+ `<<<WINDOW-END>>>`；
     答案每窗只回 `起-止 标签` 区间。验收是纯算术：从 1 起、首尾相接、到末行；标签 ∈
     块头 `speakers`；合并相邻同标签后**段数 ≤ 现状段数**（只能把碎片并回邻居或挪动
     现有切换点，不能凭空造新的换人）。一个契约同时覆盖「碎片并回」和「边界挪几个词」
     两种形态。违约判 `range-invalid` 只拒该窗口，第二轮带 `retry_reason` 重发，最多
     2 轮，耗尽仍拒或传输失败一律保持原样（与不做修复完全一致）。
   - 应用：窗口互不重叠，逐窗口把区间落到 `doc.words[].sp`；落地前再过一道
     确定性改动上限（单窗口改动词总数 >12，或任一连续改动串 >8 词 / >2.5 s ⇒
     整窗口忽略，`windowsCapped`）——"段数不增"挡不住成段改判，实测 flash 把
     片头 38 词的嘉宾引语并给了旁白；之后 `speaker_turns` 重新派生，分页器与
     主润色看到的就是干净轮次。信封字段见 CLI reference `bcut polish`。
   - **实测**（谢赛宁 7h 访谈从 MOSS 原始行重建、deepseek-v4-flash、typo/term/
     punct/filler/wordy）：`rowRealign` 0 失配（行级权威建库）；候选 738 岛
     （白名单接住 616）+ 423 不自然切换点 → 267 窗口 / 34 次调用、0 拒收。首跑
     266 窗口确认现状、1 窗口把片头 38 词嘉宾引语并给旁白（由此加了改动上限）；
     加上限后复跑 266 确认、1 窗口改 2 词（「跟的」false start 并回本人）、0 被上限
     挡住。截图处「当时打什么游戏？ | 呃，很多啊，打 DOTA 啊什么的，…一个经历。
     对。 | 哦，所以…」归属正确，全篇没有一处「啊，/的，/吗？」逐字换人；剩余的
     夹心短轮次都是 MOSS 行级判定的真实应答/重叠（美金、优雅、STORYTELLING）。

## 5.1 LLM 契约：纯文本进、句子字符串出

这是 voice-ink 迭代到 M28 才定型的关键决策，直接继承：**放弃**「带词下标的稀疏映射」
契约（模型维护下标的失败率太高），改为——

- **输入**：一页纯文本。词与词之间按停顿注入软标记：`⏸`（≥0.6s）/ `⏸⏸`（≥1.0s）/
  `⏸⏸⏸`（≥1.8s）；说话人切换处注入 `⏹`（句子**永不**跨越它）。多说话人文档的
  `⏹` 带**稳定说话人标签**：`⏹S2` 表示右侧到下一个 `⏹` 为止都由 S2 说
  （标签取 `sN` 形 id 里的数字，非规范 id 回落到首次出现序号；同一说话人在全篇所有
  页里标签一致，标签不含时间）。标记与标签都只进 payload 副本，是元数据，禁止进入
  输出——返回侧 `markers::strip_markers` 连标签一起剥除，裸 `⏹` 同样识别（兼容）；
- **输出**：`{"paragraphs": [{"sentences": ["…", "…"]}]}` ——改好的句子字符串，
  按段落分组。**没有任何下标或时间字段**；
- **任务**（prompt 四项）：① 修显性识别错误（拼写、同音字/近音字——中文日文特别强调），
  **禁止**改写、总结、增删、翻译;② 补标点;③ 按语义分句;④ 相邻句按话题聚为 1–4 句的段落;
- **覆盖性约束**：所有句子拼起来必须**恰好覆盖输入一次、保持顺序**——这一条是后续
  确定性映射能成立的前提，也是校验的第一道闸。

## 5.2 文档简报（brief / analysis）

润色前先做一次全文分析（长文分页跑，单页时与润色**合并为一次调用**省一轮）。
多页时各页并行抽取；**术语表由引擎确定性并集**（`Source` 按小写去空白/ASCII
标点归组，拼写取多数、Category 取众数、Note 取最长、Variants 取并集，落选拼写并入
Variants 后同样只保留全文字面出现过的形式），模型只再串行写一次总摘要（载荷是各页
`# Summary`，答案是空表的 context 文档；重试耗尽仍不可解析时回退到最长的分页摘要，
不因摘要失败拖垮整轮 analysis）：

```jsonc
// ai/<media>/brief.json
{ "fingerprint": "…",
  "referenceFingerprint": "…",              // 项目/来源元数据参考块指纹
  "summary": "…",                          // 内容概述，进所有后续阶段的 system prompt
  "terms": [ { "term": "BaoCut", "note": "产品名",
               "observedVariants": ["宝卡特", "包卡"] } ],   // 术语锁
  "namedEntities": ["…"] }
```

**表格解析分两档（`ParseMode`）**：用户手写的 `ai/context.md` 走 `Strict`——任何
结构或取值缺陷都判败，调用方保留旧的已验证上下文，绝不以半张表覆盖；模型答案一律
走 `Model`（§10.2 的「代码先修」），能用代码消解的问题不触发重试：

- 同一 `Source`（按归并键归一）多行 ⇒ 合并（Variants 并集、Note 取最长、Category
  取先见），记 `duplicate-id` 警告；
- 列数 ≠ 6 ⇒ 多出的中间列并回 `Note`、缺失列补默认，仅 1 列或空 `Source` 丢该行；
  未知 `Category` ⇒ `other`；`Lock`/`Origin` 非法 ⇒ 降级（模型行本就要降级）；
- 表头按首格 `Source` 放宽匹配（trim + 大小写不敏感），缺 frontmatter 但有术语表
  照常接受（指纹由引擎盖）；
- 垃圾行确定性过滤：`Source` 是单个 CJK 字 / 纯标点 / 纯数字 / 应答语气词
  （复用 speaker-repair 白名单）；
- 行数上限：单页保留前 150 行、全文归并后 400 行（按跨页出现次数降序、平局取首现，
  输出仍按首现顺序），超出部分只记警告与丢弃计数（`termsDropped`）；
- **page-fatal 只剩两种**：体积超硬顶（§10.2）、既没有 `# Canonical Terms` 小节也
  扫不到任何表格行。页级重试耗尽**不再上抛**：只要 ≥1 页成功就用成功页归并，失败页
  计入 `pagesFailed`；全部页失败才 `Err`（宿主保留旧 context）。

提示词相应收紧：`Source` 限定为「ASR 容易识别错的专名/人名/产品/技术术语/夹杂外语
词」，明确禁止普通词汇与语气词，每页 ≤80 行、同一 `Source` 只写一行。

术语锁进入润色 prompt 的「已知正确拼写」清单：相似发音/误拼一律纠正为规范形；
同时在相似度校验（§5.5）前把术语变体替换为不透明 token，避免「把错拼改成正确术语」
被误判为篡改。brief 同样服务于翻译阶段的 glossary（§8.2）。

运行 analysis 与 polish 时还读取 `project.json` 的项目标题/描述和
`media.sourceMetadata`（来源标题、描述、频道、发布日期、平台、视频 ID、URL）。
描述按字符数限长后注入，避免挤占正文上下文；该块是拼写、人名和专有名词的强参考，
不是口述内容或绝对事实来源，不能据此向转录增添词句。参考块有独立指纹，元数据变化
会使旧 brief 缓存失效。

## 5.3 分页与 carry-over

- 分页统一走 `atomize::word_count`：Latin 按词、CJK 按字、依附标点不单算；
- **页数先定、页界均衡**（所有按词分页的阶段共用）：页数 =
  `ceil(总词数 / (预算 + slack))`，slack 为预算的 10%——总量只比 N 页预算多出
  一小截时不为尾巴多切一页；随后每页目标取「剩余词数 / 剩余页数」，前页略短
  后页自动补齐，不再出现贪心装填的碎尾页（预算 6000、全文 24200 → 4 页
  ×6050，而不是 3 页 8000 时代的 6000×4+200）；剩余页数另按
  `ceil(剩余词数 / (预算 + slack))` 兜底——前页断点偏早、亏空积累时宁可多出
  一页，也不让末页超过「预算 + 一个 slack」的上限；
- analysis 与 standalone segment 的名义页预算均为 8000 词；file-v1 polish 独立
  使用 2200 词可编辑核心区（页目标按上一条均衡后逐页重算），前后各带最多
  200 词 / 3 句只读上下文，并允许 15% 溢出吸附到下一个自然断点；
- 断点选择：在页目标最后 20% 窗口内按「词位 + rank×(页目标/20)」联合评分取
  最高——rank 为**说话人切换(3) > 长停顿(2) > 句末标点(1) > 无(0)**，每高一
  档只值约 5% 页目标的提前量，高档断点不能一票否决窗口尾部更均衡的低档断点
  （真实词流实测：纯 rank 优先会让一个偏早的停顿挡住所有靠后的句末断点，
  首页欠载、末页超载 15%+），平局取靠后者；
- **轮次感知分页（有说话人信息时的 polish 分页单位）**：词流里出现过 ≥2 个 `sp`
  时，polish 的分页单位从「词流 + 断点评分」抬到**轮次序列**（轮次 = `sp` 相同的
  极大连续词段）：页 = 连续整轮次的并，页界取 +15% 溢出上限内**词成本最接近页目标**
  的轮次起点（平局取靠后），短轮次（对话、问答）自然成组；只有**单独超过页预算**的
  长轮次才在内部切开，且此时**句界优先**（句末标点），窗口内没有句界才回落到上面的
  rank 评分，仍找不到才硬切。最接近页目标的轮次边界够不到窗口下界（0.8×页目标）时
  说明下一个轮次单独就超预算：不为一句「嗯」单开一页，页界改落在那个长轮次内的句界，
  这页 = 短轮次 + 长轮次的头。页缝因此只落在轮次边界或长轮次内的句界，不再劈开一个人
  话的中段，也少了「偏早的停顿挡住句末断点」这类边界抖动。词预算与页数口径完全不变；
  **无说话人信息（全篇单一 `sp`）的文档不进轮次路径**，但 2026-08 起同样**句界优先**：
  窗口里有句末标点就取评分最高的句界，没有才回落到停顿——单人长讲实测（7h 访谈抹平
  说话人）47 个页缝里 30 个落在句中（一个 0.6s 犹豫停顿的 rank 2 总能压过窗口里的句末
  rank 1），句界优先后剩 8 个且都在完全无标点的区段；溢出区同样先够句界再够停顿。
  file-v1 的 polish 整页并行、没有 carry-over（右上下文由只读区提供），**页缝不是段落
  证据**：硬切页缝两侧段落由引擎无条件合并，后一页开头留空行是显式「另起一段」信号，
  其余页缝由 polish 波次后的 `seam-repair`（页 k 末段尾窗 + 页 k+1 首段头窗一块、带
  行号一句一行、答案只回行号区间、只采纳跨缝区间的两端、拒收即保留段钉，见文件契约
  设计 §6.2/§6.8）判定；仍有
  carry-over 的载体（segment）单位是末段，而段落本就不跨说话人切换，等价于末轮次；
  长轮次内则退回末段；
- **carry-over**（segment 载体；polish 文件契约不用——它把页波次从并行 2 min 拖成串行
  13 min，页缝改由并行的 seam-repair 判定）：每页最后一个段落不提交，与下一页 payload
  合并重发，让模型拿到右上下文后重新决定边界——**段落永远不会在页缝处被劈开**。尾段过长有雪球守卫
  （超 600 字符强制提交切分）。**守卫对「尾段只有一句」同样生效**：模型偶尔把整页
  回传成一个句子，如果这种尾段被继续 carry，下一页 payload 会从上一页页首重新开始，
  逐页翻倍（p1215 实测 30k → 106k 字符、最终落成一条 2615s / 40k 字符的句记录）。

## 5.4 映射回词原子：atom-LCS

收到句子字符串后，确定性重建词范围：

```
1. 源侧：页内每词 atomize（CJK 逐字、Latin 按词）→ 原子键序列 srcKeys
2. 出侧：句子列表扁平化后同样 atomize → outKeys
3. LCS(srcKeys, outKeys)；匹配率 < 0.7 ⇒ 本次 attempt 失败，整页重试
   （门槛低于分段阶段的 0.75——润色本来就要改文本）
4. 每句锚定其匹配到的最后一个源词 → 顺序切分词区间；尾部未匹配源词并入末句
5. 边界打磨：相邻边界在 ±10 词窗口内试探移动，仅当「两侧都不变差且至少一侧变好」
   才接受，且不得破坏说话人一致性
```

## 5.5 应用：rebind 保 id、保时间

把改好的句文本落回词区间走 `rebind`（`bcut-flow-core/src/rebind.rs`，
移植 voice-ink `TranscriptRebinding` + `SubAlign.rebindCorrected`）：

- 剥公共前后缀，仅对变化中段做词级 LCS；
- **LCS 匹配上的词原样保留**——id、t0、t1 一个都不动；
- 未匹配的新 token 造新词（`w…` id），在空隙内按字符权重插值时间
  （标点无时间份额、每 token 保底一份——`Camelot → came a lot` 按 4:1:3 确定性占据原词窗）；
  新 token 的 **`sp` 继承 LCS 邻居**（前一个保留词 > 后一个保留词 > 兜底 `span[0]`；
  LCS 表超限的退化路径取区间里词数最多的说话人）——句区间偶尔会跨说话人（⏹ 强制边界
  切不动退化为吸附到句首、或区间开头是被模型删掉的另一方语气词「呃」），2026-08 之前
  一律取 `span[0].sp`，结果是 S2 整句里每个被加了标点的字（「啊，」「的，」「吗？」是
  新 token）都标成 S1，UI 里两个说话人逐字交替；
- CJK 先按源词边界重新分词再 rebind，未改字符保持原 id 与时间；
- CJK 主导的源文在最终 rebind 前经过幂等 AutoCorrect：规范 CJK/Latin 间距、
  安全全角标点、全角字母数字与技术词大小写；
- 收尾统一过 `normalized_word_timings`。
- 整页润色全部 rebind 完成后再过一次 `word_timing_repair`。局部原词窗窄于新增 token
  的厘秒保底时，修复器向相邻健康窗口扩张，保证 `t0` 非降序与无交叠；随后按新词 id
  清理 `breaks` / `paraBreaks` / `hidden` 的孤儿键并刷新版式指纹。句记录的 `t0/t1`
  取修复后的词时间，避免审计产物与正文分叉。

**这就是增量体系的根基**：小范围润色只换被动过的词的 id，
从而分段（id 键）不过期、翻译（组文本指纹）只有被碰的组过期。

## 5.6 校验、降级与产物

- **单句跨度上限（映射后，不拒页）**：任一映射句的**源词跨度**超过 1200 字符
  （`MAX_SENTENCE_SOURCE_CHARS`，即 `span_chars` = Σ词面+1，与 `MAX_CARRY_CHARS`
  同口径）或 300 秒，或 corrected 单句自身超过单段容量（Latin 300 词 / CJK 500 字，
  `segment-repair` 只能在句间插空行，超容量单句没有可修切缝）⇒ 该句判 **超长句**。
  LCS 匹配率与相似度对「整页原样回传」都是高分放行，这道判据是唯一能识别它的。
  阈值取自真实语料分布（单句源跨度最长约 412 字符 / 27 秒）与既有常量，只拦病态、
  不碰正常长句。**超长句不再让整页 attempt 失败**（旧规则以 `document-oversize`
  整页拒绝 + 重试 + 兜底，一次真实事故里 p014 1652 字 / p042 1822 字的同一说话人
  无句号长句让整页重试三次仍原样回传，最终整页退回原文；旧的 900 字符 corrected
  「重切」也只认既有句号，从不创造边界，已删除）：主波次**首轮即接受**正文，超长句
  由波次后的 `punct-repair` 定向补标点（见下）切开，正文与分段职责分离——润色分段
  只要求"顺手加句读"，不再靠拒页逼模型断句；
- **定向补标点 `punct-repair`（波次后、补分段之前）**：引擎把最终接受集里仍超长
  的句子跨页凑到一起，每句包一对 `<<<SENTENCE-BEGIN id=sNN min-sentences=K>>>` /
  `<<<SENTENCE-END id=sNN>>>` 栅栏（正文按 atom-LCS 把源词停顿投影成 `⏸`/`⏸⏸`/`⏸⏸⏸`
  软提示，`K` = ⌈句词数 / (单段容量/2)⌉ ≥ 2），按 2200 词预算二次分页；有 worker
  槽数时把页数补到槽数（每页至少一句）填满并发。提示词与润色不同：**只允许新增句末
  标点**（`.?!` / `。？！`），非标点字符逐字复述、不改错别字、不改措辞，条目之间互不
  干扰。逐句验收（`parse_punct_repair_page`，agent `task submit` 镜像 lint 与引擎同一
  实现）：栅栏 id 缺失/不配对 ⇒ `missing-id`；词面被改写/增删（去标点后 atom 序列
  不等）⇒ `source-drift`；一个句末标点都没加 ⇒ `sentence-oversize`；`。，` 类冲突
  标点先**代码归一**（记 `punctuation-normalized` 警告、不拒句），悬垂假句末 ⇒
  `surface-artifact`。通过的句按新句读切片、逐片 atom-LCS 回贴
  源词并 `heal_boundaries`（映射失败也算 `sentence-oversize`：句保持原样），切片仍
  超长只是"进入下一轮"。**轮就是重试**：`PUNCT_REPAIR_MAX_ROUNDS = 3`，第 2 轮起
  带 `attempt = round` 与 `retry_reason = "[sentence-oversize] sNN: <上一轮意见>；…"`
  （被拒句是其 Problem 的 `[code] detail`，切开后仍超长的片是"上一轮拆分后仍超长
  （原因）：请继续在语义完成处补句末标点"），页 id `pr{round}-{serial:03}`，可重试
  传输错误只算本轮没拿到答案。**轮次耗尽后引擎按源时间轴确定性切句**保证出口没有
  超长句：候选切点按 说话人切换(5) > 既有句末标点(4) > ≥1.8s 停顿(3) > 0.6–1.8s
  停顿且 corrected 落在逗号/分号后(2) > 停顿或逗号任一(1) 评分，在词数窗口
  [容量/5, 容量·4/5]（同时受 1200 字符 / 300 秒硬顶）内取最高分、同分取最靠后，
  左片去掉尾部逗号后按语言补 `。`/`.`；对每片循环直到全部不超长。计数以
  `punctRepairedSentences`（模型切开）/ `punctSplitSentences`（引擎兜底切开）/
  `oversizedSentences`（两者之后仍超长，应恒为 0）上报；
- **哨兵栅栏恢复（`recover_fences`，先于定位）**：实测 7 次「栅栏缺失」里 5 次只是
  漏写 `<<<EDIT-END>>>` 而 `<<<CONTEXT-AFTER>>>` 还在，1 次漏 CONTEXT-AFTER、1 次漏
  EDIT-BEGIN，**核心区本身都完整**。因此先按相邻栅栏推断：EDIT-END 缺而 CONTEXT-AFTER
  在 ⇒ 以后者为核心区终点、只读下文区视为空；CONTEXT-AFTER 缺 ⇒ 核心区在 EDIT-END
  收尾；EDIT-BEGIN 缺而 CONTEXT-BEFORE 在 ⇒ 从其后扫，剥掉与载荷只读上文区归一化
  相似度 ≥0.85 的前缀，剥不掉才 page-fatal；栅栏重复取第一组合法顺序。恢复动作记
  `fence-recovered` 警告。两条 EDIT 栅栏都缺且推不出 ⇒ `document-truncated`（page-fatal）；
- **只读区漂移一律 advisory**：解析只取核心区，输出里的只读区从不写回真相，核心区
  另有词流真相门独立把关。表面级顺手修与整段截断现在都只记 `content-ignored` 警告；
- **提示词与镜像 lint**：file-v1 契约明确说明“换行/空行不结束句子”以及 1200 字符 /
  300 秒单句上限，并说明超长句会被送回一轮 `punct-repair`（顺手加句读就省掉这一轮）。
  submit 镜像 lint 仍拒绝答案新引入的非法控制字符，防止 `ã\u{80}\u{82}` 一类
  UTF-8 mojibake 被通用清洗静默剥成普通字母、直到引擎映射后才表现为超长句；
  `。，` / `，。` / `，，` / `..` 这类冲突相邻标点改为**代码归一**（句末强标点赢，
  记 `punctuation-normalized`），悬垂假句末与中文正文里 20+ 字母的疑似英文粘连
  （如 `purereinforcementlearning`）改为按段落记 `surface-artifact` 警告——它们
  **不再拒页**，而是映射成句后进 `polish-retry` 的句级补做队列；镜像 lint 因此也不
  再因为一句表面瑕疵把整份答案判 `rejected`；
- **相似度校验（不拒页）**：低相似度句是**单元级**失败，直接进句级补做队列；旧的
  「>30% 句未过门 ⇒ 整页 `source-drift`」已删除（两句页里的一句就能拒掉整页并重掷
  全部句子）。页级 `source-drift` 只剩 atom-LCS 映射失败（覆盖率 <0.7 / 无可映射句 /
  LCS 表过大）；
- **句级补做波次 `polish-retry`（json-v0，波次化）**：候选 = 低相似度句 ∪
  `surface-artifact` 句。载荷仍是
  `{"sentences":[{"startWordIndex":…,"reason":…,"originalWords":…,"previousAttempt":…,
  "contextBefore":…,"contextAfter":…}]}`（新增 `reason ∈ {low-similarity,
  surface-artifact}`），按每页 ≤40 句分页、逐句验收，败句第 2 轮带 `retry_reason`
  定向意见；**轮就是重试**，共 2 轮。耗尽收口按理由分流：`low-similarity` 退回原词
  （`fallback: true`，计 `fallbackSentences`）；`surface-artifact` **保留模型文本**
  并计 `surfaceArtifactSentences`——字词本身是对的，退回原词只会把一个表面瑕疵换成
  一整句未润色文本，`bcut check` 的 `polish-false-sentence-end` /
  `polish-surface-artifact` 警告继续兜底；
- **页原子容量硬约束（发页前）**：把答案回贴到源词走 atom-LCS（`lcs.rs`）。中段
  ≤ 2500 万 cell 走全表回溯（历史路径，结果与 voice-ink 逐位一致），更大走线性空间
  Hirschberg，总 cell 时间上限 2.5 亿（≈15.8k×15.8k 原子）；超过返回 `None`，
  引擎报 `atom-LCS table too large`（可重试：答案远长于页）。中文一字一原子，
  1.0.9 曾按 12000 字符切页得到 10111 原子的页，而旧上限 2500 万（√≈5000）在
  比对之前就拒表——**任何答案都过不了回贴，逐字相同的零改动答案也一样**，引擎
  却当作模型答错重试 3 次后整页兜底（491/627 句退回原文，check 仍 ready）。
  现在分页器与校验器同一把尺：`polish_page_atom_capacity()` = √cap / 2（答案
  可能是源的 2 倍），默认预算最坏一页 ≈2800 原子远在其内；任何计划页的核心区
  原子数超过容量时在**调 LLM 之前**以 `Terminal` 终止
  （`polish page pNNN too large: N source atoms exceed the validator capacity (M)`），
  不发页、不重试。segment 引擎的 diff 兜底层与该容量同源受益；
- **降级阶梯（拒绝即缩窄）**：整页尝试 ×2（第 2 次带 problems 意见）→ 仍 page-fatal
  的页按 `plan_polish_pages` 对**核心词区间对半重规划**成两页（同一分页器、同样的
  上下文预算，切点仍落在句界/停顿/说话人边界），两半各发 1 次（计 `splitRetryPages`）
  → 仍失败的**半页**才走标点/30 词兜底切分（原词保留，计 `fallbackPages`）→ 句级
  `polish-retry` 波次（2 轮）→ 仍不过的句按上面的分流收口。总调用量与旧的「整页
  ×3」同量级，但兜底粒度减半；
  超长句（单句源跨度 > 1200 字符 / 300 秒或 corrected 超单段容量）**不算页失败**：正文
  首轮即接受，波次后先跑 `punct-repair` 定向补标点（最多 3 轮），耗尽再按源时间轴确定性
  切句；这一步必须先于补分段——补分段只能在句间插缝；
  分段退化（单段超 300 词 / CJK 500 字）**不算页失败**：正文首轮即接受，波次后把仍超限
  的段落跨页凑批走 `segment-repair` 索引契约（每段一块 `<<<BLOCK k | n sentences | c words |
  at least m paragraphs>>>`/`<<<BLOCK-END>>>`、带行号一句一行、答案只回 `a-b` 行号区间、
  逐块验收、二次分页、最多 3 轮），耗尽仍超限的多句段落由引擎按句间停顿等级确定性收口
  （`fallbackParagraphs`），出口不再有多句超限段落、segment 戳照常盖；模型给出合法区间但
  某个子段仍超限时，溢出 ≤15% 的由引擎按停顿等级即时补切（不为 584→526 这类纯容量收敛
  再发一轮），溢出更多的带"仍有 N 词"意见进下一轮让模型按语义拆；区间非法（`range-invalid`）
  或只回一个区间（`paragraph-oversize`）按原规则重试；
  多说话人文档里「嗯。」「哦。」这类夹在同一说话人之间的短插话各自成段是规范 §18.5 的
  Para 派生规则（说话人一切换必然另起段）使然、不是分段缺陷（7h 访谈实测 1965 段里
  1284 段），polish 成功信封以 `shortInterjectionParagraphs`（≤10 字且 ≤3 s）上报计数
  供 UI 折叠/内联展示，**不改派生、不合并**（2026-08 裁决）；
- **产物** `ai/<media>/polish.json`：句记录（`firstWordId/lastWordId/t0/t1`）+
  逐处修改建议 `{cat: "typo"|"punct", find, replace, firstWordId, lastWordId}`
  （归一化后相等 ⇒ `punct`）。建议列表供 GUI/CLI review，应用与否都不影响时间轴；
- **假句末告警**：润色跑过之后，`bcut check` 出 `polish-false-sentence-end`——
  句末标点落在悬垂连接词/介词上（`… because.` / `… of how.` / `And.`），
  这类假句末会派生出无谓语的病态短 Sentence 并把噪声传导给 translate/align 分批。
  判据是 `seam::dangling_sentence_end`（先确认以句末标点收尾，剥掉标点与 closer
  后再看最后一个实义词），只对可判定语言开（en / zh），复用 align 的悬垂词表、
  不扩表；英语 wh 宾语前置后的合法介词悬置（如 `what it reaches out to`）不报。
  完整中文句末的 `的`（如“是的。”“这是很重要的。”）不报，只有孤立碎片“的。”
  仍报；`方向` / `对比` / `总和` 与 A 不 A 问句 `跟不跟` 这类已完整成词的句末同样
  豁免。显示切缝继续使用原来的 `ends_dangling` 严格判据，不受这些整句豁免影响。
  **只出 warning、不进 `next[]`、引擎不拒**：判据是启发式，且定向重润色
  会重写词面并使既有译文失配，不该落在可自动执行位；`fix` 给出
  `bcut polish <project> --paragraphs <p-…>` 供人工决定；
- **表面产物告警**：润色后 `bcut check` 另扫冲突相邻标点，以及中文 code-switching
  中 20+ 字母的纯 Latin 单 atom；命中时出 warning `polish-surface-artifact`，附句、
  段与同样的定向 polish `fix`。这是提交镜像 lint 的交付侧兜底：旧项目或旧 runner
  写入的产物也能被发现，严格门禁不会因词数、宽度统计正常而误判已就绪；
- **兜底句阻断**：整页兜底与单句保留原词都只在产物逐句 `fallback: true` 上记账，
  `stages.polish` 照样盖戳、`polish=fresh`——但兜底不是"润色完成"，是"这些句没
  润色"。`bcut check` 读与 `stages.polish` 同指纹的 `ai/polish.json`，凡 `fallback`
  记录两端词仍存在即报 **blocker** `polish-fallback`（不看 `--for/--lang`；`--strict`
  只影响退出码），`fix` = `bcut polish <project> --paragraphs <p-…>`（兜底句所在
  段落）并进 `next[]`；产物指纹不符（review 待接受、旧残留）或句已删的记录静默过期。
  信封 `data.fallbackSentences` 是全篇口径（`fallbackPages` 现在是本轮兜底的**页或
  半页**数，`splitRetryPages` 是对半缩窄后重发的半页数）；
- **提交**：`stages.polish = fingerprint(words)`；若此前从未分段，顺带从润色的
  段落分组导出段落钉写 `paraBreaks` 并盖 `stages.segment`（一次 LLM 调用喂两个阶段）；
- **均衡断点布局**：标点定稿后，若 transcript 尚无任何 `breaks` 覆盖（无人工或历史
  版式干预），运行确定性布局优化器（`bcut-flow-core::layout`，对拍 designs 原型的
  M51b/M54）：按 §18.5 派生 → 用「带展示 padding 的窗口 + 目标语 CPS 上限」找出
  读不完的 Cue（溢出孤儿短尾、停顿断行的语速尖峰），移缝优先、必要时合并，最后落成
  **最小 break 钉集**写 `breaks` 并刷新 `stages.asrLayout`（管线自身版式改动不算
  人工编辑）。已有钉集时整步跳过，绝不覆盖用户意图。

参数：`temperature 0.2`，重试 3 次 × 2s 退避，页间隔 1s，串行（carry-over 依赖）。

## 5.7 润色收尾：说话人实名推断（speaker-names）

diarization 只给得出 `s1`/`s2` 这样的声音 id，三端 UI 于是一直显示 `S01`/`S02`
占位名。`speaker::propose_names` 的确定性启发式只认**自我介绍**（`my name is …` /
`我是…`），而访谈、播客、圆桌里的实名绝大多数由**对方**给出（"today I'm joined by
Andrew Ng"、"有请张三"），或者只出现在标题与简介里——那些证据没有任何可写的句式，
启发式必然空手。这一波（`kind = "speaker-names"`，`engines/speaker_names.rs`）把
这件事交给模型，默认开启，`--no-speaker-names` 关掉。

- **位置在 polish 的最后**（正文已 `apply` 落盘、上面所有波次跑完之后）：
  ① speaker-repair 会重写 `words[].sp`，可能把一个假聚簇整个吸收掉，先命名就会把
  名字挂在一个已经没有词的说话人上；② 润色后的文本才有标点，第三方介绍
  （"欢迎 Andrew Ng。"）远比生 ASR 好读。放进 analysis 也不行——`ai/context.md`
  指纹新鲜时整个 analysis 会被跳过，命名波次会跟着一起消失。
- **编辑面只有 `speakers[<id>].name`**。`sp` 与 `speakers[].name` 都不进阶段指纹，
  改名不会让 polish / segment / translate / align 变 stale，因此这一波对已翻译的
  项目是安全的（重新跑 polish 则不然）。
- 门禁：`--no-speaker-names`（`disabled`）、空词流（`no-words`）、`--paragraphs`
  定向重润（`scoped-run`）、没有占位说话人（`no-placeholders`）。待命名 = 名字仍是
  占位**且**在 `doc.words` 里还有词。
- 证据载荷（file-v1 `text/plain`）：`<<<OPENING | n words | speakers S1,S2>>>` 开场白
  窗口（400 词，带 ⏹/⏸ 标记）+ 每个首次登场落在开场白之外的说话人一块
  `<<<SPEAKER S2 | first speaks around hh:mm:ss | n words>>>`（前 60 词 + 后 120 词；
  介绍通常出自**对方**之口，所以上文比下文重要）+ `<<<NAMES-ASK>>>` 待答标签表。
  系统提示另带项目/来源元数据与 analysis 的命名实体——全名常常只在标题里出现。
- 答案：`<<<NAMES>>>` … `<<<NAMES-END>>>` 内一行一个 `S1 = Andrew Ng`，证据不足回
  `?`。验收全是字符串级：标签集与载荷所问**恰好相等**、不重复、名字非空、≤40 字符、
  不含 `=`、本身不是占位名。任一不满足即整份答案不可用（这一波只有一次调用，落一半
  名字不如重发一次），第二轮带 `retry_reason` 重发，最多 2 轮，耗尽保持占位名
  （`rejected`）。
- 落盘：标签 → id **必须**经 `SpeakerLabels::speaker_for_label`。标签只在「全部 id
  都是干净的 `s<数字>` 且编号互不相同」时才等于编号，否则退回首次出现序号——
  `format!("s{n}")` 会静默张冠李戴。写之前**再过一次**占位判据，用户在这中间改过名字
  的说话人绝不覆盖。
- 账目进信封与 `report.json` 的 `speakerNames.wave`：`skipped? / targets / calls /
  proposed / named / unknown / rejected / names[]`。`speakerNames.candidates` 仍是
  `propose_names` 的确定性候选（供人工复核，不自动应用）。
- `--review`：候选整份 `TranscriptDoc`（含 `speakers` 表）进暂存，accept 时整份写回，
  实名随候选一起落地；反过来说，accept 之前手工改的名字会被候选盖掉。
