# 13. 与 voice-ink 的对照与刻意差异

> 出自 [bcut 转录后处理 AI 管线技术方案（润色 / 分段 / 分章节 / 翻译 / 字幕对齐）](../bcut-ai-pipeline-design.md)

| 维度 | voice-ink | 本方案 | 差异原因 |
| --- | --- | --- | --- |
| 词时基 | 时间线时间（文档与时间线一体） | **媒体源时间**（§18） | 一份转录被多个合成文档共享；映射经 clip（格式规范 §18.6） |
| 阶段状态 | `doc.stageStamps` 存在编辑器文档里 | transcript 的 `stages` 字段 + `ai/` 产物目录 | 转录是独立文档（§18），状态随转录走 |
| 翻译落盘 | `doc.trans[lang][key]`（cue/组混合键） | 各源 `trans[lang][sentenceId]` 是完整译句真相；`transAlign` 仅为展示覆盖；时间线路由不落成第三份真相 | 句键单一化；剪切/复用只改变投影与可见词 stamp |
| LLM 层 | 仅 provider 直连（GUI 内） | **双执行模式**：provider / agent 应答循环 | CLI 设计 §8 的既有决策；CI 与 Agent 会话同一契约 |
| 分段产物 | `paraPins` → config | `paraBreaks` 覆盖表（§18.4） | 复用 spec 已定义的覆盖表，不新增机制 |
| 实现语言 | Swift（GUI 内嵌） | Rust `bcut-flow-core`（纯逻辑）+ CLI 宿主 | 与 speech 侧同构的 core/host 分层，三端复用 |
| 进度 | `flow-live.json` + kqueue | 同结构 + `task watch --jsonl` | 增加流式消费入口，GUI 依旧可监听文件 |

**逐字继承（不改动）的机制清单**：FNV-1a 双指纹及其用途分工、⏸/⏹ 软标记、
分页 rank 断点 + carry-over、atom-LCS 映射与 0.7/0.75 门槛、rebind 的
「LCS 保词 + 权重插值」、分段五层阶梯与「边界容忍漂移，文本从不说谎」、章节 NDJSON
契约与六步清洗、翻译紧凑 echo 与句 id 续跑、组级 stale + 段落级重跑、
词时间归一化的「每词保底 1 tick」、修复的「时间操作不动指纹」、
「精修绝不作废已完成的转录」、json_object + fence-strip + 语义校验三层结构约束、
「不可重试错误中止整个 run」。

---

*本方案基于 voice-ink Pipeline/Translation/AI 域的实现调研（2026-07）提炼；
prompt 细节与常量以移植时的对拍测试为准，本文数值为设计基线。*
