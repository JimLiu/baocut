# 2. 总体架构

> 出自 [BaoCut 剪辑域协议设计（Cut / Clip / 元素 / 水印 / 工程导出）](../bcut-edit-domain-design.md)

## 2.1 两层剪辑模型与媒体视图

```
┌─ 媒体层（per source）────────────────────────────────────────┐
│  源媒体 + transcript（真实源时间，永不改写）                     │
│  cuts[]：无损假删除区间（源时间；口癖/静音/文稿剪辑落在这里）      │
│      │                                                        │
│      ▼  折叠 cuts（纯派生，不落盘）                             │
│  【媒体视图】≈ 数据库视图：                                     │
│    · 视图时长 = 源时长 − Σcuts                                 │
│    · 视图字幕 = 剪掉 cut 词后的 Cue/词戳（视图时间）             │
│    · 对外表现如同物理裁剪；内部全是真实时间                       │
└──────────────┬───────────────────────────────────────────────┘
               │  clip 引用视图区间
┌─ 时间轴层 ────▼───────────────────────────────────────────────┐
│  clips[]：有序编排序列（可分割/裁剪/重排/真删除，undo 可逆）      │
│  tracks[]：叠加元素（B-roll/文字/水印/音频，锚时间轴或词）        │
│  时间轴时间 = 各 clip 视图窗口时长的前缀和 = 成片输出时间          │
└──────────────────────────────────────────────────────────────┘
```

两层的可逆性契约刻意不同：

| | Cut（媒体层） | Clip（时间轴层） |
| --- | --- | --- |
| 删除语义 | **假删除**：cuts 条目存在即"剪掉"，restore 即删条目 | **真删除**：clip 从数组移除，数据模型不保留 |
| 可逆性 | 数据模型级（无损集合，任意时刻可精确恢复） | 会话级（`.bcut/history` journal undo/redo） |
| 典型操作 | 剪口癖、剪静音、按文稿删句 | 拆条、截取片段、调顺序、丢弃整段 |
| 生效范围 | 该媒体的**所有**引用处一次生效 | 只影响时间轴上这一处 |

## 2.2 文件与职责边界

```
myfilm.bcut/
  project.json        项目清单（主媒体身份、语言、阶段戳）——不变
  transcript.json     主媒体词级转录（bcutTranscript 0.3）——不变
  transcripts/        附加源转录：<srcId>.json（同 0.3 schema，media.id = srcId）——新增
  timeline.json       剪辑域唯一真相：sources（内含各源 cuts）/ clips / 叠加轨 / 主画面——新增
  studio/style.json   字幕与画面呈现的项目级持久真相
  studio/data.json    派生投影（新增 timeline 与视图节）——扩展
  ai/cuts.json        剪切溯源（append-only）——新增
  ai/broll-suggestions.json  B-roll 建议工件——新增
  screentext.json     屏幕文字 OCR 工单队列（非文档数据）——新增
```

职责铁律（延续现有分层）：

- `transcript.json` 仍是**文本与时间的唯一真相**，锚媒体源时间，剪辑永不写它；
- `timeline.json` 是**剪辑意图的唯一真相**：每个源剪掉什么（cuts）、时间轴摆什么（clips）、叠什么（tracks）、怎么动（animate）；
- `studio/style.json` 是**字幕与呈现样式的持久真相**；`studio/data.json.style` 只是它的派生副本；
- **落盘一律真实源时间**；视图时间与时间轴时间是求值结果，出现在投影、命令回执与 UI，不出现在存储——"内部真实时间、外部视图时间"是本协议的存储纪律；
- `studio/data.json` 仍是纯派生投影，只增加 timeline / 视图投影节；
- BCF 合成文档（`.bcut.json`）**不进产品项目**；需要 BCF 渲染语义的场合（叠加烧录、动画采样）由实现从 `timeline.json` **编译派生**等价结构，方向单向、不落盘（§4.3）；
- 一切写入经 `bcut` / `bcut serve`，短持有 `.bcut/lock`，进 `.bcut/history` journal。

## 2.3 三层时间域（规范性）

| 时间域 | 定义 | 谁使用 |
| --- | --- | --- |
| **源时间**（per srcId） | 媒体文件自身时钟的秒 | 落盘字段全部：`words[].t0/t1`、`cuts[].t0/t1`、`clip.in/out`、元素 `srcStart` |
| **视图时间**（per srcId） | 该源折叠 cuts 后的连续秒 | 媒体视图对外契约：视图字幕/词戳、`clip` 命令的入出点参数、素材面板 |
| **时间轴时间** | clips 视图窗口按数组序拼接的秒；**即成片输出时间** | 编辑器时间轴、元素 `start/end`、词锚点求值结果、导出/烧录 |

时间轴上**不存在 cut 段**（这是与老版最大的差异）：剪切在媒体视图层就已折叠，clip 真删除后也不留痕，时间轴时间与输出时间合一，不再需要独立的 OUTPUT 折叠域。

规范映射函数（任何实现必须一致，含容差与 seam 语义）：

```
// 媒体层：源 ↔ 视图（per srcId）
viewTime(src, t)      = t − Σ dur(完全位于 t 之前的 cut)      t 落在 cut 内 → 无映射
srcTime(src, v, bias) : 反向；bias ∈ {preceding, following}
                        UI 停留取 preceding，导出前进取 following（对齐老版 SeamBias）

// 时间轴层：视图 ↔ 时间轴
clipViewIn/Out(c)     = viewTime(c.srcId, c.in / c.out)       端点落 cut 内时吸附到相邻 kept 边界
viewDur(c)            = (clipViewOut − clipViewIn) / c.rate
tlStart(i)            = Σ_{j<i} viewDur(clip_j)
tlTime(src, w)        = tlStart(c) + (viewTime(src, w) − clipViewIn(c)) / c.rate
                        （w 须落入 c 的有效窗口；0 个命中 = 被剪/未编排，N 个 = 素材复用）

// 事件折叠（字幕/元素窗口 → 时间轴）
clampEvent(start,end) : 事件窗与 kept∩clip 窗口求交；整段被剪或保留 < 10ms → 丢弃
```

精度与容差的分层归属（v0.5 按实现定案）：映射函数本身保持全精度、不做帧取整——`1/fps` 帧对齐发生在**消费点**（WordSpan 落定 §3.3-3、烧录/导出的采样与写入层），fps 不进入映射层签名；相邻段 1µs 缝合容差归 `bcut-editable` builder（进 writer 前统一收紧，§6.2/§6.3）；`clampEvent` 的 10ms 阈值是 crate 级常量 `bcut_timeline::MIN_EVENT_DURATION`，所有 Rust 调用点必须消费该常量，JS/Swift 端以同值镜像。这组函数是老版 `ClipPartitionIndex` + `CutTimelineMap` 的分层重构，落 `bcut-timeline` crate（§5.5），Rust 单实现、三端（CLI/serve/Studio JS/Swift）经契约夹具对拍（夹具含 10ms 丢弃样例；Swift 侧 views 表同样由夹具驱动）。

**关键推论（本模型的核心收益）**：clip 落盘存源时间，因此对某个源**新增 cut 时，所有引用该区间的 clip 自动缩短；restore 时自动伸长**——内容跟着词走，剪口癖对整条时间轴一次生效，无需任何 ripple 改写。cut/restore 操作**不改动任何 clip 字段**。（2026-09-28 起，1.283.0：画面与声音只在元素上，所以同一个写事务还会让按数字时间放的元素跟随时钟——片段名下的视频元素收到剩下的源区间、其余元素按成片时刻换算——diff 因此还含元素的改动；词锚点元素不动。规则见 [BCF §19.1](../../bcf/baocut-format-spec/19.md)「元素跟随时钟」。）
