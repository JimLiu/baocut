# 1. 背景与决策基线

> 出自 [BaoCut 剪辑域协议设计（Cut / Clip / 元素 / 水印 / 工程导出）](../bcut-edit-domain-design.md)

## 1.1 立项前遗留问题与当前收口

Mac App 首发移植曾把剪辑域整体推迟：老 voice-ink 的 cut/clip/broll/element/animation/watermark 协议不直接复刻，等待两层模型重新设计。立项前的缺口是：

- 产品项目是**纯 transcript + studio 投影**：`project.json` + `transcript.json` + 派生 `studio/data.json`，目录内没有任何合成文档；
- `hidden` 词覆盖表只影响字幕派生，**没有任何写路径**能表达"剪掉这段视频"；
- `export --to mp4` 只烧字幕（`SubtitleRenderPlan`），不跳剪切段、不合成叠加物；
- BCF 侧（`bcut-core`）clip `segment`/`loop`/`playbackRate`、元素树、动画 preset、词锚点 `~` 均已实现，但与转录世界只有单向词锚点桥；
- 格式规范 [§18.6](../../bcf/baocut-format-spec.md) 已预埋规范性推论："删除一段转录文字 ⇔ 对该 WordSpan 做 clip 切割与移除……文本编辑器就是剪辑器"，但 WordSpan 在 Rust 侧零实现。

这些缺口现已由 `bcut-timeline`、`bcut-editable`、CLI/serve、Studio、Mac 适配层与迁移器闭合。上面列表保留为设计动机，不代表当前能力状态；实际完成面见 §9。

## 1.2 已拍板决策（2026-08-01）

| # | 问题 | 决策 |
| --- | --- | --- |
| 1 | 剪辑真相层 | **媒体域无损剪切 + 新增项目级 `timeline.json`**；BCF 合成文档按需编译派生，仍是渲染域消费者 |
| 2 | Cut 与 Clip 的关系 | **两层分离**（v0.2 修订）：**Cut 属于媒体**——每个视频/音频源各自持有无损剪切集合（口癖 / 文稿驱动的剪辑发生在这里），数据模型级可逆；**Clip 属于整体时间轴**——引用媒体"剪切后视图"的有序编排单元，可整体分割/裁剪/重排，删除是**真删除**，可逆性靠 undo/history |
| 3 | 媒体视图 | 每个媒体源对外呈现**类数据库视图**：外部时间 = 折叠 cuts 后的连续时间，字幕（含词戳）同样以视图时间呈现，"就像物理裁剪过一样"；内部存储全部保持真实源时间，视频从不物理裁剪 |
| 4 | 主轨素材范围 | **首版即完整多源主轨**：数据模型与命令面首版就支持把附加素材编排进时间轴（对齐老版 M-clip） |
| 5 | 工程导出范围 | **全六目标对等迁移**：CapCut/剪映、Premiere（FCP7 XML）、Resolve（FCPXML/FCP7 XML）、Final Cut Pro（FCPXML 1.9/1.10）、Shotcut（MLT）、Kdenlive，共享一个中立 OUTPUT 时间 IR |
| 6 | 成片 MP4 | **跳 cut + 全叠加烧录**：按视图/编排折叠、字幕重定时，B-roll/元素/水印/动画经共享 Rust 渲染内核烧入画面（零漂移原则延续） |
| 7 | 水印 | **文本水印是 text 元素的角色派生**；图片水印是 image 元素；**HTML 水印不再支持**——老项目的 HTML 水印迁移时按其已栅格化产物归入 image 元素，`html` 原文丢弃 |
| 8 | B-roll | **就是 image / video 元素**，不设独立数据类型；`broll` 只保留为命令面门面与元素 role 标注 |
| 9 | 动画 | **沿用 BCF 动画模型**（preset + keyframes 纯数据、封闭缓动枚举、编译期展开），老版 preset 词汇映射进 BCF 词汇表 |
| 10 | cuts 落位 | **内聚于源**（v0.3 修订）：`cuts[]` 是视频/音频源条目的内部字段，不是顶层表——源被删除时剪切随之删除；各源转录（真实源时间戳）同样归属于源，物理文件保持分离（`transcript.json` / `transcripts/<srcId>.json`） |
| 11 | 全局字幕与翻译 | **全局字幕 = 派生视图**（v0.3 修订）：内容跟源走、呈现跟时间轴走。译文存各源转录的 `trans[lang][sentenceId]`，素材被剪/拼接/复用/换位译文全部继续有效；翻译任务按**时间轴投影**装配上下文、按 `(srcId, sentenceId)` 散写回；句子 staleness 指纹使用**可见词序列**；成片字幕上的编辑路由回源 trans 表；样式/字幕轨集（第 108 轮起为 `tracks`，旧称显示模式 `mode`，现为其派生值）/排版的持久真相是项目级 `studio/style.json`，并投影到 `studio/data.json.style`。无源的"字幕"（标题卡、音乐段手写句）不是字幕，是 text 元素 |

## 1.3 老版遗产：保留什么、纠正什么

老 voice-ink 剪辑域（`Sources/VoiceInk/Models/TimelineModels.swift`、`ElementModels.swift`、`Export/Project/*`）中被验证有效、本设计**保留**的：

1. **剪切的无损性**：剪切从不触碰 `words[]`，翻译键 / 阶段戳 / undo 天然稳定；词的剪切状态由词中点**派生**，不存在词级 cut 标志。
2. **叠加物统一为轨道上的元素**：`texts/broll/watermarks` 在老版后期已收敛为 `tracks[].elements[]` 的投影，新协议直接从统一模型起步。
3. **元素变换用画布归一化坐标（%）**：成片画幅在导出期可变（16:9 / 9:16），元素位置必须画幅无关；CapCut 的 transform 也是归一化模型。
4. **导出必经中立 OUTPUT 时间 IR**（EditableTimeline）：折叠与窗口归零在 IR 层一次完成，六个 writer 与字幕 sidecar 消费同一结果——"画面 / 字幕 / sidecar 永不打架"。
5. **动画两层持久化**：文档只存 preset 引用 + 冻结版本，渲染期编译成关键帧。
6. **preflight blocker/warning 码表**、audit 闸门（B-roll 落剪切区、闪切、无溯源等）。

**纠正**的：

1. 老版"Clip IS the Cut"把剪切与编排揉进同一个主轨分区（cut 只是 clip 上的布尔标志，cut 段仍占时间轴）→ 新协议**分层**：剪切是媒体的属性（源级 `cuts[]`，假删除、可逆），编排是时间轴的属性（`clips[]`，真删除、靠 history 可逆）。剪口癖天然是"对这条素材的所有使用一次生效"，而不是"对时间轴上的某一处生效"。
2. 老版 clip 存 `{start, end, src}` 三份时间，`start/end` 与数组序冗余 → 新协议 clip **只存源时间区间，时间轴位置由数组序前缀和派生**（对齐 BCF"场景表派生 cue 表"的单一来源纪律，见 §3.4）。
3. 老版元素只能锚时间轴秒，ripple 靠 `mapTime` 收口点手工平移 → 新协议元素时间**支持词锚点**（`~srcId:wordId`，复用 BCF §5.2 文法），"讲到这个词出现 B-roll"成为格式能力，剪切后自动跟随。
4. 老版剪切溯源外挂 `ai/cuts.json` 且 skill 文档与代码漂移 → 溯源仍走 `ai/cuts.json`（与其他 AI 阶段产物同级、同审计地位），但条目 schema 进本协议正文（§3.8），由 `bcut spec` 自描述。
5. 老版 `source:"html"` 水印 → 按决策 7 取消。
6. 老版 `screentext` 依赖"必须住在 `tr-text` 轨"的隐式合成约定 → 新协议轨道语义显式化（§3.6），无隐藏排序规则。
