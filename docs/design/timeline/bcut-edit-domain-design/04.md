# 4. 派生与投影

> 出自 [BaoCut 剪辑域协议设计（Cut / Clip / 元素 / 水印 / 工程导出）](../bcut-edit-domain-design.md)

## 4.1 studio/data.json 扩展

`refresh()` 继续是幂等纯派生，新增 `timeline` 节：

```jsonc
"timeline": {
  "rev": 7,                        // timeline.json 独立单调 rev（与转录 rev 同机制）
  "duration": 743.1,               // 时间轴总长（= 成片时长，无 cut 段）
  "views": {                       // 媒体视图（per srcId，"main" 在内）
    "main": { "viewDuration": 743.1,
              "keptSpans": [ { "t0": 0, "t1": 12.40, "viewStart": 0 },
                             { "t0": 13.10, "t1": 47.02, "viewStart": 12.40 } ],
              "cuts": [ { "id", "t0", "t1", "kind?" } ] }
  },
  "clips": [ { "id", "srcId", "in", "out",
               "tlStart", "tlEnd", "viewIn", "viewOut" } ],   // tl*/view* 为派生便利字段
  "tracks": [ /* 元素窗口已求值为时间轴秒（词锚点已解析），place/animate 原样 */ ],
  "main": { /* 原样 */ }
}
```

- `views.keptSpans` 就是"数据库视图"的物化契约：前端与 Agent 用它把任何源时间/视图时间互换，无需自己重算 cuts 补集；
- 词锚点在投影里**求值为秒并保留原锚点串**（`{start: 42.6, startAnchor: "~main:g42.0"}`）；
- `cues[]`/`sentences[]` 保持媒体源时间不变——**视图字幕与时间轴折叠是消费端行为**（经 `views` + `clips` 两张表在 JS 侧复算，契约夹具对拍，见 §5.5）；
- 派生仍由 `studio_projection::refresh()` 单点完成，timeline 变更与转录变更共用 rev+fingerprint 失效机制。

## 4.2 全局字幕 = 派生视图

原则一句话：**内容跟源走，呈现跟时间轴走**。成片（全局）字幕不是一份数据，而是"按时间轴顺序装配各源视图字幕"的实时派生——任何时刻都可以从 `sources[].cuts` + `clips[]` + 各源转录逐位重建。

**派生链**：

1. 每个带转录的源先派生**视图字幕**：按词派生 Cue（§18.5），剪掉 cut 词（§3.3-4），词戳换算为视图时间——"好似物理裁剪后的字幕"；
2. 再按 clips 编排把各源视图字幕映射到时间轴（§2.3 `clampEvent`）：整条被剪/未编排的 cue 省略但**编号连续**，保留 < 10ms 的丢弃，跨拆条边界的 cue 按 clip 窗口截断，素材复用的句子两处显示；
3. **样式与呈现是时间轴/项目级配置**（持久化在 `studio/style.json`，投影为 `studio/data.json.style`：字体、字幕轨集 `tracks`〔第 108 轮起「画面上排哪几行」的真相；旧的显示模式 `mode` orig/trans/bi 已降级为由轨集派生的只写兼容字段〕、排版位置、双语布局）——多源拼接的成片字幕外观统一，与内容来源无关；
4. 没转录的附加源被编排进来 → 那段就是没字幕（或先 `clip transcribe`）——派生模型天然正确的行为；"没有源的字幕"（音乐段手写一句话、标题卡）**不是字幕，是 text 元素**（§3.6），模型里已经有了。

**转录编辑器**（源视图）：被剪的词以"删除线/折叠"呈现（UI 态），视图模式下隐去并展示视图时间。`hidden` 词与 cut 词在字幕层合并生效（都不出字），但来源可区分（一个是字幕意图、一个是剪辑派生）。markdown 导出保持字面不重定时；其余导出（SRT/VTT/ASS/MP4/工程字幕轨）全部消费第 2 步的时间轴装配结果——语义对齐老版 `CutTimelineMap` + `presentedSubtitleEvents`，推广到多源。

**翻译如何运转**（决策 11，四条规则）：

1. **译文跟素材走**：`trans[lang][sentenceId]` 表继续存在各源自己的转录里（[Transcript v0.3 §18.7](../../bcf/baocut-format-spec.md) 已支持，`sentenceId = s-<首词id>` 锚源词）。素材被 cut、被拼接、被复用、被换位置——已有译文全部继续有效，一个字不用重翻；复用两次的句子只翻一次、两处显示。
2. **翻译任务的输入是时间轴投影**：`translate` 按时间轴顺序装配所有**可见**句子（跨源、剪掉 cut 词之后的），把成片语序作为上下文喂给 LLM——成片语序才是观众听到的语序，比任何单源的原始语序都更对（这正确处理了多条视频拼接的语境问题）；然后按 `(srcId, sentenceId)` 把结果**散写回各源的 trans 表**。
3. **半句被剪 → 定向重译**：句子 staleness 指纹从"源词序列"扩展为"**可见词序列**"（现有 `transSrc` 机制的直接延伸）。cut/restore 改变了某句的可见词 → 该句译文 stale → 只重译那一句。翻译的对象始终是观众实际看到的文本。
4. **全局字幕的编辑是路由**：UI 在成片字幕上改一句译文，实际写回对应源的 trans 表（`(srcId, sentenceId)` 定位）——与今天 studio 改 cue 写回 transcript 覆盖层是同一个模式，不新增机制；`transcript/apply` 的 `translation` op 增加跨源路由即可。

对既有翻译管线的具体改动：`transSrc` 指纹计算改为可见词序列，cut/restore（含 clip 增删裁、删源）事务后**即时**触发 stale 扫描——结果进 CLI 回执与 `timeline/apply` 响应的 `staleTranslations`，不等 `bcut check` 惰性浮现；`translate` 的装配阶段读 timeline 投影而非单转录；阶段戳/指纹按 srcId 分槽（各源转录文档自带 `stages`，附加源经 `clip transcribe` 走同一构建器写入 asr/asrLayout 戳）。**stale 判定的保护性边界**：只有带 `transSrc` 戳的译文才可能 stale——纯人工填写的译文（编辑路由不写戳）永不判 stale，防止 check 引导重译覆盖人工文本（与单文档 `stale_sentences` 同语义）。润色/分段/章节是否对附加源开放另行排期（§11）。

## 4.3 与 BCF 的桥（单向、编译期）

`timeline.json` 可被确定性地编译为等价 BCF 文档片段（不落盘，或经未来 `export --to bcf` 显式落盘）：

```
clips（扣除 cuts 展开为 kept 子段） → visual 轨主 clip 序列：video 元素 + mediaStart/segment/rate
元素                               → overlay clip（place → style px 按目标画布换算；animate 原样）
词锚点                              → BCF ~ 锚点（refId 换算为对应 clip id 限定形式）
字幕                               → captions 轨 from 派生（复用 §8.4）
```

这是叠加烧录与 BCF 渲染域复用的语义基础：**烧录器不重新发明采样语义，它消费的就是 BCF 展开后的动画/元素模型**（§6.5）。同时把 [格式规范 §18.6](../../bcf/baocut-format-spec.md) 的"引用窗口"定义扩展一条：**timeline clip 的 kept 子段也是媒体引用点**（修订清单 §10）。反向（BCF → timeline）不存在——BCF 展开产物不回填 timeline 文档。注意这条只界定 timeline 域：项目以 TSX 为真源（`entry` 存在）时，界面对 BCF 元素的编辑按格式规范 §13.3 的三通道契约回写 TSX/数据层（方案见 [bcut-bcf-direct-edit-design.md](../../bcf/bcut-bcf-direct-edit-design.md)），与 timeline 域互不越界。
