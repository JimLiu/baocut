# 6. 导出

> 出自 [BaoCut 剪辑域协议设计（Cut / Clip / 元素 / 水印 / 工程导出）](../bcut-edit-domain-design.md)

## 6.1 导出目标注册表（已实现）

[cli-design §9.1](../bcut-cli-design.md) 承诺的注册表 trait 已在 `core/crates/bcut-kernel/src/services/export_registry.rs` 落地：

```rust
trait ExportTargetImpl {
    fn token(&self) -> &'static str;              // "srt" … "capcut" "premiere" …
    fn arg_schema(&self) -> Value;                // 特有参数，进 bcut spec export
    fn run(&self, ctx: &ExportCtx) -> ExportReport;  // 接收 OUTPUT 投影后的时间轴
}
```

`ExportReport` 统一 `{format, path(s), laneCount, segmentCount, blockers[], warnings[], omitted[], lossy}`，可编辑工程另带 `deliveries[]` / `summary` 与 BCF 项目的 `film{path, rendered, stale}`（specVersion 1.228.0）。`lossy` 是**计算值**：本次导出确实发生损失（`summary.dropped > 0` 或存在 `attr-*` 降级 warning）才为真，不回声 `--allow-lossy` 旗标；隐藏轨、隐藏元素与输出窗外的元素是 `skipped`，不算损失。`spec` 从注册表生成，测试对拍 clap 值集与目标参数，消灭 enum/spec 漂移。目标 token：`capcut · premiere · resolve · final-cut-pro · shotcut · kdenlive`（与老版稳定 token 一致）。

## 6.2 OUTPUT IR（老版 EditableTimeline 的 Rust 对等）

`bcut-editable` crate，唯一入口 `build(timeline, transcripts, studio_style, options) -> (EditableTimeline, PreflightReport)`：

```rust
struct EditableTimeline {
    canvas: Canvas,                  // outputSize(natural, --ratio, --size)
    fps: f64, duration: f64,         // 时间轴时间（= 输出时间）
    main_transform: Transform, main_muted: bool,
    subtitle_layout: SubtitleLayout, // x/y/width/order/gap/backgroundMode ← studio style
    lanes: Vec<Lane>,                // kind: video|audio|text；数组序即目标轨道序
    assets: Vec<Asset>,
}
```

构建规则（对齐老版 builder 语义，按两层模型重述）:

1. **主画面 lane**：每个 clip 按其源 cuts 展开为 kept 子段序列（`srcStart` 逐段推进、`rate` 换算），进 `main-track` lane；相邻缝 ≤1µs 强制对齐；
2. **元素**：元素窗口是时间轴时间，直接进 lane；引用媒体的元素其源钟越过所引源的 cut 段时**切段并推进 `srcStart`**（video/audio 推进，text 不涉及）；`hidden` 轨 / 元素、`clampEvent` 丢弃项进 `skippedElementIds`；
3. **泳道扇出**：同轨时间重叠的元素拆到相邻 lane（`<trackId>+<n>`，后者在上）；
4. **字幕**：与 sidecar 完全相同的重定时结果（§4.2）生成 text lane（双语拆 `tr-subs` + `tr-subs-trans`，共享几何进 `subtitle_layout`；`backgroundMode:"shared"` 报 `bilingual-shared-background` warning）；
5. **动画**：原生落法下整体丢弃，逐元素 `attr-animation` warning（各 NLE 无对等词汇；成片烧录不受此限）；`--bake lossy` 时连同其他有损属性烘焙成 alpha 视频，见 v2 设计稿 §3；
6. **烘焙产物**：宿主按 `plan_bakes` 烘出的 `BakedAsset` 登记成资产 `baked-<elementId>`（无 `sourceId`，按 `path` 解析，`hasAlpha` / `sequence` 照抄），片段放原轨、原时间区间、恒等变换铺满画布；模板层是 `template` lane，位于所有元素 lane 之下、主画面之上。

Preflight 码表冻结为协议一部分（真值源 `bcut_editable::preflight_code`，消费方禁止本地复写字符串）：

- **blocker**：`missing-media`（永不可降）· `empty-output` · `lossy-drop`（`summary.dropped > 0` 且未给 `--allow-lossy`，由宿主判定）· `film-missing`（BCF 动画项目还没有成片且没给 `--render-film`，由宿主判定）；
- **warning**：`attr-mask/attr-effects/attr-animation/attr-tile/attr-corner-radius/attr-text-style/attr-transform/attr-transition/attr-audio-fade/canvas-background/bilingual-shared-background/caption-sequence/reference-media/media-copied/capcut-restart-required/untested-editor-version`；烘焙相关 `element-baked/template-baked/bake-unavailable/bake-failed/film-rendered/film-stale`；`unsupported-element`（按策略放弃）；
- **请求原因码**（只出现在 `BakeRequest.reason` 与 `deliveries[].reason`，不单独成 issue）：`no-native-form`（目标没有原生落法）· `lossy-attr`（`--bake lossy` 下为保住有损属性而烘）。

`caption-sequence`：原文轨套了倒鸭子跨句动态排版时，字幕仍按普通行进 `tr-subs`，排版与镜头不进 NLE，见 [`bcut-daoyazi-caption-design.md`](../../subtitle/bcut-daoyazi-caption-design.md) §12。`attr-transition` / `attr-audio-fade` 是原先静默丢掉的视频转场与音频淡入淡出，现在逐元素报。`PreflightReport` 另带 `deliveries[]`（每个进入输出窗的元素与模板层落成 `native | baked | dropped` 之一，带 `reason` / `asset`）与 `summary{native, baked, dropped, skipped}`。

**码的可达性**（2026-09-24 随可编辑工程导出 v2 A1 改写，取代 v0.5 的「reserved 码」澄清）：元素集早已扩到 12 种 kind，`unsupported-element` 现已可达——表示「按 `--bake` 策略放弃」（`--bake none` 下没有原生落法的元素、Lottie 源贴纸、模板层），以及宿主缺源的防御路径；`attr-blend` 仍不可达（模型无 blend 字段），保留在码表。`--allow-lossy` 不再是预留位：`summary.dropped > 0` 时无此旗标以 `lossy-drop` 失败，有则照常写出，warning 与烘焙从不阻断，语义见 v2 设计稿 §6。

落法决策表（原生 / 烘焙 / 放弃）、烘焙接口与报告格式见 [可编辑工程导出 v2](../../editor/bcut-editable-export-v2-design.md)。

## 6.3 CapCut / 剪映 writer 移植要点

`CapCutDraftWriter`（42.7KB）按行为对等移植进 `bcut-editable`，实测校准常量**逐个保留**（这批是真金白银的实机逆向成果）：

- 草稿文件：`draft_info.json` + 字节级相同的 `template-2.tmp` 双写、`draft_meta_info.json`、`draft_cover.jpg`；portable 模式另加 `baocut-manifest.json`（sha256 清单）；
- 骨架来自净室采集的消毒空模板（bundle 资源随 CLI 分发），writer 只改自有字段；
- 版本前缀白名单 `8.7.* / 9.0.*`，版本不匹配不阻断（诊断性记录）；
- 单位与换算：整数微秒；`transformX = (pct-50)/50`、`transformY = (50-pct)/50`；`fontSizeDivisor = 50/9`；`lineWidthScale = 0.82/0.80`；`backgroundInsetFactor = 1.5`；`shadowFeatherDivisor = 6`；
- 已知坑固化为测试：`background_*` 生效必须把 `check_flag` 47→63（bit 16）；overlay/watermark 无自动换行需预折行物化 `\n`；MP4 音频尾只裁 `source_timerange` 绝不裁 `target_timerange`；`render_index = laneIndex*10000 + segmentIndex`；
- 媒体模式 `reference | auto | copy`（auto 按 CapCut 沙盒可读性判定）；安装模式 staging 校验（draft lint）→ 原子发布，必要时 `capcut-restart-required`。

## 6.4 其余五 writer

`FCP7ProjectWriter`（Premiere / Resolve legacy `.xml`）、`FCPXMLProjectWriter`（FCP / Resolve `.fcpxml`，`--fcpxml-version 1.9|1.10`、`--event-name`）、`MLTProjectWriter`（Shotcut `.mlt` / Kdenlive `.kdenlive`，`--profile source|canvas`、`--bin-layout flat`）对等移植。它们只消费 `EditableTimeline`，与 CapCut writer 互不感知——IR 中立性由"新增 writer 零改 builder"验证。

## 6.5 成片 MP4：跳 cut + 全叠加烧录

`export --to mp4` 升级为完整合成（决策 6），管线：

```
timeline.json ──§4.3 编译──▶ 等价 BCF 展开（元素/动画 → keyframes，词锚已求值）
                                  │
timeline_media 以 ffmpeg filter graph 压平 clip×kept 主轨
  （trim/atrim + setpts/atempo + concat，生成临时规范 MP4）
                                  │
OverlayRenderPlan::render_rgba(tlT)   ← SubtitleRenderPlan 的泛化
  = 字幕层（现有内核原样） + 元素层（BCF sample 语义采样 place/animate → 光栅化）
                                  │
native_video 单输入逐帧合成 → 平台编码器（AVAssetWriter / Media Foundation）
```

- **零漂移**：serve 的 `__bcut/subtitle/overlay` 端点同步升级为全叠加 overlay（保持既有缓存键 + `next_change` 失效边界机制），预览与导出同一 `OverlayRenderPlan`；
- 音频：主画面 kept 子段拼接 + audio 元素混音（volume 静态 + 淡入淡出由 preset 展开）；（2026-09-16 改：「主画面 kept 子段」只是旧式文档的口径；分离 / 元素文档的原声来自每一件 `kind: video` 元素自己的声音，不分 `srcId` 与轨，静音逐元素写 `muted`，见 [product-design §12.0](../../product/product-design/12.md#120-三种文档形态与统一口径2026-09-16)）
- cut、变速、多段/多源主轨的规范化明确依赖 PATH 中的 `ffmpeg`；平台原生后端只接收压平后的单输入，继续负责零漂移叠加与 H.264/AAC 编码。性能退路沿用 [§4.4](../../../archive/mac/bcut-mac-app-port-design.md) 的"区间预渲染 overlay 序列"，不存在降级为近似绘制的选项。
