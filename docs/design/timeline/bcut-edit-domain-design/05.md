# 5. 命令面与 serve

> 出自 [BaoCut 剪辑域协议设计（Cut / Clip / 元素 / 水印 / 工程导出）](../bcut-edit-domain-design.md)

## 5.1 `bcut cut`（媒体层：无损剪切）

全部遵守现行信封 / 错误 kind / 退出码契约；写命令回执带 `changed[]` 与新 id；`--json` 全覆盖；进 `bcut spec` 自描述。

```
cut detect <proj> [--src <srcId>] [--dry-run] [--no-pauses] [--no-fillers]
                  [--min-pause 0.8] [--compress-to 0.3] [--max-gap 3.0]
                  [--filler-lang auto|en|zh] [--fillers a,b] [--trim-chapter-starts]
cut match  <proj> [--src <srcId>] --query <text> [--regex] [--whole-word]
                  [--scope match|para] [--action cut|keep] [--dry-run] [--note "…"]
cut add    <proj> [--src <srcId>] (--start A --end B | --words wA..wB) [--note "…"]
                  # --start/--end 为该源的源时间；--view 开关改为按视图时间解释
cut restore <proj> <cutId,…|--all> [--src <srcId>]
cut list   <proj> [--src <srcId>] [--kind silence|filler|badTake|manual|match|offScript] [--map]
cut script <proj> --script <file> [--src <srcId>] [--take last|first] [--snap <秒>] [--dry-run] [--report <path>]   # 1.291.0 起
```

- 一切以**源**为对象：缺省 `--src main`；`restore` 收 **cutId**（老版收 clipId 的语义随两层分离终结），cutId/clipId 接受唯一前缀（§5.2 id 解析纪律，无 name 层）；
- 静音 / 固定 filler 检测是本地纯函数；badTake 与上下文 filler 由 LLM cleanup 阶段产出（`task start cleanup` / `auto --rough-cut`，溯源写 `ai/cuts.json`）——CLI 从不调 LLM 的纪律不变；
- 回执附带受影响面：`{cut: {t0,t1,removedSec,snapped}, cutId, affectedClips: [c1], viewDuration}`；
- **事务后 stale 扫描进回执**（§4.2 规则 3 的落点）：所有改变字幕可见性的命令（cut add/restore/detect/match、clip add/trim/remove、source remove）在成功回执附 `staleTranslations: {lang: ["srcId:sentenceId", …]}`，并把定向重译命令写进信封 `next`；无 stale 时两者省略。

## 5.2 `bcut clip`（时间轴层：编排）与元素命令

```
clip list       <proj>            # id · 源/视图区间 · 时间轴位置 · 词摘要
clip split      <proj> (--at <tl秒> | --word <wordId>)
clip add        <proj> (--file <path> | --src <srcId>) [--in A --out B]   # in/out 为视图时间
                       [--after <clipId> | --before <clipId> | --at-end]
clip move       <proj> <clipId> (--after <clipId> | --before <clipId> | --to <n>)
clip trim       <proj> <clipId> [--in A] [--out B]                        # 视图时间
clip set        <proj> <clipId> --rate <factor>                           # 1 原速，2 两倍速
clip remove     <proj> <clipId,…>          # 真删除；可逆靠 undo/history
clip transcribe <proj> --src <srcId,…> [--model …] # 批量附加源转录 → transcripts/<srcId>.json

source list     <proj>                     # 源清单：引用计数、转录/剪切状态
source remove   <proj> <srcId> --yes       # 删源：级联删除源内 cuts（决策 10），
                                           # 列出受影响 clip/元素并要求确认；孤儿转录文件明示
```

批量 `clip transcribe` 在命令生命期内复用 Qwen/Whisper 的 ASR、VAD 与对齐器
实例，每个 source 开始时由流处理器重置 VAD 状态。这是命令内优化，不引入常驻模型进程；
每个源仍以独立 history 事务写入，全批结束后统一刷新 Studio 投影。MOSS 为受控例外：
为了不让约 1.7GB 说话人模型与约 0.9GB 词级对齐器同时常驻，按 source 释放、精修并
重载；低内存设备的峰值上界优先于该引擎的批量启动速度。

**`bcut element`**（统一元素面）：

```
element list   <proj> [--role broll|watermark|screentext] [--track <id>]
element add    <proj> --kind text|image|video|audio
               (--text "…" | --file <path> | --src <srcId>)
               [--start A --end B|none | --at-word wA[..wB]]
               [--track <id>] [--role …] [--rect "x,y,w"] [--mode …] [--fit …] …
element set    <proj> <elId,…> [--x --y --w --scale --rot --opacity --start --end
               --grayscale --blur --brightness --mask --volume --muted --hidden
               --text --name …]                 # 整批单事务；flag 按 kind 能力矩阵校验
element remove <proj> <elId,…>                  # 整批单事务，任一 selector 失败则不落盘
element style  <proj> (--id <elId> | --role … | --all-text)
               (--apply <styleId|name> | --patch '{json}' | --save <name> | --refresh)
               [--force-size]                   # 缺省不改字号（保 screentext OCR 字号）
```

**门面命令**（skill 对等回归；底层同 element/cut/clip 实现）：

```
broll add|update|remove|list|suggestions|preview   # update/remove 接受 <elId,…>；add 缺省：image 4s pip / video ≤8s fullscreen
watermark add   (--text "…" | --file <img>) [--tile on] [--style …] [位置缺省 85,10,22 / opacity 0.6]
screentext scan|add|show|translate|set|insert|apply|list|clear
animation list|show|apply|clear|preview|save|saved|forget
frames <proj> (--at t[,t…] | --start A --end B [--count N]) [--size N] [--tile]
```

门面只注入 role、轨道和产品缺省值：B-roll 与 element 的时间窗/展示/通用 patch、
水印与 element 的展示参数、B-roll 与 animation 的 preview 参数均来自共享的 clap
flatten 结构；`bcut spec` 测试逐字段对拍，防止门面独立演化成第二套协议。

id 解析顺序统一：精确 id → 唯一前缀 → 唯一 name，否则 `ambiguous`。

## 5.3 serve 编辑事务：`POST /<id>/__bcut/timeline/apply`

AI 建议的逐项接受 / 忽略 / 撤回（`Command::Review`、`POST /__bcut/review/apply`）另有一条审阅写路径，见 [`bcut-talking-head-cut-design.md`](../../editor/bcut-talking-head-cut-design.md) §7.2。

交互式剪辑不可能每次操作起子进程。新增与 `transcript/apply` 平行的事务端点：

```jsonc
{ "baseRev": 7, "label": "剪掉口误",
  "ops": [
    // —— 媒体层（假删除，作用于 cuts）——
    { "kind": "cutRange",   "srcId": "main", "start": 12.4, "end": 13.1, "note": "…" },
    { "kind": "cutWords",   "srcId": "main", "first": "g42.0", "last": "g43.2" },
    { "kind": "restoreCut", "cutId": "cut-2" },
    { "kind": "retimeCut",  "cutId": "cut-2", "t0": 12.2, "t1": 13.1 },   // 1.303.0：原地改区间，id 与来源不变
    // —— 时间轴层（编排；removeClip 是真删除）——
    { "kind": "splitClip",  "at": 30.0 },
    { "kind": "addClip",    "srcId": "src-a1", "in": 2, "out": 8, "after": "c1" },
    { "kind": "moveClip",   "clipId": "c2", "before": "c1" },
    { "kind": "trimClip",   "clipId": "c2", "base": [2, 8], "set": [2, 6.5] },
    { "kind": "removeClip", "clipId": "c2" },
    // —— 元素与主画面 ——
    { "kind": "addElement", "track": "text", "element": { /* §3.6 */ } },
    { "kind": "patchElement", "elId": "el-2", "base": { /* 所见值 */ }, "set": { "place": { "x": 40 } } },
    { "kind": "removeElement", "elId": "el-2" },
    { "kind": "setMain",    "set": { "muted": true } }
  ] }
```

- 语义与 `transcript/apply` 完全同构：`baseRev` 乐观锁（失配 409 `stale`）、`.bcut/lock` 短持有（冲突 423 `busy`）、逐条 base 校验进 `skipped[]`（`reason: "base-mismatch"`，**HTTP 仍是 200**，客户端必须检查 `skipped[]` 才能发现丢写）、成功后进程内 `refresh()` 投影、`rev+1`、写 `.bcut/history` journal（`timeline.json` 进历史库，**undo/redo/history 端点零改动地覆盖剪辑**——真删除的 clip 由此可逆）；
- base 校验规则：`base` 是稀疏子集，只比对其中出现的键；对象递归、数组要求等长且逐元素匹配；**数值按值比较而不按 JSON 表示比较**——磁盘 `timeline.json` 里的 `50.0` 与客户端 `JSON.stringify(50)` 发出的 `50` 视为相等，客户端无需为了命中 base 而刻意保留小数表示；其余标量按严格相等；
- 另有整文档 op `replaceTimeline {document}`（v0.5 补记）：把整份 timeline.json 原子替换，供尚未拆细粒度 op 的客户端整体提交；当前 Mac 编辑器即走此 op（细粒度 op 化是 §11 已登记缺口）；
- 含可见性变更 op（cutRange/cutWords/restoreCut/retimeCut/addClip/trimClip/removeClip/replaceTimeline）的事务，响应附 `staleTranslations`（同 §5.1 回执语义），前端可当场引导定向重译；
- Studio 前端与 Mac App 编辑器同走此端点；Agent / 脚本走 §5.1/§5.2 的 CLI 批处理面，两通道底层同一套 `bcut-timeline` 变换实现，禁止两套语义。Studio 侧的剪辑操作 UI 尚未落地（见 §11），当前前端只消费投影做播放跳段与译文编辑路由。

### 5.3.1 命令行整批编辑与试运行（`1.281.0`）

现状（2026-09-28）：`/timeline/apply` 等三条旧端点已在 `1.160.0` 合并为 `POST <project>/__bcut/edit/apply`（`EditBatch`：`channel` 取 `timeline` / `transcript` / `style`），上面的 op 形状与语义不变。[Agent 编辑缺口方案](../bcut-agent-editing-gaps-plan.md) G2 给它补了三样东西，都不新增 op、不改 op 语义：

- **命令行入口** `bcut edit apply <项目> --file <ops.json|->`（参数见 [参考 `bcut edit`](../bcut-cli-server-reference/06/bcut-edit.md)）。与 serve / App / `Command::EditApply` 是同一个执行体（`bcut-kernel::kernel::edit::apply_locked`：项目锁 → `cancelJob` 复查 → 撤销栈 → `bcut-workspace::apply`），Agent 一个文件交一批 op，全有或全无、一步撤销，不必一条命令一次子进程、一次撤销。
- **试运行** `dryRun`：`bcut-workspace::apply` 的 `preview_timeline` / `preview_transcript` / `preview_style` 与真跑共用 op 分派，停在第一次落盘之前（不捕获旁路改动、不写 journal、不刷投影）；timeline 通道逐条应用并收集全部被拒的 op（`rejected[{index, failure}]`），transcript 通道在同一份稿上顺序应用、遇到第一条被拒即停。零 op 试运行只读当前版本。
- **op 登记表** `bcut-workspace::edit_ops`：三通道 31 种 op 的字段、类型、必填、枚举与缺省，由 `bcut spec edit` 投出；数值字段的 `type` / `range` / `unit` / `timeBase` 用命令行数值参数同一个 `NumParam`（`bcut_protocol::param`），同一个量与命令行参数共用 `edit_ops` 顶部的常量。测试从 `apply_timeline_op` / `stage_inline_op` / 附加源路由 / 独占 op 分支的源码里扫出分发的 op 名，钉住与登记表相等，并对每种 op 跑「最小合法输入通过、缺必填被拒」。

写时间轴的咽喉 `bcut-workspace::timeline::commit_timeline_opts(project, timeline, label, history, &WriteOptions{dry_run, base_rev, label})`（`mutate_timeline_with` 是它的「读 → 改 → 提交」包装）同时把写后的版本记进线程本地槽，CLI 信封在输出前取出写进 `data.rev`——所有经这条咽喉写 `timeline.json` 的命令（`clip` / `cut` / `element` / `template apply` …）自动带版本，不逐条命令手写（`project undo` / `redo` / `restore`、`reframe` 换视频源与配音混音不经这条咽喉，各自当场记一次）；以后给这些命令加 `--dry-run` / `--base-rev` 只需在 clap 上加参数、传进 `WriteOptions`。

## 5.4 播放与预览

- serve 媒体端点按 srcId 扩展：`__bcut/media?src=<srcId>`、`filmstrip`/`thumb`/`waveform` 同理；
- 预览播放器（Studio / Mac App AVPlayer）读 `studio/data.json.timeline` 的 `views` + `clips` 做**播放期跳跃**：clip 内跨 cut 段 seek 到 kept 下一段（容差吸收抖动——对齐老版 `cutEnd(containing:)`），clip 边界切换源。叠加层走 §6.5 的 overlay 端点，**预览与导出出自同一采样内核**（零漂移决策延续）。
