# 4. 数据模型

> 出自 [BaoCut 剪口播技术方案（原型第 192–197 轮 → 内核 / serve / App v2 / Web）](../bcut-talking-head-cut-design.md)

## 4.1 已剪：原型字段 → 真实落点

| 原型 `cut` 字段 | 落点 | 说明 |
|---|---|---|
| `id` | `cuts[].id`（`cut-<n>`）与 `ai/cuts.json.entries[].id` | `next_id("cut-")` |
| `start / end` | `cuts[].t0 / t1` | 源时钟秒（原型是时间轴秒 + `srcStart` 折算，真产品直接是源时间） |
| `kind` | `entries[].kind`（闭合）+ 新增 `entries[].category` | `pause → silence`、`take → badTake/retake|falseStart`、`repeat → badTake/repeat`、`filler`、`manual` |
| `text` | 派生：`wordIds` → 当前 `words[]` 文本；停顿为 `detail`（`1.4s → 0.3s`） | 不存文本，词是真相 |
| `why` | `entries[].reason` | 已有 |
| `state: 'cut'` | 在 `cuts[]` 中存在 | `restoreCut` 即消失 |
| `by` | 派生自 `entries[].origin`：`manual → you`、`detect|cleanup → ai`；新增 `entries[].via: "app"|"cli"|"agent"` 区分 `agent` | `via` 由写入方填（App/Web 写 `app`，CLI 直跑写 `cli`，Agent 会话内的 CLI 写 `agent`，取 `BAOCUT_AGENT_SESSION` 环境存在与否） |
| `batch` | 新增 `entries[].batch: <jobId>`，接受建议时从审阅条目继承 | 手动剪无 `batch` |

`ai/cuts.json` 新增字段 `category / via / batch` 均可选，老文件不迁移。`append_cut_provenance` 按 id 去重合并，不需要改写策略。

## 4.2 建议：`ai/reviews/cleanup.json` v5

```jsonc
{
  "reviewVersion": 5,
  "kind": "cleanup",
  "status": "pending",                     // 派生：任一条 pending → pending；否则 settled
  "batch": "job-20260907-1432",            // 本轮扫描的任务 id（serve job id 或 CLI 生成的 ulid）
  "baseWordsFingerprint": "812:g1.0:g88.4:1k3z9x",  // fingerprint(words)，取代 baseTranscriptSha
  "createdAt": "...", "updatedAt": "...",
  "params": { "strength": "standard", "minPause": 0.8, "compressTo": 0.3, "maxGap": 3.0, "fillerLang": "auto" },
  "items": [
    {
      "id": "sug-1",                        // 本文件内稳定；新一轮扫描重编
      "category": "filler",                // filler | pause | retake | falseStart | repeat
      "kind": "filler",                    // 溯源闭合 kind：silence | filler | badTake
      "srcId": "main",
      "firstWordId": "g3.0", "lastWordId": "g3.2",   // pause 时两者相同 = afterWord
      "t0": 12.41, "t1": 13.22,            // 源时钟；pause 是压缩后要剪掉的范围
      "reason": "句首口癖", "detail": "嗯，就是，",
      "alternative": null,
      "state": "pending",                  // pending | accepted | dismissed
      "cutId": null,                       // accepted 时写 cut-<n>
      "decidedAt": null
    }
  ],
  "artifact": { /* CleanupArtifact 原样保留，供 lint 与审计 */ }
}
```

**读取时派生规则**（`bcut-editor-core::cut_mode::effective_state`，纯函数，输入 `item + CutSet`）：

1. `accepted` 且 `cutId` 不在 `cuts[]` → 视为 `pending`（C4）。
2. `pending` 且 `[t0, t1)` 与 `CutSet` 相交（`contains_cut_range`，容差 0.01）→ 视为 `superseded`（被手动剪覆盖；不显示、不计数、接受时进 `skipped`）。
3. 其余按 `state`。

**升级**：读到 `reviewVersion: 3` 的文件按 `status` 整体映射（`pending` → 全部 `pending`；`accepted` → `applied[]` 中的 `accepted`、其余 `dismissed`；`rejected` → 全部 `dismissed`），首次写回时升到 5。`CLEANUP_ITEMS_REVIEW_VERSION = 5`（`review/cleanup_items.rs`）只对 `cleanup` 生效，`broll` 仍用 `ACTION_REVIEW_VERSION = 3`（两 kind 分支）。

## 4.3 不变式与 lint

- 已剪不变式沿用 `bcut-edit-domain-design.md` §3.10（有序不重叠、`clip-empty-after-cuts`、`cut-mid-word`、`cut-no-provenance` 等），不新增。
- 新增 review lint（`bcut review lint` 与 `bcut lint` 同时报）：`review-item-orphan-word`（`firstWordId/lastWordId` 已不在 `words[]`，条目失效）、`review-fingerprint-stale`（`baseWordsFingerprint` ≠ 当前，整份建议标 stale，UI 显示「文稿已变化，建议可能过时 · 再找一遍」但**不拒绝接受**未失效条目）。
- `pending` 条目之间不重叠（生成侧 `merge_proposals` 保证；读侧不再校验）。
