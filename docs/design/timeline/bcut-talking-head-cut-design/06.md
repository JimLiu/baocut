# 6. 检测流：`cleanup` 的增量语义与词表

> 出自 [BaoCut 剪口播技术方案（原型第 192–197 轮 → 内核 / serve / App v2 / Web）](../bcut-talking-head-cut-design.md)

## 6.1 增量与替换（C9）

`run_cleanup_cmd --review` 的落盘改为：

1. 读旧审阅文件（若有）；保留 `accepted / dismissed` 条目的 `(firstWordId, lastWordId, category)` 作为「已决集合」。
2. 本地检测 + LLM → `merge_proposals` → `skip_already_cut(&CutSet)`。
3. 新提案中命中「已决集合」的：`accepted` 者丢弃（它已经是 cut），`dismissed` 者丢弃（用户否决过）。
4. 剩余提案编成新的 `pending` 条目；旧 `pending` 全部丢弃（被本轮替换）。
5. 写 v4 文件，`batch` = 本次任务 id；`changed = ["review.cleanup"]`。

不带 `--review` 的直接应用路径不变（`AI: cleanup` journal 标签，收据撤销走 `task_undo`）。

## 6.2 类目与词表（C8）

- LLM 答案 `cat` 增加 `repeat`（说了两遍同一句 / 同一意思，保留后一遍），`validate_page` 与 `lint_agent_answer` 同步放行；`repeat` 与 `retake / falseStart` 一样映射到溯源 `kind: badTake`，`category` 保留细类。默认保留后一遍（`keep_later = true`），`can_flip` 逻辑沿用 `review.rs`。
- 提示词 `engines/cleanup.rs` 的 system 段加 `repeat` 定义与「保留后一遍」规则；prompt 改动同步本地 Agent（`task.rs:1023` lint）与 provider 两路（AGENTS.md 纪律）。
- `ZH_SOFT` 补「嗯」「啊」「呃呃」；「嗯」是软词（可作应答语），需标点隔离才命中。`ZH_HARD` 不动。

## 6.3 旗标统一（G5）

- `bcut cleanup` 增加 `--max-gap`（默认 3.0，透传 `make_detect_options`）与 `--no-pauses`（`--no-silences` 的别名，help 标注）；`bcut cut detect` 增加 `--no-silences` 别名。`serve` 的 `cleanup` 任务选项表（`job_kinds.rs:245`）加 `maxGap`。
- `docs/design/cli/bcut-cli-server-reference.md` 同步；`bcut spec` jobKinds 自动投影。
