# 8. 视图落地

> 出自 [BaoCut 剪口播技术方案（原型第 192–197 轮 → 内核 / serve / App v2 / Web）](../bcut-talking-head-cut-design.md)

## 8.1 共同交互规格（两端一致，判据来自 §5）

- Transcript 面板顶行 Segmented「改字 / 剪辑」；`entry = clean` 打开默认剪辑态。剪辑态正文 = 按段落 / 章节铺开的 `para_tokens`（只对可视行调用）；改字、拖段、查找替换只在改字态。
- 标记：已剪的字划掉（红底细划线）、建议的字橙底虚线下划、停顿在所属 cue 尾插 `◷ 1.4s` 小标（已剪态划掉）。
- 单击普通字 = 跳播；点建议 → 菜单「接受 · 剪掉 / 忽略这一条 / 试听这一处」；点已剪 → 「恢复这一段 / 试听这一处」。
- 拖选：按下第一个 token → 移动更新 `CutSelection {live: true}` → 松手 `live: false`、播放头跳到 `span.source_start` 对应的时间轴时间、选区不在可视区则滚到中间。时间轴同步画一块贯穿标尺以下所有行的高亮（拖选中虚线、松手实线）+ 左上标签 `span.label`；跨已剪段画多块。
- 浮动工具条：选区第一行上方，「**1.9s** 00:07.1 – 00:09.1 ｜ 剪掉 ⌫ · 试听 · 取消 Esc」；`live` 不出、滚出收起。
- 汇总条三态、每步 toast + 撤销、脚注文案——全部取 `summary_text` / `CutOp` 的返回，不在视图拼字符串。
- 时间轴：缝标记（细竖线 + 上方 `−0.8s` 角标，hover 展开为「已剪 口癖 · 0.8s · 恢复」；点击 = 恢复）；建议段 = 橙虚线段（点 = 接受）。二者都不是块：不进 `SelectionSet`、不吸附、不可拖。不新增轨、也不合并出「主视频」行（原型第 196 轮，用户裁决 2026-09-07）。**剪口是全局的，缝像播放头一样贯穿标尺与所有轨**，角标挂在标尺上，同一位置相邻的已剪段并成一道；transport 加「展开已剪段」开关，开着时缝撑开成贯穿所有轨的空槽带（标尺那截成阴影、不落刻度数字），刻度数字始终是成片时刻（原型第 197 轮，用户裁决 2026-09-07；App / Web 待同步，见原型台账 #203）。
- transport 时间码在成片比源短时多报「成片 3:14」（`view_duration`）。

|---|---|---|---|

**Web 三批复核裁决（2026-09-07，W-11）**：D-C8 / D-C9 跟 App（无选区隐藏工具条；完整
compose 组不拖裁）；D-C10 跟 App 的 notice 色并补类目 title；D-C15 Web 有完整色条提示，
App 保留无 tooltip 差异；D-C16 用 `stale - cut` 兼容旧投影。Agent 打开 Web 会话页、工具页
留进度卡；无可靠任务绑定不借用上一条 job 的百分比。模型活动显示真实字段、不虚构分页。
本批撤回在 Web 按稳定批次 ID 经「恢复已接受 + 忽略待定」两次 review 请求完成，保留无关
编辑；App 原有 journal 还原点机制不变。中途失败 / skipped 不报整批成功，允许重试。
以上实现机制与布局差异明确保留，不把协议事务、未知进度或原型演示数据当成生产事实。
