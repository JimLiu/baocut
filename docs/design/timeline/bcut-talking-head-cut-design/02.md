# 2. 现状盘点（2026-09-07，逐文件核实）

> 出自 [BaoCut 剪口播技术方案（原型第 192–197 轮 → 内核 / serve / App v2 / Web）](../bcut-talking-head-cut-design.md)

## 2.1 媒体层无损剪切（已完成，v0.5）

- `core/crates/bcut-timeline/src/schema.rs`：`Source.cuts: Vec<Cut>`，`Cut {id, t0, t1, ref}`，源时钟秒、半开区间；`sources / clips / tracks / main / template` 顶层封闭（`additionalProperties: false`）。
- `core/crates/bcut-timeline/src/cuts.rs`：`CutSet::new` 校验有序不重叠；`word_is_cut(t0, t1)` 是全仓唯一的「词被剪」判定（词中点落在 `[t0, t1)`）；`view_time / source_time(bias) / kept_spans / kept_intersections`；`insert_cut` 在 `CUT_MERGE_GAP = 0.02` 内合并、保留较早 id；`restore_cut`。
- `core/crates/bcut-timeline/src/words.rs`：`resolve_word_span(words, first, last, duration, fps, pad_pre, pad_post)`——0.05s 呼吸垫、帧网格外扩、**绝不跨相邻可见词**（跳过 `hidden`），空区间报错。
- `core/crates/bcut-timeline/src/map.rs`：`TimelineProjection::clamp_source_event(src, t0, t1, MIN_EVENT_DURATION)` 把源区间投成一个或多个时间轴片段，跨已剪段就断开。
- `core/crates/bcut-workspace/src/timeline/ops.rs`：`cutRange`（:177）、`cutWords`（:220）、`restoreCut`（:285）；`apply_cleanup_suggestions`（:825）以 `mutate_timeline(project, "cleanup accept", "AI: cleanup", …)` 逐条 `insert_cut` + `record_cut_provenance`；`detect_words`（:958，跳过 `hidden`）、`cleanup_detect_proposals`（:1065）、`make_detect_options`（:971）。`cut list --kind` 的闭合枚举在 :926（`silence | filler | badTake | manual | match`）。
- `ai/cuts.json`：append-only 溯源，`entries[] {id, kind, t0, t1, srcId, reason, detail, origin: detect|cleanup|manual|match, at, wordIds?, afterWord?}` + `params` + `fingerprint`；`restore` 不删条目。这是**开放的** sidecar，加字段不需要 dataVersion。

## 2.2 检测器与 cleanup flow

- `core/crates/bcut-timeline/src/detect.rs`：`detect_silences`（阈值 0.8、压缩到 0.3 / 句末 0.4、`max_gap` 3.0、跨章不剪除非 `trim_chapter_starts`）、`detect_fillers`（`EN_HARD / EN_SOFT / ZH_HARD = [呃, 额] / ZH_SOFT = [那个, 这个, 就是, 然后呢, 对吧, 你知道吧, 反正, 其实]`，软词需标点隔离）、`merge_proposals`（badTake 吞掉被覆盖的 filler）、`skip_already_cut`。**「嗯」不在任何词表里。**
- `core/crates/bcut-flow-core/src/engines/cleanup.rs`：`PAGE_BUDGET 6000`，LLM 只见页内索引 / 文本 / 说话人 / `pauseBefore` / `alreadyCut`，返回 `{"cuts":[{a, b, cat: retake|falseStart|filler, alt?, reason}]}`；`validate_page` 与 `lint_agent_answer` 镜像五条守卫（页内、类目、filler ≤ 6 词、不跨说话人、不与已剪相交）；产物 `CleanupArtifact {fingerprint, strength, suggestions[] {firstWordId, lastWordId, category, alternative?, reason, t0, t1}}`。
- `core/crates/bcut-engine/src/flows/cleanup.rs`：`run_cleanup_cmd` 本地 + LLM → `merge_proposals` → 写 `ai/cleanup.json`；`--review` → `stage_action_review_locked`，否则直接 `apply_cleanup_suggestions`；`changed = ["ai.cleanup", "review.cleanup"|"timeline.cuts"]`，`next = bcut review accept <proj> cleanup`。
- 两个入口的旗标不对称：`bcut cut detect --no-pauses` vs `bcut cleanup --no-silences`；`cleanup` 没有 `--max-gap`（走 `make_detect_options` 的硬编默认）。
- 注意 `polish` 的 `filler` 检查是**破坏性**的（经 rebind 从 `words[]` 删词，`engines/polish.rs:785`），剪口播不得复用它。

## 2.3 审阅事务

`core/crates/bcut-workspace/src/review.rs`：`ACTION_REVIEW_VERSION = 3`；`<proj>/ai/reviews/cleanup.json` = `{reviewVersion, kind, status: pending|accepted|rejected, baseTranscriptSha, baseTimelineSha, createdAt, updatedAt, summary: {suggestions}, artifact}`；`accept_action_review`（:801）校验两份 sha，**任一变化即整份拒绝**，`--items` 零基索引，成功后 `status: accepted` + `applied[]`；`reject` 整份作废。没有协议 `Command`，只有 CLI `bcut review accept|reject`。

## 2.4 写路径、撤销与协议

- `core/crates/bcut-workspace/src/apply.rs::apply_timeline`：`ProjectLock` → `preflight_versions` → `history.sync_from_disk` → `capture_external` → `timeline_revision` CAS（409 stale）→ 逐 op → `TimelineProjection::build` lint → sidecars → `atomic_write` → `record_edit` → `refresh()` → `staleTranslations` 扫描。可见性变更的 op 已含 `cutRange / cutWords / restoreCut`。
- `core/crates/bcut-workspace/src/history.rs`：journal 双栈存**组**（`group` id），`set_edit_group` / `new_group_id`；组内任一文件被外部改动则整组拒绝。
- `core/crates/bcut-editor-core/src/task_undo.rs`：收据撤销**只**从 journal 里的 `AI: <kind>` 条目派生；`--review` 模式不写 timeline，因此今天 review 型 cleanup 的收据没有撤销位。
- `core/crates/bcut-protocol`：`EditChannel::Timeline {ops}` 无类型 JSON op，`cutWords` 不需要新变体；`SPEC_VERSION = "1.58.0"`（`version.rs:112`），新增 `Command` 变体 = minor bump；WS 只有 `doc` / `agent` 两个频道，`doc.changed` 携 `DocDelta`（`set / unset / put / remove` 四种 op）。
- `core/crates/bcut-serve/src/contract_tests.rs` 两道门：端点表 ↔ `router.rs` 派发集合相等；新 handler 只准经 `Kernel::dispatch/query` 走信封，且 `(file, variant)` 要登记进 `KERNEL_API_CALL_SITES`。

## 2.5 `bcut-editor-core` 与 App v2 已有的审阅 UI

- `core/crates/bcut-editor-core/src/review.rs`：`CutProposal {kind silence|filler|badTake, reason, detail, t0, t1, removed_sec, word_ids, early_ids, late_ids, can_flip, keep_later}`、`CutReview {items, filter, cursor}` 及 `visible / current / stats_text / step / toggle_current / item_for_word / span_menu_text / flip_item / accepted_indices`、`cut_review_word_sets(review, words) -> (cut, kept)`、`cut_review_from_suggestions(json)`（retake / falseStart → badTake）、`resolve_command_args`。
- `apps/baocut/src/app/editor/review_bars.rs`：Mac `CutReviewBarView` 的移植——统计 + 筛选 + 上一条 / 下一条 + Keep / Cut + flip + Dismiss all + Apply cuts ⌘↵；`resolve_review` 起 **`bcut review accept` 子进程**。
- `apps/baocut/src/app/editor/timeline/cutseg.rs`：Video 轨上的剪口段 `.cutseg`，只画 `EditorState::cut_review`（待应用的建议，`accepted` 位决定外观），与审阅条共享同一份状态。
- `apps/baocut/src/app/editor/lists/transcript.rs`：:1072 `cut_review_word_sets` 画建议划线，:1082 `edits::cut_word_ids(&editor.derived.cuts, &words)` 画已剪划线。
- `apps/baocut/src/app/editor/mod.rs:1093`：`refresh_reviews` 直接读盘 `engine::review::list` → `AiReview::parse_list`。
- 装载点只有一个：`app/editor/entry.rs:332 write_content` 在项目以 `Ptype::Clean` 打开时把 `pending_cleanup` 交给 `cut_review`（`entry_mode.rs:214` 的 `Entry::Clean` 布局才开 `cut_review / cut_segments`）。从 AI 工具卡随时「再找一遍」之后没有第二条装载路径。
- `lists/transcript.rs:1452 render_body` 已有词级命中（`layout.index_for_position` → `word_index_at_byte_offset`）与词锚定浮层（`word_anchor_rect`），缺的只是按下-移动-松开的**区间累积**与多词高亮样式。
- 两个既有缺陷 / 限制（本方案顺手修与登记）：
  - **`cutseg.rs` 时钟用错**：`prep.scale` 建在 `editor.duration`（时间轴时钟，`EditorState::content_end()`，内核 `TimelineDoc::content_end`；分离文档只看元素 end，见 [product-design §12.0](../../product/product-design/12.md#120-三种文档形态与统一口径2026-09-16)）上，却直接 `scale.x(proposal.t0)` 画源时钟的建议区间；第一刀剪掉之后所有后续建议段都左漂。§5.4 改走 `clamp_source_event`。
  - **gpui 画不了虚线下划线**：`UnderlineStyle` 只有 thickness / color / wavy，文件头已登记「用同色 1pt 实线等价」。见 §8.4 D-C7。
- 已在树上的正确写法：`lists/subtitle.rs::toggle_cut` 用 `edits::cut_range_op / restore_cut_op` 包成 `Mutation::Timeline` 走 `commit_labeled`，一次手势一条历史；`review_bars.rs::apply_cuts` 却绕过 `EditorState::commit` 去起子进程。剪辑模式的手动剪与恢复沿用前者。

也就是说 App v2 已经有「一份建议、全接受或全 Dismiss、Apply 后整批落盘」的 Mac 式审阅，原型第 192 轮的剪辑模式是它的**上位替代**：同一份状态源，换成逐条持久、与手动剪并存、汇总条 + 划线菜单 + 浮动工具条。

## 2.6 Web

- `features/editor/timeline/rows/ClipsRow.tsx` 只在 cut 处画 2px 缝；`TrackArea.tsx` 的叠层只有吸附线与 `Playhead`（唯一逐帧 `Clock` 订阅者，ADR-W07），没有区间高亮与标签层。`ClipsRow` 的 filmstrip 与 cue 投影已经正确走 `timelineToSource / projectTimedItems`，时钟没错。
- `state/timeline.ts` 只有 `splitClipOp / removeClipOp / removeElementOp / elementSpanOp`；wasm 已导出 `cutRangeOp / restoreCutOp / cutWordIds`（`bcut_wasm_editor.d.ts:264/268/298`）但没有 atom 包装。
- `state/optimistic.ts` 的 `DocOverlay` 没有剪口键（只有 `elements` 会碰 `timeline.tracks`），乐观划线无处落。

- serve 全部 `__bcut` 路由里没有 `review`；`GET /__bcut/jobs/<id>/artifact` 只对导出类任务开放。Web 今天拿不到建议，也没有接受路径。
