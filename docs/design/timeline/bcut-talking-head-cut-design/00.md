# 0. 一页概要

> 出自 [BaoCut 剪口播技术方案（原型第 192–197 轮 → 内核 / serve / App v2 / Web）](../bcut-talking-head-cut-design.md)

1. **不新增数据结构，不动 `timeline.json` schema。** 原型 `cuts[]` 里 `state: 'cut'` 的项就是既有的 `sources[].cuts[]`（无损假删除，播放 / 字幕 / 导出 / 六个 NLE writer 已全部折叠它）；`kind / text / why / by / batch` 落在本就开放的 sidecar `ai/cuts.json`。`state: 'suggested'` 的项就是既有的 `ai/reviews/cleanup.json`，本方案把它从「整份 pending / accepted」升级为**逐条状态**并放宽「时间轴一动就整份作废」的门。
2. **手动剪 = 既有 `cutWords` op，AI 建议接受 = 既有 `apply_cleanup_suggestions`。** 呼吸垫、帧对齐、不跨相邻可见词、0.02s 合并、`clip-empty-after-cuts` lint 全部现成。
3. **建议与手动剪并存**靠两条规则：接受时逐条对当前 `CutSet` 做重叠校验而不是比对整份 `baseTimelineSha`；已接受的建议若其 `cutId` 在 `cuts[]` 里消失（⌘Z 或恢复），读取时回到待定态。
4. **写路径统一到协议。** 新增 `Command::Review`（`specVersion` 1.58.0 → 1.59.0，minor），serve 出 `GET /__bcut/reviews` 与 `POST /__bcut/review/apply`；App v2 的 `resolve_review` 从起 `bcut review accept` 子进程改成 `Kernel::dispatch`，Web 第一次拿到审阅写路径。
5. **两端只画，不算。** 字 token 化、标记派生、选区 → WordSpan → 时间轴片段与时码标签、汇总条三态文案、浮动工具条状态机、键位谓词全部进 `bcut-editor-core::cut_mode` 并经 wasm 暴露，`core/fixtures/editor/cuts.json` 三层对拍。
6. **时间轴上已剪的段折叠成缝标记，不像原型那样原位画斜纹**——这是内核既有语义（§2.3 三层时间域），也是 Descript 的做法；建议段仍原位画虚线（它没生效，时间还在）。分歧登记进原型台账。
