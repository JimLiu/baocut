# 3. 关键裁决

> 出自 [BaoCut 剪口播技术方案（原型第 192–197 轮 → 内核 / serve / App v2 / Web）](../bcut-talking-head-cut-design.md)

| # | 裁决 | 依据 / 代价 |
|---|---|---|
| C1 | **已剪真相 = `sources[].cuts[]`，属性进 `ai/cuts.json`，不新增顶层表。** | `timeline.json` 顶层封闭；`cuts[]` 已被播放、字幕投影、章节、导出、六 writer 折叠；`ai/cuts.json` 开放且已带 `kind / reason / wordIds / origin`。原型 `by / batch / text` 各有落点（§4.1）。 |
| C2 | **建议真相 = `ai/reviews/cleanup.json`，reviewVersion 3 → 5（4 已被 chapters 覆盖层占用），条目带 `state`。** 不把建议写进 `timeline.json`。 | 建议「接受前不影响播放与导出」正是「不进 timeline」；App v2 与 `bcut-editor-core::review` 已读这份文件；不动 `TIMELINE_CURRENT`。 |
| C3 | **接受门从「整份 `baseTimelineSha`」改为「逐条对当前 `CutSet` 重叠校验」；transcript 门改为 `fingerprint(words)` 内容指纹。** | 手动剪一刀不能让 9 条建议全作废；建议引用的是词 id + 源时间，只要词还在、时间没变就有效。重叠者进 `skipped[]`（原因 `already-cut`），HTTP 200，与 `timeline/apply` 的 `skipped` 口径一致。 |
| C4 | **撤销后的建议态派生，不存**：`state: accepted` 且其 `cutId` 不在 `cuts[]` → 读取时视为 `pending`。 | ⌘Z 撤回接受、`restoreCut` 恢复、外部进程 `cut restore` 三条路都会让 cut 消失，读时派生比每条路都去改审阅文件可靠；也保证 journal 只追踪 `timeline.json`。 |
| C5 | **手动剪 = `cutWords`；建议接受 = `apply_cleanup_suggestions`（`cutRange` 语义）。** 不新增 `timeline/apply` op。 | 停顿建议的 `t0/t1` 已含压缩后保留的头尾（`detect_silences`），必须按范围剪；词建议已在生成时经 WordSpan 落定。 |
| C6 | **审阅写路径进协议：`Command::Review {project, kind, action, items, batch}`，specVersion 1.58.0 → 1.59.0。** App v2 从子进程改 `Kernel::dispatch`，Web 经 serve。 | ADR-4 内核常驻优先；contract_tests 要求新 handler 走信封；一次接受 = 一条 journal 组。 |
| C7 | **时间轴：已剪段折叠成缝标记；建议段原位虚线。** | 三层时间域是内核契约（视图时间 = 源时间折叠 cuts），播放 / 字幕 / 导出都按它走，UI 不能另立一套「原位斜纹」的时钟。缝标记带 `−0.8s` 角标、点击 = 恢复，仍满足「看得见、点得回」。原型分歧登记 §8.4。 |
| C8 | **类目分两层**：溯源 `kind` 仍是闭合的 `silence|filler|badTake|manual|match`（`1.291.0` 起多 `offScript`：`cut script` 剪掉的稿外话，见[口播成片方案稿 §5.1](../../video/bcut-talking-film-design/05.md#51-按稿预剪)）；细类 `category: filler|pause|retake|falseStart|repeat` 写在 `ai/cuts.json` 与审阅条目上，UI 文案按细类。 | 不动 `ops.rs:926` 与 lint 规则；LLM 新增 `repeat` 类目映射到 `badTake`。 |
| C9 | **cleanup 的增量语义**：新一轮扫描替换所有 `pending` 条目，保留 `accepted / dismissed` 条目的记录，`skip_already_cut` 跳过与已剪重叠的提案。 | 与原型 §12.6「新一轮扫描替换未处理的建议，已剪的不动」一致；`dismissed` 保留是为了不把用户已否决的同一处再提一次（按 `firstWordId..lastWordId` 去重）。 |
| C10 | **剪辑模式的全部判据进 `bcut-editor-core::cut_mode`，经 wasm 暴露，fixture 对拍。** | 与交互移植方案同一分层；两端不得各算一遍时码。 |
| C11 | **收据撤销（review 型）= 整批 `pending` 条目 → `dismissed`，重做 = 回 `pending`；已接受的剪辑不受影响。** | 原型 §15.3 明文；journal 不追踪审阅文件，这条撤销走 `Command::Review` 而不是 `history undo`。 |
| C12 | **不引入「实验项目」内核概念。** | 任意无元素项目即是；差异只在空态文案与向导预设（§8.4）。 |
