# 1. 目标与范围

> 出自 [BaoCut 剪口播技术方案（原型第 192–197 轮 → 内核 / serve / App v2 / Web）](../bcut-talking-head-cut-design.md)

## 1.1 原型需求 → 现有能力 / 缺口

| # | 原型要求（§12.6 / §13.1 / §15.3） | 现有能力 | 缺口 |
|---|---|---|---|
| R1 | AI / Agent 扫描口癖、停顿、重复起句写成建议，接受前不影响播放和导出 | `bcut cleanup --review` 把本地检测 + LLM 建议写进 `ai/cleanup.json` 与 `ai/reviews/cleanup.json`，不碰 timeline | 建议是整份 `pending`，无逐条状态；LLM 类目无「重复」 |
| R2 | 逐条接受 / 忽略、整批接受 / 忽略 | `bcut review accept <proj> cleanup --items i,j`（零基索引）/ `reject` | 一次 accept 后整份变 `accepted`，剩下的条目没有「仍待定」态；忽略只能整份 |
| R3 | 建议与手动剪并存；新扫描替换未处理的建议、已剪的不动、与已剪重叠的跳过 | `skip_already_cut(proposals, &CutSet)` 生成时已跳过已剪 | `accept_action_review` 比对 `baseTimelineSha`，手动剪一刀后整份建议被拒 |
| R4 | 文稿拖选一段字按 ⌫ 剪掉 | `cutWords {srcId, first, last}` op + `resolve_word_span` | 两端都没有字级拖选与剪辑模式 UI |
| R5 | 已剪的字划掉、点一下恢复；已剪段在时间轴可见 | App v2 `lists/transcript.rs` 已按 `derived.cuts` 画删除线；`restoreCut` op | 时间轴折叠后已剪段不可见；Web 无标记 |
| R6 | 每一步 toast + 撤销；任务收据撤销 = 整批建议撤走 | journal 组撤销；`AI: cleanup` 标签驱动 `task_undo` | `--review` 模式不写 journal，收据撤销无从挂；⌘Z 撤回接受后审阅文件状态与 `cuts[]` 脱节 |
| R7 | 文稿选区同步画到时间轴并标「1.9s · 00:07.1 – 00:09.1」 | `TimelineMap::clamp_source_event` 可把源区间映射成时间轴片段 | 没有选区真相、没有折算、没有标签文案 |
| R8 | 选区上方浮动工具条：时长 + 起止时码 / 剪掉 ⌫ / 试听 / 取消 Esc | — | 全无 |
| R9 | 试听一处（前后各留 0.6s / 0.4s） | App v2 悬停预览 once 窗口 | 需要绕过折叠、按源时钟播一段 |
| R10 | 剪辑实验项目：没有任何元素，不预埋建议 | 任意无元素项目即是 | 只差空态文案；不需要内核概念 |

## 1.2 共享 / 自理的划线

沿用 [`bcut-editor-interaction-port-design.md`](../bcut-editor-interaction-port-design.md) §2.1 的三条红线：凡「同一份输入必须得出同一个结论」的判据进 `bcut-editor-core`，视图只留平台惯例。本方案里进核心的是：token 切分、标记派生、选区几何与时码文案、汇总条文案、工具条状态机、键位谓词、试听窗口、撤销后的建议态派生；留给视图的是：拖选命中、浮层定位、GPUI / DOM 绘制、播放器控制。

## 1.3 不在范围

- 不改 `timeline.json` 顶层字段与 `Cut {id, t0, t1, ref}` 形状；不改 `transcript.json` 与 `words[]`（剪切从不触碰词，见 [`bcut-edit-domain-design.md`](../../cli/bcut-edit-domain-design.md) §1.3）。
- 不做 clip 层（`splitClip / removeClip`）的联动改造；剪口播只在媒体层 `cuts[]` 工作，隐式单 clip 即可。
- 导出侧剪缝淡入淡出只做每缝两侧各 `--seam-fade-ms`（默认 10ms）的线性斜坡，不做交叉淡化（不改成片时长；§11 已裁决）。
- `skills/baocut/templates/studio` 已退役，不适用。
