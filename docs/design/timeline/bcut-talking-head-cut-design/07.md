# 7. 写路径与协议

> 出自 [BaoCut 剪口播技术方案（原型第 192–197 轮 → 内核 / serve / App v2 / Web）](../bcut-talking-head-cut-design.md)

## 7.1 手动剪与恢复：复用 `timeline/apply`

- 剪选区：`POST /<id>/__bcut/timeline/apply {baseRev, label: "剪掉 1.9s", ops: [{kind: "cutWords", srcId, first, last}]}`；响应的 `applied[]` 里带 `cutId`、`snapped: true`，`staleTranslations` 照旧。
- 恢复：`[{kind: "restoreCut", cutId}]`；全部恢复 = 一批 op。
- 改剪掉的范围（`1.303.0` 起；展开态拖空槽带左 / 右边缘）：`[{kind: "retimeCut", cutId, srcId?, t0, t1}]`（源时钟秒）——剪口原地改区间，`id` / `ref` 与 `ai/cuts.json` 的来源类别保留（溯源条目只改 `t0` / `t1`），元素按 `ClockEdit::Retime` 以当前成片为基准跟随（主视频画面与先 `restoreCut` 再 `cutRange` 相同；数字时间叠加元素的起止落进新剪掉的范围时按当前成片收，不先撑回恢复后的样子，可能与先恢复再剪不同），一步撤销；与同源其它剪口重叠 `invalid_arg`（贴边可以），区间没变时批次 `unchanged`。撤销只退 `timeline.json`，溯源侧车不进 journal（与 `cutRange` 写溯源同一局限，读溯源按 id 关联，不影响显示）。
- 溯源：`cutWords / cutRange` 写 `ai/cuts.json` 时补 `via`（服务端从请求头 / 调用方推断：serve 请求 → `app`，CLI → `cli` / `agent`）。
- `DocDelta`：`doc.changed` 已推 `timeline` 的 `put/remove`；`GET /__bcut/doc` 的 `timeline` 投影已含 `views[srcId].cuts` 与 `keptSpans`（投影字段名是 `views`，文件里是 `sources`），两端据此重算 `CutMarks`，不需要新字段。

## 7.2 审阅：`Command::Review`

```rust
// bcut-protocol/src/command.rs
Command::Review { project: PathBuf, kind: String /* cleanup | broll | … */,
                  #[serde(flatten)] action: ReviewAction }
#[serde(tag = "action", rename_all = "kebab-case")]
pub enum ReviewAction { Accept { items: Vec<String> }, Dismiss { items: Vec<String> },
                        Restore { items: Vec<String> } /* dismissed → pending */,
                        AcceptAll, DismissAll { batch: Option<String> }, RestoreAll { batch: Option<String> } }
pub struct ReviewApplied { rev, doc_rev, seq: Option<u64>, applied: Vec<ReviewItemResult>, skipped: Vec<ReviewItemResult /* reason: already-cut | orphan-word | not-pending */>, review: Value /* 写回后的文件 */, can_undo, can_redo }
```

- `items` 用 v4 的稳定 `id`（`sug-<n>`），不再用零基索引；CLI `bcut review accept --items` 同时接受两种写法（数字 = 索引，兼容 skill 文档）。
- 内核 `dispatch_inner` 新臂 → `bcut_workspace::review::apply_review(project, history, kind, action)`：`ProjectLock` → 读 v4（或升级 v3）→ 逐条 `effective_state` → `accept` 的条目经 `apply_cleanup_suggestions`（一条 journal 条目，标签 `AI: cleanup`，`set_edit_group` 同组）→ 写回审阅文件 → 返回。
- argv 投影：`review accept|reject|restore <project> <kind> [--items …] [--all] [--batch …]`；`bcut review reject` 改为逐条 `dismiss` 语义（不带 `--items` = `DismissAll`）。
- serve 端点（登记 `serve_contract.rs` + `router.rs` 派发 + `contract_tests.rs::KERNEL_API_CALL_SITES`）：
  - `project.reviews`：`GET /<id>/__bcut/reviews` → `Query::Reviews {project}` → `AiReview::parse_list` 的输入（全部 kind 的文件）。
  - `project.review-apply`：`POST /<id>/__bcut/review/apply` → `Command::Review`。
- `SPEC_VERSION` 1.58.0 → 1.59.0（新增 Command/Query 变体，minor），`version.rs` changelog 一行，`docs/generated/*` 重生成，`docs/design/cli/bcut-cli-server-reference.md` 手写同步，`skills/baocut/references/editing.md` 补 `review` 用法。`requireSpec` 区间 `>=1.31,<2.0` 不需要动。

## 7.3 App v2 的写路径切换

`apps/baocut/src/app/editor/review_bars.rs::resolve_review` 与 `app/mod.rs::refresh_reviews` 从 `engine::review::list` + 子进程改为 `Kernel::query(Query::Reviews)` / `Kernel::dispatch(Command::Review)`，回执经既有 `AppStore` 回执通道（`app/mod.rs:393`）。子进程路径删除，不留双写。

## 7.4 撤销

| 动作 | 写入 | 撤销机制 |
|---|---|---|
| 剪选区 / 恢复一段 / 全部恢复 | `timeline.json` 一条 journal 条目 | 编辑器 ⌘Z = `history undo`；toast 撤销同源 |
| 接受一条 / 全部接受 | `timeline.json` + `ai/cuts.json`（sidecar 随 timeline 同事务）+ 审阅文件 | ⌘Z 撤回 timeline；审阅条目按 C4 派生回 `pending`，不需要第二条撤销 |
| 忽略一条 / 忽略全部 | 仅审阅文件 | 汇总条 toast「已忽略这一条建议 · 撤销」= `Review::Restore {items}`；不进 journal，不占 ⌘Z 栈（原型分歧 D-C2） |
| 任务收据（review 型 cleanup） | — | 撤销 = `DismissAll {batch}`，重做 = `RestoreAll {batch}`；`task_undo` 对 `review.cleanup` 型任务改读审阅文件而非 journal，状态 = 该 batch 下是否还有 `pending`（`Undoable` ↔ 有；`Undone` ↔ 全 dismissed；全 accepted → `Hidden`） |
| 任务收据（直接应用型 cleanup） | `timeline.json`（`AI: cleanup`） | 不变 |

## 7.5 跨客户端同步

- 同一 serve 下的 Web 与 App：`timeline` 变更走 `doc.changed`；审阅文件变更由内核在 `Command::Review` / cleanup 任务结束时推一帧 **`Event::ReviewChanged {project, kind}`**（`Event` 枚举带 `#[serde(other)] Unknown`，老客户端忽略；仍是 minor）。WS `doc` 频道复用，不新开频道。
- 外部进程（`bcut cleanup --review` 不经内核）：与今天的 `timeline.json` 外部改动同一处理——App v2 的文件层监听（`reload_banner`）已覆盖 `ai/reviews/`，Web 由任务完成帧触发重拉 `GET /__bcut/reviews`。
