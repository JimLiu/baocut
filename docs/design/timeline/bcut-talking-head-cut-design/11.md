- 不新增 `timeline/apply` op、不新增 transcript 覆盖表、不 bump `TIMELINE_CURRENT / TRANSCRIPT_CURRENT`。
- ~~不做「展开已剪段」（Descript 的 Show deleted）开关；缝标记 hover 已能看见剪了什么。若用户反馈需要，作为 P5 单独立项。~~ **已被第 197 轮推翻**（2026-09-07）：用户要求默认折叠、由 transport 开关撑开成空槽带；`cut_mode::fold_view(expanded)` 与 App v2 `BCUT_GPUI_CUTS_EXPANDED` 已落地，Web 待补（§15）。**第 200 轮再收口**（2026-09-07）：独立的「展开已剪段」开关退役，展开 = transport 全局「剪辑」开关（`expanded = cut.active`），关着时时间轴不画任何已剪 / 建议痕迹（缝标记撤）；`BCUT_GPUI_CUTS_EXPANDED=1` 留作 `BCUT_GPUI_CUT_MODE=1` 的别名。
- 不给译文做自动跟剪：原文被剪切的译文只标 `staleReason: cut`，由 `bcut translate --only-stale --after-cut`（隐含 `--only-stale`，项目须带 `timeline.json`）成批重译；投影 stale 现算不落盘，所以**所有编辑写路径的投影必须带 `check`**（`bcut-workspace::apply::edit_projection`，`e318281e8` 修掉 App 剪切后 stale 被抹掉的缺陷）。

- 不做 clip 层与剪口的联动（split 已剪段等）；`clip-empty-after-cuts` lint 兜底。
- 不为 Agent 会话的 `bcut cleanup --review` 做收据组撤销的特殊处理：它不写 journal，收据撤销按 §7.4 走 `DismissAll {batch}`。

**开放问题**

1. **剪缝音频**（已裁决，2026-09-07）：导出参数 `--seam-fade-ms`（协议 `ExportOptions.seamFadeMs`）默认 **10**，`0` = 硬拼接。实现是每处缝两侧各做一段线性淡出 / 淡入（头段不淡入、尾段不淡出、单段无缝），**不是**交叉淡化——交叉淡化要各段多取 fade 长的源素材，会改成片时长与字幕 / 元素时钟；10ms 的直流跳变抑制足够消掉咔哒，人声上听不出电平坑。淡化长度夹到段长一半。`ffmpeg` 后端在段音频链插 `afade`，`native` 后端在 `write_mix` 拷完样本后对该 slot 的 PCM 斜坡，两者同读 `AssemblyPlan::seam_fades`。未做：真实素材的对比试听（只有单测），默认值若要改只动 `DEFAULT_SEAM_FADE_MS`。
2. **LLM `repeat` 的召回与误报**：提示词改动需跑 `core/fixtures/launch-golden/` 的口播样本对比 conservative / standard / tight 三档的接受率；若 `repeat` 误报高，默认只在 `tight` 档启用。
3. **超大项目的 token 视图**：七小时 transcript 约 6–8 万 token，GPUI 的 `div` 流式布局按段落虚拟化是否够用，P2 用 `core/fixtures/` 的 7h fixture 实测帧时间；不够则退到按 cue 行布局。
4. **多源项目**：`cutWords` 已带 `srcId`，但剪辑模式的 token 视图默认只铺 `main`；多源口播（多机位）的建议与选区如何落到非 main 源，本轮不解，UI 只对 `main` 开放剪辑态。
5. **`bcut review reject` 语义变更**（整份作废 → 逐条 `dismiss`）对既有 skill 文档与 Mac 1.x 归档表面无影响，但 `broll` 仍走 v3 整份语义，两 kind 分叉需在 `review.rs` 明示。
