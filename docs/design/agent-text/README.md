## 需求与现状

用户已经在「Agent 提供方」配置并登录 Agent，希望文本工具复用该账号，避免再注册 API 平台、填写密钥。需求有明确的使用价值，属于新增能力；报告未包含运行失败或特定 Driver 的复现。

当前文本工具经 `models.generateText` 调用在线 API，任务与进程内翻译共用 `TextRunner`。`AgentProviderSource` 只有 `agent:codex` 的 `generateImage`，没有文本执行者。普通 Agent 会话可以写作，但其上下文、工具权限、输出与生命周期不等同于固定文本任务。参考[架构 §6.1](../../architecture/architecture-design.md#61-能力--来源)及[§6.9](../../architecture/architecture-design.md#69-智能体作为-provider)。

## 原型方案

入口为原型 `/#/tools/text`。保留要求、可选 Space 文档／字幕、保存位置、生成记录和文档结果操作，在要求之前增加「生成方式」：

- **模型 API**：保留现有模型选择与行为。打开工具时默认仍为这一项，避免自动改变外发接收方；选择只记在文本工具草稿里。
- **已登录 Agent**：先展示 Codex CLI、Claude Code 两个候选，读取原型的公共 Agent 连接状态，使用所选 Agent 自己的默认模型。无需另填 API key；不修改会话的全局默认 Agent、文本 API 默认模型或翻译流程。

Agent 模式只发一次要求与附上的材料，拟以一份文本结果结束，沿用文档保存与 Space 结果操作。它不是打开完整创作会话、让 Agent 在项目里执行任意工具。界面明确展示接收方与账号费用含义：命令在这台电脑上运行，要求和材料仍可能发给 Agent 账号的服务方；订阅登录不等于本地推理或免费调用。

这是产品入口提案，原型中的 `textRequest` 只描述模拟输入，不是新的 Runtime DTO。原型结果带有示例标记，没有真实文本生成质量或沙箱保证。

## 状态与失败

- 未安装、未登录、停用或启动异常：允许查看并选中，但主按钮说明原因，提供「管理 Agent…」；不悄悄换到另一个 Agent 或付费 API。
- 生成要求为空、要求与材料合计超过现有 16,000 字符上限：拒绝提交；切换来源不清空要求和材料。
- 模拟运行、完成、取消与结果操作沿用文本工具原有演示。取消不发布结果。
- 没有候选 Agent 时保留设置入口与不可用原因。真实接入后，排队期间的退出登录、停用、取消、超时、限额和空输出必须各自有可理解的错误；原型不把这些未知状态演成真实成功。

## 确认后的实现边界

先逐一验证 Codex CLI 与 Claude Code 的一次受限文本调用，再开放对应 Driver；其他 Agent 按同样的合同独立验证后加入。已配置普通会话不自动证明可提供文本服务。

- 复用已有 Driver 的机器协议；独立、短生命周期的调用，不恢复用户会话，不带视频上下文、MCP 服务、项目路径或工具权限。不能靠提示词保证隔离：实际 Driver 必须能拒绝不必要的文件、命令与网络工具；做不到的 Driver 不开放。
- 明确消息顺序、系统要求、纯文本输出、输出上限、取消、超时、进程关闭、并发队列和错误合同。不将思考片段、工具日志或中间回复直接拼成最终输出，不自动重试可能重复计费的 Agent 回合。
- 登录／安装由已有设置负责，不读取、复制或导出原生账号凭据。API key 登录的 Agent 也可能收费，不能笼统登记为订阅内；用量未知时如实记录未知。
- 授权、用量与保存使用现有 Runtime 权威路径，提交前说明要求与材料的接收方。模型 API 的全局默认、结构化翻译与对外模型服务先保持现状；若后续要把 Agent 放进全局 `generateText` Provider 列表，另行定义 JSON Schema、预算和批量翻译等消费者的合同。
- Windows 与 macOS 分别验证可执行文件解析、参数传递、进程取消与隔离；Web 实现按当前能力范围审计，不能把原型的 Web 无 AI 入口当作真实共享 UI 的能力判断。

## 规格差异与验收

[产品 §2.7](../../product/product-design.md#27-工具)及[架构 §6.1](../../architecture/architecture-design.md#61-能力--来源)目前将独立文本工具定义为一次模型 API 请求，不创建 Agent 会话；[§6.9](../../architecture/architecture-design.md#69-智能体作为-provider)首版只开放 Codex 生图。本提案增加专用 Agent 文本调用，**尚未修改上述正式合同**。确认后应在同一实施任务同步对应规范、实现与测试。

原型验收：模型 API／Agent 切换保留输入；已连接 Agent 在未配置 API 时可模拟提交；未就绪 Agent 阻止提交且不自动换来源；成功结果明确标为示例并可在 Space 查看；键盘能操作来源单选组与 Agent 选择；原有 API 流程仍可用。执行原型的构建、模型／生成物测试、设计系统检查与 HTTP 页面检查，结果在 PR 中报告。

真实验收须另覆盖：无凭据／无网络的假 Driver 生命周期测试、消息与最终结果抽取、工具拒绝、账号状态变化、取消／超时／崩溃收尾、重复提交、费用记录、材料外发授权、文档发布，以及经用户明确授权的各 Driver／平台真实调用。原型通过不代表这些验收通过。
