# 轻量编辑器：设计稿

状态：方案稿（2026-10-19），待用户确认后再改实现与规范。

轻量编辑器是同一个视频编辑器的另一种视图：画面居中，底下是按段分格的进度条，右边是当前段的脚本与逐句台词，画面上可以直接画标记发给会话。它面向「看一遍、指出哪里要改」的人：智能体生成的讲解片要审一遍、转写或翻译好的口播要对一遍，这些人不需要时间线、检查器与分轨。时间线视图仍在，顶栏一键切换，两边共用一份视频与一份观看态。本文只写在[产品设计 §5](../../product/product-design.md#5-编辑器) 与[章节化代码动画片](../motion-video/motion-video-design.md)之上增加什么；已有的字段与合同按章节号引用，不重复。原型在 `designs/baocut`（`app/model-lite.js`、`app/editor-lite.jsx`、标记工具 `app/model-markup.js` / `app/stage-markup.jsx`、`app/data.js` 的 `p15`）。

## 1. 问题与目标

### 1.1 现状

- 编辑器只有一种视图（产品设计 §5.1）：预览、检查器、时间线、内容面板。创作、审阅、精修是同一视图的三种布局（§5.2），差别只在哪块先展开，时间线与检查器始终在。
- 讲解片（动画片设计 §2）一章一个代码包、一段旁白、一份脚本；审一遍的人想知道「这一场说了什么、画面对不对、哪句要改」，这些在章节页（§5.1）里能看到，但章节页在内容面板，与画面隔着时间线。
- 转写或翻译好的视频，文稿页能逐句跟随，画面上的标注（§5.3）能发给智能体，但两者分在两个面板，标注只带时刻，不带「第几章第几句」。
- 给外行看的入口（会话里打开生成的视频、Space 里点开一部片）落到完整编辑器，第一眼是时间线与分轨。

### 1.2 目标

| # | 要求 | 本文的回答 |
| --- | --- | --- |
| 1 | 画面 + 底部播放器，进度条按段分格，右侧可收起的脚本与逐句，图层开关 | 轻量视图的布局（§3） |
| 2 | 每段的素材（图、文字、代码包、旁白）可列出；脚本显示是否复用协作文档编辑器 | 侧栏的素材折叠（§3.3）；不复用，用 Markdown 只读渲染（§7） |
| 3 | 画面上的标记工具（选择元素 / 评论 / 画笔 / 形状 / 文字，颜色与粗细，撤销）带时间戳整组发到会话输入框 | 沿用视频标注，补五种种类、样式、元素与截图字段、段落落点（§4） |
| 4 | 顶栏「轻量 / 时间线」切换，共用同一份视频文档，说明哪些状态保留 | §5 |
| 5 | 「段」统一场景（智能体视频）与章节（转写、翻译视频），说明数据来源与兜底 | §2 |
| 6 | 默认打开规则，专业用户怎么切回与记住偏好 | §6 |

不做的：轻量视图不是第四种布局，也不是新的编辑器。它不改视频（只改观看态与偏好），不做脚本编辑（改脚本仍在章节页或交给智能体），不做分轨与裁剪。

## 2. 段：一种抽象，四种来源

### 2.1 段是什么

段（segment）是轻量视图的基本单位：进度条的一格、侧栏的一页、标注的落点。一段有：

| 字段 | 含义 |
| --- | --- |
| `id` | 来源对象的 ID（场景 ID、章节 Marker ID）；旁白分段与整条由视图按位置生成（`speech-3`、`whole`），不进视频 |
| `kind` | 来源：`scene`（场景）、`chapter`（章节）、`speech`（旁白分段）、`whole`（整条） |
| `index`、`title` | 序号与标题；没有标题时按来源起名（「第 3 段」、「0:42–1:08」） |
| `start`、`end` | 时间线上的绝对秒数，段与段相接、不重叠 |
| `status` | 只有场景有：计划中 / 已配音 / 已生成 / 过期，过期带哪一层（动画片设计 §2.2 的 `stale`、§2.4） |
| `script` | 脚本 Markdown，只有场景有 |
| `lines[]` | 逐句：`{id, start, end, text, trans?}`，时间是绝对秒数，有译文时带译文 |
| `assets[]` | 这一段用到的素材：`{kind: bundle \| audio \| footage \| image, label, at?, src?}` |

原型：`app/model-lite.js` 的 `segments()` 与 `segmentAt()` / `lineAt()`。

### 2.2 四种来源与兜底顺序

按下表从上往下取，命中第一个就用，不混用：

| 优先 | 来源 | 什么视频 | 段 | 逐句 | 素材 |
| --- | --- | --- | --- | --- | --- |
| 1 | 章节表的场景（动画片设计 §2） | 智能体生成的讲解片、MV | 一章一段；`status`、`script` 来自章节表 | 章节的旁白对齐结果（词级时间按句合并）；没有对齐时用旁白音频的转写 | 代码包（名字与版本）、旁白音频、参考图、章内 footage 实例 |
| 2 | 序列上的 `chapter` Marker（视频格式规范 §3.13） | 转写、翻译、带章节的口播 | 一个 Marker 到下一个 Marker 为一段；最后一段到片尾 | 这一段时间范围内的字幕句（有译文轨时带译文） | 这一段时间范围内的图片、视频与音频实例 |
| 3 | 按停顿分组的字幕句 | 有转写但没有章节的视频 | 相邻两句间隔 ≥ 1.8 s 或累计 ≥ 60 s 时断开；段名取首句前几个字 | 组内的句 | 同上 |
| 4 | 整条 | 没有转写也没有章节的视频 | 一段，标题是视频名 | 空；侧栏提示「转写后这里会列出台词」 | 全部实例 |

旁白分段的两个阈值进用户偏好，不进视频：换阈值不改视频，也不算修改。转写进行中按第 4 种显示，转写完成后重算，段条就地变成分组。

### 2.3 当前段与当前句

- 当前段：播放头 `t` 满足 `start ≤ t < end` 的段；最后一段含 `end`。
- 当前句：这一段里 `start ≤ t` 的最后一句——句与句之间的空隙算前一句（字幕的 tail 还显示着）；段开头到第一句之前没有当前句。
- 点一段：点的不是当前段就跳到它的开头；点的是当前段，按点的位置换算时间（当前段的格就是这一段的进度条）。
- 上一段 / 下一段：跳到上一段或下一段的开头，与全屏播放器的「上一章 / 下一章」同一语义（产品设计 §5.3）。

### 2.4 变化时怎么办

段是从视频派生的，不单独存。视频改了（智能体重做一章、章节 Marker 挪了、字幕重切）就重算；播放头不动、选中的段按 ID 找回，找不到时落到播放头所在的段。场景过期时段条与侧栏头部都标出来（§3.3），不阻止播放。

```

│ │                  播放画面                    │ │ 倒着为什么不掉          │ │

│ │   [标记工具条，标记时浮在画面底上]           │ │ ▾ 脚本（Markdown）      │ │
│ │   选元素 评论 画笔 形状▾ T｜●▾ ━▾｜↶ ↷ 🗑｜发送 × │ │ 旁白 · 6 句 — 当前句高亮 │ │

│ ┆                                   ▲ 播放头：一根线穿过当前片            ┆  │
```

### 3.1 画面

就是时间线视图的舞台（`stage.jsx`）：同一份画布、同一个播放器、同一套字幕渲染与实时合成层（产品设计 §5.3）。差别只有两点：不画时间线视图的点选层（选元素是标记模式里「选择元素」工具的事，§4.1），舞台下沿的工具条只保留右端那一组——标记（§4）、音量（点开弹层：静音 + 音量杆，与时间线一样）、全屏、脚本侧栏开关；左端的画幅、倍速归时间线视图（倍速在全屏播放器里仍能调），字幕显隐见 §3.4。工具条的几何、底色与时间线视图同一条。画面的提示（「实时预览，导出前要烘焙」）照旧。

### 3.2 播放条与片条

- 章节进度条：播放条上面一条，就是时间线视图顶上的那一条（`timeline.jsx` 的 `ChapterBand`）：按段分格、当前段实心，悬停浮出那一刻的画面、时码与段名，点一下跳过去；段就是 §2 的段。
- 播放条：左边是播放 / 暂停、从头开始、循环（只是这个窗口的观看态，不进视频）、时钟（`1:10 / 3:26`，分不补零、秒不带小数；悬停在片条上时先显示那一刻，淡一度）。右边是片条的缩放（下一条），与时间线视图播放条右端同一组。音量、全屏、侧栏开关在舞台工具条上（§3.1）。全屏播放器与时间线视图共用（产品设计 §5.3）。上一段 / 下一段不占按钮，点片即跳。
- 片条：一段一片，片宽按时长比例、片之间留空隙，片上只写名字（窄了省略，再窄只剩一块色）；当前片灰得更深。播放头是一根穿过当前片、上下各伸出一点的线，底下带小把手。悬停显示该片的完整标题、时间范围、时长与第一句台词；悬停处画一根细线预览。
- 在片上按下并拖是拖播放头（scrub），松手停在那里；点一下跳到那一刻；键盘 Enter / Space 跳到片头。
- **缩放**：默认整条铺满播放条的宽度（100%），场景多了片会挤成一块色，所以播放条右端是 缩小 · 百分比 · 放大（每档 ×1.5，最大 800%），写法与时间线视图的缩放一样；点百分比弹出菜单：放大、缩小、铺满 · 100%、适应当前段（当前段撑满视野、段头贴左边）、缩放到播放头（播放头居中；铺满时先放大一档）。⌘ / Ctrl + 滚轮（触控板捏合）围绕指针连续缩放。放大后横向滚动，播放头出了视野就滚过去让它落在视野 1/3 处（拖播放头时不抢）。缩放是这个窗口的观看态，不进视频、不进偏好。菜单不标 ⌘= / ⌘− 快捷键：那组键今天归时间线的缩放（§11 第 10 条）。
- **拖片的右边改时长**。两种段两种语义：
  - 场景（讲解片）：拖的是这一场的 `duration`（动画片设计 §3.1：归属改为 `user`，画面要按新长度重做），后面的场景整体推开，总长跟着变。不能短过旁白末句 + tail（§2.3 的 0.4 s）；没有旁白的最短 1 秒。字幕 cue 随边界之后的部分一起平移。
  - 章节（章节表）：拖的是与下一章的边界，总长不变，两边各至少留 1 秒；末章的右边是片尾，没有把手。
  - 旁白分段与整条一段没有把手（它们是派生的，没有可改的时长）。
  - 拖的时候把手上方浮出新时长与增减量（`54s +14.3s`），预览按同一套最短 / 最长规则夹住，松手才生效。松手后 toast 报结果并带「撤销」；也进编辑器的撤销栈。把手可聚焦，← / → 各 1 秒，⇧ 各 0.1 秒。
- 键盘：Space 播放，← / → 跳 5 秒，⇧← / ⇧→ 上一段 / 下一段，与全屏播放器一致；删除等编辑快捷键在轻量视图里不生效。⌘Z / ⇧⌘Z 在轻量视图里只归开着的标记层（§4.1）；拖边界的撤销走提示上的「撤销」钮，那一步也进编辑器的撤销栈，切到时间线视图能 ⌘Z 回去。

原型：`app/editor-lite.jsx` 的 `LiteTransport`、`LiteSegBar`、`LiteStageBar`；片的几何与拖边预览在 `model-lite.js` 的 `chipSpans()`，时长规则在 `retimeScene()` / `moveChapterBoundary()` / `resizeBounds()`，缩放的档位、标签与菜单在 `zoomIn()` / `zoomOut()` / `zoomLabel()` / `fitZoom()` / `ZOOM_MENU`。

### 3.3 侧栏

默认展开，用户收起后记住（偏好 `liteSide`）。从上往下：

- 头部：「场景 3 / 7 · 章节表」（来源与序号）、标题、时间范围与时长；场景过期时一枚「过期 · 脚本」徽章。
- 脚本（折叠，默认开）：场景的脚本 Markdown 只读渲染（§7）；没有脚本的来源不显示这一节。
- 台词：按来源叫「旁白」或「字幕」，一行一句，序号、正文、译文（有的话）、起始时码；当前句高亮并滚进视野，点一句把播放头放到句首。没有句子时一句提示。
- 素材（折叠，默认关）：这一段的素材列表，每条一个图标、名字与说明（代码包名与版本、旁白时长、实拍片段的来源与入点、参考图），右侧「跳到」把播放头放到它出现的时刻；只列、只跳，不做替换与编辑。

### 3.4 图层开关

一组开关，**按这部视频实有的轨道生成**，没有的轨道不出现。入口待定：播放条上原来的「图层」文字钮已去掉（右端让给缩放），原型里暂时没有打开这组开关的地方，候选位置是舞台工具条左端（时间线视图在那里放字幕显隐，这组开关正是它的扩展），见 §11 第 11 条：

| 分组 | 开关 | 来源 | 开关改什么 |
| --- | --- | --- | --- |
| 字幕 | 每条字幕轨一个（原文 / 译文 / 双语按轨道名） | 字幕轨（视频格式规范 §5） | 舞台的字幕显隐（产品设计 §5.3），按轨分开 |
| 画面 | 实拍画面 | 场景里的 footage 实例或视频轨上的非主片段 | 这个窗口画不画这些实例 |
| 画面 | 来源标注 | 带来源的 footage 实例 | 画面角上「来源 · xxx」的贴片 |
| 画面 | 贴片 / 字卡 | 文字、图片、贴纸元素 | 同上 |
| 画面 | 水印 | 导出设置里的水印 | 预览里画不画 |
| 声音 | 配乐 | `role: music` 的音频轨 | 监听时静音，与时间线视图的配乐静音同一份 |

全部是这个窗口的观看态：不进视频、不进撤销、不影响导出（与字幕显隐、倍速同一规则）。字幕与配乐的开关与时间线视图共用一份状态（§5），其余只在轻量视图有意义，切到时间线视图不带过去。

### 3.5 顶栏的切换

顶栏标题右侧一枚分段控件「轻量 | 时间线」，旁边一个小菜单「默认打开」（§6）。切换是即时的，不弹确认，不丢状态（§5）。

## 4. 标记与批注

### 4.1 工具

轻量视图的「标记」是产品设计 §5.3 标注模式在画面上的另一套界面：开着时画面上铺一层标记层，画面底上浮一条工具条（照截图标注器的样子）。画的东西先留在画面上，能选中、拖动、改颜色、撤销；最后一次「添加到对话」把整组变成视频标注进输入框。工具条从左到右：

| 组 | 工具 | 快捷键 | 手势 | 变成什么 |
| --- | --- | --- | --- | --- |
| 工具 | 选择元素 | ⇧⌘S | 悬停画面上的节点出高亮与说明卡（选择器、尺寸、可访问性的名称 / 角色 / 键盘可聚焦，照 DevTools）；点一下把它框住 | `element`（新）：`region` 是元素在画面里的框，`element` 记它是谁（见下） |
| | 评论 | ⇧⌘C | 点画面任意位置落一枚印章（头像缩写），弹出输入框；点在元素上时连元素一起定位 | `comment`（新）：`region` 是印章的点，`text` 是评论，`element` 可选，`shot` 是带印章的那一帧截图 |
| | 画笔 | — | 拖出一道线 | `pen`（新）：归一化点列 `points[]` 与外接框 |
| | 形状 ▾ | — | 菜单：直线 / 箭头 / 矩形 / 圆 / 编号；前四个拖出来，编号点一下落一枚按顺序编号的圆点 | `line`（新）/ `arrow` / `box` / `ellipse`（新）/ `pin` |
| | 文字 | — | 点一个位置原地输入（占位「输入文字」），Enter 结束 | `text` |
| 样式 | 颜色 ▾ | — | 红 / 蓝 / 绿 / 黑 / 白；选中了标记就改那一条，否则改之后画的 | `style.color` |
| | 粗细 ▾ | — | 2 / 4 / 6 / 8 px，同上；文字按粗细定字号 | `style.width` |
| 历史 | 撤销 / 重做 / 清空 | ⌘Z / ⇧⌘Z | 每次加、删、挪、改样式进一步 | — |
| 发送 | 添加到对话 | — | 没有能发的标记时禁用；发完退出标记模式 | 整组转成视频标注（§4.3） |
| | 关闭 | Esc | 画面上还有没发的标记时先问「放弃这些标记？」（继续标记 / 放弃） | — |

选中与编辑：任何工具下点已有标记都选中它（不另设「选择」工具）；矩形、圆与元素框有八枚把手，直线与箭头两端各一枚，拖标记本身是平移；Delete 删选中的。空白的文字与评论不算能发的标记，关闭时也不问。

元素是什么：字幕行记 `{kind: "caption", id, text}`，HTML 动画视频里的节点记 `{kind: "html", selector, w, h, name, role, focusable}`（选择器是 `tag#id.class`，可访问名与角色照 DevTools 的 Accessibility 面板），实时合成层与贴片记 `{kind: "element", id, text}`。每种都派生一句给人看的 `label`（「字幕 · “它没有掉下来”」「button#play.bc-icon-button · 32 × 32」）与一句给模型看的英文 `detail`（`caption s01:l3 "…"`、`html button#play 32×32 name="播放" role=button`）。元素与评论的标签用它代替区域的说法：「00:12.4 · 字幕 · “它没有掉下来也没有慢下来” · s01 · 第 3 句」。

评论：输入框带「发给智能体」勾选（默认勾上）。勾着按发送，这一条立刻进输入框（印章截图随它），印章从画面上消失、变成输入框里的标注；不勾就留在画面上，与别的标记一起等「添加到对话」。正式版的 `shot` 是真截当前帧再把印章画上去的图片附件，随消息一起交给智能体；原型只记时刻与印章位置，输入框里的缩略图是示意。

种类表（`BC_STAGE_NOTES.KINDS`）加 `pen` / `line` / `ellipse` / `element` / `comment`，与今天的 `box` / `arrow` / `text` / `pin` 并列；时间线视图的标注条仍只列框 / 箭头 / 文字 / 编号，但两边画好的互相能看见、同一份草稿（`videoNotes[videoId]`）。标记的颜色与粗细随标注存成 `style`，时间线视图照它画。

工具条的样子照截图标注器（选择 / 画笔 / 形状 / 文字 ｜ 颜色 / 粗细 ｜ 撤销 / 重做 / 清空 ｜ 添加到对话 / 关闭）；「选择元素」与「评论」照幻灯片编辑器（`apps/slides-editor`）把选中元素附到评论、发到会话的做法。不共用实现——设计稿与幻灯片的标注绑的是画板里的元素，视频标注绑的是时刻、归一化区域与画面上的节点，中间没有能复用的层。

### 4.2 落点：时刻之外加一段一句

每条标注除产品设计 §3.2.3 的字段（视频、版本、播放头、区域、种类、批注）外，再带标注时的落点：

```
segment: {id: "s03", kind: "scene", index: 2, title: "倒着为什么不掉"}
line:    {id: "s03:l2", index: 2, text: "那一个有点危险的做法……"}   // 没有当前句时省略
```

落点是标注时算出来的快照，不随段的重算改变；智能体拿它定位「第 3 场第 2 句这里」，比一个毫秒数好认。批注框的标签写「01:10.0 · 框 · 画面正中 · s03 · 第 2 句」。

### 4.3 发给会话的消息

与今天一样进输入框的「视频标注 · N 条」，随下一条消息发出；只带标注时正文「请按这些视频标注修改。」。画的标记不逐条要批注——一组标记就是一句话的附件，只有文字与评论带 `批注：`。消息里的块多出落点、样式、元素与截图这几行（没有的省略）：

```
<baocut-video-annotations video="…/倒着开的跑车.baocut" revision="12">
1. 01:10.0 (70000 ms) · box · x=0.42 y=0.36 w=0.18 h=0.22
   style: red 4px
   segment: s03 (scene #3 倒着为什么不掉) · line 2: 那一个有点危险的做法……
2. 01:10.0 (70000 ms) · text · x=0.60 y=0.30
   style: red 4px
   segment: s03 (scene #3 倒着为什么不掉) · line 2: ……
   批注：字太小
3. 00:12.4 (12400 ms) · element · x=0.16 y=0.84 w=0.68 h=0.05
   style: blue 4px
   element: caption s01:l3 "它没有掉下来也没有慢下来"
   segment: s01 (scene #1 钩子) · line 3: 它没有掉下来也没有慢下来
4. 00:12.4 (12400 ms) · comment · x=0.40 y=0.30
   style: blue 4px
   element: html button#play.bc-icon-button 32×32 name="播放" role=button
   segment: s01 (scene #1 钩子) · line 3: ……
   screenshot: attached, frame at 12400 ms with the stamp at (0.4, 0.3)
   批注：这里慢一点
candidateBoundsMs: 12400–70000（候选范围，不是要改的区间）
</baocut-video-annotations>
```

`screenshot` 那一行对应随消息一起交出的图片附件（当前帧 + 印章），智能体看图找位置；`element` 给的是英文 `detail`，让它能在源文件或 HTML 里找到那个节点。

语义不变（产品设计 §3.2.3）：默认含义是「改源视频这个时刻附近」；段落落点只是定位，智能体不把它当成「重做整段」的指令。skill「收到视频标注时的解读」补一句：带 `segment` 的标注优先用章节表的工具改那一章（动画片设计 §6）；带 `element` 的标注改那个元素（字幕行、合成层或 HTML 节点），不是改它附近的画面。

原型：`app/model-markup.js`（标记层的状态：工具、样式、历史、几何、把手、转成标注），`app/stage-markup.jsx`（`LiteMarkupLayer` 画面上的层与元素拾取、`LiteMarkupBar` 工具条），`app/model-stage-notes.js` 的 `normalize()`、`promptText()`，`app/stage-notes.jsx`（发出去之后的显示与输入框里的缩略图）。

## 5. 两种视图，一份视频

视图只是看法：两边读写同一份视频文档、同一份撤销栈、同一个会话。切换不重新打开视频，不重建播放器。

| 状态 | 跨视图保留 | 存在哪 |
| --- | --- | --- |
| 播放头、播放 / 暂停、倍速、监听音量 | 是 | 窗口的观看态（今天就有） |
| 字幕显隐、配乐静音 | 是 | 观看态；轻量视图的图层开关（§3.4，入口待定）改的就是它们 |
| 标注模式、当前标注种类、标注草稿 | 是（草稿按视频存） | `videoNotes[videoId]`（产品设计 §3.2.3） |
| 内容面板的当前页（文稿 / 字幕 / 章节…） | 是 | 路由的 `tab`；轻量视图不显示内容面板，但切回来还在那一页 |
| 选中的元素、时间线选区、缩放 | 是 | 编辑器状态；轻量视图不显示也不清掉 |
| 侧栏展开、图层开关里只属于轻量视图的项 | 轻量视图自己的 | 偏好 `liteSide`；其余只在内存 |
| 当前视图 | — | 路由 `view=lite \| timeline`（§6） |

路由里带 `view`：从会话、Space 或链接打开时可以指定视图；切换时只替换路由，不新开编辑器。全屏播放器两边共用，退出全屏回到进入前的视图。

## 6. 默认打开与偏好

打开一部视频时按下表从上往下取：

| 优先 | 依据 | 结果 |
| --- | --- | --- |
| 1 | 路由里的 `view` | 照它 |
| 2 | 这部视频上次用的视图 | 偏好 `editorViewByVideo[videoId]` |
| 3 | 用户的全局默认 | 偏好 `editorViewDefault`：「总是轻量」/「总是时间线」 |
| 4 | 按视频种类 | 在会话里打开（Home 的会话功能区）且有章节 → 轻量；其余（Space 打开的、没有章节的、`focus`、模板预览）→ 时间线。§11 第 2 条按保守的备选定下 |

- 每次切换都记到 `editorViewByVideo`，下次打开这部视频沿用；只留最近的 200 部。
- 视频菜单（视频栏右端的 ⋯）里的「默认打开」三选一：自动（默认）/ 轻量编辑器 / 时间线编辑器，写 `editorViewDefault`。专业用户选「时间线编辑器」后，新视频一律时间线，已经按视频记过的仍按视频。
- 偏好是界面持有的（架构设计 §5.10）：与时间线高度、面板宽度存在同一份编辑器状态里（`packages/ui` 的 `baocut.editor`），不进视频、不进用户库——Web 端没有 `settings.set`，进了用户库 Web 就改不了。同一部视频换一台机器打开按那台机器的偏好。
- 路由的 `?view=` 只在打开时用一次，用过就从地址里去掉（`replace`）：它不进功能区标签的身份，刷新与回退不再强制。

原型：`app/model-lite.js` 的 `defaultViewByKind()`、`viewFor()`、`remember()`；`app/shell.jsx` 的 `MovieViewSwitch`。

## 7. 脚本显示：要不要复用协作文档编辑器

问题：侧栏里的脚本能不能用 `apps/docs-editor`（[协作文档](../docs/docs-design.md)）的富文本编辑器显示、顺手编辑。

| 看点 | 协作文档编辑器 | 只读 Markdown 渲染 |
| --- | --- | --- |
| 数据 | 要一份文档目录、grant、door 与 mux 连接；脚本今天是章节表里的一个 Markdown 字段 | 直接渲染字段 |
| 宿主 | 一个 iframe，Web 端还要另一个回环主机名（canvas 设计的同一限制） | 原生组件，Web 端照常 |
| 编辑 | 能改，但改了要写回章节表并标「脚本已改」，还要防止与智能体同时写 | 不能改，改脚本走章节页或交给智能体 |
| 体积与启动 | 每切一段重载一个编辑器，或者常驻一个再换文档 | 零成本 |
| 与动画片设计 §5.1 的决定 | 那里已经决定脚本「不做富文本编辑器」，Markdown 够用 | 一致 |

建议：**不复用**。侧栏的脚本用会话里已有的 Markdown 渲染（原型的 `AgentMarkdown`；Web 端退回按段落渲染的纯文本），只读；底下一行「改脚本：交给智能体」把这一段的 ID 与脚本作为引用标签放进输入框，与章节页的「重做这一章」是同一动作。什么时候重新考虑：脚本变成独立的协作文档（多人改、带评论）时，侧栏改为嵌入那份文档的只读视图。

## 9. 与现有规格的差异

实现前要改这些规范（第一阶段涉及的三条已于 2026-10-19 随实现改好：产品设计 §5.1 / §5.2 / §5.3 舞台条、架构设计 §5.10 的界面持有、路由；验收规范 §6.3 加了 T41–T43）：

- 产品设计 §5.1 / §5.2：编辑器有两种视图；轻量视图不属于三种布局之一，布局只在时间线视图里切。顶栏切换与默认规则（§6）写进 §5.2。
- 产品设计 §5.3「标注」：种类加画笔、直线、圆、元素、评论；标注字段加落点 `segment` / `line`、样式 `style`、元素 `element`、截图 `shot`；轻量视图的工具条与标记层（§4.1）。§3.2.3 的消息块加落点、样式、元素、截图几行，批注改为可选。
- 产品设计 §3.2.3：无改动，只补落点一行的例子。
- 动画片设计 §5.1 章节页：章节页与侧栏显示同一份脚本与状态；侧栏只读，章节页能改。写明两者的分工，不合并。
- 视频格式规范：无改动。段不进视频；视图偏好（`editorViewDefault`、`editorViewByVideo`、`liteSide`）是界面持有的（§6），不进 Runtime 的设置表；旁白分段的阈值暂时固定（§11 第 3 条），要暴露时再定存哪里。
- 命令协议 `conversations` 与 skill「收到视频标注时的解读」：认识 `segment` / `line` / `element` / `screenshot`，带场景落点的优先用章节表的工具，带元素的改那个元素；评论的截图作为图片附件随消息给。
- 路由：编辑器路由加 `view` 参数（Home 的 `/c/<id>?video=…&view=lite`、Space 的 `/space/<分类>?video=…&view=lite`）。实现里它不进功能区标签的身份（`WorkspaceItem`），打开时用一次就去掉（§6）；原型的 `isSame` 把它算进去只是原型的简化。

## 11. 待评审事项

1. **轻量视图的名字与位置**：顶栏写「轻量 / 时间线」，还是「看 / 剪」「审阅 / 编辑」？它不属于创作 / 审阅 / 精修三种布局，要不要在 §5.2 里把「审阅」布局直接换成轻量视图？**第一阶段定为「轻量 / 时间线」，三种布局不动**（产品设计 §5.2 已照此写）；改名只改文案。
2. **默认打开**：转写、翻译入口打开的视频默认轻量（§6 第 4 条）是否过头？剪口播的人可能更想直接看文稿页。备选：只有章节表或会话生成的视频默认轻量，其余一律时间线。**第一阶段按保守的备选实现**：在会话里打开且有章节的视频轻量，其余时间线（§6）；要放宽时只改 `defaultEditorView`。
3. **旁白分段的阈值**（1.8 s / 60 s）要不要暴露给用户调，还是固定。
4. **脚本编辑**：按 §7 不复用协作文档编辑器、侧栏只读；是否接受「改脚本只能交给智能体或去章节页」。
5. **新的标注种类**（画笔、直线、圆）要不要也出现在时间线视图的标注条上；原型里只在轻量视图列出。**第一阶段：时间线视图的标注条仍只列原四种（`TIMELINE_VIDEO_ANNOTATION_KINDS`），新五种只在轻量视图的工具条上；两边的舞台都画得出全部九种，所以轻量视图发出的标注切到时间线视图照样看得见。**
6. **侧栏宽度与收起**：360 px 固定，还是可拖；收起后台词是否以浮层形式跟随播放。
7. **图层开关里的「实拍画面」**：关掉实拍只是预览不画，还是同时给智能体一个「不要实拍」的提示？本文按前者。
8. **Space 与会话的打开入口**：会话里的视频卡片、Space 的视频条目是否直接带 `view=lite`，让第一眼一定是轻量视图，而不依赖种类推断。
9. **轻量视图里拖场景时长**（§3.2）：讲解片的章长默认归旁白（动画片设计 §2.3），拖一下就把归属改成 `user`、画面要重做。要不要在松手前先确认，或只允许拖长不允许拖短；章节表的边界拖动没有这层顾虑。**第一阶段：只做章节边界的拖动，场景时长等章节表落地再定。**
10. **缩放快捷键**：⌘= / ⌘− / ⌘0 今天归时间线的缩放（`editor-keys.jsx`），在轻量视图里按下去改的是看不见的时间轴。要不要按当前视图分流——轻量视图里改片条缩放；菜单上的快捷键提示等分流后再标。**第一阶段：按视图分流，轻量视图里这几个键改片条的缩放（⌘0 回到 100%），菜单上仍不标快捷键**；要不要标等用过再定。
11. **图层开关的入口**（§3.4）：播放条上的「图层」钮已去掉。放舞台工具条左端（替代时间线视图的字幕显隐钮，一枚钮弹出整组开关），还是干脆只保留字幕显隐、把实拍 / 贴片 / 水印的开关砍掉？原型暂时两者都没有。**第一阶段：放舞台工具条左端，一枚「图层」钮弹出整组开关；只列预览今天能开关的（字幕按原文 / 译文、配乐），实拍 / 来源标注 / 贴片 / 水印预览还没有开关，暂不列；一个开关都没有的视频不摆这枚钮。**
12. **选择元素的范围**：字幕行与合成层今天能拾取；HTML 动画视频的节点要从预览的 iframe 里拿（选择器、尺寸、可访问名），跨 iframe 的拾取与高亮要在实时合成层（产品设计 §5.3）里开口子。拾取到多深（最内层节点，还是场景定义过的「元素」）待定，原型取最内层。**第一阶段：拾字幕行（同一条 cue 的几行合成一个框，标签带台词）与画面上的合成层实例（跳过主视频；标签取文字实例的内容或实例名）；指针落在实时播的 HTML 动画上时，再经实时合成层的桥（`pick`）问 iframe 里那一点下的节点，深度照原型取最内层（`elementFromPoint`，不归到场景定义的「元素」），卡片照 DevTools 列选择器、尺寸与名称 / 角色 / 键盘可聚焦，点下记 `{kind: "html", …}`；问不到、超时或页面回得不对时退回那个合成层实例。iframe 的 `inert` 与 `pointer-events: none` 不挡页面里的 `elementFromPoint`（2026-10-19 在 Electron 上核对），拾取不用摘掉 `inert`。高亮由标记层按页面回的框画，不进页面。**
13. **评论的「发给智能体」**：勾着是立刻进输入框，不勾是留在画面上等整组发。要不要再有一种「只给人看、不发」的评论（像幻灯片编辑器的评论线程），还是视频里的评论一律是给智能体的。**第一阶段：视频里的评论一律给智能体——勾着立刻进输入框并附截图，不勾留在画面上随「添加到对话」一起发（那时每条评论也各附一张截图）；没有只给人看的评论。**
14. **截图的生成**：评论的 `shot` 由谁截——实时预览直接截画布（快，但 HTML 动画要走 iframe 的截图），还是让 Runtime 烘焙那一帧（准，但慢）；图片大小与是否存进会话记录。**第一阶段：实时预览直接拷预览画布、在落点画上印章存成 PNG，走输入框的草稿图片（与手动贴图同一条路，随消息进会话记录，不另存）；大小就是预览画布的像素；HTML 动画的 iframe 层不在画布上，截不进去，截不出图时提示并照样加评论。Runtime 烘焙留作备选。**
15. **编号的起点**：编号按这一组从 1 起，发出后再画从 1 重来；要不要接着上一组的编号，让一次会话里的编号唯一。**第一阶段照此：按这一组从 1 起、撤销或删掉中间一枚后面的重排、添加到对话后下一组从 1 重来；要不要接着编等用过再定。**
16. **脚本的数据来源**：章节表（动画片设计 §2.2 的 `chapter-sheet` 文档）还没有落到视频数据里，侧栏的脚本（§3「侧栏」、§7）没有东西可渲染；第一阶段只有逐句。章节表落地时侧栏按段取 `scenes[].script` 只读渲染，Web 退回纯文本。
