# 视频写成博客文章

把一个视频写成不看视频也能读好的文章。它既不是整理过的文稿，也不是总结：总结告诉读者这一期讲了什么，博客文章把这一期的内容完整地重讲一遍。

动笔前先用 `skills_read` 读本 skill 的 `references/writing-baseline.md`：材料、基线、两类读者与视角、篇幅与风格、默认值都在那里，下面不重复。

## 1. 取材料

1. 用 videos_inspect 看视频的文档。没有转写（kind 为 speech 的文档）时先转写，告诉用户转写在进行。转写没润色过时人名、术语可能有错字，对照视频信息核对。
2. 带时间码的文稿：export（kind `transcript`、format `md`、timestamps `true`；有几份文稿时按它列出的候选用 documentId 指定），jobs_inspect 等到 completed，读 outputs 里的文件。时间是剪辑后时间线上的时间。
3. 视频信息：videos_inspect 给出的视频名与章节；来源标题、作者、发布平台、链接只用用户提供的。
4. 没有视频（例如只从链接下载并转写）：jobs_inspect 的 outputs 里有 SRT、TXT，直接读。
5. 长文稿先分段读（按章节或时间），每段记下主题块和要引用的原话及时间码，再合起来写成品。

## 2. 先定视角

博客文章两类读者都服务。用户说了视角就照办；没说时按基线里「视角」一节判断。

| | 作者视角 | 观众视角 |
| --- | --- | --- |
| 什么时候 | 视频是用户自己的 | 视频是别人的 |
| 写给谁 | 用户的读者：关注用户的人、搜到这篇的人 | 没看过视频、想了解内容的人 |
| 目标 | 一篇能以用户名义发布、让人想读下去的文章 | 一篇能代替看视频的文章：完整、忠实 |
| 口吻 | 用户本人；可以用第一人称 | 第三人称转述，观点归给说它的人 |
| 开头 | 抓人（见下） | 说明出处，再说这篇讲什么、对谁有用 |
| 固定栏目 | 加上用户偏好里的署名、结尾的关注语等 | 不给用户署名或推广 |

**作者视角的开头**。头几句告诉读者读下去能得到什么：从这个视频最值得看的一点开始，可以是一个结论、一个结果、一个问题或一个场景。不寒暄；不用「今天想跟大家聊聊」开头。抓人的东西正文里必须兑现。语气先按这次的风格，其次按用户的偏好，都没有时按用户在视频里说话的方式；用户在视频里的观点和保留意见不因语气改变。

**观众视角的开头**。第一段说明这是谁的视频、哪一期、发在哪里（按视频信息），说话人是谁、为什么值得听，再说这篇讲什么。全文始终分得清哪些话出自视频里的人；不要把别人的观点说成用户的，不替说话人下他们没下的结论。

**多人对话**两种视角里都可能出现：要么写成转述（按主题分组，观点归到人），要么保留问答体；问答体也要编辑过，不是贴文稿。

## 3. 从说到写

- 去掉口头禅、重说、半截话和离题的闲聊；同一点说了好几遍的，留最清楚的一遍。
- 把说话时靠语气和手势传达的东西写出来：「这个」「那边」指的是什么，当时屏幕上在演示什么。
- 顺序可以调：结论提前，散在视频各处的同一个话题合成一节。调的过程中因果不能变。
- 保留例子、数字、步骤和原话里的关键措辞。它们是文章最有价值的部分。
- 立场不变。说话人留了余地的地方（「我猜」「可能」这一类），文章里也留余地。

## 4. 结构

- 标题由内容决定，从最值得读的一点出发；作者视角的标题还要吸引人，同样只说视频兑现的东西。
- 开头按第 2 节。
- 正文分节，小标题说这一节讲什么，不写「第一部分」。
- 结尾在内容结束处停下；作者视角有固定的结尾栏目就加上。
- 视频的章节可以作为分节的起点，但章节是给观众跳着看的；文章的分节按阅读的需要来。

## 5. 配图

有些内容要配图才说得清：幻灯片、演示、图表、实物、操作的结果。在这些地方写明需要什么画面、对应视频里哪个时间点（取自文稿的时间码），下面配一句图说。

- 图辅助文字，不代替文字：去掉图，这一段仍然读得明白。
- 只在需要画面的地方配图，不为好看每节一张。
- 视频里没有、要另外画的插图标明是补的。
- 这里没有从视频取帧的工具：图交给用户按时间点截取。用户要配图又同意生成插图时，可以用 image 生成，并标明是生成的。

## 6. 补背景的边界

补背景遵守基线第 4 条。在博客文章里尤其要注意：补的是帮助读者理解视频内容的事实，不是你自己对这个话题的延伸讨论。不加视频没有表达的观点。

## 7. 篇幅与风格

博客文章没有固定长度：写到清楚为止。

| 篇幅 | 博客文章是什么样 |
| --- | --- |
| 短 | 一篇短文：只讲这个视频里最值得讲的一两件事，讲清楚 |
| 中（默认） | 视频的主要内容都覆盖到；关键的例子和步骤保留 |
| 长 | 完整重讲视频内容：每个论证、例子、步骤和数字都在，背景补全，每个需要画面的地方都写明了配图 |

| 风格 | 在博客文章里 |
| --- | --- |
| 平实（默认） | 把内容讲清楚，不评论。作者视角默认用用户在视频里说话的方式 |
| 科普 | 为外行重新组织：从读者已经知道的讲起，逐个解释术语，多用例子和比喻 |
| 吐槽 | 作者带着态度讲：评论和调侃。观众视角里，对方说了什么照实转述，评论是作者的 |
| 其他 | 照用户的描述写；给了范本时学它的语气和结构 |

## 8. 交付

- 写成工作目录里的 Markdown 文件（如 `<视频名>.blog.md`；多种语言时在扩展名前加语言标签）。不同篇幅或风格的版本各存一份；大改之前把上一版另存，小修直接改。会话不属于项目时工作目录用户看不到：再用 downloads_save 放进下载目录，把它返回的 path 告诉用户。
- 向用户说明：文件的真实路径；用的是哪种视角、依据是什么；文稿之外补了哪些背景；哪些信息没有核实、哪些链接要用户补；哪些配图需要用户截取。

## 9. 自查

- 视角对：作者视角用用户的口吻；观众视角说明了出处，没有把别人的观点说成用户的。
- 开头：作者视角的头几句让人想读下去，并且正文兑现了；观众视角第一段给了出处。
- 不看视频也读得明白；每个「这个」「那里」都有所指。
- 每个事实都在文稿或视频信息里；补的背景分得清，而且确定。
- 说话人的立场和保留意见都在。
- 没有整段照搬文稿，也没有写成总结。
- 需要画面的地方写明了要什么画面；去掉图也读得明白。
- 篇幅与风格是这次要的档位与风格；评论与转述分得清。
