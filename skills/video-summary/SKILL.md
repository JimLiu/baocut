# 视频内容总结

写给读者：没看过视频、想知道这一期讲了什么、哪些部分值得回看的人。目标：读完的人知道讲了什么，信得过，并且找得到想重看的那一段。

动笔前先用 `skills_read` 读本 skill 的 `references/writing-baseline.md`：材料、基线、两类读者、篇幅与风格、默认值都在那里，下面不重复。

## 1. 取材料

1. 用 videos_inspect 看视频的文档。没有转写（kind 为 speech 的文档）时先转写，告诉用户转写在进行。转写没润色过时人名、术语可能有错字，对照视频信息核对。
2. 带时间码的文稿：export（kind `transcript`、format `md`、timestamps `true`；有几份文稿时按它列出的候选用 documentId 指定），jobs_inspect 等到 completed，读 outputs 里的文件。这里的时间是剪辑后时间线上的时间，剪掉的词不在里面；要点的时间就取它，不要自己估算。
3. 视频信息：videos_inspect 给出的视频名与章节；来源标题、作者、链接等只用用户提供的。
4. 没有视频（例如只从链接下载并转写）：jobs_inspect 的 outputs 里的 SRT 带时间码，直接读。

## 2. 产出是什么

两部分：

- **总结正文**：按主题组织的一篇文字，把这一期的内容讲清楚。
- **要点**：一组短句，每条是一个值得记住的结论、方法或数字，注明它依据的那段在视频里的时间，读者能从它跳回视频的那一段。

两部分各司其职：正文给完整的来龙去脉，要点是导览，扫一眼要点就知道该回看哪一段。要点的条数取决于篇幅和内容，不凑数。正文里值得回看的地方也可以注明时间。

## 3. 动笔之前

先从文稿里弄清五件事，它们不进成品：

1. **谁在说话**。每位说话人是谁、以什么身份说。只依据文稿里的自我介绍、别人的介绍和视频信息；文稿里只有说话人编号、又无从确认时，用「主持人」「嘉宾」这类角色，不猜名字。
2. **为什么值得听**。与这一期主题直接相关的经历或位置，一两句话。文稿和视频信息里都没有就不写。
3. **主题块**。按主题分组，不按时间切片；视频里几处讨论同一个话题，合成一块。
4. **新东西**。哪些观点、方法和数字观众最可能没听过。给它们篇幅；大家都知道的一笔带过。
5. **要补的背景**。不补读者就看不懂的人名、产品、事件和术语。

## 4. 正文

- **开头**一段说清：这是什么（访谈、演讲、教程），在谁和谁之间，说话人是谁、为什么值得听，这一期讲了哪些事。不用悬念开头。
- **中间**按主题块写，每块一个小标题。用完整的段落，不要把观点拆成一串零散的列表项：列表装不下「因为……，所以……」。本身就是列表的内容（步骤、清单、对比）例外。
- **保留说话人的声音**。观点归给说它的人。以转述为主；只有特别精准、改写就会走样的少数几句才逐字引用，引文与文稿一致，去掉口头禅。
- **每个主题块**写到读者能复述：主张是什么，理由或例子是什么，有数字就带数字。
- **结尾**停在最后一个主题块。不另加「总结」「展望」或号召。平实风格不加自己的评价；带评论的风格里，评论一看就是作者的。

## 5. 要点

- 每条一句话，单独看也能懂：主语、对象和结论都在这句话里；不写「他接着讨论了这个问题」。
- 挑结论、方法、数字和新东西；跳过开场寒暄、过渡和大家都知道的。
- 每条注明它依据的时间，指向这个话题开始的地方，取自文稿的时间码，不估算。
- 按在视频里出现的顺序排；说同一件事的两条合并。
- 要点与正文一致；不出现正文里没有的事实。

## 6. 不同的视频，不同的侧重

| 视频 | 侧重 |
| --- | --- |
| 访谈、播客 | 嘉宾的观点及其依据；主持人的问题只在有助于理解时保留 |
| 演讲、讲座 | 论证的主线：问题、主张、证据、结论 |
| 教程、演示 | 做成了什么、前提条件、步骤、常见错误；步骤写成有序列表 |
| 评测、对比 | 比的是什么、在什么条件下、结论与保留意见 |
| 叙事、纪录片、vlog | 发生了什么、转折在哪里；用户想保留的悬念不剧透 |
| 会议、讨论 | 决定了什么、谁负责、还有什么没定 |

## 7. 篇幅与风格

总结没有固定长度：写到清楚为止，视频里有多少值得讲的就写多少。同一个视频的短版和长版差得很多是正常的。

| 篇幅 | 正文 | 要点 |
| --- | --- | --- |
| 短 | 几段：这是什么、谁的，最重要的结论及其依据。不用小标题；其他主题不写，或在最后用一句话带过 | 只有最重要的几条 |
| 中（默认） | 如第 4 节：开头一段，每个主题块一节，每节写到能复述 | 每个主题块都有；每个值得回看的地方一条 |
| 长 | 每个主题块写全：论证的每一步、例子、数字、值得引用的原话、前因后果都保留，并讲清主题块之间的关系。读完不必再看视频 | 每个值得回看的地方一条 |

文稿很长又要长版时，后半部分和前半部分写得一样充分；不因为文稿长就把后面写薄。

风格体现在叙述与评论上；视频说了什么不随风格变：

| 风格 | 在总结里 |
| --- | --- |
| 平实（默认） | 只转述，不评论 |
| 科普 | 假定读者是外行：多解释术语和背景，抽象的观点配一个比喻或例子；比喻是补的，读者分得清 |
| 吐槽 | 转述保持准确，再加作者的评论：哪句说得好、哪里站不住、哪段在绕圈子。评论以文稿为依据 |
| 其他 | 照用户的描述写 |

不论什么风格，要点都不加评论：它是导览，准确转述就够了。

## 8. 交付

- 写成工作目录里的 Markdown 文件（如 `<视频名>.summary.md`；多种语言时在扩展名前加语言标签，如 `<视频名>.summary.en.md`）。不同篇幅或风格的版本各存一份，按版本命名；大改之前把上一版另存，小修直接改。会话不属于项目时工作目录用户看不到：再用 downloads_save 放进下载目录，把它返回的 path 告诉用户。用户只要在对话里看时，直接回复正文与要点。
- 向用户说明：文件的真实路径；文稿之外补了哪些背景；哪些信息没有核实；没照办的偏好或删掉的内容。

## 9. 自查

- 每个事实、数字和名字都能追溯到文稿或视频信息。
- 没有任何地方猜测说话人的身份。
- 没看过视频的人能看懂每一段；每个专有名词第一次出现时都解释了。
- 没有流水账；没有「先讨论了……，然后讨论了……」的写法。
- 转述没有替说话人加态度或评价；没有空洞的夸奖。带评论的风格里，评论与转述分得清。
- 每条要点单独看能懂，它注明的时间那里确实说了这件事。
- 篇幅与风格是这次要的档位与风格；没有注水的段落，也没有为变短丢掉关键事实。
