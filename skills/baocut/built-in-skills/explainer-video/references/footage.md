# 实拍与动画一起讲

`SKILL.md` 第 6 节的细则。讲一件真实发生的事（产品发布、实验、比赛、事故、自然现象），手里又有原始画面，而这期的底仍是动画（要讲的是机制）时，就让实拍和动画分工。一句话的分工是：实拍证明「真的发生了」，动画讲清「为什么会这样」。下面是分工和衔接的思路，没有固定的穿插比例或段落顺序，按这期的内容挑着用。底反过来是实拍、要讲的是人和事（纪录片形态）时，这页的「切回讲解」「回到动画」不适用，照 `references/documentary.md`。

目录：1 分工　2 衔接的几种办法　3 节奏　4 来源与标注　5 制作与核对

## 1. 分工

- **实拍负责**：奇观本身；真实的尺度与环境；当事人自己说的话；仪表、屏幕上的读数这类一手证据。
- **动画负责**：实拍里看不见的东西（内部结构、力、气流）；放慢或换个角度才看得清的动作；原理示意；数字与对比。
- 一个镜头拿不准用哪种时，问这一句在说什么：说「发生了什么」，优先用实拍；说「为什么」，用动画。只有动画，观众难以相信；只有实拍，观众看不懂。

## 2. 衔接的几种办法

- **先看再问**：开头放实拍里的奇观，然后替观众把疑问说出来，作为全片的路线。后面每答完一个问题，可以回到对应的那段实拍。
- **讲完再看一遍**：原理讲完，把刚才那段实拍再放一遍，旁白告诉观众每个动作是什么，例如「这一下是副翼在压，飞机才开始转弯」。同一段画面，第二次看懂了，最有收获感。
- **实拍里的读数当证据**：画面上的仪表和数字，先在实拍里指给观众看，再到动画里换算、核对（「和仪表上那个数对得上」）。观众会觉得结论是自己验证过的。
- **当事人原声**：最关键的说法让当事人自己说。`clips.json` 给这段 `audio: true` 与 `gap: true`，旁白在这里停下、留出片段的长度，片段放完再接着讲；字幕上面一行是成片语言、下面一行是原话，前面写说话人（`subs`）。现场声（欢呼、引擎声、发车）也可以这样放，音量用 0–1 的数压一点。旁白转述时说清是谁说的。
  - 当事人的几段原话背靠背连着放，中间硬切，不回到动画：几个 `gap` 片段给同一个 `line`，按 `clips.json` 的先后连放，共用一段留白。不要在两段原声之间插一句旁白，把本来一次放得完的话拆成两段；「他还补了一句」「话锋一转，他说起了真正的好处」这类过渡句一律删掉。
- **引出原声的那句压在实拍上**：说清接下来看什么的那句（「第二次就不一样了，我们直接看现场的录像」），压在前一段实拍上说，说完硬切进原声；不要切回动画说一句再切出去，也别一句讲到一半突然切成原声。原声放完，下一句接着刚听到的往下说（「他说的这个数字……」），不复述他刚说的话。引出的话跟着这一期的话题写，同一期里别反复用同一个句式；画面本身够清楚时不必铺垫，直接切。
- **用动画重放实拍**：实拍角度看不清时，用 3D 按实拍的动作重演一遍，换到看得清的角度。重放只做示意，不补实拍里没有的细节。
- **用历史或同类作对照**：讲一样新东西时，把以前用过同一个思路的东西并排放出来（真实的老照片或档案画面，或者标明是示意的剪影），一句话点出「思路相同」。

## 3. 节奏

- 切换跟着意思走，不按固定秒数，同一个意思里不来回切。底是动画时，一段实拍通常几秒到十来秒，够看清那个动作就切回讲解；短档的配额更紧，见 `references/length-and-pace.md` 第 1 节。这些秒数是动画打底的经验值，不是实拍该占多少的上限：实拍本身在讲故事时让它讲下去。
- **实拍连成一整块**：实拍和动画是两种风格，来回切会让观众一直换眼睛。相关的实拍排在一起放完，比如几段历史档案、几段现场画面，旁白直接压在实拍上讲，一块放完再回到动画。块里后一段紧接前一段时给 `follow: true`（不看 `line` / `cue`，接在上一个片段的原长之后），中间硬切。
- **回到动画要值得**：两块实拍之间回到动画，至少要有一个有内容的节拍：几秒钟、有新信息。只为一两秒的空档切回动画，不如让两块接成一块。
- 实拍起点落在旁白说到它的那一句或那个词上（`clips.json` 的 `line` 与 `cue`），这样观众听到「火箭离开发射台」时，画面上正好是这一下。
- **转场只用在动画与实拍的边界上**，也不是每个边界都要：说到哪个词就切到哪个画面时，硬切最干脆。需要过渡时，进实拍（`in`）与回动画（`out`）各自按这一刀的意思挑：`dissolve` 是时间过去、情绪放缓、从画面回到讲解；`wipe`、`slide` 是「换一处看」或并排对照；`zoom` 是凑近看一个细节；`iris` 是揭晓、把目光收到一点上。一般 0.3–0.8 秒。同一期别所有片段套同一组进出，也别为了花样每次换一种。实拍之间首尾相接时硬切，块中间的片段不写 `in`、`out`（写了脚本也会去掉相接的那一侧）。
- **切进去，还是放成画中画**：实拍不一定要整屏切过去。要观众只看这一下（奇观、当事人开口）时整屏切；要实拍和讲解同时看时，把实拍放成画中画（`clips.json` 的 `pip`），动画在下面照常讲：一边放真实画面，一边用 3D 按同一个动作重演；实拍里的仪表一直在角上，动画同时换算那个数；老画面放在角上，旁边讲现在的版本。画中画不换风格，比来回整屏切更少打断，一块里也可以整屏和画中画交替。
  - 框放在画面里空着的那一边，不压主体、不压 2D 面板和字幕带；同一期里位置固定，一般占画面宽的三到四成，小了看不清。框里只放一段画面，不叠第二个画中画。
  - 带双语字幕的原声整屏放（字幕要在底部，压在框里太小，脚本也不让 `pip` 带 `subs`）；画中画多半静音，或者用 0–1 的音量压在旁白下面。
  - 画中画进出也是动画与实拍的边界，可以给 `in`、`out`；`zoom`、`dissolve` 让框从原地长出来、淡下去，比整屏的 `wipe`、`slide` 更合适。
- 实拍上不压要读的图解。实拍和图解要同时看时，用上面的画中画，或者让动画先停一下。
- 开头用实拍时，第 0 帧仍是封面（`SKILL.md` 第 6 节）：先停在封面上，再切进实拍。

## 4. 来源与标注

- 每段实拍都要能说清来源。画面一角标一个小的来源标签，用成片语言写，比如「画面：<来源>」，不压主体，也不压字幕；全片位置一致。片尾或简介里写明来源与版权归属。
- 只用真实画面讲真实的事。生成的视频、动画重放都不冒充实拍；剪辑也不改变原意，比如把演示说成实测、把计划说成已经做到。
- 素材的优先顺序：用户给的、当事方官方发布的，再到第三方。第三方画面先问用户能不能用。能不能用由用户判断；交付时列出用了谁的画面、各多长。
- **老画面**（早年的电视转播、档案片）多是 4:3，带黑边或台标条：用 `crop` 按原片像素先裁掉黑边，再给 `fit: "contain"` 整幅放进画面、两侧补黑，别为了铺满把画面放大、裁掉一半。年份与出处写进来源标签；本地文件剪过头尾时，在 `note` 里记下它的 0 秒对应原视频的哪一刻，方便回查。
- 参考别人做的讲解片时，学它的讲法、论证顺序和画面手法；事实与数字回到一手来源核对，不照搬它的画面、文字和段落结构。

## 5. 制作与核对

- 有命令行环境时，用本 skill 的 `scripts/overlay.mjs`：按 `clips.json` 剪出预览用的小片段和成片用的片段，把来源标签与双语字幕烧进去、原声做淡入淡出并对齐响度，放到单独的一条视觉轨上（默认压在代码画面上面；`footage.layer` 为 `under` 时垫在透明的代码画面下面当底），带上转场与音量；水印也放在单独的一条轨上。要旁白停下的片段先用 `scripts/gaps.mjs` 在旁白里留白，再打包。用法见 `references/production-scripts.md`。
- 预览页（`scripts/preview.mjs` 写配置）会把实拍叠在代码画面上，跟着旁白一起播，留白、原声、双语字幕与转场都照成片的样子画，在烘焙前就能看衔接顺不顺。旁白接得生不生硬，要放出声音听一遍。
- 段落变长、变短之后，`assemble.mjs` 的波纹会带着实拍和水印一起挪，跑 `overlay.mjs --check` 核对位置有没有对上。
- videos_frames 取的帧不合成上层的轨道。要看实拍有没有盖住该看的东西、标签和字幕撞不撞，用 export 给 `purpose: preview` 与 `ranges`（几段各出一个文件）导出要看的片刻，从导出的文件里抽帧看。
