# 3D 讲解

`SKILL.md` 第 4、5 节的细则：主题本身是立体的时候（东西怎么动、力往哪个方向、里面藏着什么、在空间里怎么转），用 3D 讲。这里记的是思路和坑，不是镜头表。每期都从「观众这一秒要看懂什么」倒推画面；同一系列连着几期，别每期都长成同一个样子。代码怎么写、怎么烘焙，照 `video-production` 代码场景细则里 WebGL 那一条。

目录：1 什么时候用　2 核心思路　3 3D 与 2D 叠起来　4 节奏　5 自检时对照的坑

## 1. 什么时候用

- **值得用**：原理依赖空间关系（朝向、里外、上下、旋转、力的方向）；真实画面里看不到的部分（机器内部、心脏里的瓣膜、地下的岩层、气流）；要把一件真实发生的事换个角度重放一遍。
- **不必用**：讲的是数字、流程、对比、概念之间的关系，这时 2D 图解更清楚、做得更快，还能走指令烘焙。一期也不必从头到尾都是 3D：3D 管空间，字、数和图解交给 2D，两层叠在同一帧里。
- **成本先说清**：WebGL 只能逐帧截图烘焙，1080p 实测约 7–18 帧/秒，随场景复杂度变化，八分钟的片子要半小时上下。烘焙前先在本机预览页里改到满意（`SKILL.md` 第 5 节）。开工前把这些告诉用户。

## 2. 核心思路

- **一个主体讲到底**：同一个模型（一辆车、一台机器、一颗细胞）贯穿全片，变的只是视角、透明度、拆开的程度和叠在上面的东西。观众不用每段重新认它，比喻也一直有地方落脚。
- **让看不见的东西有形**：空气、压力、力、电流、热这类看不见的东西，各给一个固定的画法（小球、箭头、流线、发光区），全片沿用；一种颜色只代表一样东西。画面的量跟着物理量走：压力低的地方小球稀，推力越大箭头越长。观众看疏密和长短就能懂，用不着读数字。
- **力要画出箭头**：讲受力（吸力、重力、推力、阻力）的画面，把力画成箭头，从受力的那一点出发、指向力的方向。每种力一个固定颜色，箭头长短对应大小，全片沿用；力变了箭头跟着变长变短，几种力一起作用时并排画出来，观众一眼就能比出谁大。
- **原地透视，不另起一张图**：讲内部结构时，让外壳变透明、剖开或炸开，部件在原位亮起再标注，讲完合回去。这样观众始终知道这个部件在整体的哪里。
- **镜头一次只做一件事**：一句话对一个镜头意图，比如看清这个部件、看清力的方向、看清有多大。镜头运动慢而连续，说到关键词那一刻停稳，不为好看绕圈。讲方向时，选一个能同时看到「力」和「结果」的角度。
- **给尺度一个参照**：放一个观众熟悉的参照，比如人、车道、高度标尺、身边的物件。画面上出现真实的高度或距离时，标尺同时出现。
- **示意就说是示意**：模型外形、部件位置、运动轨迹都是按资料简化的，在稿子或画面上交代一次。动画里随手设的读数（速度表、g 值、高度）不写成像真实数据的数，免得被当成来源里的数字引用。
- **外形认得出**：模型细节可以简化，但轮廓、比例、颜色要和真实画面对得上，切到实拍时观众能认出是同一样东西。
- **简单的光和材质就够**：干净的底色、少量主光、低多边形或光滑的单色模型；把复杂度省下来，留给「看不见的东西」那一层。风格从主题里来，不必每期都是黑底发光。

## 3. 3D 与 2D 叠起来

- 字、数字、表盘、原理图、问题页眉，画在 3D 上面的一张 2D 画布上，不做成 3D 里的立体字。这样字锐利、好排、好改，换语言时也只动这一层。
- 2D 面板要压到主体时，先在面板后面压一层半透明暗底，或者把主体挪到画面一侧，别让面板和模型抢同一块地方。
- 字幕带照代码场景细则第 6 节空出来：标签、图例、说明文字都不放进去。
- 讲一个和空间无关的小原理（一段电路怎么接、一个反应式）时，可以暂时离开 3D：把 3D 压暗或推远，让原理图占主位；讲完回到模型上，用模型把刚讲的道理演一遍。

## 4. 节奏

- 节拍跟着字时间走（`SKILL.md` 第 5 节）：翻转、喷气、亮起这些动作，落在旁白说到那个词的时刻。
- 一段分几幕时，每幕从一句旁白的开头起。换幕时把上一幕的标签、面板和粒子收干净，不残留到下一幕。
- 冲击效果（落地的烟、强光、震动）一段里一两处就够，放在这一段的结论上。
- 一个镜头太久不动，观众会走神；动得太多又看不清。按「这一句要看懂什么」决定动多少。

## 5. 自检时对照的坑

用预览页按正常速度看一遍，再按代码场景细则取帧拼表看：

- 面板或数字压在主体上；标签掉进字幕带。
- 镜头追得太远，地面或场景到了边（地面要比镜头能看到的范围大）；烟雾、粒子把整屏糊成白色。
- 穿模：主体穿过地面或轨道、部件穿出外壳、标签被模型挡住。
- 上一幕的叠层还留着，或者该亮的部件到下一幕才亮。
- 同一种颜色在不同段代表不同的东西。
- 讲受力的画面没有箭头，或者箭头长短和力的大小对不上、同一种力换了颜色。
- 示意读数看起来像真实数据。
- 和实拍放在一起时，模型和真东西对不上。
