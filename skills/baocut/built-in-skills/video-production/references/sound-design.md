# 声音设计：发布片、产品演示与屏幕录制

`SKILL.md` 第 5 节「音效」「配乐」的细则。做产品发布片、动效片、产品演示或屏幕录制类的片子，或者用户要打磨声音时读。工具怎么用（配方表、参数、结果字段）用 `skills_read` 读 `baocut-catalog-music`；这里只讲怎么配、配完怎么核对。

带数字的几条出自开源项目 earshot 对 7 部专业产品发布片（SaaS 与 AI 产品发布、动效片，网页交付）的测量。样本小，当作「专业的片子这样做过」，不是规则。

## 1. 音乐打底，重音少而准

- **先选曲，再按它剪。** 7 部里 6 部几乎全片都有音乐，速度 108–136 BPM。段落变化、揭晓与 Logo 落在小节线上（`assets_analyze` 的 `bars`）；长度不合时从中间整小节剪掉，保留曲子自己的结尾。一首曲子用到底，不在几首不相干的曲子间跳。
- **一开口就有声。** 参考片的第一声都在半秒以内，开头不比整体轻多少。不要静音冷开场。
- **正文响而稳。** 最响的 3 秒只比整体响度高 1–3.5 LU。能量靠编配塑造（加减层、滤波扫、揭晓前的停顿），不靠大幅调音量。
- **结尾落地。** 最后 3 秒仍在正文的响度，淡出短（多在零点几秒），声音停了就结束，不留空白。
- **节奏密，重音少。** 每秒 2.5–8 个起音，真正跳出来的每秒只有一两个。设计过的音效只给揭晓、Logo、关键 UI 动作与段落变化，小动作交给音乐；剪辑点优先落在 `assets_analyze` 的 `accents` 上。
- **不必每个切点都配一下。** 配乐够密时，几乎每个切点下面本来就有声音，参考片在切点上的命中率与碰巧的基线差不多。没有密集配乐（只有旁白与音效）时，每个切点都该有声音。
- **大揭晓一两次：** `riser` 蓄势，所有声音停 0.1–0.5 秒，`impact` 落在揭晓那一帧。全片用一两次，不是每场都来。

## 2. UI 拟音

- 屏幕上点一下配一个 `click`，落在光标按下的那一帧，不是界面有反应的时候。
- 打字一个字符一个 `keypress`；连打时每下换一个 `seed`、间隔略不均匀，别让相邻两下是同一个声音。
- 元素弹出、通知出现用 `pop`。
- UI 拟音要短、要轻：比配乐的峰值低 10–15 dB，是音乐下面的细节。
- 优先用拟真配方（`click`、`keypress`、`pop`、`impact`）；振荡器做的提示音和呼声放在一起会显得廉价，只在风格本来就电子、故障风的片子里用。

## 3. 响度

- 导出时 `loudness` 为 true 用 BaoCut 的缺省：−16 LUFS、真峰值 −1.2 dBTP，各平台都稳妥。
- 网页与 YouTube 上常见的做法是约 −14 LUFS、真峰值不超过 −1 dBTP。YouTube 只把偏响的片子调轻，偏轻的会一直偏轻。要更冲的社交剪辑时，`loudness` 传 `{ integratedLufs: -14, truePeakDb: -1 }`。
- 参考片里 6 部解码后真峰值超过 0 dBTP、播放时削波。这是常见毛病，别学。

## 4. 配完核对

1. 用 export 导出时间线的音频：`kind: audio`、`format: wav`，不给 range。文件里的秒就是时间线的秒。
2. `assets_analyze` 按 `path` 分析这个文件，`cues` 填要对上的时间线时刻：`videos_shots` 的 `cuts[].at`、揭晓与 Logo 的时刻、放音效的位置。
3. 看 `sync`，设计过的时刻与一般切点分开判断：
   - 揭晓、Logo、放音效的位置应当几乎全是 `ok`。只核对这些时刻时，`hitRate` 要明显高于 `chance`。
   - 一般切点在配乐够密时命中率接近 `chance` 是正常的（见第 1 节），不用追求更高；只看其中关键切点的结果。
   - `misses` 里的 `near` 按 `delta` 挪（正的是声音晚到，把音效往前挪 `delta` 秒）；关键时刻是 `none` 的，按第 1 节判断要不要补。
4. 关键段落加 `sheet: true` 画一张听音表（每张最长 120 秒，长片按 `range` 分段），用看图的工具看：开头有没有声、结尾有没有落地、重音是否落在关键时刻、有没有意外的空白。
