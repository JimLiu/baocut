# 口型时间轴：输入、选项与核对

`lipsync.mjs` 把配音和逐字时间算成主播的时间轴 `host-track.js`（`window.HOST_TRACK`），同时写一张给人看的核对表 `lipsync-check.txt`。结果只由输入和 `--seed` 决定，重跑得到同一份。

## 1. 输入

| 有什么 | 怎么给 |
| --- | --- |
| `production-scripts` 的逐字时间 `timing/<段>.json`（`{dur, lines:[{text, start, end, chars}]}`） | `--timing timing/intro.json`，句子按 `lines` 分 |
| 转写结果 `baocut.asr-result/v1`（`segments[].words[]`，整数刻度 + `timescale`） | `--words intro.words.json`，句子按 `segments` 分 |
| 自己的词表 `[{w, t0, t1}]`（秒；也认 `window.X = [...]` 这样的 JS 文件） | `--words words.json`，停顿超过 0.6 秒或句末标点处分句 |
| 只有声音 | 只给 `--audio`：没有读音，按音量开合、按元音的音色挑圆唇或咧嘴，闭唇字不保证闭上 |

转写拿逐字时间：`baocut transcribe` 给配音的 `file` 并带 `noVideo: true`（知道语言时给 `language`），`baocut jobs inspect` 等到 completed，结果里 `pipeline.summary.transcribeJobId` 是内层转写任务；再 `baocut jobs inspect` 它，用 `baocut artifacts save` 把它的转写结果（`artifactId`）存成 `<名>.words.json`。

转写的文字和旁白稿不一致（错字、同音字）时口型照样能用：口型按读音来，同音字读音相同；读错的词用读音表纠正（第 3 节）。

`--audio` 一定给，而且给放进视频的那份配音：音量决定静音时闭嘴、轻读时嘴小、声音没来时不提前张嘴。配音下面垫着音乐或几个人同时说话时，给单独的人声。

## 2. 选项

| 选项 | 说明 |
| --- | --- |
| `--out` | 时间轴 JS 的路径（必填） |
| `--lang` | BCP 47 语言标签，缺省 `auto`（按文字猜：有假名是日文、有汉字是中文、有谚文是韩文，否则英文）。中文旁白里夹着英文词时照写 `zh-CN`，英文词按英文读 |
| `--offset` | 秒。配音在成片里从第几秒开始；时间轴里所有时刻都加上它，包就从 0 秒放。不给时把包放在配音的起点（`place.at`） |
| `--dur` | 秒。时间轴的长度，缺省取配音长度或最后一个字后 0.5 秒 |
| `--fps` | 帧率，缺省 30，照视频 |
| `--faces` | 表情区间，见第 4 节 |
| `--readings` | 读音表，见第 3 节 |
| `--seed` | 眨眼、点头、朝向的随机种子，缺省 1。两个主播用不同的种子，免得动作同步 |
| `--var` | 时间轴的变量名，缺省 `HOST_TRACK`；两个主播时分开（`HOST_A_TRACK`） |
| `--check` | 核对表路径，缺省与 `--out` 同目录的 `lipsync-check.txt` |

## 3. 核对表与读音表

核对表先写总数（帧数、口型变化次数、眨眼与点头次数、各口型占比），再逐句逐字一行：

```text
line 1  0.00–2.14  大 家 好 我 是 宝 玉
    1.28  我    wo      F·E        FFFFB
    1.52  宝    bao     A·D·E      BAADDDEE
```

列依次是：字的开始时刻、字、读音（和字相同时空着）、读音给的口型顺序、画面上这个字占的帧实际出的口型（每帧一个字母）。查这几样：

- b p m 开头的字里有 `A`（闭唇）；f v 开头的有 `G` 或 `B`；u w o 的字里有 `F` 或 `E`。
- 句间停顿是 `X`（不说话的嘴）；句中一长串 `X` 多半是音量太低或时间偏了。
- 读音列错了（多音字、日文汉字、品牌名、缩写），或是 `?`（读不出），写读音表。

读音表是 `{ "词": "读音" }` 的 JSON，带 `--readings readings.json` 重跑：

```json
{ "银行": "yin hang", "今日": "きょう", "BaoCut": "bao cut", "GPT": "G P T" }
```

- 读音可以写拼音（带不带声调都行）、假名、谚文，或拼法相近的英文。
- 词要和核对表里的字对得上：从某个字的开头到某个字的结尾，不能切在字中间；长的词先匹配。
- 中文词的拼音音节数和字数相同时，按字逐个换读音；否则整个词并成一个单位，按读音的音节数分配时间（日文汉字、缩写多是这种）。

## 4. 表情区间

`faces.json` 写哪几句换表情，名字和角色包里 `face` 组的补丁一致：

```json
[{ "line": 1, "face": "smile" }, { "t0": 8.2, "t1": 9.6, "face": "smile" }]
```

- `line` 从 1 数，和核对表的 `line` 一致；区间从这句第一个字前 0.15 秒到最后一个字后 0.3 秒。也可以直接写 `t0`、`t1`（秒，不含 `--offset`）。
- 写成 `{ "default": "smile", "items": [...] }` 时，不在任何区间里也用这个表情。
- 进出各淡入淡出 0.2 秒；同一表情相隔不到 0.4 秒的区间连成一段。表情里照常眨眼（眨眼的补丁盖在表情上面），所以表情补丁的眼睛要睁着，见 [角色包：正面像、改图与打包](art.md) 第 2 节。

## 5. 口型怎么定

每个字（音节）按读音排出一串口型：声母定闭唇 `A`（b p m）、咬唇 `G`（f v）、圆唇 `F`（w、u 介音），其余辅音多是 `B`；韵母定张口 `D`（a）、半张 `C`（e）、圆 `E`（o）、撮 `F`（u ü）、咧 `B`（i）。再按音量定张多大：音量分小、中、大三档（门槛 0.25、0.5，上下留 0.04 的回差，不在门槛附近来回跳），`D` 小声画 `B`、中等画 `C`，`C` 小声画 `B`，`E` 小声画 `F`；闭唇、咬唇、`B`、`F` 不随音量变。静音超过 80 毫秒闭嘴（清辅音声母前最多留 150 毫秒）；字与字停顿超过 150 毫秒闭嘴。嘴比声音早 30 毫秒。

再落到视频帧上：每帧取占时最长的口型，20 毫秒以上的闭唇一定留下一帧 `A`；其余口型至少停 55 毫秒（30 fps 是 2 帧）。不够长的一段如果比前后都闭（两个张嘴之间的一下闭合）或都开，从前后够长的段借帧补够，保住这一下开合；借不到、或者只是从小到大一路过去的中间档，就并进相邻、张得更开的那段。最后在跨度大的开合中间补一帧过渡：闭嘴和 `D` 之间是 `C`，`F` 和 `C`、`D` 之间是 `E`，前后两段都超过最短停留时才补，由张得更开的那段让出这一帧。

b、p 的闭唇不往前提：它本来就落在爆破前那段安静的空隙里，再往前会在上一个字还响的时候闭嘴。

眨眼、点头、朝向也在这里定：每句说完停顿时眨一次，其余 1.8–5.6 秒一次，约七次里一次连眨；每句第一个音节点头，其余音节轻点；每句换一个朝向。代码包按这些时刻画，幅度在 [主播代码包：HostKit 的画法与摆放](kit.md) 调。

## 6. 时间轴的格式

写自己的画法时用得到；时刻都是成片的秒（已加 `--offset`）：

| 字段 | 说明 |
| --- | --- |
| `version` | 1 |
| `fps`、`dur`、`offset` | 帧率、长度（不含 offset）、起点 |
| `mouth` | `[[t, 口型]]`，从 t 起换成这个口型（X A B C D E F G） |
| `blinks` | `[t]`，每次眨眼的开始 |
| `nods` | `[[t, 力度]]`，每次点头的开始与力度（0.5–1） |
| `turns` | `[[t0, t1, x, y]]`，每句的朝向：x −1..1 向左右，y −0.3..0.7 向上下 |
| `faces` | `[[t0, t1, 名字]]`，表情区间；另有 `face` 时是缺省表情 |
