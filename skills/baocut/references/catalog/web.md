# 网页版编辑器：看画面、拖拽调整、请用户审

<!-- surface: cli -->
## 何时用

你手上只有命令行，没有 BaoCut 的编辑器。下面这些事要在编辑器里做，就经本机的 Web 服务打开网页版编辑器：

- **看合成后的画面**：{{tool:videos_frames}} 取的是素材画面（`composited: false`），字幕、文字、贴纸与叠加的元素不在里面；编辑器的预览是合成后的，字幕位置挡没挡人脸、叠加的位置对不对在这里看。
- **播放**：从某个时刻起连着看一段，看剪点前后、画面节奏。
- **所见即所得的调整**：拖字幕的位置、拖动或缩放画面上的元素、在时间线上拖片段，这类用眼睛定位置的事。
- **请用户审**：视频能预览了，把这部视频的审片页开在宿主的浏览器面板里，并给用户整条审片链接（见「请用户审片」），用户在会话旁边或自己的浏览器里看、标记、改。

不用它的：文字与时间线上确定的修改（改字、翻译、剪口、挪片段到某秒、加章节）一律走命令，见 [editing](editing.md)、[subtitles](subtitles.md)；只想知道某个时刻画面上有什么，先取帧（[media](media.md)），够了就不开网页。

## 前置检查

- **一台机器一个 Web 服务。** 它只监听本机回环地址，端口在 BaoCut 的设置里，不要写死，也不要猜。地址看 `baocut services status` 里 Web 服务的 `endpoint`（开着时才有）。
- **`baocut web open` 不用先问。** 它属本机管理命令，但只在本机开服务、给你一条只能用一次的链接，不改视频、不改设置，开网页版编辑器时直接用。同组的其他命令仍按硬规则先问用户，尤其是改端口的 `baocut services configure web`：端口被占时不要自己换，告诉用户（见下文「常见错误」）。
- **要有 videoId。** `baocut videos list` 或上一步回执里的 `videoId`；也可以不给视频，链接落到首页。
- **宿主有浏览器面板或浏览器工具就在里面打开，否则把链接交给用户。** 你自己看画面、请用户审片都这样开（例如 Claude 桌面版的浏览器面板，页面就开在会话旁边）。不要用 `open`、`xdg-open`、`start` 这类系统命令打开带 `#code=` 或 `#key=` 的链接：代码与密钥会进进程参数，本机别的程序看得到。用户要在自己的浏览器里用完整网页版时，让用户自己运行 `baocut web open --launch`（见「交付」）。

## 命令与例子

```bash
# 开网页版编辑器并直达这个视频（服务没开会先开）
baocut web open --video <videoId>

# 只开首页
baocut web open
```

一个任务里只开一次：拿到链接后在浏览器工具里打开，之后一直复用同一个标签。只在看到登录页、401 或连接被拒时重新 `web open`（见「常见错误」）。

## 结果怎么读

stdout 不是终端时是 JSON 信封：`result.link.url` 是链接，`result.link.expiresAt` 是代码的过期时刻，`result.video` 是你给的视频。在终端里是三行文字：链接、落到哪个视频、过期时刻。

- 链接形如 `http://127.0.0.1:<端口>/home?video=…#code=…`：`#code=` 后面是**一次性代码**，两分钟内有效、只能用一次。打开后页面用它换成浏览器会话，地址栏里的代码随即去掉。
- **浏览器会话 12 小时**，绑在这个端口上。会话还在时，同一个浏览器里打开不带 `#code=` 的地址（例如上面链接 `#` 之前的部分）不用再登录。
- 落地后是这个视频的编辑器：标签上是视频名，标题下有时长、画幅与帧率。窄窗口里会话固定在第一个标签，视频是第二个标签，没被选中时点它。

## 在网页里做什么、不做什么

- **改动即时写进同一份视频。** 网页上的拖拽与修改和命令写的是同一份真相、同一份修改历史，没有「保存」或「同步」这一步。所以你在网页里改过之后、下一条写命令之前，先 {{tool:videos_inspect}} 读当前版本，不要拿旧的版本号与对象 ID 接着写；用户在网页里改过也一样。
- 网页里改错了，用编辑器的撤销，或 {{tool:edits_undo}}；不手工反向修改。
- **不碰会话与设置。** 网页版编辑器里也有 BaoCut 自己的智能体对话与设置；不要在那里发消息、改设置或批准什么，那是用户的。
- 只按实际看到的画面下视觉判断；看过哪些时刻，写进交付报告的「看过的」。

## 常见错误

| 现象 | 下一步 |
| --- | --- |
| 页面是 BaoCut 的登录页，或请求返回 401 | 代码用过或过期了、会话过期了，或服务重启过：再 `baocut web open --video <videoId>`，在同一个标签里打开新链接 |
| 连接被拒、什么都没在听 | 服务停了或 Runtime 退出了：再 `baocut web open`，它会把服务开起来；`baocut services status` 里的端口变了就用新地址 |
| `Web 服务没有开起来：端口 … 已被占用` | 别的程序（或另一份 BaoCut）占着设置里的端口。不要自己改端口，也不要结束占用它的进程：告诉用户端口被占，请用户决定换端口（`baocut services configure web --port <端口>`，属管理命令）还是关掉占用的程序 |
| `Web 客户端还没有构建` | 这台机器上的 BaoCut 没带网页版编辑器（开发版没构建）：告诉用户，改用取帧与导出一小段成片来看 |
| `VIDEO_NOT_FOUND` | `baocut videos list` 重新确认 `videoId` |
| 页面打开了但视频没打开 | 先看窄窗口里视频标签是不是没被选中；还不行就 `baocut videos list` 确认视频还在 |

## 下一步

- 看完回到命令：按看到的结果用 {{tool:edits_apply}} 等命令改，改之前先 {{tool:videos_inspect}}。
- 只是要用户确认几个时刻的画面时，导出一小段成片（{{tool:export}} 给范围）也是一种交付，见 [export](export.md)。

## 请用户审片：把审片页开到用户面前

讲解动画、翻译视频、剪辑这类要用户过目的活，做到时间线能从头播（代码画面带 `live: true` 放好、译文字幕已上、配音已放好）就请用户审，不先烘焙、不先导出成片：

```bash
baocut web review --video <videoId>
```

- **不用先问。** 与 `web open` 一样只在本机开服务、发链接，不改视频。服务没开时它先开起来，并设为随 BaoCut 启动；结果里 `result.link.autostartEnabled` 为 true（终端里多一行说明）时，在回复里告诉用户一句。
- **开到用户面前。** 宿主有浏览器面板或浏览器工具时，直接在里面打开 `result.link.url`：审片页开在会话旁边，用户不用自己找链接，也不用访问码。同时在回复里给出整条链接，用户要在系统浏览器、另一块屏幕上看，或之后再打开时用它。宿主没有浏览器时只给链接。不用系统命令打开它（见「前置检查」）。
- **原样给出。** `result.link.url` 形如 `http://127.0.0.1:<端口>/review/<videoId>#key=…`，`#key=` 是密钥，整条都要给，不截断、不改写；宿主能渲染链接就给可点的链接。
- **同一部视频始终是同一条。** 视频还在、BaoCut 开着，链接就能反复打开，重启后也能用；改完再请用户看，刷新已经打开的页面（你在浏览器面板里开的由你刷新），不必再发一条。视频被移走或删除后才失效。
- **页面只有这部视频的编辑器**：默认轻量视图，可切时间线；用户在里面的修改直接写进视频，你下一条写命令之前先 {{tool:videos_inspect}}。没有导出、任务、会话与生成，转写、翻译、烘焙、导出这些仍由你用命令做，烘焙与导出等用户说可以之后再做。
- **标记是截图模式**：用户画线、框、箭头、编号、文字后复制或下载图片，再贴回给你；没有评论，也不会自动发给你。用户贴来的截图按标记位置理解要改的地方。
- **没烘焙的代码画面由实时层现画**，审片页里看到的与烘焙后一致。宿主的浏览器面板里复制图片可能被拒（页面会提示改用下载）。没烘焙的片段在页面里是黑的时，多半是 BaoCut 版本旧，或代码包用的回环端口没开起来：请用户在系统浏览器里打开这条链接，或在 BaoCut 桌面版打开这部视频、切到审片视图；你自己看到黑屏不等于画面坏了，自查用 {{tool:compositions_preview}} 取帧。
- 链接只在这台机器上能打开，持有它的人能改这部视频：不要发到别处（聊天群、文档、提交记录）。

| 现象 | 下一步 |
| --- | --- |
| 页面说链接不完整 | 链接被截断了：把 `baocut web review` 打印的整条重新给用户 |
| 页面说这部视频已经不在了 | `baocut videos list` 确认视频；换了视频就给新视频的链接 |
| 页面说链接对这台 BaoCut 无效 | 链接来自别的机器或服务的密钥换过：再运行一次 `baocut web review` |

### 交付：给用户链接

请用户审片用审片页（上一节），它不要访问码。只有用户要用完整的网页版（会话、Space、设置）时才给 `web open` 的链接：你自己打开过的那条已经作废，交付时再运行一次 `baocut web open --video <videoId>`，把新链接给用户，并说明：

- 只能用一次、两分钟内有效，要在用户马上就点的时候给；用户来不及点，就请用户自己在终端运行 `baocut web open --video <videoId> --launch`：它在用户的浏览器里打开登录页，代码从终端粘进去。
- 不要把链接发到别处（聊天群、文档）；它只在这台机器上能打开。
- 在网页里改的东西会直接写进视频，要撤销用编辑器的撤销。

## 验收

- 一个任务里 `web open` 只在开始、遇到登录页 / 401 / 连接被拒、交付时运行，浏览器标签复用。
- 落地的是用户要的那个视频的编辑器（视频名与画幅对得上）。
- 文字与时间线的确定修改都走了命令；网页里改过之后，下一条写命令之前读过当前版本。
- 没有改端口、没有结束别的进程、没有动会话面板与设置。
- 视频能预览时把审片页开在了宿主的浏览器里（宿主有浏览器时），并给过用户整条、原样的审片链接；服务因此设为随 BaoCut 启动时告诉了用户。
- 用户说可以之前没有烘焙代码画面、没有导出成片；没用系统命令打开带 `#code=` 或 `#key=` 的链接。
- 给 `web open` 链接时是新链接，并说明了只能用一次、两分钟有效。
