# 端到端的做法

每条做法只讲判断与步骤：每步点名用哪个工具或 craft，参数与回执去对应的目录页查。用户只要求一件小事时直接做那件，不套整条流程。

开始任何一条之前：

- **没说清的先问。** 用户要做某类成片但没说清时，先问清四件事：主题、目标（发在哪、给谁看、要达到什么）、受众、手上的材料；交付物、画幅、时长、语言也一并确认。
<!-- surface: cli -->
  BaoCut 装有场景模板（`baocut templates` 列出，属本机管理命令，先问用户再看）时，可以请用户选一个模板，按它的简报问。
<!-- /surface -->
- **先看已有的。** 用户点名或已经在做的视频，先 {{tool:videos_inspect}} 看已经做到哪一步，从那里接着做。
- **证据够了就停。** 理解一条视频按 [media](catalog/media.md) 的证据阶梯：先转写、再按文字定位、再取帧，彼此独立的读取一次发完。

## 1. 链接 → 转录 → 双语字幕 → 成片

**适用**：用户给了视频链接，要字幕（原文、译文或双语），可能还要带字幕的成片或字幕文件。**不走这条**：用户明说只要一个字幕文件、不要视频（见判断表最后一行）；链接里只是一段要翻译的文字。

| 信号 | 处理 | 原因 |
| --- | --- | --- |
| 用户说了原文语言或给了人名术语 | 先 {{tool:download}} 新建视频（不带转写），再 {{tool:transcribe}} 给视频并带语言与提示 | 一步转写时来不及带上这些，识别质量差 |
| 要译文或双语 | 转写时不建字幕层，润色、翻译之后再建 | 原文层的切条按润色后的标点，才和译文层对得上 |
| 只要原文字幕 | 转写时照常建字幕层，再润色 | 润色写回时 Runtime 在同一笔里跟着改字，不用删掉重建；用户早一步看到字幕 |
| 用户只说「转录」「加字幕」 | 原文字幕，不翻译 | 默认含义 |
| 用户说「双语」 | 译文为主、原文为辅的两层字幕 | 默认含义 |
| 视频要登录才能看、网站不支持 | 照错误的 `remedy` 告诉用户，停下 | 不能绕过下载限制 |
| 用户明说只要字幕文件 | 转写时不建视频，只出 TXT 与 SRT；翻译按 {{skill:translate-subtitles}} 的文件一节 | 用户的明确要求优先 |

步骤：

1. 确认交付物（哪种字幕、要不要文件、要不要成片）与目标语言，按 {{skill:subtitle-workflow}}。
2. {{tool:transcribe}} 给链接：新建视频、下载、放上时间线、转写；要译文或双语时不建字幕层，只要原文字幕时照常建。等到完成，记下视频与转写的 ID。
3. 润色：按 {{skill:polish-transcript}}，{{tool:documents_read}} 读、{{tool:documents_put}} 写回同一份转写。{{tool:videos_inspect}} 里素材的 `source`（标题、发布者、简介）当背景参考：人名、术语的写法只在说话人明显在说它时照改，不往文稿里加东西。写回后给占位名的说话人实名，只改 `speakers[].name`，有证据才写。已有原文字幕层时它的文字跟着改，回执的 `keptCaptionCues` 是手改过、没跟着改的句子，交付时报告。
4. 章节（旁路）：作者有章节时 {{tool:chapters_adopt}} 吸到文稿上，没有时按 {{skill:video-chapters}} 自己分，用户说不要时跳过。不阻塞后面的步骤；失败不致命，最多重试一次，如实报告。
5. 重新 {{tool:documents_read}} 读润色后的转写（translateTo 给目标语言，BaoCut 显示「正在翻译」），按 {{skill:translate-subtitles}} 逐句翻译，{{tool:documents_put}} 写成译文。
6. {{tool:captions_create}} 给译文并带双语：原文层与译文层一起建好。只要原文字幕时第 2 步建的那层就是，跳过这步。
7. 用户要文件：{{tool:export}} 导出双语字幕文件；要成片再 {{tool:export}} 导出 mp4（字幕画进画面）。
<!-- surface: cli -->
   要看字幕在画面上的位置、挡没挡人脸，或请用户在编辑器里审：开网页版编辑器（[web](catalog/web.md)），交付时给用户新链接。
<!-- /surface -->
8. 交付：按 SKILL.md 的「交付」写报告。

**完成标准**：视频里有润色过的转写、一份目标语言的译文、一组双语字幕层；多位说话人时证据够的都实名了，留着占位名的说明了原因；章节写进了视频，或说明了没做、失败的原因与作者章节里没对上的条目；导出的文件路径取自结果；字幕条数与译文句数报告给用户；没看过的成片画面如实写明。

## 2. 已有视频：润色后翻译

**适用**：视频里已有转写，用户要译文字幕或双语字幕。**不走这条**：只要润色（做完第 2 步就停）；没有转写（先走第 1 条的转写步骤）。

| 信号 | 处理 | 原因 |
| --- | --- | --- |
| 转写还是识别出来的样子（错字、术语不一、标点乱） | 先润色 | 译文继承原文的错误；润色会改分句 |
| 用户说不要润色 | 跳过润色 | 用户的明确要求 |
| 已有同一语言的译文 | 在它上面改，只重译变了的句子 | 不建第二份译文 |
| 转写有几份 | 按来源素材对上用户说的那段，对不上就问 | 不猜 |
| 用户明确要用配置好的文本模型翻译 | 用 {{tool:translate}} | 只有这种情况才用它 |

步骤：

1. {{tool:videos_inspect}} 找到转写与已有的译文、字幕层。
2. 按 {{skill:polish-transcript}} 润色（含说话人实名），{{tool:documents_put}} 写回同一份转写。
3. 重新 {{tool:documents_read}}（translateTo 给目标语言），用这次的句子按 {{skill:translate-subtitles}} 翻译，{{tool:documents_put}} 写入译文。
4. {{tool:captions_create}} 建字幕层（先确认这份译文还没有字幕层）。
5. 用户要文件时 {{tool:export}}。

**完成标准**：润色在翻译之前；译文句数等于转写句数；没有重复的译文与字幕层；交付报告列出照用的术语与拿不准的句子。

## 3. 翻译配音

**适用**：用户要把视频配成另一种语言。**不走这条**：只要一句旁白（直接 {{tool:speak}}，见 [voice](catalog/voice.md)）；由旁白带着走的成片（第 8 条）。

| 信号 | 处理 | 原因 |
| --- | --- | --- |
| 还没有目标语言的译文 | 先走第 2 条写好译文 | 你自己翻译；配音按译文逐句合成 |
| 背景有音乐或环境声要保留 | 分离背景声，只压低或静音人声 | 直接静音原声会把背景一起去掉 |
| 用户要完全替换原声 | 原声静音 | 用户的明确要求 |
| 没说 | 原声压低 | 默认，保留原片的氛围 |
| 用户点名了音色或用户库里有授权音色 | 用它 | 同一角色全片同一音色 |

步骤：

1. {{tool:models_capabilities}} 看语音合成能不能用、有哪些音色；用户库音色用 {{tool:library_list}}。
2. 没有译文时按第 2 条翻译并写入。
3. {{tool:dub}} 给译文的 documentId、音色与原声处理方式。等到完成。
4. 读结果里每句的合成情况；没合成的句子报告给用户。
5. 用户要文件时 {{tool:export}} 成片或音频。

**完成标准**：配音轨在视频里，句数与译文对得上或差额有原因；原声处理按用户确认的来；语气、对齐与音量写进「要人听的」。

## 4. 剪口播

**适用**：一两个人对着镜头说话的录音要剪成能发布的视频。**不走这条**：只想从长视频里挑几段短视频（第 5 条）；只要去掉一处口误（直接剪那一处）。

| 信号 | 处理 | 原因 |
| --- | --- | --- |
| 没有转写 | 先转写 | 口播的剪点由话决定，没有转写就是瞎猜 |
| 同一段说了几遍 | 挑最完整、最自然的一遍，拿不准都留着请用户听 | 提案不检测重复的句子 |
| 想把一句挪到开头 | 只挪能单独成立的原话，限定语一起带走；先问清原位置留不留 | 调序会改变论证 |
| 要加放大、B-roll、文字 | 剪口定下之后再加 | 话没定下来，定不了画面落在哪 |

步骤：

1. 读 {{skill:talking-head-cut}}。
2. 没有转写时 {{tool:transcribe}}；{{tool:documents_read}} 读转写，按论点列出留 / 删清单。
3. {{tool:edits_apply}} 生成口癖与停顿的剪辑提案，{{tool:documents_read}} 读提案，逐条决定。
4. 把清单作为一笔修改提交（{{tool:edits_apply}}，先带预检看影响）：接受该删的建议、剪掉录废的部分。
5. 定开头；剪口定下后再加画面元素与声音处理（craft 的 `references/` 里有做法，用到时再读）。
6. 读回：{{tool:videos_inspect}} 看时长与片段，对照清单核对；导出一小段给用户听（{{tool:export}} 给范围）。
<!-- surface: cli -->
   用户要自己在编辑器里听、拖剪点时，交付时给一条网页版编辑器的新链接（[web](catalog/web.md)）；用户在网页里改过之后，下一笔修改前重新 {{tool:videos_inspect}}。
<!-- /surface -->
7. 有译文时按第 2 条只重译变了的句子。

**完成标准**：清单上该删的都删了、该留的都在；剪点在词与词之间；报告分三栏，剪口数与时长变化是量出来的，顺不顺是要人听的。

## 5. 切短视频

**适用**：从一个长视频（访谈、讲座、直播回放）里挑几段能单独发布的短视频。**不走这条**：从零做一条新的短视频；把整段口播剪干净（第 4 条）。

| 信号 | 处理 | 原因 |
| --- | --- | --- |
| 用户给了目标平台 | 按平台确认画幅与时长 | 合要求 |
| 候选片段开头不成立（要靠前文才懂） | 换一段，或向前多取一句 | 每段要能单独成立 |
| 片段比目标时长短 | 照实交，不靠填充、循环、变速凑数 | 时长是目标不是配额 |
| 用户还没挑 | 只交候选，不导出 | 让用户挑定再出文件 |

步骤：

1. 读 {{skill:shorts-segments}}。
2. {{tool:export}} 导出带时间码的文稿（或字幕），读出来按话题挑候选：每段是一个话题从钩子到讲完，几支、多长照用户说的，没说就按够格的话题定，交给用户挑。
<!-- surface: cli -->
   用户想在编辑器里边看边挑时，给一条网页版编辑器的新链接（[web](catalog/web.md)）；候选的起止仍写在文字里交给用户。
<!-- /surface -->
3. 用户挑定后 {{tool:export}} 成片，每段一个范围、各出一个文件。
4. 要竖屏又要重新取景时，先在视频里调整画面（[editing](catalog/editing.md)），再导出。

**完成标准**：每段的起止、时长与一句理由交给了用户；导出的文件一段一个、路径取自结果；画幅与用户确认的一致。

## 6. 总结与写稿

**适用**：总结、提炼要点、写成博客或公众号文章、起标题与写简介、分章节。**不走这条**：与视频无关的写作。

| 信号 | 处理 | 原因 |
| --- | --- | --- |
| 要总结、要点 | {{skill:video-summary}} | 要点带视频时间，方便跳回 |
| 要完整文章 | {{skill:video-blog}}，先问清是作者视角还是观众视角 | 两种写法不同 |
| 要标题、简介 | {{skill:titles-and-description}} | 每句都要由视频兑现 |
| 要章节写进视频 | 作者有章节或用户给了大纲：{{tool:chapters_adopt}}；否则按 {{skill:video-chapters}} 自己分 | 章节是视频的一部分；作者的分法优先 |
| 没有转写 | 先转写 | 不凭标题与印象写 |

步骤：

1. 读对应的 craft。
2. 取带时间的文稿：{{tool:export}} 导出带时间码的 md 文稿，读结果里的文件；时间就取它，不自己估。
3. 自己写。总结、文章、标题、简介是纯文字，直接交给用户（用户要文件时写成文件）。
4. 章节：作者的章节用 {{tool:chapters_adopt}} 吸到文稿上写入，读回执里的吸附统计；自己分的用 {{tool:edits_apply}} 的 `setChapters` 写入，读回执核对。

**完成标准**：每条要点、每个章节的时间都来自文稿；写的内容由视频兑现，没有编造；章节写进了视频并读回核对。

## 7. 本机文件：压缩、合并、提取音频

**适用**：用户要把本机文件压小、转成别的编码、按顺序拼成一个、取出音轨，不需要可编辑视频。**不走这条**：要在拼起来的视频上继续剪辑或加字幕（新建视频，把几段素材依次放上时间线，见 [media](catalog/media.md)）。

| 信号 | 处理 | 原因 |
| --- | --- | --- |
| 「压小一点」没给数 | 先问目标（分辨率上限或大致大小），或按 1080 高度给一个默认并说明 | 合要求 |
| 合并的几段参数不同 | 照样合并，会重新编码，耗时更长 | 参数一致时才能流复制 |
| 要提取音频 | 逐个取出音轨 | 能流复制时不重新编码 |
| 用户的原文件 | 不动，输出写到新位置 | 不动用户的原始媒体 |

步骤：

1. 确认输入文件、顺序与输出位置。
2. {{tool:transcode}}：压缩、合并或提取音轨，等到完成。
3. 把结果里输出文件的路径告诉用户，报告大小与时长的变化。

**完成标准**：输出文件存在、路径取自结果；原文件没动；大小、时长、分辨率等量出来的数报告给用户。

## 8. 旁白成片

**适用**：用户要一条由旁白带着走的成片（资讯快评、知识讲解、产品介绍、步骤教程），或给已有画面配一段多句的旁白。**不走这条**：把视频配成另一种语言（第 3 条）；只念一句话（直接 {{tool:speak}}，见 [voice](catalog/voice.md)）。

| 信号 | 处理 | 原因 |
| --- | --- | --- |
| 用户给了目标时长 | 先用这个模型念一句量出字/秒，再按它算稿子字数 | 字数定时长；写超了删句，不加速 |
| 旁白超过 60 字 | 选用户库克隆音色或 `source` 为 `builtin` 的内置音色 | 预置说话人块间音高漂 3–5 个半音，像换了人 |
| 用户点名要预置说话人 | 照用，报告里写明风险 | 用户的明确要求优先 |
| 念出来比目标长 | 删词重配那一段 | 时间线变速会放大本来的快慢差 |
| 某一句不自然 | 只重配那一句（同音色、同说明、换 seed） | 整段重配会把别的句子一起换掉 |
| 稿子里有数字、专名 | 写成读法或用读音标注 | 念错比念慢更伤 |

步骤：

1. 读 {{skill:narration}}。
2. {{tool:models_capabilities}} 看语音合成能不能用、哪些音色是 `builtin` / `library`；用一句试稿 {{tool:speak}} 量出字/秒。
3. 按预算写稿，一句一行；语气说明只写怎么说。
4. {{tool:speak}} 整段提交（同音色、同说明、固定 seed，给 {{arg:video}}），等到完成，记下时长与 seed。
5. {{tool:transcribe}} 给这个旁白素材拿字时间；按句算字/秒与停顿，找出要重配的句子并重配。
6. {{tool:edits_apply}} 把旁白放上一条轨，按句子的起止排画面与字幕。要配乐时这时再生成或放上（成片时长已定），按 [music](catalog/music.md) 放在单独一条轨上、`setDucking` 压在旁白之下。
7. {{tool:export}} 导出 2–3 处跨句边界的 5 秒片段给用户听；用户认可后再导出成片。
<!-- surface: cli -->
   画面与字幕的排布要用户看时，在网页版编辑器里请用户审（[web](catalog/web.md)），交付时给新链接。
<!-- /surface -->

**完成标准**：稿子字数在预算内、成片时长与旁白时长一致；一个音色、一套说明、seed 记录在报告里；每句的字/秒与停顿量过，异常句处理过或列出；接缝是**要人听的**，没听过就如实写。

## 9. 歌曲 → MV 或歌词视频

**适用**：用户给一首歌（多半还有歌词），要做 MV 或歌词视频，可能要双语字幕。**不走这条**：只要歌词的时间文件（{{tool:transcribe}} 加 {{arg:noVideo}}，再按 [subtitles](catalog/subtitles.md)「已有正文时」换成原文）；没有歌、要配乐的成片（第 8 条或 {{skill:video-production}}）。

| 信号 | 处理 | 原因 |
| --- | --- | --- |
| 用户给了歌词 | 歌词是正文，转写只取时间 | 唱的字常听错，外语句子会被整句认成别的话 |
| 音频文件自带歌词或字幕轨 | 文字可用，时间核对后才用 | 时间常是占位 |
| 歌词里有 `[Verse]`、`[Chorus]` 与舞台说明 | 不上字幕，用来给画面分段 | 不是唱出来的 |
| 有几行在转写里找不到 | 不估时间，请用户给时刻或不上字幕 | 底线：不编造时间戳 |
| 画面里的人要对口型唱 | 做不到，改成画面配梗、字幕承担歌词 | 没有口型同步的视频生成 |
| 用户只要一个由代码直接渲染的文件 | 在 BaoCut 之外渲染 | 进视频的代码画面才走代码包 |
| 用户给了参考视频 | {{tool:videos_shots}} 找切换，在两次切换之间用 {{tool:videos_frames}} 密集取帧，按时间段记下机位、动作、图层与图形怎么走；学它的调度，计划自己写 | 稀疏的几帧看不出动作与运镜；照搬就不是用户的片子 |
| 用户要一段节选（「15 秒左右」） | 起止落在完整的一句或一段歌词上 | 按秒数硬截会切掉最后一句 |
| 图片生成要花钱（{{tool:models_capabilities}} 的 `cost`） | 计划里写清要画几张、大约花多少，留几次重画的余量 | 用户批计划时就知道花费 |

步骤：

1. {{tool:transcribe}}，{{arg:file}} 给歌：新建视频、歌放上时间线；给 {{arg:language}}，加 {{arg:noCaptions}}，字幕层等写回原文之后再建。
2. 读转写，按 [subtitles](catalog/subtitles.md)「已有正文时」把歌词逐行对位，按 {{skill:polish-transcript}} 写回原文；对不上的行列给用户。
3. 要双语时按 {{skill:translate-subtitles}} 自己译，{{tool:captions_create}} 给译文建字幕层（{{arg:bilingual}}）；只要原文时给转写建。
4. 读 {{skill:video-production}}：风格、创意方向（梗与回收）与每段的画面先写成计划，整首歌按整帧分段，从第 0 帧排到结尾、每帧恰好属于一段；开头样段带上第一次高潮，定下质感。代码画的场景按它第 5 节「代码画面」一条去读代码场景的细则；角色与场景底图按 [media](catalog/media.md)「生成图片」的「成套素材」画，角色一张图一个，同框在代码里摆。
5. 第一帧是完整的封面；片尾署名逐字照用户给的。
6. {{tool:export}} 先导出几段预览看画面跟不跟拍，再导出成片。

**完成标准**：字幕的文字与用户的歌词逐字一致，对不上的行已告诉用户；整首歌每一帧恰好被一段画面覆盖，结尾也在，歌是一整段没切开的音频；每句的画面不越过所在段落；封面在第一帧；画面跟拍与字幕位置是**看过的**或如实写没看。

## 10. 音频 → 视频：背景、声波、字幕

**适用**：用户给一段说话的音频（播客、访谈、讲座、口述录音、档案录音），要做成能发的视频：背景、跟着声音动的声波、字幕，按内容加配图与章节。起始页「音频转视频」那句话就是这件事。源是一段说话的影像（历史演讲、讲座、新闻片），要排成同样的版面、影像只占其中一格时，也走这条。**不走这条**：歌曲做 MV 或歌词视频（第 9 条）；要按内容一镜一镜配画面的成片（{{skill:video-production}}）；只要文稿或字幕文件（{{tool:transcribe}} 加 {{arg:noVideo}}）。

背景、声波、字幕与配图是同一张版面：先按 {{skill:motion-graphics}} 的「内容背景」定方案与格子，各层的坐标从格子换算。版式不照搬示例，按这一期的内容重想。

| 信号 | 处理 | 原因 |
| --- | --- | --- |
| 声波 | **只用**内置的声波元素（[editing](catalog/editing.md)「声波与进度条」）：不写代码包、不按 {{skill:motion-graphics}} 写 HTML、不分析音量 | 默认样式与摆位见 editing「默认声波」；一笔修改就在画面上、跟着声音动，用户能换款改色；代码包要把整段音频渲染完，长录音要等很久，字幕也被堵在后面 |
| 用户要的声波样子内置款式里没有（品牌动效、特殊造型） | 仍用内置元素：挑最接近的款，用颜色与 `place` 调；告诉用户内置能换款、改色、挪位置，不改用代码包 | 代码包画的声波渲染慢、用户改不了，这条路不走 |
| 用户没说背景 | 按「内容背景」从博客正文、转写或简报写三行方案（主题与语气、画面的隐喻与视觉重心、取自本期的母题），据此定色、字与格子，HTML 只画不变的框架，截成背景图 | 未指定背景也需要设计判断；不同内容各有方向，纯色只在用户要简洁或内容适合时用 |
| 声波与字幕的颜色、字与位置 | 跟背景同一套：声波 `mainColor` 取强调色、`secondaryColor` 取中间调，位置与大小按格子；字幕的字色、字体、字重、行高、对齐与位置用 `setCaptionStyle` 按格子写（[subtitles](catalog/subtitles.md) 的样式键）；缺省样式把念到的词染成青绿，同一份 `style` 里写 `wordAnimation: {"catalogId": "none"}` 不高亮，要 KTV 改写 `textMotion: {"karaoke": {"color": …}}`，念过的颜色与 `fontColor` 都取方案里的 | 缺省的青绿声波、底部居中的白字黑描边只配深色底；不跟着改就显得拼凑 |
| 字幕的角色 | 方案定：底部一两行的配角，或版面正中的大字主文（书页、引文式的版式） | 说话的视频，字幕常常就是画面的主体 |
| 录音的语言与观众不同（外语录音给中文观众，或反过来） | 转写加 {{arg:noCaptions}}（[subtitles](catalog/subtitles.md)「要译文或双语字幕」）；润色后按 {{skill:translate-subtitles}} 译成观众的语言，{{tool:captions_create}} 给译文建字幕层做主文；版面给原文留了辅行的位置时才加 {{arg:bilingual}}（两层共用一份样式，译文大、原文小）；原文辅行要换字色、字号，或单独摆进另一格，用 `setCaptionStyle` 的 `origStyle` 写（[subtitles](catalog/subtitles.md) 的样式键） | 观众读的是译文；两层字幕不抢同一块位置 |
| 转写里说到具体的人、刊物、作品、事件、地点 | 按「内容背景」的「随内容换的层」：{{tool:assets_search}}（`kind: image`，英文 query）找许可干净的图，从被说到时起放到下一张出现，旁边写名称、年代与「来源 · 许可」；找不到合适的就不放 | 画面跟着说的内容换，观众知道在讲谁；署名与许可是用图的条件 |
| 视频分了章（第 5 步按 {{skill:video-chapters}} 分；只有一章或录音很短时不分） | 在标题区放章节文字当副标题：文字实例写 `chapter`（标题、编号或提要），从第 0 帧铺到片尾，跟着章节自己换字；录音要翻译时，章节的标题与摘要用观众的语言写（「内容背景」第 6 节） | 长录音有路标；章节不是必选，没有就留给本期标题；画面上的章节文字就是视频的章节，和字幕主文同一种语言 |
| 源是说话的影像，要排进版面（旧影像、低清、4:3，或用户要这种版式） | 按「内容背景」第 9 节：影像改成画中画放进一格，裁掉黑边与脏边，配窗框，调色与版面一致；背景图放上后再一笔挪到影像下面；字幕、配图与章节排在窗外；声波可以不放 | 旧影像铺满会糊，两侧黑边像没做完；窗外的版面放字幕、译文与背景信息 |
| 版面另有计时，或声波收得很窄 | 计时用文字实例的 `counter`（`mm:ss`），声波写 `visualizer.readout: false` 去掉框下的进度线与读数 | 画面上不出现两个时间，窄声波下的小字也看不清 |
| 同一档节目的又一期 | 沿用上一期的背景源码与配色，只换本期标题与母题 | 系列要认得出是同一档 |
| 用户给了图片，或要一张生成的背景图 | 图片放在最下面的画面轨，铺满（`setStyle` 的 `fullscreen` 加 `cover`）并拉到片尾 | 一张静图撑全片 |
| 要片名之类的字 | 按内容与版式起标题；需要独立改字时用文字实例（`insertItems` 的 `text`），也可随 HTML 背景设计并保留源码 | 标题与画面形成整体；保留后续修改的途径 |
| 要润色（默认），录音与观众同一种语言 | 转写不加 {{arg:noCaptions}}，转完字幕就在画面上；润色写回时 Runtime 在同一笔里跟着改字，不用删掉重建 | 用户在编辑器里等字幕，转完就能看 |
| 用户说不用润色 | 同样不加 {{arg:noCaptions}}，跳过润色 | 少一步 |
| 用户没说画幅 | 横版：{{tool:transcribe}} 新建的视频就是 1920×1080；要发竖屏平台时 `updateSequence` 改成 1080×1920 | 播客类多是横版 |

步骤：

1. {{tool:transcribe}}，{{arg:file}} 给音频或影像：新建视频、素材放上时间线、转写并建字幕层（不加 {{arg:noCaptions}}；要翻译时加，见上表）。不等转写完：{{tool:jobs_wait}} 短等一下，任务记录的 `videoId` 在建好视频那一步之后就有。
2. 转写进行时先放内置声波（源是影像时按方案定，可以不放）：{{tool:videos_inspect}} 拿版本、画面轨与 `sequence.durationFrames`，用 {{tool:edits_apply}} 放上。声波 `span` 从第 0 帧铺到片尾，放在同一笔 `addTrack` 新建的画面轨上；默认声波与摆位按 [editing](catalog/editing.md)「默认声波」；用户指定其他款式时同样放在字幕之上，竖版放在画面中上。已有博客或简报时先定方案，声波一放就用方案的颜色与位置。
3. 定方案、做背景：读 {{skill:motion-graphics}} 的「内容背景」，按博客、简报或转写的开头写方案与格子，HTML 截成背景图，放在声波与字幕之下的独立画面轨，声波不合进 HTML。源是影像时按第 9 节把影像放进窗，背景图放上后再一笔挪到最下面。声波的颜色、位置或 `readout` 要改时，同一笔里删掉它、按原 `span` 带上新的 `place` 与属性重新放。
4. 等转写完成，按 {{skill:polish-transcript}} 润色写回、给说话人实名。不翻译时字幕层已在画面上，文字在同一笔里跟着改，时间与切条不动；转写几乎没有句末标点、润色补了很多句末标点时，字幕条仍是按宽度和停顿切的：问过用户再删掉这层，{{tool:captions_create}} 按润色后的转写重建。翻译时润色后按上表译好、给译文建字幕层。然后用 `setCaptionStyle` 按方案与格子改字幕的字、色、描边、投影、底板、对齐与位置，竖版同一笔把字幕挪出平台控件区；当前词的青绿高亮在同一份 `style` 里按上表换掉（不高亮写 `wordAnimation`，KTV 写 `textMotion.karaoke`），颜色取方案里的。
5. 旁路：章节与视频速览，不挡字幕和导出。章节不会自动出现：转写润色后按 {{skill:video-chapters}} 自己分、写进视频。要翻译时等译文写好再写章节，标题与摘要用观众的语言，人名、术语跟译文一致；作者的章节先带 {{arg:dryRun}} 调 {{tool:chapters_adopt}} 看回执的 `rows`，再用 {{arg:outline}}（`[{ at: sourceAt, title }]`，标题换成观众的语言）正式采用。
6. 随内容换的层：读润色后的转写，列出说到的人、刊物、作品、事件与地点和时刻，按「内容背景」找图、放图与说明；有章节时加章节小标题（一个 `chapter` 文字实例铺满全片，不按章拆）；需要时加计时。同时出现的文字各放一条轨道。用了 cc-by-sa 或署名要求特殊的图，交付时告诉用户。
7. 看画面：导出一小段预览（{{tool:export}}，{{arg:purpose}} 为 `preview`，用 {{arg:ranges}} 取几段）抽开头、中间、结尾几帧，核对背景、标题、声波、字幕与配图是一套颜色、对得上格子、像这一期的内容；文字可读、声波在动且不压字幕、背景铺到片尾。{{tool:videos_frames}} 的帧里没有声波、字幕与文字实例。交付时一句话说明这期的视觉方向与理由。
8. 用户要成片：{{tool:export}} 导出 mp4。长录音的导出要一阵子，提交时告诉用户。

**完成标准**：音频是一整段没切开的；源是影像时，影像在自己那一格里，没被拉伸、没盖住字幕，黑边裁掉，出处写在画面上；背景与标题按本期内容定的方案做，声波、字幕与配图的颜色、字与位置跟它一套，第一帧就是完整画面；背景与声波（源是影像时可以没有）从第 0 帧铺到片尾，声波是内置元素、跟着声音动、不压字幕；转写润色过，画面上的字幕是方案选的那一层（原文，或观众语言的译文）；每张配图都写了来源与许可；有章节小标题时用的是章节文字、与视频的章节一致，语言与字幕主文相同；各层的位置是**看过的**或如实写没看。
