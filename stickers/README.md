# Bundled stickers

The sticker packs shown in the editor's Elements panel. There are 301 static SVGs (`<pack>-<file>.svg`) and 81 Lottie animations (`anim/dyn-<pack>-NN.json`).

`hosts/` holds the 19 built-in virtual hosts: layered character packages (`host-<id>.bcpuppet`, see `docs/spec/puppet-format-spec.md`) and a rest-pose thumbnail for each (`host-<id>.webp`, 256×384). Their catalogue (names, style, look) is `BUILTIN_HOSTS` in the same protocol file. The agent reaches them through `hosts_list` and `hosts_show`.

- The catalogue (packs, files and search words) is `packages/protocol/src/sticker-packs.ts`. Pack names are in the UI's `sticker-pack-copy.*.ts`.
- The Runtime finds this directory through `resolveStickerPacksDir`. The lookup order is `BAOCUT_STICKERS_DIR`, then `<resources>/stickers` in the packaged app, then this directory.
- The packaged app doesn't ship the Lottie files or the host packages, only `anim/provenance.json` and `hosts/provenance.json` (each file's `bytes` and `sha256`) plus the host thumbnails. The Runtime downloads a file from the asset CDN (`<BAOCUT_ASSETS_URL or https://cdn.baocut.com>/stickers/anim/<id>` or `/stickers/hosts/<id>`) the first time it's needed, checks it against the manifest and keeps it in `<home>/cache/online-assets/`. In development the files here are used directly. `npm run stage:online-assets -- <dir>` lays out the files for upload; a changed file needs a new name, because the CDN path is the cache key.
- Adding a sticker copies its bytes into the video (`stickers.applyToVideo`, managed storage). A video never points back here.
- The prototype keeps a byte-identical copy in `designs/baocut/assets/stickers/` (for `hosts/`, only the thumbnails and the manifest). `packages/runtime-core/src/templates/sticker-packs.test.ts` checks that the two copies match.

Static SVGs keep their flat fills, so each element can recolor them (`sticker.fillOverrides`, keyed by the source `#RRGGBB`). Lottie stickers carry their own clock (`sticker.loop`).
