# 从长视频里切短视频

> 用户有一个长视频（访谈、讲座、直播回放、口播），想从中挑出几段能单独发布的短视频时用：读转写挑出 3–5 段各自成立、开头有钩子的片段，交给用户挑，再按片段导出成单独的文件。需要视频的转写。不用于按主题从零做一个新的短视频，也不用于把整段口播剪干净（用剪口播）。

刷到这条短视频的人没看过长视频，也不知道前面讲了什么。头三秒没抓住他，他就划走了；中间出现「刚才说的那个」，他就不知道在说什么。所以一段短视频要自己站得住：开头就是钩子，只讲一件事，停在结论上。

最容易挑坏的样子：按长视频的章节切。一章十分钟，开头铺垫三句才说到点子上，结尾停在「接下来我们看」，里面还夹着两个亮点。那是长视频的一段，不是一条短视频。

## 1. 先有转写

没有转写（kind 为 speech 的文档）时先转写，告诉用户转写在进行。挑片段只需要原文的词时间；润色和翻译只在用户要时才做。视频已经有章节时，章节有助于定位话题，但章节的边界不是短视频的边界。

## 2. 读文稿，挑片段

读带时间的文稿：`baocut export` 导出字幕（kind `subtitles`、format `srt`）或带时间码的文稿（kind `transcript`、format `md`、timestamps `true`），`baocut jobs inspect` 等到 completed，读 outputs 里的文件。这些时间是剪辑后时间线上的时间，和下面取帧、导出用的范围是同一个时钟。

挑 3–5 段（用户说了个数就照它），每段单独看得懂。时长按用户给的范围；没给时每段 20–60 秒，30–50 秒更好：

- **在文稿里找这四种**：反常识的说法、情绪的高点、密集的干货、带转折的小故事。文稿只是线索：找到之后，用 `baocut videos frames` 在那几秒取几帧看画面（有没有可看的、说话人在不在画面里），再结合上下文判断是认真说的还是玩笑，然后列为候选。帧是素材画面，不含字幕与叠加的元素。
- **一个短视频只讲一件事**：一段里有两个亮点时，拆成两个短视频，或只留一个。
- **开头那句就是钩子**：一个反直觉的结论、一个具体的数字、一个问题。一段要铺垫三句才说到点子上，就把起点往后挪，或者不要这一段。
- **结尾自成一体**：停在结论或包袱上，不停在「接下来我们看……」这种半句话上；结尾是「关注、订阅」一类的话时，把终点提前到上一句。
- **不依赖上下文**：没有「刚才说的那个」「第二点」这类要看前面才懂的指代。
- **开头 3 秒要有人说话**：没有时把起点挪到第一句话；不在前面加标题卡。
- **入点与出点落在句子边界**：入点取开头那句第一个词与它前一个词之间停顿的中点；出点取最后一个词与下一个词之间停顿的中点。不切进词里。
- 视频剪辑过时，文稿里的时间已经是剪辑后的；用户想按剪辑前的原素材切时，先和用户确认用哪个版本。

对比一下（只是示意）：

不好：`12:00–14:30`，从「好，那我们接下来聊聊成本这块」开始，到「这个我们待会儿再展开」结束。

好：`12:41–13:22`，从「我们算过，一条视频的成本其实只有三块钱」开始，到「所以贵的从来不是生成，是返工」结束。

后一段头一句就是数字，停在结论上，中间没有指代前文的话。

## 3. 交给用户挑

每段告诉用户：入点与出点、开头那句原话、亮点（一句话）、为什么能单独成立、发现的问题（例如画面上有烧进去的字幕、分屏或并排的双机位、角落的台标或赞助条，竖屏裁切时会被切掉一半；访谈里另一人说话时画面里没有说话人）。取了帧的说看了哪几处；没看过画面的就说没看过。

按把握从大到小排。**先让用户挑**；只有用户说「你定」时才自己定，并说明理由。标题和理由用用户说话的语言写。

## 4. 导出

用户挑定之后，用 `baocut export` 导出成片：kind `video`、format `mp4`，ranges 里每段一个 `{start, end}`（时间线上的秒），每段出一个文件。`baocut jobs inspect` 等到 completed，把 outputs 里每个文件的 path 告诉用户。

- 时间线上的字幕默认烧进成片（burnCaptions）；用户不要字幕时给 `false`。
- **画幅**：导出保持视频的画幅。给出与画布比例不同的 width、height（例如横屏视频出 1080×1920）时，画面按比例放到最大、居中，其余是黑边，不裁切。这里没有按人物位置自动裁成竖屏、跟随说话人取景的功能：用户要铺满的竖屏时如实说明，请用户在编辑器里自己调画幅后再导出，或接受横屏原比例、带黑边的竖屏。
- 不要为了「高清」把小尺寸放大：放大只会更糊。
- 去口癖、收紧停顿会改动整个视频，不在这里做；用户要时先说明影响，按剪口播的做法处理。

## 5. 要避免的

- 不要按章节切，不要让一段里有两个亮点。
- 不要从铺垫开始，不要停在半句话或「关注订阅」上。
- 不要留着「刚才说的」「第二点」这类指代。
- 不要切进词里；不要在前面加标题卡。
- 不要替用户定，除非他说「你定」；不要把没看过的画面说成没问题。
- 不要承诺铺满的竖屏裁切。

## 6. 交付

每个短视频一段，写给用户挑选：

- 文件路径、在视频里的入点与出点、时长、画幅与分辨率。
- 开头那句原话。
- 做了什么、没做什么：画幅（原比例 / 带黑边的竖屏）、字幕（烧进 / 没烧），各一句。
- 发现的画面问题（烧进去的字幕、台标或赞助条、分屏或相邻画面、插话时说话人不在画面里）：有就写；看过而没有写「没看到」；没看画面就写没看。
